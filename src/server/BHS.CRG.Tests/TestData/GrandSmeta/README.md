# Образцы файлов ГРАНД-Сметы

Настоящие файлы заказчика — подборка для разбора `plan-05-grand-smeta-reader` (`PLAN-7`; вопрос
`PLAN-Q19` / В-11 закрыт 22.10.2026). Переданы владельцем 22.10.2026.

⚠️ **Файлы лежат КАК ЕСТЬ, побайтно**: не обезличены (репозиторий закрытый) и не пересохранены. В каждом
есть `Data.sign` — подпись GrandSmetaSign над `Data.xml`: любая правка файла её ломает, а разбор обязан
видеть ровно то, что пишет программа сметчика. Переименованы только сами файлы — в короткие латинские
имена `<вид>-<версия программы>-<суть>.gsfx`. `.gitattributes` держит `*.gsfx` бинарными.

## Что внутри файла

`.gsfx` — ZIP из трёх частей, у части ВОР ещё вложения:

- `Properties.txt` — windows-1251, строка `DocType=`: `sdtSmeta` (ЛСР), `sdtMarketAnalysis` (КА),
  `sdtWorksVolumes` (ВОР);
- `Data.xml` — windows-1251 (`encoding` в прологе), корень `<Document Generator="GrandSmeta"
  ProgramVersion="…" DocumentType="{GUID}">`; GUID вида: ЛСР — `{2B0470FD-477C-4359-9F34-EEBE36B7D340}`,
  ВОР — `{…-EEBE36B7D350}`, КА — `{…-EEBE36B7D354}`;
- `Data.sign` — подпись;
- `Attachments/<GUID>/*.pdf` — только у ВОР с вложениями (чертежи-обоснования); в `Data.xml` им отвечают
  элемент `Attachments` с `Binary` и ссылки `SupportingDocs` у позиций.

## Эталоны

`<образец>.etalon.json` — контрольные точки разбора ко всем 14 образцам подборки (plan-05, вариант Г): вид,
версия, реквизиты, счётчики, итоги документа и разделов, 3–6 позиций каждой формы позиции. Сняты скриптом
`etalons_from_forms.py` с **печатных форм программы** (xlsx), а не с XML образца: форма — собственное
прочтение файла программой, и эталон по XML повторил бы ошибки разбора. Формы — данные заказчика, в
репозитории их нет: `E:\Development\Office\BHS.CRG-research	estdata\grand-smetaorms\`. Пересобрать:

```bash
python -X utf8 etalons_from_forms.py "E:/Development/Office/BHS.CRG-research/testdata/grand-smeta/forms"
```

Руками эталоны не правят: расхождение разбора с эталоном разбирают и чинят разбор (или скрипт снятия).
Сверка — `GrandSmetaEtalonTests`. Числа в эталоне — строками, как в ячейке формы.

`official-2026.2.3/` — официальные схемы разработчика программы как есть: только ради сверки «официальная
отвергает, своя пропускает» на каждую правку BHS-N (`GrandSmetaSchemaTests`); разбор идёт по своей редакции
(`BHS.CRG.Modules.Plan/GrandSmeta/Schemas`).

Тесты читают файлы из репозитория через
`RepoPaths.File("src", "server", "BHS.CRG.Tests", "TestData", "GrandSmeta", …)` — в выходную папку они не
копируются.
