# e2e — живые smoke-прогоны

Дополняют юнит-тесты (`vitest`): проверяют то, что видно только в браузере. Общая
обвязка (поиск Playwright и браузера, вход, учёт проверок) — в `harness.mjs`.

## Клавиатурный smoke (`keyboard-smoke.mjs`, issue #107)

- **login-token** — вход по форме кладёт `access_token` в localStorage;
- **tab-focus-visible `<route>`** — на ключевых экранах (`/`, `/document-sets`,
  `/common-data`, `/quality-docs`, `/settings`) первый `Tab` уводит фокус с `body` на
  элемент, соответствующий `:focus-visible` (кольцо фокуса реально видно);
- **ctrl-k / palette** — `Ctrl/⌘+K` открывает командную палитру, её поле получает
  фокус, `Esc` закрывает;
- **question / help** — `?` на неполевом фокусе открывает шпаргалку, `Esc` закрывает.

## Маршрутный smoke (`routing-smoke.mjs`, issue #694)

Маршрутизация не покрыта юнит-тестами и живёт на внешней библиотеке, которая
обновляется мажорными версиями. Прогон проверяет то, что ломается при таком обновлении
в первую очередь:

- **protected-redirects-to-login** — закрытый адрес без токена уводит на вход, причём
  средствами маршрута: если бы это делал отлуп сервера, в прогоне был бы 401;
- **login-redirect-replaces-history** — редирект сделан `replace`, а не `push`
  (иначе «назад» возвращает на закрытый адрес и запирает в цикле);
- **login-lands-on-workspace** — после входа пользователь на `/document-sets`;
- **navlink-navigates-and-marks-active** — `NavLink` переходит и помечает ровно один
  пункт `aria-current="page"`;
- **history-back-forward** — «назад»/«вперёд» браузера ходят по маршрутам;
- **nested-route-params / nested-route-cold-load** — вложенный `<Routes>` раздела
  «Стройки» разбирает параметр пути и при клике, и при холодной загрузке адреса;
- **search-params-are-read** — страница действительно читает query (считаем запросы к
  серверу: без параметров запроса нет, с параметрами есть — по тексту ошибки эти два
  случая неотличимы);
- **palette-navigates** — программная навигация из командной палитры;
- **leave-guard-intercepts-nav** — при несохранённых правках переход по сайдбару
  перехватывается диалогом, а адрес не меняется;
- **admin-route-blocks-user** — не-администратора уводит из раздела настроек.

Проверки писались «от обратного»: каждая проверялась поломкой того, что стережёт, и
должна была упасть. Три первоначальных редакции падение не ловили — утверждение об
отсутствии текста проходит и на пустом экране. Если добавляете проверку, ломайте
поведение и убеждайтесь, что она краснеет.

## Предусловия

Подняты фронт (`:5173`) и бэк (`:5000`):

```bash
docker compose up -d                             # postgres + minio
dotnet run --project ../server/BHS.CRG.Api       # :5000
npm run dev                                       # :5173 (этот пакет)
```

Маршрутному прогону нужны демо-данные: хотя бы одна стройка и хотя бы один тип поля.

Playwright берётся из npx-кеша, браузер — из `ms-playwright` (пути резолвятся
динамически). При нестандартном расположении переопределите:
`PLAYWRIGHT_PKG` (путь к `playwright/index.js`) и `CHROMIUM_EXE`
(путь к `chrome-headless-shell.exe`).

## Запуск

```bash
# из src/client, Git Bash (MSYS_NO_PATHCONV — чтобы MSYS не переписал пути в аргументах)
MSYS_NO_PATHCONV=1 npm run test:e2e:keyboard
MSYS_NO_PATHCONV=1 npm run test:e2e:routing
```

Учётка по умолчанию — админ `admin@bhs.local` / `Demo12345!` (переопределяется
`SMOKE_EMAIL` / `SMOKE_PASSWORD`), адрес — `SMOKE_BASE`. Маршрутному прогону нужна ещё
учётка с ролью «Пользователь» — `SMOKE_USER_EMAIL` / `SMOKE_USER_PASSWORD`
(по умолчанию `petrov@bhs.local`).

Код возврата `0` — все проверки прошли, `1` — есть провал (имена провалов печатаются).
