# Вехи PR — выбор варианта А

22.11.2026 владелец выбрал **А — вехи внутри change**: «давай вариант А, переноси
на всю карту, статусы из OpenSpec и даты Claude сохраняем».

До реализации подготовлены три интерактивных макета на живой дизайн-системе:

- **А:** привычный порядок зонтика, под каждым change отдельные вехи PR;
- **Б:** очередь доступных работ двумя потоками Work и Plan;
- **В:** список вех и панель зависимостей выбранного PR.

В макетах использованы текущие Button, Chip, SearchInput, Checkbox, StatusText,
DataGrid, тема и шрифты BHS.CRG. Разбор выполнен исполнителем, поскольку постоянные
сессии владельца «Дизайнер» и «Архитектор» не подключены. Компоненты `shared/ui`
не меняются. Снимок задач в макетах — пример для обсуждения компоновки,
а не источник текущих статусов рабочей карты.

[Снимок выбранного варианта](variant-a.png) и [исходники всех вариантов](variants-source.zip)
сохранены здесь, чтобы решение было доступно из любой рабочей копии. ZIP содержит
пути `src/client/design-system/roadmap.html` и `src/client/design-system/roadmap/*`.
Для повторного просмотра его можно распаковать в корень рабочей копии и запустить
`npm --prefix src/client run ui:catalog`, затем открыть `/roadmap.html?variant=a`
(для остальных — `b` или `c`). Это локальный просмотр макетов, без изменения приложения.

Рабочая карта — автономный HTML в `openspec/roadmap/dist/`, собираемый стандартным
Python из текущего OpenSpec. Вариант А перенесён на все change. При этом завершённые
предпосылки свёрнуты, чтобы длинный перечень готовых опор не скрывал настоящую блокировку;
причина change раскрывается отдельно. Все задачи и даты остаются доступны.
Источник цветов — роли текущей темы клиента.

Изменения ограничены `openspec/roadmap/`, поэтому проходят как планирование
и не вызывают повышения версии приложения.
