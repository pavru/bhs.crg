# Дорожные карты BHS.CRG

Из корня рабочей копии запустите `python openspec/roadmap/build.py` и откройте
[карту этапов 3–4](dist/roadmap-3-4.html) или [карту этапа 5](dist/roadmap-5.html) в браузере. Сборщик использует стандартную
библиотеку Python 3.10+. Для просмотра достаточно одного HTML-файла.

Шаблон `roadmap.html`, сборщик `build.py` и история `claude-marks.json` хранятся
в `openspec/roadmap/`. Готовая карта собирается локально в `dist/`.

## Этап 5. Полевой API и приложение Android

Отдельная страница читает [эпик этапа 5](../changes/mob-00-epic/design.md),
его [перечень PR](../changes/mob-00-epic/tasks.md) и задачи активных и архивированных
`mob-*`. Условия вех заданы в [milestones-5.json](milestones-5.json). Пункт 0.1 зонтика
фиксирует решение по раздаче APK. После него открываются две первые вехи:
полевой контракт и локальное хранение на Android. При закрытии дочернего change
обновляют задачи, архив и галочку зонтика по тем же правилам, что у этапов 3–4.

Если PR меняет только `openspec/**` и `docs/tz/**`, он проходит как планирование.
Строгая проверка OpenSpec запускается, тяжёлые задания CI пропускаются, версия
приложения после слияния не меняется.

После обновления `tasks.md` по результатам работы пересоберите карту в той же
рабочей копии и обновите вкладку. Сборщик читает `plan-00-epic`, `work-00-epic`,
дочерние `plan-*` и `work-*`, а также `core-attachment-owner` в активных change
и в архиве. Для задач и пунктов зонтика карта читает галочки из `tasks.md`.
Для закрытия зонтика и change вне нарезки статус следует за архивом OpenSpec.

## Вехи PR и условия старта

Выбран [вариант А — вехи внутри change](design/README.md), решение владельца 22.11.2026.
Под каждой строкой зонтика показаны отдельные PR. Общие условия и проверка change
остаются отдельным раскрываемым списком; задачи между вехами не дублируются.
Плановый номер PR не равен номеру GitHub: у Work-09 PR 1 снят, остаётся веха PR 2.

Состав вех читается из заголовков разделов `PR N` в `tasks.md`. Несколько разделов
одного PR объединяются. Если PR один и разделов PR нет, в него попадают задачи,
кроме начальных условий и общей верификации. Номер задачи и ключ истории не меняются.

`milestones.json` хранит **условия, а не статусы**. Это явная карта зависимостей
по `proposal.md`, `design.md` и задачам текущих change. Упоминание другого change
в обычном тексте не становится блокировкой автоматически. После изменения плана
зависимости надо сверить и обновить вместе с ним. `fallbackPart` задаёт номер
единственной вехи, когда архивный заголовок раздела его не содержит (Work-09).

Состояния вех:

- **Задачи выполнены** — все задачи вехи отмечены в OpenSpec или закрыты указанными
  задачами отдельного архивированного change. Это не проверка
  слияния GitHub PR. Архив change и отметка зонтика показаны отдельно.
- **Можно начать** — обязательные условия выполнены для всех оставшихся задач.
- **Доступна часть** — можно начать указанные задачи; остальные ждут условий.
- **Ожидает условий** — оставшиеся задачи заблокированы названными условиями.
- **Условия не описаны** — новый change не имеет проверенного описания
  зависимостей. Карта не предлагает его как доступную работу.

Верхняя подсказка выбирает первую доступную веху, сохраняя порядок зонтика.
Фильтр «Можно начать» включает частично доступные PR. Фильтр «Ожидают» также
включает частично доступные PR и вехи с неописанными условиями.
Выполненные условия свёрнуты, невыполненные видны сразу. «Открыть условие»
сбрасывает фильтр и поиск и переводит к нужной вехе или задаче.

## Как записать зависимость

Ключ в `changes` — полное имя change или однозначное сокращение (`work-18`).
`after` на уровне change действует на все его PR; `parts.N.after` дополняет его
для PR N. Ссылка `work-18` проверяет наличие архива change, а `work-18#1` —
выполнение задач только PR 1. Так панель может ждать сервер, не ожидая архива
своего незавершённого change.

Пример условия по задачам:

```json
{
  "ref": "work-19",
  "tasks": ["1.3"],
  "label": "Владелец выбрал макет диалога закрытия",
  "for": ["1.4"]
}
```

`ref` можно опустить для текущего change. `tasks` перечисляет задачи-предпосылки;
`for` ограничивает задачи данной вехи, которые они блокируют. Без `for` условие
действует на всю веху. `1.1` — точный идентификатор, `1.` — весь раздел.
`optional: true` показывает будущую интеграцию, которая пока не мешает старту.
`parts.N.tasks` позволяет явно уточнить состав PR, `title` — его заголовок.
Статус и даты вручную в этот файл не добавляют.

## Остаток, закрытый отдельным change

`completedBy` у исходного change указывает `change`, короткую подпись `label` и
`tasks`. В `tasks` каждому номеру исходной задачи соответствует список точных
номеров задач продолжения. Карта учитывает такое закрытие, когда продолжение
архивировано и все перечисленные для этой задачи галочки стоят. Пока они открыты,
карта ведёт к продолжению и не предлагает заново начать исходную задачу.

Исходные галочки и число задач на момент архивации сохраняются. У Work-25 связь
записана в [уточнении к архиву](../changes/archive/2026-11-25-work-25-roles-e2e-violation/tasks.md#уточнение-от-27112026--остаток-закрыт-в-work-251),
а продолжение Work-25.1 показано в группе «Вне нарезки».

Сборка отвергает неизвестные задачи, ссылки, повторное назначение одной задачи
и циклические условия. Новые необозначенные change отображаются с предупреждением
о неизвестной готовности, поэтому отсутствие описания не выдаётся за разрешение начать.

Цвета автономной страницы берутся из текущего `src/client/src/theme/md3-tokens.css`;
сеть, API приложения и Node для обычной сборки и просмотра карты не нужны.

## Проверка

```powershell
python -B -m unittest discover -s openspec/roadmap -p test_milestones.py -v
python -B openspec/roadmap/build.py
node --check openspec/roadmap/roadmap.js
```

Браузерный прогон — `node openspec/roadmap/test-browser.cjs`; ему нужны существующие
зависимости `docs/tools` (`npm --prefix docs/tools ci`) и Chrome. `CHROME_PATH`
задаёт путь к другому Chromium. Проверяются состав вех, все исходные даты, поиск,
фильтры, переходы к условиям, сохранение раскрытых задач, тёмная тема и ширина телефона.

`claude-marks.json` содержит даты из `artifact_data-000.zip`, экспорт артефакта
«Дорожная карта этапов 3–4» от 16.11.2026. Они показаны рядом с соответствующими
пунктами во времени браузера. История Claude на текущий статус задачи не влияет.
