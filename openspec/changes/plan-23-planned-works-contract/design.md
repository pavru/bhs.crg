# Design: контракт «Плановые работы»

Дочерний change зонтика `plan-00-epic`, общая архитектура — `../plan-00-epic/design.md` (D10 — контракты,
D11 — право контракта, D12 — права с первым адресом, D3 — действующая редакция, D4 — деньги правом).
Здесь только решения этого change.

## Context

- Механизм контракта и `ModuleReader` — `plan-22`; признак «право контракта» — `plan-21`.
- Редакции, строки, ресурсы и метод чтения плана «по действующим» — `plan-06` (D3 зонтика: прямое
  чтение строк для сумм ловит перепись); сопоставление шифра и коэффициент пересчёта — `plan-08`;
  слой распределения — `plan-10`.
- Составы ролей уже несут коды (`plan-01`, `Api/Auth/SystemRoles.cs`); без объявления синхронизатор их
  пропускает.

## Goals / Non-Goals

**Goals:** один контракт с частями по правам; три права контракта объявлены и действуют у ролей;
потребитель при выключенном `plan` получает «не подключено».

**Non-Goals:**
- потребители — заявки (`plan-26`), «план против факта» (`plan-27`), «Ход работ» (`plan-25`), этап 4;
- опубликованный набор «Плановые работы» — `plan-28` строит его поверх этого контракта (`CORE-24`).

## Decisions

- **Интерфейс.** `IPlannedWorks.ReadAsync(ModuleReader reader, PlannedWorksQuery query, ct)`;
  `query` — стройка (обязательна), раздел стройки (необязателен), список позиций перечня
  (необязателен). Ответ `PlannedWorksAnswer`:
  - `Items`: позиция перечня, единица (классификатора), объём, распределение
    `[{sectionId | null, volume}]` — часть `volumes`;
  - `Cost`: стоимость позиции и сметная стоимость её материалов по номенклатуре
    `[{planItemId, total, materials: [{nomenclatureId, amount | not-in-estimate}]}]` — часть `cost`;
    `not-in-estimate` — смета стоимости ресурса не несёт (так бывает у базисно-индексного расчёта), и это
    не ноль. Стоимость материалов нужна «плану против факта» `costs` (`plan-27`);
  - `Materials`: `[{planItemId, nomenclatureId, quantity, unit}]` — часть `materials`;
  - `Labor`: `[{planItemId, hoursPerUnit}]` — часть `labor`;
  - `Hint`: `[{planItemId, nomenclatureIds}]` — часть `hint`;
  - `Basis`: по каким сметам и редакциям посчитано (`estimateId`, `revision`) — часть `volumes`;
  - `Unmapped`: число несопоставленных строк действующих редакций — всегда, без денег и наименований.
  Часть без права — `Hidden(permission)` из `plan-22`, а не `null` и не пустой список.
- **Право → часть.** `plan.estimate.read` открывает `volumes`, `materials`, `labor` и `hint` — всё, кроме
  денег; `plan.estimate.cost` — `cost`. Узкие права открывают по одной части: `plan.estimate.materials` →
  `materials`, `plan.labor.read` → `labor`, `plan.estimate.hint` → `hint`. Права складываются; узкие
  нужны тем, у кого `plan.estimate.read` нет.
- **Нормы трудозатрат.** `hoursPerUnit` — чел.-ч строки на её объём, пересчитанные в единицу
  классификатора коэффициентом сопоставления (D8 зонтика); строки одной позиции из разных смет —
  взвешенным средним по объёму. Иначе «по смете — фактически» завышалось бы в 100 раз (`PLAN-6.1`).
- **Только действующие.** Провайдер читает план единственным методом `plan-06` — по действующим
  редакциям; отдельного пути к строкам у него нет.
- **Объявление прав.** В `PlanModule.Permissions` три права с признаком контракта (`plan-21`):
  - `plan.estimate.materials` — «материалы позиций сметы без цен — для заявок на закупку; модуль
    „Планирование“ не открывает» (ждёт решения В-2: при ответе (б) признак снимается, и право открывает
    модуль);
  - `plan.labor.read` — «нормы чел.-ч позиций сметы без денег — для „по смете — фактически“»;
  - `plan.estimate.hint` — «наименования материалов позиций сметы стройки, без цен и количеств, —
    подсказка монтажнику».
  Всем — `ReadAllMark.Out("выдача другим модулям")`.
- **If-Match и ворота.** Нового HTTP-адреса и пишущего API нет: контракт — вызов в процессе. Ворота
  модуля `plan` правами контракта не открываются — сторож в тесте состава доступа.
- **Сторож.** `PlannedWorksContractTests`: две сметы стройки, у одной действующая редакция 2 — в ответе
  только она; несопоставленная строка — в `Unmapped`, не в `Items`; «100 м» с коэффициентом 100 даёт
  `hoursPerUnit` на «м»; только `plan.estimate.hint` — нет количеств, остальные части `Hidden`; без прав —
  все части `Hidden`; система — отказ. Тест состава `/api/account/access`: у «Монтажника» и «Снабженца»
  модуля `plan` нет. Живой хост `costs` без `plan` — «не подключено».
- **Чем ломается.** Провайдер читает строки всех редакций — план удваивается после повторного импорта.
  Право объявлено обычным — у «Монтажника» появляется пустое «Планирование».

## Risks / Trade-offs

- [Узкое право выдаст больше, чем нужно] → каждая часть — отдельный тип ответа; тест сравнивает ответ
  под узким правом с ожидаемой формой целиком.
- [В-2 решится в пользу обычного права] → снимается признак у одного права и меняется одна строка теста
  состава; контракт не меняется.
