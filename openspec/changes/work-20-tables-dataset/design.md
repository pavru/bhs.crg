# Design: таблицы и системные наборы модуля `work`

Общая архитектура — `../work-00-epic/design.md`. Здесь только решения этого change.

## Context

- Таблица модуля — одно объявление `ModuleTable` (`src/server/BHS.CRG.Modules/Tables/ModuleTable.cs`):
  `Requires`, `Isolation`, `Boundary`, колонки, служба строк `IModuleTableRows`, `RecordType`,
  `Breakdown`.
- Системный набор получается из таблицы сам:
  `src/server/BHS.CRG.Api/Modules/Tables/ModuleTableDataProvider.cs`. В MCP набор доходит через
  `src/server/BHS.CRG.Api/Mcp/DataSnapshotTools.cs`.
- Образец — `src/server/BHS.CRG.Modules.Costs/Tables/InvoiceTable.cs:220-299`. Но у счетов
  `ModuleTableIsolation.None` (`:225`): `work` — первый модуль с `PerUser` живьём.
- Сегодня служба строк получает только `Guid UserId` (`ModuleTableQuery.cs:147-149`), а граница
  выдачи — постоянная строка (`ModuleTable.cs:152`). Обе вещи меняет `work-07`, этот change их
  потребляет.
- Привязка набора с изоляцией к печатной форме уже отвергается —
  `src/server/BHS.CRG.Tests/Integration/SystemDataSetDeclarationTests.cs:273`.
- Экран записи по типу — `RECORD_ROUTES` в `src/client/src/shared/ui/recordRoutes.ts:37`. Сверка —
  `src/server/BHS.CRG.Tests/Configuration/RecordRoutesTests.cs`; каталог там собран из одного
  `CostsModule` (`:24`).

## Goals / Non-Goals

**Goals:** отчёты и строки — в таблицах, наборах, выгрузке и MCP с одной и той же изоляцией.

**Non-Goals:**
- набор «Выполненные работы» без изоляции и счётчик «не включены» — этап 6 (`WORK-36`, `WORK-37`);
- сверка `plan × work` (`CORE-32`) — этап 6: набор с изоляцией к сверке не подключается;
- сводка «сотрудник × стройка × день» — `work-23`, это свёрстанный экран, а не таблица.

## Decisions

### Ключ доступа — код модуля, отбор — параметром
`Requires: "work"`, `Isolation: PerUser`. Ключ модуля открывает таблицу любому, у кого модуль открыт:
монтажнику, менеджеру, руководителю. Что именно он видит, решает параметр доступа `work-07`.

Право контракта `work.facts.read` модуль не открывает (D3, `work-02`), поэтому Инженеру ИД таблица
закрыта без отдельной проверки.

Альтернатива — `Requires: work.report.review` — отклонена: монтажник лишился бы своих отчётов в
таблице, а руководитель с `read.all` проходил бы только через составное право.

### Колонки
- `work.reports`: дата, смена (☾ у ночной — значением колонки), сотрудник, стройка, статус, часы, момент
  подачи или автоподачи, число строк, автор ввода.
  - `RecordType: ОтчётМонтажника`, ключ строки — идентификатор отчёта.
  - `Breakdown` — строки работы отчёта.
- `work.lines`: дата, смена, сотрудник, стройка, раздел, вид работ, вариант, объём, единица, место,
  признак бригады, статус отчёта. `RecordType` нет: зерно не запись.
- Пометки очереди (`work-16`) колонкой не идут: это экран очереди, а не таблица.

### Черновик чужого отчёта (`WORK-54`)
Служба строк знает, кто спрашивает. У чужого черновика она заполняет только статус и момент
автоподачи, колонки содержимого оставляет `null`. Строки работы чужих черновиков в `work.lines` не
отбираются.

`null` у часов черновика отличим от `0`: «0 часов» — это значение принятого отчёта (`work-23`). Текст
границы выдачи говорит «черновики — без содержимого до подачи».

### Набор — тот же отбор
`ModuleTableDataProvider` передаёт параметр доступа того, кто читает набор (`work-07`). У MCP это
владелец токена (`AUTH-12.1`). Отдельной ветки отбора у набора нет, и разойтись с таблицей ему нечем.

### Ссылка в карточку — вторым из двух PR
Запись `ОтчётМонтажника` в `RECORD_ROUTES` ведёт на экран карточки `work-21`. Её вносит тот PR из
`work-20` и `work-21` (карточка), что сливается вторым: раньше ссылка вела бы на несуществующий экран.

`RecordRoutesTests` расширяется каталогом с `WorkModule`. Сверяет он в одну сторону: каждый тип с
экраном стоит за таблицей. Поэтому `work-20` без записи клиента зелёный.

### Состав PR (один)
- `Tables/ReportTable.cs`, `Tables/LineTable.cs`, `Tables/ReportTableRows.cs`, `Tables/LineTableRows.cs`
  — запросы только методом с параметром доступа (перепись `work-07`).
- `WorkModule.Tables`.
- Тесты `Work/WorkTableIsolationTests`, `Work/WorkTableDraftTests`, правки
  `SystemDataSetDeclarationTests` и `RecordRoutesTests`.
- `docs/USER_GUIDE.md`.

### Сторож
- `SystemDataSetDeclarationTests`: наборы `work.*` объявлены полностью. Набор `work.lines` к печатной
  форме не привязывается.
- `WorkTableIsolationTests`: монтажник А не находит отчёт Б отбором, ключом строки, выгрузкой и
  снимком MCP. Итоги и число строк без чужих.
- `RecordRoutesTests` с `WorkModule` в каталоге.

### Чем ломается
- Служба строк отбирает по `UserId` без стройки — менеджер видит отчёты всех строек.
- Набор читается от имени системы — агент монтажника видит все отчёты.
- Колонки содержимого у чужого черновика заполнены — нарушение `WORK-54`.

### Зависимости
`work-07`, `work-11`, `work-13`, `work-15`; ссылка — с `work-21`. Параллельно пути, этап 3 не нужен.

## Risks / Trade-offs

- [Первая `PerUser`-таблица модуля живьём — ошибки механизма всплывут здесь] → тесты изоляции на
  каждом пути ядра: таблица, строка, итог, выгрузка, набор, MCP. Сводная проверка нарушением — у
  `work-25`.
- [Таблица большая: строки за годы] → отбор и итоги — запросом к базе (`TableSql`). Индексы по
  `(construction_id, date)` и `(employee_id, date)` — в миграции этого change.
