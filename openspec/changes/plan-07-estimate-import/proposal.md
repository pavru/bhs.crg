# Proposal: импорт сметы из ГРАНД-Сметы — отчёт разбора, решение человека, редакция

Дочерний change зонтика `plan-00-epic`, общая архитектура — `../plan-00-epic/design.md` (D3, D6, D7).

## Why

Обязательный источник строк сметы — импорт файла ГРАНД-Сметы (ЛСР); повторный импорт того же расчёта
создаёт новую редакцию (`PLAN-6`). Частично разобранный файл не создаёт молча неполную редакцию:
«импортировано 280 строк из 300, 20 не разобраны ▸», и человек решает, создавать ли её (`PLAN-7`).

Импорт — первая операция «ядро + модуль»: позиции перечня в схеме ядра, строки — в схеме `plan`, общей
транзакции нет (`CORE-4`, `STG-9`). Проектируется идемпотентно сразу: позиции «найди или создай» до строк,
повтор импорта безопасен (`STG-6.1`).

## What Changes

- **PR 1 — загрузка и отчёт разбора.**
  - `POST /api/plan/imports` (файл, стройка, куда: «новая редакция сметы X» или «новая смета» с названием,
    разделом и видом — выбор человека, ждёт решения В-12): файл ложится в хранилище модуля, заводится
    запись импорта, разбор (`plan-05`) идёт фоновой операцией.
  - `GET /api/plan/imports/{id}` — состояние, вид документа и версия схемы, «разобрано N из M», перечень не
    разобранных с причиной, сводка будущей редакции (разделы, строки, итог — итог только с
    `plan.estimate.cost`).
  - ВОР и КА редакцией не становятся: ответ называет вид документа и предлагает приложить его к смете
    (`plan-11`; судьба ВОР — ждёт решения В-7). Неизвестная версия схемы — состояние «отказ» с причиной.
  - `DELETE /api/plan/imports/{id}` — отменить несостоявшийся импорт, файл удаляется.
- **PR 2 — создание редакции.**
  - `POST /api/plan/imports/{id}/commit` с `If-Match` записи импорта: при не разобранных строках — только с
    явным `acceptPartial: true`, иначе 409 с числом.
  - Порядок записи: подстановка запомненных сопоставлений (точка расширения для `plan-08`) → позиции
    перечня портом «найди или создай» (`plan-04`) для сопоставленных строк → редакция и строки одним
    сохранением модуля. Повтор после сбоя находит те же позиции и возвращает ту же редакцию (ключ импорта
    у редакции уникален).
  - Номер редакции растёт в смете; первая редакция становится действующей сама (ждёт решения В-5).
  - Журнал действий: «импорт: смета …, редакция N, строк M, не разобрано K».
- Все адреса — под `plan.estimate.edit` за воротами модуля; пишущие, кроме заведения импорта, — с `If-Match`.

## Capabilities

### New Capabilities
- Нет.

### Modified Capabilities
- `plan`: импорт ЛСР с отчётом разбора, решением человека о частичном файле и идемпотентным созданием
  редакции.

## Impact

- **Сервер, модуль:** `Data/EstimateImport.cs`, `Import/EstimateImportJob.cs` (`IModuleJobHandler`),
  `Import/EstimateImportCommit.cs`, `Endpoints/EstimateImportEndpoints.cs`; миграция `EstimateImports`.
- **Порты ядра:** `IModuleBlobs`, `IModuleJobs`, `IModulePlanItems` (`plan-04`), `IModuleActivityLog`.
- **Тесты:** `src/server/BHS.CRG.Tests/Plan/EstimateImport*` — частичный файл, сбой между позициями и строками,
  повтор, `If-Match`, ворота.
- **Документы:** `docs/USER_GUIDE.md` — импорт сметы (оглавление — `npm run toc`).
