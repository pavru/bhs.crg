# Design: полный текст обрезанной клетки таблицы

## Context

- `shared/ui/DataGrid.tsx` (423 строки): клетка — `whitespace-nowrap` (или `break-words` при `wrap`),
  значение — `DataGridValue` или `cell(row)` экрана. Сама сетка текст **не обрезает**: при обычной
  раскладке клетка растёт по содержимому, и обрезка появляется только там, где её задал экран
  (`truncate` / `max-w-*` в `cell`) или включена фиксированная раскладка `fixed` (ширины из шапки, #680).
- `shared/ui/EditGrid.tsx` — сетка правки; клетки — поля экрана, текстовые клетки (название строки
  матрицы разноски) — обычная разметка.
- `shared/ui/Tooltip.tsx` — подсказка #1394: при наведении (задержка 400 мс) и фокусе, Esc закрывает её,
  слой монтируется только открытым (закрытая «не стоит ничего, кроме обработчиков»).
- `docs/UI.md`, «Язык формы»: «У обрезанной строки (`truncate`, `line-clamp`) её полный текст остаётся
  нативным `title` с тем же содержимым: подсказка на каждой клетке длинного списка ничего не объясняет,
  она лишь дочитывает строку (#1394)». Храповик `native-title` пропускает такой `title` как законный.

### Что выяснилось сверкой (22.10.2026)

- **Текст issue — одна фраза и снимок экрана** (`665×533`); снимок здесь не разобран, экран на нём не
  назван. Метка `этап-2` указывает на экраны счетов. Какая таблица на снимке — уточняется у владельца
  вместе с выбором макета (задача 0.1).
- Обрезанные клетки сеток сегодня: `costs/AllocationMatrix.tsx:244` (`EditGrid`, `max-w-64 truncate` с
  нативным `title`), `costs/InvoiceLinesPaste.tsx:121` (`max-w-56 truncate`, без `title`),
  `document-sets/editor/MaterialsTable.tsx:80,119,140` (`DataGrid fixed`, `truncate`, без `title`).
  Реестры (`features/tables/TablePage.tsx`) клетки не обрезают — колонка растёт, сетка прокручивается вбок.
- Правило #1394 и issue говорят о разном: правило — «как показывать», когда экран обрезал строку
  (нативным `title`); issue — «показывать всегда, лёгким способом». Нативный `title` — с задержкой около
  секунды, глух к фокусу и стоит не везде; поэтому issue и появилась.

## Goals / Non-Goals

**Goals:** полный текст обрезанной клетки — силами сетки, на всех таблицах сразу; без подсказки там, где
ничего не обрезано.

**Non-Goals:**
- поля ввода в клетках `EditGrid` — их текст прокручивается в самом поле при фокусе;
- обрезка в списках вне сеток (`ListDetailShell`, строки реестра счетов) — правило #1394 там прежнее;
- новая настройка колонки «обрезать до ширины» в `DataGrid` — если макеты покажут, что она нужна,
  отдельной правкой.

## Decisions

- **D1. Это заметная переделка взаимодействия — макеты обязательны.** Новое поведение появляется в
  каждой таблице приложения сразу, и меняется правило #1394; исключение «Макеты не нужны» (`docs/UI.md`,
  «Новый экран: порядок») покрывает только перевод на готовый компонент. Порядок: разбор с Дизайнером и
  Архитектором (затронут `shared/ui`) → три макета в Claude Design → выбор владельца → код.
  Направления для трёх вариантов (Дизайнер вправе заменить):
  1. **Подсказка** — `Tooltip` с полным текстом у обрезанной клетки (вид, задержка, Esc — как у
     подсказки #1394);
  2. **Раскрытие клетки** — клетка на время наведения разворачивается поверх соседей во всю длину текста
     (как в табличных редакторах), без слоя-подсказки;
  3. **Слой с полным текстом** — подсказка с текстом и кнопкой «Копировать» (для номеров, артикулов,
     наименований, которые переносят в другие программы).
- **D2. Обрезка — по факту, при показе.** Признак «обрезано» меряется на наведении/фокусе:
  `scrollWidth > clientWidth` (или `scrollHeight > clientHeight` у `line-clamp`) у самой клетки или у
  первого обрезающего потомка (`truncate`, `line-clamp-*`). Не `ResizeObserver` на каждую клетку: в
  реестре тысячи строк, а измерение одной клетки на наведении бесплатно. Так «колонку расширили» (UI-53)
  работает само.
- **D3. Один обработчик на сетку, не на клетку.** Делегирование `pointerover` / `focusin` на `<tbody>`:
  подсказки стоят на каждой клетке длинных списков, и обёртка `Tooltip` вокруг каждой — та же цена, что
  #1394 уже снимал (PR 2/2, «три секунды»). Слой показа монтируется один, у текущей клетки.
- **D4. Экранам ничего не нужно.** Сетка находит обрезку сама — значит, клетки, которые обрезает экран
  (`cell` с `truncate`), получают показ без правки. Свой `title` обрезанной строки внутри сетки
  снимается (иначе две подсказки), правило «нативный `title` — только полный текст обрезанной строки»
  остаётся для строк вне сеток.
- **D5. Телефон.** Наведения нет: показ — пояснение, а не единственный путь (`docs/UI.md`, «Подсказка»);
  полный текст на телефоне — в открытой строке. Если владелец выберет вариант 3 с копированием, способ
  открыть его касанием решается в макете.
- **Сторож.** Тест `DataGrid`: обрезанная клетка показывает полный текст, необрезанная — нет; после
  расширения колонки — нет; щелчок по обрезанной клетке открывает строку. Тест `EditGrid`: название строки
  матрицы разноски. Живой прогон `allocation-matrix`: одна подсказка у обрезанного названия.
- **Чем ломается.** Обработчик на каждой клетке — выбор в длинном реестре снова медленный (замер, как в
  #1394 PR 2/2). Показ перехватывает щелчок — строка перестаёт открываться (тест). Нативный `title`
  остался рядом с показом сетки — две подсказки (сценарий матрицы разноски).

## Risks / Trade-offs

- [Измерение `scrollWidth` у клетки с составной разметкой (значок + текст + пометка) ошибается] → мерится
  первый обрезающий потомок, а не клетка целиком; клетка без такого потомка и без `fixed` — не обрезана.
- [Вариант 2 (раскрытие поверх соседей) спорит с закреплёнными колонками `pinned`] → это вопрос макета;
  Дизайнер показывает раскрытие у закреплённой колонки.
- [Правило #1394 меняется для сеток] → `docs/UI.md` и `instead` правила `native-title` — тем же PR.

## Открытые вопросы

**В1. Форма показа полного текста** — три макета (D1), выбор владельца. Рекомендация к разбору —
вариант 1 (подсказка): тот же слой, что #1394, без новой формы; копирование (вариант 3) — если владелец
скажет, что текст из клеток переносят.

**В2. Какая таблица на снимке issue** — подтверждение владельца, чтобы проверить решение именно на ней.
