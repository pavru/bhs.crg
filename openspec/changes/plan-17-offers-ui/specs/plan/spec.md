# Spec Delta: plan

## ADDED Requirements

### Requirement: [PLAN-10] [PLAN-11] Экран коммерческого предложения
Экран КП SHALL показывать строки, наценки на всё предложение, раздел и строку, итог и режим НДС —
числами сервера, а не пересчётом на клиенте. Себестоимость MUST показываться только когда сервер её
отдал; иначе колонки нет вовсе, а строка над таблицей называет недостающее право.

#### Scenario: Менеджер без права на себестоимость
- **WHEN** пользователь без `plan.estimate.cost` открывает КП
- **THEN** колонки себестоимости в таблице нет, над таблицей — «себестоимость скрыта правами»

#### Scenario: Наценка строки
- **WHEN** у строки своя наценка, а у КП — общая
- **THEN** строка показывает действующую наценку и откуда она взята

### Requirement: [PLAN-12] Экран статусов и версий КП
Экран SHALL давать отметить КП отправленным с датой и записать итог (принято, отклонено, без ответа)
только держателю `plan.offer.send`. Отправленное КП MUST показываться только для чтения с действием
«Новая версия»; история версий показывает, какая версия отправлена и когда.

#### Scenario: Отметка отправки
- **WHEN** менеджер с `plan.offer.send` отмечает черновик отправленным
- **THEN** окно подтверждения предупреждает, что дальше правка — только новой версией, а после подтверждения ячейки правки исчезают

#### Scenario: Без права отправки
- **WHEN** пользователь с `plan.offer.edit`, но без `plan.offer.send`, открывает черновик
- **THEN** действия «Отметить отправленным» на экране нет

#### Scenario: КП изменили под экраном
- **WHEN** пользователь сохраняет, а сервер отвечает 409 устаревшей версии
- **THEN** экран говорит «КП тем временем изменили — перечитайте» и сохраняет набранное

### Requirement: [PLAN-13] Экран расхождения КП со сметой
Когда сервер помечает КП «смета изменилась», экран SHALL показывать полосу с номерами редакций и
действие «Обновить по смете», которое открывает разницу из предпросмотра сервера. Ответ «смета
изменилась после предпросмотра» MUST перечитывать разницу и показывать её заново, а не применять.

#### Scenario: Обновление после показа
- **WHEN** менеджер открывает «Обновить по смете»
- **THEN** окно показывает добавленные, снятые, изменённые и неоднозначные строки до подтверждения

#### Scenario: Смета ушла вперёд под окном
- **WHEN** подтверждение получает 409 по отпечатку
- **THEN** окно перечитывает разницу и объясняет, что смета изменилась

### Requirement: [PLAN-10.1] Экран прайс-листа и КП по прайс-листу
Экран прайс-листа SHALL показывать вид работы, единицу, действующую цену и дату начала, историю цен;
правка доступна держателю `plan.pricelist.edit`. Окно КП по прайс-листу MUST показывать строку без цены
пометкой сервера, а итог — «неполный».

#### Scenario: Нет права правки прайс-листа
- **WHEN** пользователь с `plan.offer.read`, но без `plan.pricelist.edit`, открывает прайс-лист
- **THEN** цены видны, действий правки нет

#### Scenario: Вид работы без цены
- **WHEN** в КП по прайс-листу добавлен вид работы без цены на дату
- **THEN** строка помечена «нет цены в прайс-листе», итог помечен «неполный»

### Requirement: [PLAN-22] Блок производных под сметой
Карточка сметы SHALL показывать по редакциям сделанные из них КП и графики с покрытием и пометкой
«устарело» из ответа сервера. Блок, скрытый правами, MUST говорить, какое право нужно, и не показывать
чисел.

#### Scenario: Сметчик без прав КП
- **WHEN** «Сметчик» без `plan.offer.read` открывает карточку сметы
- **THEN** блок КП говорит «скрыто правами: нужно право на коммерческие предложения», чисел в нём нет
