# Design: экраны коммерческих предложений и прайс-листа

Дочерний change зонтика `plan-00-epic`, общая архитектура — `../plan-00-epic/design.md` (D2, D4, D5, D17,
D18). Здесь только решения этого change.

## Context

Сервер — `plan-13` (КП, наценки, статусы, версии), `plan-14` (прайс-лист, КП без сметы), `plan-15`
(печать), `plan-16` (расхождение, обновление, производные). Навигация модуля и панели карточки стройки —
`plan-02`; карточка сметы — `plan-09`. Готовые компоненты `shared/ui`: `DataGrid`, `EditGrid`, `Modal`,
`ConfirmDialog`, `RowActionsMenu`, `StatusBadge`, `EmptyState`, `DateField`, `NumberInput`, `Tabs`,
`ListDetailShell`. Образец НДС «в том числе / сверху» на клиенте — `features/costs/invoiceVat.ts`.
Слово «план» в клиенте занято планом документов (#796) — папка `features/planning` (D1).

## Goals / Non-Goals

**Goals:** менеджер делает КП из редакции и по прайс-листу, наценивает, печатает, отмечает отправку и итог;
видит, что смета ушла вперёд, и обновляет КП после показа разницы.

**Non-Goals:** печать вне шаблона (шаблон правится в редакторе шаблонов, `plan-15`); телефонная раскладка
сверх правил оболочки; графики — `plan-20`.

## Decisions

- **Макеты:** раунд П3, три варианта, выбор владельца — вписать сюда ссылку. Код — после выбора (D18,
  `docs/UI.md` «Новый экран: порядок»). Раунд решает: где КП в «Сметах» (вкладка карточки сметы или блок
  производных), вид карточки (list-detail или страница), как показана наценка трёх уровней.
- **PR 1.**
  - `features/planning/offers/OffersPage.tsx` — глобальный список на `DataGrid`: номер, стройка, источник
    («смета ред. N» | «прайс-лист»), статус, дата отправки, итог (колонка цены — только из ответа сервера).
  - `OfferCard.tsx` — строки на `EditGrid` в черновике и `DataGrid` после «отправлено»; наценки — поле КП,
    раздела и строки; итог и НДС — числа сервера, клиент их не пересчитывает (как `invoiceVat` —
    только показ режима).
  - Колонки себестоимости нет в разметке вовсе, если сервер её не отдал (`hidden` в ответе, D4); строка над
    таблицей называет право.
  - `OfferStatusActions.tsx` — «Отметить отправленным» (дата, `ConfirmDialog`: «после отправки правка —
    только новой версией»), итог. Кнопок нет без `plan.offer.send` — по доступу из `/api/account/access`.
  - `OfferVersions.tsx` — история версий: номер, статус, дата отправки.
  - `OfferDriftBanner.tsx` и `OfferRebaseDialog.tsx` (`Modal wide`) — разница из `rebase-preview`; 409 по
    отпечатку — перечитать и показать заново с объяснением.
  - «Сделать КП» в карточке сметы — `CreateOfferDialog.tsx` (`Modal` 512 px).
  - 409 по `If-Match` везде — «КП тем временем изменили — перечитайте», набранное сохраняется.
- **PR 2.**
  - `features/planning/pricelist/PriceListPage.tsx` — `DataGrid`: вид работы, единица, действующая цена,
    «с даты»; правка — `Modal` с `DateField` и `NumberInput`; история — раскрытие строки.
  - `PriceListOfferDialog.tsx` — КП по прайс-листу; строка `no-price` — пометка сервера, итог «неполный».
  - `features/planning/estimates/EstimateDerivatives.tsx` — блок производных под сметой; `hidden` —
    «скрыто правами: нужно право …», без чисел.
- **Живой прогон** `e2e/plan-offers-smoke.mjs`: «Менеджер проекта» делает КП из посеянной редакции,
  отмечает отправленным, правка недоступна, «Новая версия» доступна; «Сметчик» не видит раздела КП.
- **Сторож.** vitest: без `cost` в ответе колонки себестоимости нет в разметке; отправленное КП не даёт
  ячеек правки; 409 при обновлении перечитывает предпросмотр. Живой прогон под ролями.
- **Чем ломается.** Клиент считает итог сам — расходится с печатью; колонка себестоимости с пустыми
  ячейками — читается как «ноль».

## Risks / Trade-offs

- [В-8 и В-9 решатся иначе] → меняется показ базы наценки и режима НДС; раскладка экрана — нет.
- [Три уровня наценки путают] → итог строки показывает, какая наценка действует (носитель сервера
  `markupSource`), а не только процент.
