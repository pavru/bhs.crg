# Proposal

## Why

Каталог компиляции Typst ([CORE-21] [CORE-22]) кладёт в один каталог `assets/` три вида файлов: картинки
полей `img_N.*`, вложения `att_N.*` и ассеты-картинки шаблона `{Name}{ext}`. Ассеты пишутся последними,
а имя ассета проверяется только на «не пусто». Ассет с именем `img_0` и файлом `.png` молча заменяет
картинку первого поля: PDF и отладочный комплект выходят с чужой картинкой, и ошибки нет. Отказ только
по `img_\d+` / `att_\d+` дыру не закрывает: имя с `/` дотягивается до любого подкаталога. Нашёл
`/code-review` PR #1901 (change `core-generation-input-one-path`); поведение старше, на master было так же.

Решение выбрал владелец 11.11.2026, все три части сразу.

## What Changes

- Картинки и вложения полей переезжают из `assets/` в свой каталог `fields/`: `/fields/img_N.ext` и
  `/fields/att_N.ext`. В `assets/` остаются только ассеты шаблона, путь `image("/assets/{Name}.{ext}")`
  не меняется. Шаблоны берут поля через `.src` из `data.json`, путь приходит готовым, поэтому
  существующие шаблоны не ломаются. В дев-базе ни один из 33 шаблонов не пишет `assets/img_` или
  `assets/att_` напрямую.
- Имя ассета-картинки при создании — простое имя файла: буквы, цифры, пробел, `-`, `_`, `.`. Без `/`,
  `\`, `..` и пробела по краям. Иначе 400 с названным правилом, и файл в хранилище не загружается.
  Пробел оставлен по решению владельца: имена вроде «ГОСТ 21.101. Форма 3» поддержаны с #476.
- Ассет-картинка с негодным именем из старых данных или из резервной копии не пишется в каталог. Генерация
  отказывает (400) и называет ассет. Отладочный комплект отдаётся и называет его в `README.txt`.
- Подсказка имени в окне загрузки ассета очищается до допустимых знаков. Иначе предложенное имя
  («Печать (скан)») получало бы отказ сразу после выбора файла.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `core`: новые требования к каталогу компиляции генерации ([CORE-21] [CORE-22]). Файлы полей
  и ассеты шаблона друг друга не перезаписывают. Имя ассета-картинки — простое имя файла. Ассет с
  негодным именем — отказ генерации с названной причиной.

## Impact

- Сервер: `TypstCompileDirectory`, `TypstGenerator` (константа каталога полей, отказ),
  `DebugBundleArchive` (`README.txt`), домен `TemplateAsset` (правило имени), `TemplateAssetEndpoints` и
  `TemplateAssetHandlers` (отказ 400), новое исключение отказа в `BHS.CRG.Application/Generation`.
- Клиент: `TemplateAssetsPanel.tsx` — очищенная подсказка имени. Экран не меняется.
- Данные: миграции нет. Старые ассеты с негодным именем остаются в базе и в копиях. Они больше не
  перезаписывают чужие файлы и называются в отказе генерации. Исправление — удалить и загрузить
  заново под допустимым именем.
- Зависимость: код опирается на `TypstCompileDirectory` из PR #1901. PR этого change открывается после
  слияния #1901.
