# Актуальность результатов фоновой обработки

## Context

Распознавание использует общую очередь ядра. Набор хранит входные данные и производные результаты. Пока идёт обработка, пользователь может продолжать работу с набором.

## Goals / Non-Goals

Цель — сохранить связность исходных данных и производных результатов при конкурентной работе. Изменения проводятся через действующие входы, права и интерфейс. Поддержка новых видов заданий рассматривается отдельно.

## Decisions

### D1. Редакция входных данных [CORE-25]

При постановке задачи сервер фиксирует редакцию данных, нужных обработчику. Обработчик проверяет её до дорогой работы и атомарно при применении результата. Проверка при сохранении нужна, потому что входные данные могут измениться во время обработки. Состав редакции определяется данными операции, чтобы сопутствующие правки по возможности не отменяли обработку.

### D2. Применение результата и сообщения [CORE-25] [AUTH-12.1]

Действующие права, правила допуска и данные операции проверяет сервер. Входы оформляют исход средствами своего контракта. При необходимости действия сотрудника сообщение указывает на действующий интерфейс. Результат и связанные записи сохраняются согласованно. Очистка временных материалов учитывает итог записи и актуальные ссылки.

## Risks / Trade-offs

- При смене редакции в конце обработки часть работы теряется. Ранняя сверка сокращает число лишних запусков, а итоговая защищает запись.
- При обновлении могут остаться задания без редакции. Для них предусмотрен понятный исход с возможностью запустить обработку заново.

## Migration Plan

Предусмотреть редакции для существующих наборов без замены их данных. Проверить обновление очереди и обычные сценарии выполнения в тестовой среде.
