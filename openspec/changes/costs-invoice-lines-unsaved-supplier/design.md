# Design: соответствия не запоминаются за поставщика, которого уже сменили

## Context

Мотивация — proposal.md. Сейчас:

- `PUT …/lines` после записи строк зовёт `SupplierMatching.RememberSafelyAsync(db, invoice.SupplierId, worth, …)`
  — по поставщику из базы; у каждой строки есть флаг «не запоминать» (`remember`).
- Клиент берёт поставщика из сохранённого вида (`refEntryId(view.requisites[K.supplier])`,
  `InvoiceLinesTable.tsx:140`) и по нему же спрашивает запомненное (`useLaidMatchSuggestions`,
  `askMatchSuggestions`).
- Несохранённые правки шапки живут в `InvoiceForm` (`edits`); таблица строк о них знает только флагом
  `headerDirty`, без поставщика.

## Goals / Non-Goals

**Goals:** запоминание не уходит за поставщика, которого человек сменил; причина видна.

**Non-Goals:** автосохранение строк и шапки (отложено); общая запись шапки и строк одним запросом.

## Decisions

### D1. Способ — решение владельца (задача 0.1)

- **(а) Строки ждут шапку.** Пока смена поставщика не сохранена, «Сохранить строки» недоступно с
  причиной «сначала сохраните поставщика в шапке». Просто и честно, но запирает работу со строками
  из-за поля шапки.
- **(б) Строки без запоминания.** Строки пишутся, каждая — с «не запоминать» на эту запись; у строк —
  «выбор не запомнен: поставщик в шапке не сохранён». После сохранения шапки запоминание само не
  догоняет — выбор запомнится при следующей записи этих строк. Сервер не меняется.
- **(в) Запоминание при «Разобран».** Запоминание переезжает с записи строк на переход «разобран»: там
  шапка обязана быть сохранена, а выбор сверен с бумагой. Чище по смыслу и снимает вопрос и у будущего
  автосохранения, но черновики перестают учить память, и меняется COST-7.1 (когда запоминается).

Архитектор называет (в) чище по смыслу, но оставляет выбор владельцу из-за черновиков. Моя
рекомендация — (б) сейчас: дефект закрыт без правки сервера и без запирания строк; (в) — вопрос к
большому разбору автосохранения, где запись строк станет частой.

**Принято владельцем 08.11.2026: (б) по рекомендации** — строки без запоминания; совместимо с 12.

### D2. Подсказки запомненного при несохранённой смене

Спрашивать запомненное по несохранённому поставщику нельзя без правки адреса подсказок, а по прежнему —
значит подставлять чужой опыт. Правило: при несохранённой смене поставщика подстановок нет, у
`SupplierMatchNote` — «подсказки по поставщику появятся после сохранения шапки».

### D3. Как таблица узнаёт о смене

`InvoiceForm` отдаёт таблице не только `headerDirty`, но и «поставщик изменён и не сохранён»
(сравнение `edits` с сохранённым видом по ключу поставщика). Без второго источника правды.

### D4. Что показало воспроизведение (0.2, 09.11.2026)

Change написан до costs-invoice-screen-10, где появилась одна «Сохранить» (D-10.7, #1786). Она пишет шапку
РАНЬШЕ строк, и порядок выбран именно из-за #1657 (`invoiceSave.ts`). Поэтому:

- **Запись не воспроизводится.** Строки сейчас пишутся только вместе с шапкой, и выбор запоминается за
  новым поставщиком — тем, что сохранён тем же нажатием. Так и должно быть: позицию выбирали для счёта
  нового поставщика. Решение (б) поэтому относится к записи строк **без шапки**. Сегодня такой записи
  нет, она появится с автосохранением (12). Сделано правилом шага строк: смена поставщика не сохранена
  и шапка этим нажатием не записана → «не запоминать» у каждой строки, причина названа уведомлением.
- **Подсказки воспроизводятся.** При несохранённой смене подставлялось «запомнено» из памяти
  прежнего поставщика. По D2 его не подставляют и не предлагают: `SupplierMatchNote` с 11 стал
  пунктом перечня индикатора (`invoiceStatus.ts`, `matches-*`), причина — там. Пометка «запомнится»
  говорит, что выбор уйдёт за поставщиком из шапки. У пометки «запомнено», поставленной ещё до смены,
  сказано, что при сохранении она снимется.
- **После ревью PR #1830.** Защита держится не только на признаке смены, но и на том, чей опыт.
  - Предложение помнит поставщика, по которому его спросили (`MatchOffer.supplierId`). Опыт другого
    поставщика строке не предлагается.
  - Ответ, пришедший после смены поставщика, в строку не ложится.
  - Чужую пометку снимает при записи то, за кем строки пишутся (`foreignMark`), а не то, сменила ли
    шапка поставщика этим же нажатием. Иначе шапка, записанная прошлым нажатием при упавших строках,
    оставляла бы пометку прежнего.
  - Окно выбора позиции подбирает подходящие по поставщику из шапки и называет его в плашке.
  - Смену отменили, не сохраняя, — о строках, набранных за это время, спрашивают по прежнему поставщику.

## Risks / Trade-offs

- [При (б) человек ждёт, что выбор запомнится после сохранения шапки] → текст у строк называет, что
  запомнится при следующей записи строк; либо после сохранения шапки строки помечаются как требующие
  записи.
- [При (в) запоминание при «Разобран» с сотней строк] → тот же `RememberSafelyAsync`, одна запись
  журнала на переход, как сейчас на запись строк.
