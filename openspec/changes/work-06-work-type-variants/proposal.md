# Proposal: варианты вида работ — справочник ядра `ВариантРаботы`

Дочерний change зонтика `work-00-epic`, общая архитектура — `../work-00-epic/design.md` (D7, D2).

> **Сужен решением нарезки этапа 3 (22.10.2026, D18 зонтика).** Дверь видов работ `/api/work-types` и
> типизированные порты видов работ и сотрудников строит `plan-03-work-types-door`: сметчик заводит вид
> работы из окна сопоставления раньше, чем появятся варианты. Здесь остаются справочник
> `ВариантРаботы`, его дверь и варианты в порту.
> Дельта спецификации уже сокращена: требования, которые заводит этап 3, из неё сняты.

## Why

Строка отчёта называет вид работы и, если у вида они есть, вариант (`WORK-5`, `CORE-8`). Сегодня
вариантов нет нигде: у типа `ВидРаботы` (`CoreRecordTypes.cs:117-147`) поля «Варианты» из примера
`TYPE-9` нет, а массив целью в объявлении типа ядра не бывает (`CoreRecordTypes.cs:52-53`). Решение
владельца — справочник ядра `ВариантРаботы` со ссылкой на вид работы, под `core.worktypes.edit`
(`WORK-49`, Р-4). Свободный текст в JSON вида работ дал бы варианты без постоянного идентификатора:
строку отчёта нечем было бы удержать при переименовании, и запрет удалять занятое не сработал бы.

Право `core.worktypes.edit` открывает дверь видов работ `/api/work-types` (`plan-03`); варианты
получают вторую дверь под тем же правом.

## What Changes

- Тип ядра `ВариантРаботы` (уровень «расширяемый»): обязательное поле ядра `ВидРаботы` (ссылка на
  запись вида работы) и `Наименование`. Объявляется ядром рядом с `Сотрудником` и `ВидомРаботы`.
- Дверь ядра `/api/work-variants`: чтение под `core.catalog.read`, заведение, правка, удаление, архив —
  под `core.worktypes.edit`, каждый пишущий адрес, кроме заведения, — с `If-Match`. Ссылка варианта на
  вид постоянна.
- `/api/common-data` записи типа `ВариантРаботы` не пишет — отказ с адресом двери.
- ~~Дверь видов работ `/api/work-types` под `core.worktypes.edit` и право «Инженеру ИД»~~ — строит
  `plan-03-work-types-door` (D18 зонтика).
- Удаление занятого варианта — отказ (`CORE-34.1`), архив вместо удаления (`CORE-34.4`).
- Варианты в порту видов работ: `IModuleWorkTypes` (`plan-03`) получает у вида список вариантов с
  признаком архива и принадлежность варианта виду. ~~Сам порт, признаки по тэгам, «справочник не
  заведён»~~ — `plan-03`. Первый потребитель вариантов — `work-13`.

## Capabilities
