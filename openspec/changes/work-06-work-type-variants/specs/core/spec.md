# Spec Delta: core

## ADDED Requirements

### Requirement: [WORK-49] [CORE-8] Варианты вида работ — справочник ядра со своей дверью
Ядро SHALL держать варианты вида работ записями типа `ВариантРаботы` со ссылкой на запись вида работы
и вести их адресами `/api/work-variants`: чтение под `core.catalog.read`, заведение, правка, удаление и
архив — под `core.worktypes.edit`. Ссылка варианта на вид MUST быть постоянной с момента заведения.
`/api/common-data` записи этого типа MUST NOT заводить, править, удалять и архивировать.

#### Scenario: Сметчик заводит вариант
- **WHEN** пользователь с `core.worktypes.edit` отправляет `POST /api/work-variants` с видом работы «Прокладка кабеля» и наименованием «в лотке»
- **THEN** ответ несёт идентификатор варианта, его `version` и `workTypeId`
- **AND** `GET /api/work-variants?workTypeId=…&purpose=choice` возвращает его среди вариантов вида

#### Scenario: Без права на классификатор
- **WHEN** пользователь только с `core.catalog.edit` заводит, правит, удаляет или архивирует вариант
- **THEN** ответ 403, запись не меняется

#### Scenario: Правка без версии
- **WHEN** `PUT /api/work-variants/{id}` пришёл без заголовка `If-Match`
- **THEN** ответ 400, вариант не меняется

#### Scenario: Правка по устаревшей версии
- **WHEN** две вкладки правят один вариант, и вторая сохраняет с прежним `version`
- **THEN** ответ 409 «вариант тем временем изменили»

#### Scenario: Перенос варианта на другой вид
- **WHEN** правка варианта называет другой `workTypeId`
- **THEN** ответ 409 «вариант к другому виду работ не переносится: заведите новый»

#### Scenario: Вариант к архивному виду работ
- **WHEN** вариант заводят к виду работы, отправленному в архив
- **THEN** ответ — отказ с именем поля `ВидРаботы`, а не новая запись

#### Scenario: Два одинаковых варианта одного вида
- **WHEN** у вида уже есть неархивный вариант «в лотке», и заводят ещё один с тем же наименованием
- **THEN** ответ 409 с названием существующего варианта

#### Scenario: Запись мимо двери
- **WHEN** клиент заводит, правит, удаляет или архивирует запись типа `ВариантРаботы` адресом `/api/common-data`
- **THEN** ответ 409 с адресом `/api/work-variants`, запись не создаётся и не меняется

#### Scenario: Тот же экран каталога
- **WHEN** сметчик открывает варианты в системном каталоге «Данных»
- **THEN** список и форма те же, что у любой записи, а сохраняются они адресами `/api/work-variants`
- **AND** пользователю без `core.worktypes.edit` действия записи не предлагаются

#### Scenario: Адрес двери без права
- **WHEN** в группе `/api/work-variants` появляется адрес без политики права
- **THEN** перепись ворот адресов падает с названием адреса

### Requirement: [WORK-59] [CORE-8] Виды работ — та же дверь под `core.worktypes.edit`
Ядро SHALL вести записи типа `ВидРаботы` адресами `/api/work-types` по образцу двери вариантов: чтение
под `core.catalog.read`, заведение, правка, удаление и архив — под `core.worktypes.edit`, каждый пишущий
адрес, кроме заведения, — с `If-Match`. `/api/common-data` записи этого типа MUST NOT заводить, править,
удалять и архивировать.

#### Scenario: Сметчик правит вид работы
- **WHEN** пользователь с `core.worktypes.edit` и без `core.catalog.edit` сохраняет вид работы «Прокладка кабеля» адресом `PUT /api/work-types/{id}` с актуальной версией
- **THEN** вид работы сохраняется, ответ несёт новую `version`

#### Scenario: Правка вида без версии
- **WHEN** `PUT /api/work-types/{id}` пришёл без заголовка `If-Match`
- **THEN** ответ 400, вид работы не меняется

#### Scenario: Правка вида по устаревшей версии
- **WHEN** правка вида работы называет версию, которую тем временем сменили
- **THEN** ответ 409 «вид работы тем временем изменили»

#### Scenario: Без права на классификатор
- **WHEN** пользователь только с `core.catalog.edit` правит вид работы адресом двери
- **THEN** ответ 403, вид работы не меняется

#### Scenario: Вид работы мимо двери
- **WHEN** клиент заводит, правит, удаляет или архивирует запись типа `ВидРаботы` адресом `/api/common-data`
- **THEN** ответ 409 с адресом `/api/work-types`, запись не меняется

#### Scenario: Инженер ИД сохраняет правку видов работ
- **WHEN** экземпляр обновлён до версии с дверью
- **THEN** роль «Инженер ИД», правившая виды работ через `core.catalog.edit`, получает `core.worktypes.edit`, и состав `/api/account/access` по системным ролям совпадает с ожидаемым

### Requirement: [CORE-34.1] [CORE-34.4] Занятый вариант не удаляется, а уходит в архив
`DELETE /api/work-variants/{id}` SHALL удалять только вариант, на который никто не ссылается, и MUST
требовать `If-Match`. Занятый вариант SHALL отправляться в архив адресами `…/{id}/archive` и
`…/{id}/unarchive` (тоже с `If-Match`): он пропадает из выбора, ссылки на него целы.

#### Scenario: Удаление занятого варианта
- **WHEN** на вариант ссылаются строки записей модуля, и его удаляют
- **THEN** ответ — отказ с числом держателей, вариант остаётся

#### Scenario: Удаление и архив без версии
- **WHEN** удаление или архив варианта пришли без `If-Match` или с устаревшей версией
- **THEN** ответ 400 или 409 соответственно

#### Scenario: Архивный вариант в выборе и в показе
- **WHEN** вариант отправлен в архив, и клиент читает варианты вида с `purpose=choice` и с `purpose=display`
- **THEN** в выборе его нет, в показе он на месте с признаком `archived`

#### Scenario: Свободный вариант
- **WHEN** удаляют вариант, на который никто не ссылается, с действующей версией
- **THEN** ответ 204, повторное удаление — 404

### Requirement: [WORK-25] [CORE-20.4] Вид работы и варианты — модулю типизированно
Ядро SHALL отдавать модулю вид работы типизированно: код, наименование, единицу, признаки «требует
места», «требует материалов», «попадает в ИД» и варианты с признаком архива. Признаки MUST читаться по
тэгам `work.requiresLocation`, `work.requiresMaterials`, `work.producesId`, а не по ключам полей.
«Справочник не заведён» MUST отличаться от «вариантов нет».

#### Scenario: Заказчик переименовал поле признака
- **WHEN** у типа `ВидРаботы` поле с тэгом `work.requiresLocation` носит ключ, отличный от поставленного ядром
- **THEN** модуль получает признак «требует места» по тэгу, как прежде

#### Scenario: Вид без вариантов
- **WHEN** модуль спрашивает вид работы, у которого вариантов нет
- **THEN** он получает вид с пустым списком вариантов, а не отказ

#### Scenario: Справочник видов работ не заведён
- **WHEN** на экземпляре нет типа `ВидРаботы` (нет справочника единиц) и модуль спрашивает виды работ
- **THEN** ответ называет «справочник „Вид работы“ не заведён», а не пустой список

#### Scenario: Чей это вариант
- **WHEN** модуль проверяет пару «вид работы А, вариант вида Б»
- **THEN** ответ называет, что вариант принадлежит другому виду, — по нему модуль отвергает строку
