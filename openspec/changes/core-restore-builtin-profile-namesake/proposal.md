# Proposal: встроенный профиль распознавания из копии заменяет тёзку

## Why

Issue #1570 (bug): копия рабочей системы не восстанавливается на чистый экземпляр — отказ базы
`23505` на `IX_recognition_profiles_Code`, откат всего восстановления. Причина: сидер заводит
встроенные профили (`invoice`, `titleblock`, `spec-table`, `cable-journal`, `cover-title`) под
идентификаторами своей установки, копия везёт правленный встроенный профиль под идентификатором
исходной, а `RestoreRecognitionProfilesAsync` сличает только по `Id` и вставляет второй профиль с тем
же `Code`. Достаточно один раз поправить встроенный профиль (в рабочей системе правили `invoice`), чтобы
копия перестала переезжать на новый сервер. Тот же класс беды у типов закрыт #1400
(`ReplaceTypeNamesakesAsync`); профили распознавания остались.

## What Changes

- Перед восстановлением профилей здешний встроенный профиль с тем же `Code`, но другим `Id`
  (**тёзка**), уступает место профилю из копии: копия — то, что переносят. Идентификатор берётся из
  копии, и ссылки внутри копии (наборы данных, группы листов, данные модулей) остаются верными сами.
- **Ссылки этой системы на тёзку переживают замену**: известные держатели ядра — карта профилей набора
  (`dataset_files."RecognitionProfiles"`) и группы листов (`dataset_files."Grouping"`) —
  переписываются на идентификатор из копии.
- Держатель, которого восстановление не умеет переписать (найден проходом по схеме или портом
  держателей модулей), — **отказ с названием** профиля и держателя, а не отказ базы о ключе.
- Тёзка, правленный на этой системе, заменяется с предупреждением в отчёте восстановления, которое
  его называет.
- Замена называется в отчёте предупреждением: «профиль „…“ этой системы заменён профилем из копии».

## Capabilities

### New Capabilities
- Нет.

### Modified Capabilities
- `core`: восстановление копии на экземпляр с другими идентификаторами встроенных профилей распознавания.

## Impact

- **Сервер:** новый partial `Infrastructure/Backup/BackupService.Restore.ProfileNamesakes.cs`, вызов
  из `BackupService.Import.cs`; проход по схеме из `BackupService.Restore.TypeNamesakes.cs` обобщается
  (держатель любого идентификатора, а не только типа). `BackupService.Restore.cs` не растёт — он в
  `file-size-baseline.json`.
- **Миграций нет**, формат копии не меняется.
- **Клиент:** не меняется — предупреждения уже показываются отчётом восстановления.
- **Тесты:** новый интеграционный класс рядом с `RestoreModuleTypesTests` (образец #1400).
