# Design: распознавание счёта по профилю — общая архитектура

Документ общий для дочернего change `invrec-05-unplaced`. Мотивация — `proposal.md`. Разбор Архитектора и
Дизайнера — в их отчётах (раздел 18.10.2026).

## Context

Сверено по коду ветки от master `c9586405`. Правило «ключ поля профиля = ключ поля счёта» построено:
- строки — таблица `InvoiceScanLines.Targets` (`Modules.Costs/Endpoints/InvoiceScanLines.cs:66`):
  восемь полей строки, в том числе `Артикул` → `SupplierCode`; ключ сравнивается точно после обрезки
  пробелов;
- шапка — `InvoiceScanHeader.Of` (`InvoiceScanHeader.cs:65`): цели ключей даёт ядро
  (`IModuleRecognitionTargets`) — поля модуля и поля, дописанные заказчиком в тип; разбор по виду поля;
  предложение под полем несёт и разобранное значение («Взять»);
- слияние в пустые поля и охрана записи по полям — `InvoiceScanReading.ApplyAsync`/`GuardedAsync`.

## Decisions

### D1. Решения владельца (18.10.2026)
1. **Общее правило, не заплатка:** ключ поля или колонки профиля совпадает с ключом поля счёта — поле
   заполняется. Шапка — поля типа «Счёт», включая дописанные заказчиком; строки — объявленные ключи
   постоянных колонок строки (в том числе `Артикул`). Спец-кода «артикул» нет.
2. **Контроль ослаблен:** при сохранении профиля соответствие полям счёта не проверяется — профиль кормит
   и наборы данных. Модуль сам заполняет всё, что совпало; что не легло — видно в итоге распознавания
   счёта с причиной.
3. **`Основание` → поле «Основание»**, а не «Назначение».
4. **Описания колонок строк уходят модели** — уточнение профиля влияет на распознавание строк.
5. Счета читаются встроенным профилем «Счёт на оплату» (своя копия вида — только для наборов данных); на
   продакшене колонка `Артикул` добавлена во встроенный.

### D3. Не входит (позже, без срочности)
- `Артикул` в заводском профиле: у правленых копий загорелось бы «обновился», как в #1410. Сверено: в
  заводском профиле его по-прежнему нет нарочно (`CostsRecognitionProfiles.cs:58`).
- Подсказки в редакторе профиля: куда ляжет колонка, «Ещё можно заполнить», предупреждение «перестанет
  попадать».
- Свои поля заказчика у строк счёта (`CORE-16`) — отдельный эпик.
- Дозаполнение строк при повторном распознавании счёта, у которого строки уже есть: правило «распознанные
  не добавляются» не трогаем; заведённые счета артикул задним числом не получат.
- Перевод редактора профилей на `EditGrid`/`Checkbox` — в рамках #1414.

## Risks / Trade-offs

- [Ослабленный контроль профиля без #1484 — молчаливая потеря колонки] → до #1484 не легшее названо
  текстом в замечаниях распознавания (`StrayNote`, примечание шапки); `invrec-05` делает это полным и
  постоянным.
