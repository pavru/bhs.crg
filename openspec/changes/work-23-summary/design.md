# Design: сводка «сотрудник × стройка × день»

Общая архитектура — `../work-00-epic/design.md` (D4, D8, D15, D17). Здесь только решения этого change.

## Context

Всё, из чего складывается клетка, уже лежит на сервере к старту:
- отчёты и их статусы — `work-13`, `work-15`;
- момент автоподачи и конец окна подачи мгновением — `work-15`;
- назначения, «стройки менеджера», `IModuleClock.TodayOnSiteAsync` и сутки стройки для мгновения —
  `work-11`;
- период работы сотрудника — `ModuleEmployee.EmployedFrom` / `EmployedTo` (`work-11`);
- параметр доступа и граница выдачи `boundary` / `boundaryOutcome` — `work-07`.

Своей таблицы у сводки нет: это проекция чтения. Порт часов —
`src/server/BHS.CRG.Modules/Ports/IModuleClock.cs`.

## Goals / Non-Goals

**Goals:**
- «не поступал», «не назначен», «вне периода работы» и «окно открыто» различимы данными сервера;
- черновик виден наличием (`WORK-54`);
- менеджер не видит чужих строек ни строкой, ни числом.

**Non-Goals:**
- последний выход устройства на связь — этап 5: носитель `not-tracked` закладывается сейчас;
- выгрузка часов и табель — этап 6;
- сводка как таблица `CORE-33` и набор данных — `work-20`.

## Decisions

- **Макеты:** раунд Р5, выбор владельца — вписать сюда ссылку. Условия раунда: 1280 px, 31 день, две
  смены в клетке. PR 1 (адрес) макетов не ждёт; PR 2 (экран) — ждёт.
- **Состав PR.**
  - **PR 1 — адрес.**
    - `src/server/BHS.CRG.Modules.Work/Summary/SummaryEndpoints.cs` — `GET /api/work/summary?from&to&construction`
      в группе `/api/work`. Ворота — составная политика «любое из» `work.report.review`,
      `work.report.read.all` (`work-03`).
    - `Summary/SummaryLayout.cs` — чистая функция. Вход: назначения, отчёты, периоды работы, «сегодня» и
      окна по стройкам. Выход: строки и клетки с кодами. Вся логика кодов — здесь, без базы.
    - `Summary/SummaryStates.cs` — каталог кодов: `report`, `zero-hours`, `draft`, `not-received`,
      `not-assigned`, `not-employed`, `window-open`, `future`.
    - Чтение отчётов — только изолированным методом с параметром доступа (`work-07`). Перепись `work-07`
      ловит `Set<Report>()` и в этом файле.
    - Клиентский каталог — `WORK_SUMMARY_STATES` в `src/client/src/shared/api/work.ts`, рядом с
      `WORK_MARK_CODES` (`work-16`).
  - **PR 2 — экран.**
    - `src/client/src/shared/api/workSummary.ts`.
    - `src/client/src/features/work/summary/SummaryPage.tsx` — `PageHeader`, отбор стройки —
      `SitesFilter`, период — `DateInput precision="month"` или `DateRange` (по Р5).
    - Сетка — `DataGrid` с `pinned={2}`, колонки дней объявляются из ответа, клетка — `cell`. Своей
      `<table>` нет (`ui:ratchet`).
    - `SummaryCell.tsx` — одна или две записи, ☾ у ночной.
    - `SummaryLegend.tsx` — легенда кодов.
    - Запись `report` открывает карточку `work-21` через `recordRoutes.ts`.
- **Правило «окно открыто» не дублируется.** Конец окна для отсутствующего отчёта считает то же правило
  `work-15`, что пишет мгновение в отчёт: функция окна и общий файл примеров `MOB-18`. Своей
  арифметики суток в сводке нет.
- **Черновик без содержимого — по построению.** Запись `draft` строится из колонок статуса и момента
  автоподачи; строки отчёта для неё не читаются. Тест сериализации проверяет, что у `draft` нет полей
  часов и идентификатора.
- **Чужая стройка — 404.** Отбор по стройке вне параметра доступа отвечает как несуществующая стройка:
  по 403 можно было бы перебором узнать, какие стройки есть. Решение — по `WORK-39`.
- **If-Match не нужен.** Адрес только читает; новых пишущих адресов в change нет.
- **Носители (D15):** коды клетки, `hours`, `status`, `autoSubmitAt`, `shift`, `contact.state`,
  `boundary`, `boundaryOutcome`, `reason`. Клиент из отсутствия записи ничего не выводит: записи нет
  только у дня вне запрошенного периода.
- **Сторож.**
  - `Work/SummaryLayoutTests`: «не поступал» ≠ «не назначен»; Владивосток в 20:00 по Москве; ночная и
    дневная в одних сутках; `draft` без часов; уволенный — `not-employed`.
  - `Work/SummaryEndpointTests`: чужая стройка — 404; монтажник — 403; 32 дня — 400; хост без модуля —
    501.
  - `Work/SummaryStateCatalogTests`: каталог сервера = `WORK_SUMMARY_STATES` клиента.
  - vitest: одна ночная запись — ☾ без деления; `draft` не открывает карточку.
- **Чем ломается.**
  - Клиент рисует пустую клетку как «не подал» — и «не назначен» становится упрёком.
  - «Будущий день» считается по поясу компании — во Владивостоке вечером сегодняшний день помечен
    будущим.
  - Черновик отдаёт часы — нарушен `WORK-54`.
- **Зависимости:** `work-07`, `work-11`, `work-13`, `work-15`, `work-03` (составная политика и раздел
  рейла); PR 2 — ещё `work-21` (карточка). Этап 3 не нужен.

## Risks / Trade-offs

- [31 колонка × сотни строк — тяжёлый ответ] → ответ отдаёт только записи клеток, без повторения дат.
  Замер на посеве 200 строк × 31 день — в PR 1; постраничность по строкам — если ответ больше 1 МБ.
- [1280 px не вмещают 31 колонку с часами] → у `DataGrid` своя прокрутка вбок, ширины окна не
  подпираются. Вид клетки решает Р5.
