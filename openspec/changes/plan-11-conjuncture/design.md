# Design: конъюнктурный анализ

Дочерний change зонтика `plan-00-epic`, общая архитектура — `../plan-00-epic/design.md` (D4, D6, D17).
Здесь только решения этого change.

## Context

Сверено по коду master `6b81e51e`.

- Файлы модуля — `IModuleBlobs` (`BHS.CRG.Modules/Ports/IModuleBlobs.cs:31`), файловые колонки
  объявляются в `IAppModule.Files` и сверяются `ModuleFileInventoryTests`.
- Разбор файла КА — `plan-05` (формат OpenXML конъюнктурного анализа, версия схемы с файлом).
- Шаг «отчёт разбора → решение человека» — `plan-07` (фоновая операция `IModuleJobs`).

## Goals / Non-Goals

**Goals:** анализ хранится со сметой, читается целиком, цены закрыты правом на стоимость.

**Non-Goals:**
- привязка предложений к ресурсам строк сметы («цена ресурса обоснована анализом №…») — не требуется
  `PLAN-9` и без образцов файлов не проверяется; возвращается с первым запросом проверки;
- правка анализа в системе и запись обратно в ГРАНД-Смету (`PLAN-7`, `STG-14`).

## Decisions

- **Хранение.** `ConjunctureAnalysis` (смета, название из файла, файл, версия схемы, дата импорта,
  `xmin`) и дочерние `ConjunctureItem` (позиция: наименование, код, единица, выбранная цена, способ
  выбора) и `ConjunctureOffer` (позиция, поставщик — названием и ИНН из файла, цена, дата предложения).
  Поставщики хранятся текстом из файла, а не ссылкой на организацию ядра: анализ — свидетельство файла,
  заводить по нему организации в справочник незачем.
- **Деньги** (D4). Без `plan.estimate.cost` ответ несёт поставщиков и позиции без цен и `hidden: ["cost"]`;
  с правом — всё.
- **ВОР** (решение В-7): запись `VolumeStatement` — файл, версия схемы, строки для просмотра; тот же
  адрес загрузки с `kind=vor`, те же отчёт и принятие. Денег в ВОР нет — правило D4 её не касается. При
  ответе В-7 (б) или (в) ВОР уходит из этого change в отдельный.
- **Загрузка.** `POST /api/plan/estimates/{id}/conjuncture` — файл, разбор фоновой операцией, ответ —
  отчёт `plan-05`; `POST …/conjuncture/{jobId}/accept` создаёт запись. Без принятия запись не создаётся.
  Заведение новой записи не требует `If-Match` (нечего называть); удаление
  `DELETE /api/plan/conjuncture/{id}` — требует. Чтение — `GET /api/plan/estimates/{id}/conjuncture`.
  Ворота модуля, запись — `plan.estimate.edit`, чтение — `plan.estimate.read`.
- **Экран.** Раздел в карточке сметы: список анализов, позиция → предложения поставщиков, выбранная цена
  отмечена. Раскладка — по выбранному варианту макета П1 (`plan-09`); отдельного раунда макетов нет, если
  П1 его покрыл, иначе — вопрос владельцу.

## Решения при коде (сервер)

Приняты исполнителем при коде группы 1 — в Decisions выше их не было:

- **Загрузка — запись импорта `plan-07`.** `POST …/estimates/{id}/conjuncture` заводит `EstimateImport` в эту смету
  тем же путём, что «Новая редакция» (файл → запись → очередь), ответ — отчёт импорта. Принятие —
  `POST …/conjuncture/{importId}/accept` (в Decisions — `{jobId}`: ключ — импорт, у него и задача, и отчёт). Импорт в
  смету, загруженный из окна «Загрузить смету», прикладывается тем же адресом. После принятия импорт **удаляется**, а
  файл переходит к приложению одной фиксацией: отчёта у приложения нет, «ждёт решения» с ним кончается. Повтор
  принятия находит заведённое по ключу импорта (единственный индекс) — 200 с `repeated`.
- **`kind=vor` при загрузке не передаётся:** вид называет сам файл — как везде в импорте («вид файла определяет разбор
  по содержимому»). Принятие ЛСР — 409 «создайте редакцию»; импорта в новую смету — 409 «приложить не к чему».
- **Не разобранное — с согласием, как у редакции:** модель КА и ВОР теперь хранится у импорта (раньше — только вид),
  отчёт называет «N из M» и пометку `partial`; принятие без `acceptPartial` — 409 с числами.
- **Выбранная цена.** «Выбранной цены» файл КА не пишет (`plan-05`): есть `Position/@MainSubPosition` — «номер
  выбранной в КА вложенной позиции». Способ выбора: `chosen` — номер в файле (отсчёт с единицы — по слову схемы; ни в
  одном образце атрибута нет, проверено правкой образца), `min` — минимальная отпускная без НДС, `none` — цен нет.
  Выбранная цена — отпускная без НДС выбранного предложения. Номер вне числа предложений — позиция не разобрана.
- **Код ресурса** — группа КСР предложения (`KSRGroup`): своего кода у позиции КА в файле нет; код вида
  «ТЦ_…» печатная форма собирает сама.
- **Чтение:** список — `GET …/estimates/{id}/conjuncture` и `…/volume-statements`; позиции анализа —
  `GET /api/plan/conjuncture/{id}/items?offset=&limit=` (предложения внутри позиции), строки ВОР —
  `GET /api/plan/volume-statements/{id}/lines`; файл источника — `GET …/{id}/file`; удаление ВОР —
  `DELETE /api/plan/volume-statements/{id}` с `If-Match`. Без права на стоимость у позиции и предложения нет поля
  `cost` вовсе, корень страницы — `hidden: [{code: "cost"}]`; ставка НДС — не деньги, видна.
- **Файл анализа — только с `plan.estimate.cost`** (разбор Дизайнера §78 D1): в нём все цены предложений, и под
  одним `read` скачивание обходило бы D4. Без права — 403 с названным правом. Файл ВОР денег не несёт — под `read`.
- **Удаление сметы** без редакций уносит её приложения каскадом и убирает их файлы — как несостоявшиеся импорты.
- **Отчёт импорта КА/ВОР** (`notEstimate`): импорт в смету — «приложите его к смете»; импорт в новую смету —
  «уберите импорт и приложите файл в карточке сметы». Фраза `plan-09` «приложения появятся позже» ушла.
- **Журнала действий** у приложений нет (заведение и удаление не пишутся в журнал сметы) — не названо в Decisions.
- **Сводка строки списка по варианту 1** (задача 1.5): у приложения — `chapters` (глав среди разобранного) и у
  анализа `suppliers` (поставщиков по ИНН, без ИНН — по имени; у ВОР `null`). Счётчика приложений у сметы нет
  нарочно: «Приложения N» складывается из двух списков, которые карточка всё равно читает.
- **«Входит в № 12»** — `parentNumber` у строки ВОР считается при чтении, без новой колонки: ГРАНД-Смета пишет
  подчинённую (`SlaveRow`) следом за своей работой, вышестоящая — ближайшая не подчинённая выше в той же главе.
  Подчинённая первой строкой страницы находит её одним запросом до начала страницы.

## Решения при коде (экран)

- **Верхний уровень карточки «Редакции | Приложения N»** — разбор Архитектора 09.11.2026. В `shared/ui/Tabs` есть
  только вид MD3 *secondary* (`underline`); `SegmentedButton` для переключения панели неверен по смыслу (радио, а
  не вкладки, UI.md); «Приложения» последней вкладкой среди редакций смешивает разнородное и ломает «ещё N».
  Рекомендация — добавить в `Tabs` вид MD3 *primary* («Редакции | Приложения») над нынешними вкладками редакций
  (*secondary*). Это правка `shared/ui` — отдельный change (`sharedui-md3-22-primary-tabs`), не plan-11. Запасной
  путь без него — `Tabs variant="segmented"` (на телефоне становится вторым рядом `underline`). **Ответ владельца
  09.11.2026 — отдельный change.** `sharedui-md3-22-primary-tabs` ведёт своя сессия; строка «Редакции |
  Приложения N» в карточке (задача 2.2) ждёт его слияния и архива, ветка plan-11 потом обновляется от master.
  `shared/ui` plan-11 не трогает. Адрес: `?view=attachments`, выбранное — `?attachment=ka:<id>`; редакции — без параметра.
  Попутно (Архитектор): `RevisionTabs` рисует `Tabs` без `TabPanel` — `aria-controls` ведёт в никуда; при
  вложении строки редакции оборачиваются в `TabPanel`.
- **Ряд в карточке — после слияния `sharedui-md3-22-primary-tabs` (#1840, архив #1843).** `Tabs variant="primary"`
  «Редакции N | Приложения N» (число у обоих, как на листе 1 П11), ряд редакций и строки — в его `TabPanel`, строки
  редакции — в `TabPanel` ряда редакций. Смена раздела — шаг истории («Назад» браузера возвращает к редакциям), выбор
  приложения в списке — замена адреса, без шага. Приложенное (из «Приложить файл…», из «Новой редакции» в карточке,
  из общего окна загрузки на странице смет или стройки) открывается в «Приложениях» самим собой; редакция из ЛСР,
  брошенной в «Приложить файл…», — в «Редакциях». «Новая редакция» в шапке карточки остаётся в обоих разделах.
  Попутно: `Tabs` ставит счётчик вплотную к подписи, и диктор слышит «Приложения3» — у карточки пробел перед числом
  свой (`Count` в `EstimateCard`); `shared/ui` plan-11 не трогает, поправка общего компонента — за его доменом.
- **Вопросы листа 0 (2–12) — ответы владельца 09.11.2026** (принял предложенное: «Да, согласен» на 2, 3, 7;
  остальные — по предложенному):
  - 2. КА/ВОР раньше ЛСР — **только после ЛСР**: окно загрузки сметы говорит «сначала загрузите смету», импорт
    можно убрать; сервер так и отказывает (409 «приложить не к чему»). Пустой сметы принятие не заводит.
  - 3. ЛСР в «Приложить файл» — **то же окно**, «Создать редакцию» вместо «Приложить»: импорт уже в этой смете.
  - 4. Новый файл того же КА ложится сверху, «Заменить» нет.
  - 5. Файл КА — только с правом на цены (сделано, см. «Решения при коде (сервер)»).
  - 6. Способ выбора словом виден и без права на цены.
  - 7. Состав ВОР в этом change — шифр, чертежи, примечание, формула и «входит в №». **Отложено** (отдельный
    change, заведёт координатор по слову владельца, здесь не делается): листы PDF-чертежей, переменные формул,
    таблица расчёта объёмов, заголовки внутри глав (разбор Дизайнера §78 D3).
  - 8. Печати КА/ВОР из системы нет — скачать файл.
  - 9. В журнал сметы «приложил / удалил» не пишется.
  - 10. Отметки «по КА» у строки-материала ЛСР нет.
  - 11. Телефон — тот же вид, КА и ВОР, только чтение.
  - 12. Поиск — в одном приложении.

## Risks / Trade-offs

- [Формат КА в версиях программы меняется] → разбор по схемам, неизвестная версия — отказ (`plan-05`).
- [Анализ большой — сотни предложений] → чтение постранично по позициям; файл источника всегда скачивается.
