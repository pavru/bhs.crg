# Design: «Назад» на телефоне закрывает поповер

## Context

- `shared/ui/historyLayers.ts` — `useHistoryLayer(open, onBack)`: на телефоне (`!WIDE`) слой кладёт запись
  истории при открытии и снимает её, когда закрыт своими средствами; переход по ссылке при открытом слое
  уже разобран механизмом (`carry`, `HistoryLayersHost`) — им пользуются пункты `Menu` с `to`.
- `shared/ui/Menu.tsx` — прецедент обёртки: `Menu` сам зовёт `useHistoryLayer`, а пакет
  `@radix-ui/react-dropdown-menu` берёт только он (сторож `scripts/menu-layer.test.mjs`, «Меню одно»).
- PR #1975 (открыт на 15.11.2026): `DateInput` зовёт `useHistoryLayer(pickerOpen, …)` с возвратом из списка
  месяцев к дням и на телефоне закрывает календарь `IntersectionObserver`-ом на значке, когда поле ушло из
  видимой части, — `hideWhenDetached` спрятал бы календарь вместе с записью.
- `shared/ui/windowsAreHistoryLayers.test.ts` ловит только `<Dialog.Root` без `useHistoryLayer(` в файле.
- `scripts/menu-layer.test.mjs` (`strayLayers`) узнаёт слой поповера по импорту `@radix-ui/react-popover`.

## Goals / Non-Goals

**Goals:** каждый поповер, открываемый касанием, — слой истории на телефоне; один механизм, а не девять
копий; сторож, который видит забытый поповер.

**Non-Goals:** вид поповеров, их место и размер; поповер-лист на телефоне вместо поповера (как у
`InvoicePlaceField`) — отдельное решение с макетами; списки подсказки и `Select`.

## Decisions

- **D1. Слой — каждый поповер из перечня, кроме частей поля.** Критерий исключения — правило `docs/UI.md`:
  слой открывается и закрывается набором в поле (`SuggestBox`). Поповер на странице — тоже слой: правило
  #1418 говорит «верхний слой, а не страница под ним», без оговорки об окне, а без записи «Назад» при
  открытом условии отбора уводит со страницы таблицы. Пояснения (`Explained`, `CaveatPhrase`) — тоже: на
  телефоне их открывают касанием, и закрыть их «Назад» естественнее, чем щелчком мимо (решение владельца, В2 — да).
- **D2. Глубина — обёртка `shared/ui/Popover.tsx` (решение владельца, В1 — А).** Модуль повторяет части Radix
  (`export * from '@radix-ui/react-popover'`), а свой `Root` перекрывает звёздный реэкспорт: управляемый
  (`open` / `onOpenChange`) и неуправляемый (`defaultOpen`), он сам зовёт `useHistoryLayer(open, …)`;
  `onBack?: () => boolean` — для слоя со своим шагом назад (список месяцев календаря). Экран меняет
  только импорт: `import * as Popover from '@/shared/ui/Popover'`.
  - *Почему не вызов на месте (вариант Б).* Девять мест, два из них неуправляемые — им пришлось бы
    заводить состояние; наблюдатель якоря повторился бы в каждом с `hideWhenDetached`. И сторож «в файле с
    `<Popover.Root` есть `useHistoryLayer(`» слеп по построению: `InvoicePlaceField` уже сегодня его
    проходит — вызов там у листа, а поповер слоя не имеет. Обёртка даёт сторожу правило, которое не
    обойти: пакет берёт только она, как `Menu` у меню.
  - *Цена.* Новый файл в `shared/ui` и правило сторожа — по `docs/UI.md`, «Новый экран: порядок», п. 1 это
    повод для разбора с «Архитектором»; этот раздел и есть письменный разбор (В3).
- **D3. `hideWhenDetached` на телефоне — закрытие.** `Trigger` и `Anchor` обёртки сообщают `Root` свой
  элемент; `Content` с `hideWhenDetached` на телефоне ставит `IntersectionObserver` на якорь и закрывает
  слой, когда якорь ушёл из видимой части. На рабочем столе — прежнее «спрятать». Так сделан календарь в
  #1975; после переезда `DateInput` свой наблюдатель снимает. `ComputedFieldEditor` закрывает список при
  уходе кнопки на любой ширине и переносит фокус — его наблюдатель остаётся: закрытие снимает запись так
  же, двойного закрытия нет (второй `setOpen(false)` ничего не меняет).
- **D4. Двойной слой запрещён.** Поповер на обёртке не зовёт свой `useHistoryLayer` — иначе две записи и
  «Назад», которая «ничего не делает» один раз. `ActivityCenter` свой вызов убирает; у `InvoicePlaceField`
  вызов принадлежит листу (`open && !wide`), поповер — только на рабочем столе, где обёртка записей не
  кладёт.
- **D5. Сторож.** `windowsAreHistoryLayers.test.ts`, второе правило: файлы (без тестов), импортирующие
  `@radix-ui/react-popover` (статически или `import()`), — только `shared/ui/Popover.tsx` и список
  `FIELD_PARTS = ['/src/shared/ui/SuggestBox.tsx']` с причиной в доккомментарии. Правило вынесено функцией и
  проверено на образце (файл с прямым импортом ловится) — сторож обязан срабатывать.
  `scripts/menu-layer.test.mjs`: `LAYER_PACKAGES` узнаёт и `@/shared/ui/Popover` (и `./Popover` внутри
  `shared/ui`) — без этого после перевода `strayLayers` не видит ни одного поповера и молча зеленеет;
  образец с импортом обёртки — в его тестах.
- **D6. `DateInput` переезжает в обёртку** после слияния #1975: `onBack` — возврат из списка месяцев,
  наблюдатель значка — общий из D3. Страховка — `DateInput.history.test.tsx` из #1975 без правок.
- **D7. Макеты не нужны.** Правка сводится к уже записанному правилу #1418 и не меняет, что человек видит
  и делает на экране: состав, раскладка и шаги прежние, меняется только ответ системной «Назад» на
  телефоне. Тот же довод владелец принял для календаря (#1975, решение 22.10.2026). Подтверждает
  владелец 15.11.2026 (В3).

## Risks / Trade-offs

- [Переход по пункту поповера (`TableViewHeader`) при открытом слое: снятие записи гоняется с переходом]
  → механизм уже разобран для пунктов `Menu` с `to`; тест обёртки и сценарий спеки «Переход по пункту»
  это закрепляют.
- [Перевод забыл свой `useHistoryLayer` — двойная запись] → D4; тест `ActivityCenter` на узком экране:
  одна «Назад» закрывает панель.
- [Поповер с полем ввода (`FilterChips`, `SitesFilter`, `ComputedFieldEditor`): первая «Назад» на Android
  убирает клавиатуру, поповер остаётся, вторая закрывает его] → так и задумано: поповер открыт касанием,
  а не набором; набранное в окне под ним цело.
- [Обёртка тянет `useHistoryLayer` и в поповеры, которые на телефоне не показываются] → на телефоне без
  открытия записи нет; на рабочем столе записей нет вовсе.

## Migration Plan

Один PR после слияния #1975: обёртка с тестом → перевод мест → сторожа → `docs/UI.md` → живой прогон.
Откат — revert PR; данных и сервера change не касается.

## Решение владельца (15.11.2026)

Все три рекомендации приняты:

- **В1 — А.** Обёртка `shared/ui/Popover` и сторож «пакет только через неё» (D2). Отклонён Б —
  `useHistoryLayer` в каждом месте и сторож по файлу (слеп к файлу с листом и поповером, как
  `InvoicePlaceField`).
- **В2 — да.** Поповеры на странице и пояснения (`Explained`, `CaveatPhrase`) — тоже слои (D1). Отклонено
  «только над окнами» с оговоркой «над окном» в правиле #1418.
- **В3 — макеты не нужны** (D7). О разборе с «Архитектором» владелец отдельно не сказал; письменный
  разбор — раздел D2.
