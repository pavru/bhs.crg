# Spec Delta: work

## ADDED Requirements

### Requirement: [WORK-21] [WORK-46] Панель «Назначения» в карточке стройки
Карточка стройки SHALL показывать панель «Назначения» тому, у кого есть `work.assign` или
`work.sites.all`: сотрудник, вид назначения («монтажник» | «менеджер») и период; у менеджера без
конца — «без срока». Действия правки панель MUST показывать, только если ответ сервера разрешает
спрашивающему назначать на этой стройке; иначе действий нет вовсе, а строка над списком называет
причину из ответа.

#### Scenario: Менеджер своей стройки
- **WHEN** менеджер с действующим назначением «менеджер» открывает карточку своей стройки
- **THEN** панель показывает назначения стройки и кнопку «Назначить на период»

#### Scenario: Менеджер чужой стройки
- **WHEN** пользователь с `work.assign` без назначения «менеджер» на этой стройке открывает её карточку
- **THEN** кнопок правки в панели нет, а строка над списком называет причину из ответа сервера

#### Scenario: Пользователь без права назначать
- **WHEN** у пользователя нет ни `work.assign`, ни `work.sites.all`
- **THEN** пункта «Назначения» в карточке стройки нет

#### Scenario: Назначений нет
- **WHEN** на стройке нет ни одного назначения
- **THEN** вместо пустой сетки панель говорит «на стройку никто не назначен» и предлагает назначить, если правка разрешена

### Requirement: [WORK-21] Правка назначения с версией
Окно правки назначения SHALL отправлять версию, полученную при чтении, и MUST называть отказ
словами: 409 устаревшей версии — «назначение тем временем изменили — перечитайте», 403 — «назначать на
этой стройке может её менеджер», 422 — причина сервера. Пересечения и «не останется менеджера» окно
показывает из ответа, а не вычисляет само.

#### Scenario: Назначение изменили под окном
- **WHEN** сосед изменил назначение, пока окно было открыто, и пользователь сохраняет
- **THEN** сервер отвечает 409, окно остаётся открытым с набранным и предлагает перечитать

#### Scenario: Период пересекается с другим назначением
- **WHEN** сервер отвечает, что новый период пересекается с действующим назначением того же сотрудника
- **THEN** окно показывает пересечение словами из ответа и не закрывается

#### Scenario: Последний менеджер снимает себя
- **WHEN** единственный менеджер стройки снимает своё назначение, и сервер отвечает 409 «на стройке не останется менеджера»
- **THEN** окно подтверждения показывает эту причину, назначение остаётся в списке

### Requirement: [WORK-21] Массовое «назначить на период»
Окно «Назначить на период» SHALL принимать период и список кандидатов с сервера. Кандидат,
исключённый сервером, MUST оставаться в списке неактивным с причиной из ответа («уволен 01.10»,
«вне периода работы»), а не пропадать. Запись пачки — целиком или никак: при отказе окно остаётся
открытым с отмеченными и показывает причину у каждого отказавшего.

#### Scenario: Уволенный сотрудник среди кандидатов
- **WHEN** у кандидата в ответе сервера `eligible: false` и `reason` «уволен с 15.11»
- **THEN** строка кандидата неактивна, флажок не ставится, причина видна текстом рядом с именем

#### Scenario: Смена периода
- **WHEN** пользователь меняет период в окне
- **THEN** кандидаты перечитываются с сервера под новый период, отмеченные и всё ещё допустимые остаются отмеченными

#### Scenario: Один негодный в пачке
- **WHEN** сервер отвечает на пачку из пяти отказом 422 и называет одного сотрудника с причиной
- **THEN** окно говорит «ни одно назначение не заведено», у названного сотрудника видна причина, отметки остальных целы

#### Scenario: Пачка записана
- **WHEN** сервер завёл все назначения пачки
- **THEN** окно закрывается, а панель показывает новые назначения после перечитывания

### Requirement: [WORK-21] [WORK-47] Выбор сотрудника — кандидаты от сервера
Общий выбор сотрудника SHALL показывать кандидатов, присланных сервером, с причиной исключения у
недоступных. Сотрудника без связи с учётной записью выбор MUST помечать «нет учётной записи» по полю
ответа: такому сотруднику можно назначить стройку, но вводить отчёты сам он не сможет.

#### Scenario: Сотрудник без учётной записи
- **WHEN** у кандидата `account.state` равно `none`
- **THEN** выбор показывает пометку «нет учётной записи», а выбрать его можно

#### Scenario: Справочник сотрудников не заведён
- **WHEN** сервер отвечает причиной «справочник „Сотрудник“ не заведён»
- **THEN** выбор говорит это словами, а не «никого не нашлось»
