# Proposal: экран назначений

Дочерний change зонтика `work-00-epic`, общая архитектура — `../work-00-epic/design.md` (D5, D15, D17).

## Why

Назначения (`work-11`) решают всё остальное в модуле: из них монтажник выбирает стройку, из них
получаются «стройки менеджера» и участники бригады (`WORK-21`, `WORK-46`). Без экрана их некому
завести: адрес есть, а менеджер проекта до него не дотянется. Массовое «назначить на период» нужно
с первого дня: бригаду из восьми человек на месяц по одному не назначают.

## What Changes

- Панель «Назначения» в карточке стройки — через механизм панелей модулей (`work-03`). Список
  назначений стройки: сотрудник, вид («монтажник» | «менеджер»), период, действия строки.
- Окно правки одного назначения (`Modal`, 512 px): период, у менеджера — открытый конец. Запись с
  версией, отказ 409 называется словами.
- Массовое окно «Назначить на период» (`Modal wide`): период и кандидаты с сервера; исключённый
  кандидат виден с причиной («уволен 01.10», «вне периода работы»), а не пропадает.
- Пересечения периодов показывает сервер; клиент их не считает.
- Новый общий компонент `shared`: выбор сотрудника — кандидаты и причины исключения от сервера. Его
  же берёт «ввести за сотрудника» (`work-22`).
- Пустые состояния с причиной; «вы не менеджер этой стройки» — из ответа сервера, а не догадкой.
- Раздел инструкции пользователя о назначениях.
