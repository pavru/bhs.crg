# Design: экран назначений

Общая архитектура — `../work-00-epic/design.md` (D5, D15, D17). Здесь только решения этого change.

## Context

Сервер назначений строит `work-11`: адреса, кандидаты с причиной исключения, пересечения периодов,
If-Match на правке, граница выдачи «ваши стройки (N)» и `reason: not-assigned`. Этот change — только
клиент. Механизм панелей модулей в карточке стройки строит `work-03`: сейчас список панелей ручной
(`src/client/src/features/document-sets/ConstructionDetail.tsx:110-118`).

## Goals / Non-Goals

**Goals:** менеджер назначает монтажников на свои стройки по одному и пачкой; причины «нельзя» видны
словами; выбор сотрудника годится и для `work-22`.

**Non-Goals:** экран сотрудников (`work-01`), список «мои стройки» монтажника (`work-22`), назначения на
телефоне (этап 5).

## Decisions

- **Макеты:** раунд Р2, выбор владельца — вписать сюда ссылку. Код — после выбора (D17, `docs/UI.md`
  «Новый экран: порядок»).
- **Состав PR (один).**
  - `src/client/src/shared/api/workAssignments.ts` — запросы React Query к адресам `work-11`; версия из
    ответа чтения уходит заголовком `If-Match`. Общие типы модуля — в `shared/api/work.ts` (`work-16`).
  - `src/client/src/features/work/assignments/AssignmentsPanel.tsx` — панель стройки, регистрируется
    механизмом `work-03` с фильтром по пространству. Список — `DataGrid` (`density` обычная, действия
    строки — `RowActionsMenu`). Пустое состояние — `EmptyState` вместо сетки.
  - `AssignmentDialog.tsx` — `Modal` 512 px: `DateRange`, вид назначения — `Select` с видами, которые
    разрешил сервер. Открытый конец у менеджера — пустое «по».
  - `BulkAssignDialog.tsx` — `Modal wide` 896 px: таблица кандидатов на `DataGrid` с `Checkbox` в
    колонке экрана (`interactive`), причина исключения — `cell`.
  - `src/client/src/shared/ui/EmployeePicker.tsx` — новый общий компонент: поиск, кандидаты и причины
    от сервера, пометка `account.state` (`work-01`). Пикер «найти и выбрать одно» — `Modal` 512 px.
- **Адреса `work-11`.**
  - Список — `GET /api/work/assignments`, кандидаты — `GET /api/work/assignments/candidates`
    (`eligible`, `reason`).
  - Заведение — `POST /api/work/assignments` и `POST /api/work/assignments/bulk`. Пачка заводится целиком
    или никак: 422 называет отказавших.
  - Правка и снятие — `PUT` / `DELETE /api/work/assignments/{id}` с `If-Match`. Последний менеджер
    стройки — 409 «на стройке не останется менеджера».
  - Заведение версии не называет — исключение `work-11` с обоснованием.
- **Носители (D15).** Причины исключения, пересечения, отказ пачки и «не останется менеджера» — поля
  ответа `work-11`, клиент их не вычисляет.
  ⚠️ Признака «может ли спрашивающий назначать на стройке S» в `work-11` нет: проверка
  `Access/AssignmentGate.cs` живёт только в пишущих адресах. Нужно поле ответа списка (например,
  `canAssign` с причиной). Оно дописывается в `work-11` до слияния этого PR. Иначе кнопки пришлось бы
  рисовать по праву без стройки, а это и есть «чем ломается».
- **Без новых пишущих адресов.** If-Match и ворота модуля и права — у `work-11`. Здесь — отправка
  версии и разбор 400/403/409/422 словами.
- **Сторож.** Тест vitest: кандидат с причиной исключения рисуется неактивным с причиной; без права
  правки в разметке нет кнопок, а не неактивные кнопки. Живой прогон `work-assignments-smoke.mjs`:
  менеджер назначает двоих на период; второй менеджер чужой стройки кнопок не видит.
- **Чем ломается.** Клиент отбрасывает исключённых кандидатов — уволенный «пропал», и менеджер ищет
  его в справочнике. Кнопка правки рисуется по `work.assign` без стройки — на чужой стройке она
  ведёт к 403.
- **Зависимости:** `work-11` (адреса и носители), `work-03` (панели карточки стройки), `work-01`
  (`account.state`), макеты Р2. Этап 3 не нужен.
- **Храповики.** `ui:ratchet`: ни `<table>`, ни нативных флажков, ни своих ширин — сетки и окна из
  `shared`.

## Risks / Trade-offs

- [Механизм панелей `work-03` ещё не слит] → change не стартует до него: ручная вставка пункта в
  `ConstructionDetail.tsx` вернула бы ручной список.
- [Кандидатов много — бригады крупных строек] → поиск в окне по ФИО; постраничность — по замеру, если
  сервер отдаёт больше двухсот.
