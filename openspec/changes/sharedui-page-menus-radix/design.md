# Design: три ручных меню на страницах — на Radix

## Context

- `features/templates/EditorPanel.tsx`:
  - `RequisitePicker` (`:40–92`): `open`, свой `mousedown` на `document` (`:49–56`), список
    `absolute top-full … z-50 w-80 max-h-80 overflow-y-auto` (`:71`) с липким заголовком «Реквизиты · <тип>»
    и пунктами по `flattenFields` с отступом `0.75 + depth rem`; составные — `opacity-60
    pointer-events-none`. Выбор зовёт `insertAtCursor` (`:289`, `executeEdits` в Monaco).
  - Сплит-кнопка «Сохранить» (`:355–391`): стрелка под `<Tooltip name>`, меню `absolute top-full right-0 …

  с `menuOpen`, меню `absolute z-10 mt-1 w-52 … shadow-lg` (`:214`) — группы и «+ Новый документ».
  Лента групп — `flex-1 overflow-auto` (`:586`).

### Что выяснилось сверкой (22.10.2026)

- Строки сдвинулись: «Перенести в группу» — `:214` (в issue `:213`), лента — `:586` (было `:588`).
  `EditorPanel.tsx:71` и `:378`, `TemplatesPage.tsx:311` — на месте.
- Живых прогонов, которые открывают эти три меню, нет (поиск по `e2e/`).

## Goals / Non-Goals

**Goals:** три меню — Radix с порталом и клавиатурой меню; уровень `manual-dropdown` — ноль.

**Non-Goals:** поиск по реквизитам (у «Реквизита» его нет и сегодня); новые пункты меню.

## Decisions

- **D1. Все три — `DropdownMenu`.** В них пункты-действия без поля ввода; у меню есть стрелки, поиск
  по первой букве, `Esc`, щелчок мимо и возврат фокуса — без своего кода. Свои `mousedown`-слушатели и
  `ref` для них удаляются. Альтернатива для «Реквизита» — `Popover` — отклонена: поля ввода нет,
  а клавиатуру пунктов пришлось бы писать самим.
- **D2. Составное поле — `DropdownMenu.Label`, а не `disabled`-пункт.** Это заголовок группы: стрелки
  его перешагивают так же, как недоступный пункт, но диктор не читает «недоступно» там, где выбирать
  нечего по смыслу. Отступ по глубине остаётся у заголовков и пунктов. Альтернатива из issue
  (`disabled`) рабочая; выбрано точнее по смыслу.
- **D3. Высота «Реквизита».** `max-h-[var(--radix-dropdown-menu-content-available-height)]` и прокрутка
  внутри, `collisionPadding={8}`: у невысокого окна меню сдвигается и прокручивается, а не уходит под
  край. Липкий заголовок «Реквизиты · <тип>» — `DropdownMenu.Label` сверху.
- **D4. Фокус после вставки — в редактор.** Radix возвращает фокус на триггер при закрытии; после
  выбора реквизита это отменяется (`onCloseAutoFocus` с `preventDefault`) и фокус ставится в Monaco,
  иначе курсор вставки терялся бы. После Esc — фокус на триггере, как положено.
- **D5. Сплит-кнопка.** `<Tooltip name><DropdownMenu.Trigger asChild>` вокруг стрелки целиком
  (`docs/UI.md`, таблица контролов, «Подсказка»). Стрелка — нативный `<button>` со значком; станет ли
  она `IconButton` — решает `sharedui-icon-button-screens` (её сплит-форма с заливкой `bg-brand` не
  круглая, вероятно останется кнопкой со своим видом и в уровне `icon-button`).
- **D6. Вид слоя** — как у `RowActionsMenu`: `bg-surface`, `border-stroke`, `shadow16`, портал в body без
  `container`; `z-10` и `shadow-lg` уходят.
- **D7. Макетов нет:** вид и место меню не меняются, меняются слой и клавиатура по принятому правилу
  «Слои над окном».
- **Сторож.** Правило `manual-dropdown` с уровнем ноль; тесты компонентов `RequisitePicker`
  (стрелки перешагивают группу, Enter вставляет, Esc возвращает фокус) и полосы выделения
  `PdfGroupingEditor` (выбор группы зовёт `onMoveSelected`, щелчок мимо закрывает).
- **Чем ломается.** Фокус после вставки ушёл на кнопку «Реквизит» — следующий набор текста не попадает в
  шаблон (тест D4). Меню в ленте с `container` — правило `portal-container`.

## Risks / Trade-offs

- [Ctrl+S перехватывается в фазе захвата (`EditorPanel`) — меню открыто, фокус в нём] → сохранение по
  Ctrl+S срабатывает только при фокусе в Monaco, как сегодня; меню на это не влияет.
- [«Реквизит» у типа с сотнями полей — длинное меню] → как сегодня, плюс поиск по первой букве Radix.
- [`PdfGroupingEditor` в уровне размера] → правка его только худеет.
