# Tasks: целостность версий шаблона

Функциональный PR (bug) — без метки `version:minor`, в описании `Closes #1922`, `Closes #1923`,
`Closes #1924`. Предпочтительно после слияния `id-debug-bundle-template-choice` (#1401), при варианте Б
в 0.1 — обязательно после его архива (design D9).

## 0. Решения владельца

- [ ] 0.1 **#1923: что значит закрепление документа за шаблоном.** Ответ вписан в design D6, при Б или В
  дельта и раздел 3 переписаны до кода [ID-3]. Варианты:
  - **А (рекомендация).** Новая версия пересаживает закреплённые документы на себя, вместе с
    переопределениями параметров, и сбрасывает выпущенные в черновик. Закрепление означает «этот
    шаблон». Интерфейс и так даёт выбрать только действующую версию.
  - **Б.** Закрепление остаётся за версией. Генерация, предпросмотр и вкладка генерации понимают
    погашенную версию и печатают ею. Нужна правка правила #1401 после его архива.
  - **В.** Как есть: окно новой версии только предупреждает, документы не генерируются, пока им не
    выберут шаблон заново.
- [ ] 0.2 **#1924: как сравнивать названия.** Ответ вписан в design D1 [ID-3]. Варианты:
  - **точное совпадение (рекомендация).** Так группируют страница, сервер и «Недавние». Ввод только
    обрезается по краям.
  - **без учёта регистра и пробелов.** Меняет группировку в трёх местах и может склеить существующие
    шаблоны («Основной» и «основной»); тогда к 0.4 добавляется правило слияния.
- [ ] 0.3 **Счёт по копии рабочей базы** (стенд с копией базы заказчика), до слияния. Числа агрегатом —
  в описании PR, без названий [ID-3]:
  - группы с несколькими действующими версиями и группы с повторными номерами — запрос из описания
    PR #1921;
  - документы, у которых `TemplateIds` указывает на погашенную версию, — отдельно те, у чьего
    шаблона есть действующая;
  - документы с одиночным `TemplateId` на погашенной версии.

  Нужно разрешение владельца на запуск на стенде. Если доступа нет, владелец запускает сам.
- [ ] 0.4 **Правила разовой починки** (design D8). Ответ вписан в D8 до кода миграции [ID-3]:
  - лишние действующие гаснут, остаётся версия с наибольшим номером, «по умолчанию» переходит к ней —
    подтвердить;
  - повторные номера: **перенумеровать** поздние по `CreatedAt` в `max+1…` (рекомендация) или
    **разделить** повторные v1 в отдельные шаблоны «(2)»;
  - закрепления `TemplateIds` за погашенными версиями пересадить на действующую, без сброса статуса и
    PDF (рекомендация, только при А). Одиночный `TemplateId` не трогать;
  - то же ли делать восстановлению копии с закреплениями её документов (рекомендация — да).
