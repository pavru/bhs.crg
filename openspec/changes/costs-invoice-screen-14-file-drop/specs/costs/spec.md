# Spec Delta: costs

## MODIFIED Requirements

### Requirement: [COST-8] Распознавание счёта
Скан или файл счёта SHALL можно распознать профилем модуля через службу распознавания ядра; офисные
файлы `.docx`, `.xlsx`, `.xls` показываются читаемым образом и распознаются по нему. Распознанное —
предложение, его подтверждает человек; строки MUST NOT появляться в учёте сами.

#### Scenario: Поставщика нет в справочнике
- **WHEN** распознанный поставщик не найден среди организаций
- **THEN** он предлагается к созданию из названия и ИНН (`costs.organization.create`), но сам не создаётся

#### Scenario: Несколько файлов сразу
- **WHEN** пользователь перетаскивает несколько файлов счетов
- **THEN** на каждый файл заводится черновик, распознавание идёт фоновыми задачами — кроме файлов, уже приложенных к счетам (они придержаны), и повторов внутри броска (из них заводится один, остальные названы в итоге)

#### Scenario: Файл, который не читается
- **WHEN** счёт заводят из PDF, который не открывается (повреждён, под паролем или внутри не PDF), или распознавание такого файла запускают кнопкой
- **THEN** черновик заведён, а распознавание отказывает причиной «сам файл не читается» (`BadFile`) — одинаково при настроенном и ненастроенном движке: проверка файла идёт раньше проверки готовности движков, и ни движок, ни его проба зрения не вызываются

## ADDED Requirements

### Requirement: [COST-6.7] [COST-31] Бросок файла на страницу счетов — новые черновики
Целью броска SHALL быть всё окно страницы счетов, включая шапку приложения и рейл. Бросок MUST всегда
означать новые черновики: открытый счёт от броска не меняется. Где бросок не принимается, это сказано
словами или видно по отсутствию цели — без молчаливого промаха.

#### Scenario: Бросок на открытый счёт
- **WHEN** пользователь бросает один файл на панель файла или таблицу строк открытого счёта
- **THEN** заводится и открывается новый черновик, а у прежнего счёта файл, версия и строки прежние

#### Scenario: Бросок на шапку или рейл
- **WHEN** файл брошен на шапку приложения или рейл страницы счетов
- **THEN** он принимается так же, как брошенный на список

#### Scenario: Идёт загрузка
- **WHEN** файл тащат над окном, пока идёт пакет или одиночная загрузка
- **THEN** покрытие говорит «Идёт загрузка N из M — бросок примем после неё», и бросок не принимается

#### Scenario: Открыт модальный слой
- **WHEN** файл тащат над окном, пока открыто окно (оплата, разноска, удаление, окно повтора)
- **THEN** цели нет и покрытия нет: слой важнее

#### Scenario: Без права заводить счета
- **WHEN** файл тащит пользователь с `costs.invoice.read` без `costs.invoice.edit`
- **THEN** покрытия и цели нет, как нет и кнопки «Счёт из файла»

#### Scenario: Запись текущего счёта не дошла
- **WHEN** один файл брошен, пока запись открытого счёта отказала
- **THEN** черновик не заводится, пользователь остаётся на счёте, и причина названа

### Requirement: [COST-6.7] Повтор файла спрашивают до выгрузки
Перед отправкой файлов клиент SHALL считать SHA-256 каждого в любом контексте браузера, в том числе по
HTTP без защищённого контекста, и задавать один вопрос по отпечаткам на бросок. Исходов три: двойников
нет, двойники есть, проверка не ответила. Клиент MUST NOT говорить «файл новый».

#### Scenario: Установка по HTTP
- **WHEN** страница открыта по `http://<адрес>:<порт>`, а брошенный файл уже приложен к счёту
- **THEN** окно повтора появляется так же, как по HTTPS, а отпечаток браузера побайтно равен серверному

#### Scenario: Двойников нет
- **WHEN** вопрос ответил пустыми перечнями
- **THEN** черновики заводятся без окна, и о новизне файла ничего не сказано

#### Scenario: Проверка не ответила
- **WHEN** вопрос по отпечаткам отказал 5xx, оборвался или отпечаток не посчитался
- **THEN** черновики заводятся без окна, пакет не останавливается, итог говорит «Повтор не проверен — если файл уже был, счёт скажет об этом»

#### Scenario: Ответ на заведение потерялся
- **WHEN** пользователь повторяет файл, чей ответ на заведение не пришёл
- **THEN** сначала уходит вопрос по отпечатку, и найденный свой черновик назван «это вы завели» без второго черновика

### Requirement: [COST-6.7] Окно повтора одного файла
При двойниках одного файла клиент SHALL показывать окно до заведения: карточка каждого двойника (номер,
поставщик, состояние, кто завёл) с «Открыть», основное действие «Не заводить» (фокус, Enter, Esc) и
«Завести ещё один черновик». Окно MUST NOT перехватывать Enter у того, кто печатает в поле.

#### Scenario: Enter и Esc
- **WHEN** окно повтора открыто и пользователь нажимает Enter или Esc
- **THEN** черновик не заводится, и пользователь остаётся там, где был

#### Scenario: Завести ещё один
- **WHEN** пользователь выбирает «Завести ещё один черновик»
- **THEN** заводится ровно один черновик как сознательный повтор, и его «тот же файл» стоит «к сведению»

#### Scenario: У файла несколько счетов с разными номерами
- **WHEN** у двойников файла два и более разных номера
- **THEN** окно говорит, что в файле уже разобрано несколько счетов, а «Завести ещё один черновик» заметнее; по умолчанию — «Не заводить»

#### Scenario: Пользователь печатает
- **WHEN** ответ пришёл позже секунды после броска, а фокус стоит в поле ввода
- **THEN** окно не открывается; снэкбар без таймера «Файл уже у счёта N · Решить» открывает то же окно

### Requirement: [COST-31] Пакет с повторами — без окна
Повторы в броске нескольких файлов SHALL придерживаться, а не заводиться и не спрашиваться окном. Итог
называет заведённые, придержанные и выбранные дважды; у придержанных — «Открыть» и «Завести всё равно».
Пакет MUST NOT двигать экран. Где списка нет, ход и итог — в центре активности.

#### Scenario: Десять файлов
- **WHEN** брошено 10 файлов, из них 2 уже приложены к счетам и 1 выбран дважды
- **THEN** заведено 7, итог «Заведено 7 · придержано 2 · 1 выбран дважды», открытый экран не сменился

#### Scenario: Завести всё равно
- **WHEN** у придержанной строки нажато «Завести всё равно»
- **THEN** заводится один черновик как сознательный повтор, строка уходит из придержанных

#### Scenario: Списка нет
- **WHEN** пакет брошен при ширине, где списка счетов нет
- **THEN** ход с «Остановить» и итог видны в центре активности, итог сам не исчезает

#### Scenario: После перезагрузки
- **WHEN** страница перезагружена, а у пакета остались придержанные строки
- **THEN** строка говорит «выберите файл заново» вместо «Завести всё равно»

### Requirement: [COST-6.7] Файл к счёту — только явным действием
Приложение и замена файла открытого счёта SHALL идти только через окна «Приложить файл…» (пустая панель
файла) и «⋮ → Заменить файл…» — с площадкой для броска и кнопкой выбора. Замена MUST спрашивать: «Прежний
файл будет удалён без возврата».

#### Scenario: Пустая панель файла
- **WHEN** файл брошен на пустую панель файла счёта, заведённого вручную
- **THEN** заводится новый черновик, а в панели остаётся кнопка «Приложить файл…»

#### Scenario: Замена с площадкой
- **WHEN** в окне «Заменить файл…» на площадку брошен файл
- **THEN** окно спрашивает об удалении прежнего файла, и файл заменяется только после согласия

#### Scenario: Замена недоступна
- **WHEN** счёт заперт закрытым периодом или его файл распознаётся
- **THEN** пункта «Заменить файл…» нет

### Requirement: [COST-6.7] «Счёт из файла» при открытом счёте — в сводке
При открытом счёте вход «Счёт из файла» SHALL стоять в сводке всегда, при любой ширине и при видимом
списке. Подпись — во всплывающей подсказке и `aria-label` «Счёт из файла — или перетащите файл в окно».

#### Scenario: Открыт счёт на 1280
- **WHEN** открыт счёт при ширине, где списка нет
- **THEN** «Счёт из файла» в сводке открывает тот же выбор файлов, что палитра команд

#### Scenario: Счёт не открыт
- **WHEN** открыт список без счёта
- **THEN** вход стоит в шапке списка, а не в сводке
