# Proposal: бросок файла на всё окно, повтор до выгрузки, приложение и замена

Дочерний change зонтика `costs-invoice-screen-00-epic`, общая архитектура — `../costs-invoice-screen-00-epic/design.md` (D1, D5, D7, D8, D10).

## Why

В варианте Г колонки списка, единственной цели броска (`InvoiceScanDrop`, D4 #1093), часто нет: на 1280
и при открытом файле на 1366 список свёрнут (D2 зонтика). Бросок мимо неё отклоняет `useDropMissGuard`
курсором «нельзя», без слов. Повтор файла сегодня обнаруживается только после заведения — оговоркой
«тот же файл» и строкой пакета. Замена файла удаляет первичку без вопроса (попутный дефект зонтика).

Решения владельца по листу «Ф» (27.10.2026):
- бросок на всё окно — всегда новые черновики;
- повтор спрашивается до выгрузки, с запасным SHA-256 для установки по HTTP;
- «Не заводить» по умолчанию;
- пакет без окна;
- «Приложить файл…» у пустой панели;
- окно замены с площадкой и вопросом.

Сервер для этого делает ребёнок 03.

## What Changes

- **Цель броска — всё окно страницы счетов**, включая шапку и рейл. Бросок всегда заводит новые
  черновики, открытый счёт не меняется. У покрытия есть состояние «идёт загрузка — примем после неё».
  Пока открыт слой или у пользователя нет права, цели нет.
- **Отпечаток в браузере:** `crypto.subtle` в защищённом контексте, иначе свой SHA-256 по частям файла,
  без новой зависимости. Совпадение с сервером проверяет общий набор примеров C#/TS.
- **Один вопрос на бросок** (`GET …/invoices/same-file`) и три исхода:
  - пусто — заводим;
  - двойники — окно или придержанная строка;
  - не ответила — заводим и говорим «повтор не проверен».

  Повтор внутри броска находят по отпечаткам ещё до сети.
- **Окно повтора одного файла** — basic dialog MD3:
  - карточки двойников;
  - «Не заводить» — фокус, Enter, Esc;
  - «Завести ещё один черновик» — сознательный повтор (`acceptRepeat`);
  - запоздавшее окно не забирает Enter у печатающего, вместо него снэкбар «Решить».
- **Пакет без окна:**
  - придержанные повторы с «Открыть» и «Завести всё равно»;
  - итог «Заведено 7 · придержано 2 · 1 выбран дважды»;
  - где списка нет, ход и итог показываются в центре активности. Пакет экран не двигает.
- **«Мог завестись»:** повтор файла, чей ответ не пришёл, сначала спрашивает по отпечатку.
- **«Приложить файл…»** в пустой панели файла и окно **«Заменить файл…»** — с площадкой для броска и
  вопросом «Прежний файл будет удалён без возврата».
- **«Счёт из файла» при открытом счёте** — в сводке, всегда.

## Capabilities

### New Capabilities
- Нет.

### Modified Capabilities
- `costs`:
  - [COST-8] «Распознавание счёта» — сценарий «Несколько файлов сразу» с повторами;
  - новые требования о броске, повторе до выгрузки, окне повтора, пакете, приложении и замене, входе в
    сводке ([COST-6.7], [COST-31]).

## Impact

- **Клиент:**
  - `shared/ui/fileDrop.ts` — захват броска окном страницы вместо отказа (D1 дизайна);
  - `shared/utils/fileFingerprint.ts` — отпечаток и свой SHA-256 (новый); сторож
    `secureContextApis.test.ts` получает его в список допустимых;
  - `features/costs`:
    - `InvoiceScanDrop.tsx` → покрытие всего окна;
    - `scanBatch.ts` — придержанные, «выбран дважды», «не проверено»;
    - окно повтора, окна приложения и замены (новые файлы);
    - `InvoicesPage.tsx` — подключение;
    - сводка (из ребёнка 10) — вход «Счёт из файла»;
  - `features/activity/ActivityCenter.tsx` — раздел пакета счетов. Это оболочка, поэтому прогоняется весь
    список живых прогонов CI.
- **Сервер:** не меняется — всё нужное даёт ребёнок 03.
- **Зависимости:**
