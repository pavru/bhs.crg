# Design: бросок файла на всё окно, повтор до выгрузки, приложение и замена

## Context

Общая архитектура — `../costs-invoice-screen-00-epic/design.md` (D7). Мотивация — `proposal.md`.
Разборы, на которых стоит этот документ: Архитектор и Дизайнер по листу «Ф» (27.10.2026), макет «Ф»
(`mock/drop.js`).

Как устроено сегодня:
- **Цель броска — только колонка списка.** `InvoiceScanDrop` обёрнут вокруг `nav` в `InvoicesPage.tsx`.
  Всё остальное окно ловит `useDropMissGuard` (`shared/ui/fileDrop.ts`, ставится в `App.tsx`): он
  отклоняет бросок `dropEffect = 'none'`, без слов. Пока идёт загрузка, цель выключена так же
  беззвучно.
- **Пакет** — `scanBatch.ts`. Он живёт вне страницы и переживает уход, отправляет N последовательных
  `POST from-scan` и знает исходы «заведены», «не приняты», «повторы» (`repeats` — по `sameFile` уже
  после заведения). Любой отказ, кроме 400 и 413, останавливает пакет (`failure()`).
- **Одиночный путь** (`useAddFromScan` → `sendScan`) не делает предпроверки размера и вида: отказ
  приходит с сервера тостом.
- **`crypto.subtle` запрещён сторожем** `shared/utils/secureContextApis.test.ts` (#848). Поставка по
  умолчанию открыта по `http://…:8080`, а там его нет.
- **Центр активности** (`features/activity/ActivityCenter.tsx`) показывает задачи сервера
  (`useActiveJobs`) и уведомления. Клиентских задач в нём нет.

## Goals / Non-Goals

**Goals:**
- Бросок нигде не теряется молча: черновик или видимая причина.
- Проверка повтора работает одинаково по HTTP и HTTPS.
- Enter не заводит и никуда не уводит. Пакет не останавливает человека окном.

**Non-Goals:**
- Телефон: перетаскивания там нет. Окно повтора то же, вход — `PrimaryFab`, как сейчас.
- «Ещё счёт из этого файла» в «⋮» панели файла (предложение Дизайнера). Решения владельца по нему нет,
  после приёмки — отдельным change.
- Отмена одиночной загрузки «Остановить» до ухода байтов — вне решений листа «Ф».
- Сервер — ребёнок 03.

## Decisions

### D1. Захват броска окном страницы — в `fileDrop.ts`, а не вторым слушателем

Цель на всё окно не может быть React-обёрткой вокруг части страницы: шапка и рейл живут в оболочке.
Второй слушатель на `window` спорил бы с `useDropMissGuard` порядком регистрации: страж ставится в `App`
раньше и отклоняет бросок первым.

Решение:
- `fileDrop.ts` получает захват `claimWindowDrop({ accepts, onFiles })` — один на окно, снимается при
  уходе со страницы;
- страж, если захват есть, отдаёт событие ему, а не отклоняет;
- `useFileDragActive` не меняется;
- покрытие рисует страница счетов, поверх всего окна, с `pointer-events: none`. Оно гаснет на `drop` и
  `dragend`.

Состояния захвата:
- **принимаем** — `copy`, «Отпустите — заведём черновик / N черновиков»;
- **занят** — `none` и надпись «Идёт загрузка N из M — бросок примем после неё»;
- **модальный слой открыт** — захват молчит, курсор «нельзя», без покрытия;
- **нет права** — захвата нет вовсе.

*Отвергнуто:* обернуть `AppShell` целью счетов. Оболочка начала бы знать о модуле, а цель на других
страницах — притворяться выключенной.

### D2. Отпечаток в браузере — `crypto.subtle` или свой SHA-256 по частям, без зависимости

`shared/utils/fileFingerprint.ts`:
- `fingerprintOf(file, signal)` → hex в нижнем регистре;
- в защищённом контексте — `crypto.subtle.digest('SHA-256', await file.arrayBuffer())`. Файлы идут по
  одному, так что в памяти один файл (≤ 50 МБ);
- без защищённого контекста — свой SHA-256 (FIPS 180-4) по частям `file.slice(…)` по 4 МБ, с уступкой
  циклу событий между частями: экран не замирает;
- `localId.ts` — прецедент своей реализации там, где Web Crypto нет по HTTP.

Сторож `secureContextApis.test.ts`: `fileFingerprint.ts` и его тест вносятся в `ALLOWED`. Комментарий
сторожа говорит, почему здесь можно: есть запасной путь, и тест доказывает его равенство.

**Совпадение с сервером** проверяет общий набор примеров C#/TS (заводит 03, задача 1.5). Vitest
сверяет обе ветки с набором и с эталонными векторами FIPS — пустая строка, «abc», 448 бит, миллион
«a». Отдельно проверяются границы частей: размер части ±1, 55/56/63/64/65 байт.

**Почему без зависимости.** Алгоритм — около сотни строк с эталонными векторами. Зависимость ради одной
функции добавила бы поставщика в цепочку сборки клиента. Если замер (задача 1.2) покажет больше 1 с на
50 МБ на ноутбуке, свой путь переезжает в Web Worker — без смены формы функции.

*Отвергнуто:* только `crypto.subtle`. В типовой поставке по HTTP окно не появлялось бы никогда, и это
был бы отказ, переодетый в результат.

### D3. Порядок броска: проверки → отпечатки → вопрос → решение → отправка

1. Предпроверка `precheck` — одна для одного и для многих файлов: вид, пусто, размер, папка.
2. Отпечатки всех годных файлов. Повторы внутри броска — по отпечаткам, до сети: заводится первый по
   `inOrder`, остальные идут в итог «выбран дважды — заведён один черновик».
3. Один вопрос `sameFileByFingerprints` (ребёнок 03). Отказ вопроса **не идёт через `failure()`**:
   там любой не-400 останавливает пакет. У вопроса своя ветка — «повтор не проверен».
4. Решение:
   - **один файл с двойниками** — окно (D4);
   - **пакет** — двойники придерживаются (D5);
   - **пусто или не ответила** — отправка.
5. Отправка — как сегодня, `sendScan`. «Завести ещё один» и «Завести всё равно» шлют `acceptRepeat`.

«Остановить» и счётчик «N из M» работают после шага 4. Пропущенные в окне файлы попадают в итог «не
заведены по вашему решению» без «Повторить».

**«Повтор не проверен».** Для одного файла — снэкбар «Повтор не проверен — если файл уже был, счёт
скажет об этом», для пакета — строка итога. Строки в самом счёте клиент не хранит. После заведения
ответ `from-scan` уже несёт `sameFile`, посчитанный сервером, и форма и индикатор показывают двойника
как обычно. Отдельная пометка «не проверено» в счёте стала бы неправдой, как только сервер посчитал.

**«Мог завестись».** «Повторить» у строки «ответ не пришёл» сначала спрашивает по отпечатку. Двойник с
`mine: true`, заведённый после начала пакета, — это свой черновик: строка становится «заведён (ответ
потерялся)», и второго не будет.

### D4. Окно повтора — basic dialog, «Не заводить» по умолчанию

`Modal` из `sharedui-md3-13`, `role="alertdialog"`, `aria-describedby` на пояснение.
- **Карточка двойника** — номер и дата, поставщик, состояние словами сервера, «завёл Петров» или «вы,
  2 мин назад». Без имени строки «кто завёл» нет. «Открыть» с `aria-label` «Открыть счёт 2611 от
  22.10.2026».
- **Действия справа налево:** «Не заводить» (крайняя, фокус, Enter, Esc, щелчок мимо), «Завести ещё
  один черновик» (text). Если у двойников два и более разных номера — tonal и пояснение «В этом файле
  уже разобраны счета 2611 и 2612…».
- **Запоздавшее окно.** Если с броска прошло больше 1 с, а `document.activeElement` — поле ввода, окно
  не открывается. Вместо него снэкбар без таймера «Файл уже у счёта 2611 · Решить» (`sharedui-md3-12`),
  нажатие открывает то же окно. Порог 1 с — от разбора Дизайнера, проверяется прогоном.
- **«Открыть»** — уход со счёта: он идёт путём смены счёта (D5 зонтика — сначала дописать текущий;
  до ребёнка 12 — нынешняя охрана ухода).
- Пока окно открыто, захват броска молчит (D1). Закрытое окно возвращает фокус к сводке.

### D5. Пакет — придержанные строки, дом итога по месту

`ScanBatch` получает:
- `held: HeldScan[]` — файл (`File` в памяти вкладки) и двойники;
- `doubled: string[]` — выбранные дважды;
- `unchecked: boolean` — вопрос не ответил.

Итог — «Заведено 7 · придержано 2 · 1 выбран дважды». У придержанных «Открыть» (обычный переход: пакет
живёт вне страницы) и «Завести всё равно». После перезагрузки файла нет, и строка говорит «выберите
файл заново».

**Дом.**
- Список виден — полоса `InvoiceScanBatchBar` над ним, как сейчас.
- Списка нет — раздел «Загрузка счетов» в центре активности: ход с «Остановить» и итог, который сам
  не исчезает. «Открыть» ведёт к полосе или к счёту.
- Центр активности получает клиентский источник задач — хук `scanBatch` уже вне страницы — рядом с
  серверными задачами. Второй кнопки в шапке нет (`docs/UI.md`: «вторую кнопку для ещё одного потока
  событий не заводят»).

### D6. Приложение и замена — окно с площадкой; площадка — своя для экрана

- **Пустая панель файла** счёта без файла — кнопка «Приложить файл…». Бросок на панель — это бросок в
  окно, то есть новый черновик (D1). Тихо приложить чужую бумагу к чужому счёту так нельзя.
- **«⋮ → Заменить файл…»** и **«Приложить файл…»** открывают окно с площадкой «Перетащите файл или
  выберите…» и кнопкой выбора. У замены второй шаг — вопрос «Прежний файл будет удалён без возврата»,
  дальше `POST …/{id}/scan` с `If-Match`, как сейчас.
- Пункта замены нет у запертого счёта и при идущем распознавании (правило есть, сохраняется).
- **Площадка** — компонент экрана (`features/costs/InvoiceFileDropArea.tsx`) на `fileDrop.ts` и общей
  `Button`. В детях `sharedui-md3-*` площадки нет. Если она понадобится второму экрану, её поднимут в
  `shared/ui` по правилам `docs/UI.md`. На время окна площадка — свой захват броска поверх захвата
  страницы.

### D7. «Счёт из файла» в сводке

`IconButton` с `Tooltip` и `aria-label` «Счёт из файла — или перетащите файл в окно». Исполнитель — тот
же, что у палитры (`usePaletteIntent` / `PALETTE_ACTIONS.invoiceScan`), своей кнопки-двойника нет.
Правило места одно: вход стоит в шапке того, что занимает экран. Открыт счёт — в сводке, всегда. Не
открыт — в шапке списка.

## Risks / Trade-offs

- [Свой SHA-256 медленный на 50 МБ] → части с уступкой циклу и замер (задача 1.2). Больше 1 с — Web
  Worker.
- [Гонка двух вкладок между вопросом и выгрузкой] → оговорка `sameFile` после заведения остаётся
  страховкой.
- [Центр активности — оболочка] → правка оболочки гоняет весь список живых прогонов
  (`npm run -s test:e2e:ci`). Заход в чужой домен — один раздел и источник задач.
- [`shell-07-scan-drop-hint` (#1435) не слит и описывает колонку как цель] → кто сливается вторым, тот
  правит свою спецификацию. Строка-подсказка внизу колонки остаётся верной: колонка остаётся частью
  окна, а текст «перетащите сюда» нужно сверить. Задача 0.4.
- [Окно повтора на каждом броске у того, кто заводит третий счёт из одного PDF] → «Не заводить» по
  умолчанию стоит один повторный бросок. Пояснение и tonal при разных номерах.

## Migration Plan

- **PR 1** — отпечаток, захват окна, вопрос, окно повтора, придержанные в полосе, вход в сводке.
- **PR 2** — центр активности, «Приложить файл…», окно замены с вопросом.
- **Откат** — каждый PR откатывается отдельно. Сервер от клиента не зависит: вопрос — чтение, а
  `acceptRepeat` необязателен.
