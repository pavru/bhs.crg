# Proposal: «план против факта» материалов — модуль `costs`

Дочерний change зонтика `plan-00-epic`, общая архитектура — `../plan-00-epic/design.md` (D4, D10, D17, D18).

## Why

`COST-21` и `COST-26` требуют сравнить сметную стоимость материалов с фактическими затратами по
разноске: где материалов купили больше сметы, а где — меньше. Строки без пары не прячутся: материал вне
сметы и сметный материал без закупки — это и есть то, что нужно увидеть. Факт — двумя числами:
**разнесено** и **оплачено**; сравнение со сметой — по разнесённому, чтобы смонтированный, но не
оплаченный материал не давал несуществующей экономии.

Сметная стоимость — данные `plan`, закрытые правом `plan.estimate.cost` (`PLAN-23`, D4 зонтика); `costs`
читает её контрактом «Плановые работы» (`plan-23`, часть `cost`) в правах спрашивающего. Ждало модуля
`plan` (`STG-17`).

## What Changes

- Отчёт `GET /api/costs/estimate-vs-costs` по стройке (отбор по разделу): строка — позиция номенклатуры;
  колонки — сметная стоимость материала (сумма по действующим редакциям), разнесено, оплачено,
  расхождение «разнесено − смета». Строки только сметные и только закупленные — показываются.
- Сметная стоимость без права `plan.estimate.cost` — колонка «скрыто правами» с кодом права; у материала,
  чью стоимость смета не несёт, — «нет в смете», а не ноль; `plan` выключен — «не подключено». Отчёт
  остаётся полезным и так: разнесено и оплачено по номенклатуре.
- Экран — вкладка отчёта «Затраты по стройке» (макеты П6), выгрузка в XLSX тем же механизмом (`COST-22`).
- Право отчёта — `costs.report.read`, как у «Затрат по стройке»; новых прав нет.

## Capabilities

### New Capabilities
- Нет.

### Modified Capabilities
- `costs`: отчёт «план против факта» материалов по стройке со сметной стоимостью из контракта.
