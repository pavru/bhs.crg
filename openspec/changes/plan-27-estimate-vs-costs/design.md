# Design: «план против факта» материалов

Дочерний change зонтика `plan-00-epic`, общая архитектура — `../plan-00-epic/design.md` (D4 — деньги
правом, D10 — контракты, D17 — носители, D18 — макеты). Здесь только решения этого change.

## Context

Сверено по коду master `6b81e51e`.

- «Затраты по стройке» — `GET /api/costs/site-costs` под `costs.report.read`
  (`Modules.Costs/Endpoints/SiteCostsEndpoints.cs:91-93`); деньги считает `CostViews`
  (`Data/CostViews.cs:31`). Срезов по номенклатуре в отчёте нет: есть стройки, разделы, поставщики.
- Строка счёта ссылается на номенклатуру (`COST-7`), разноска — по количеству (`COST-10`): доля строки на
  стройку несёт и количество, и деньги.
- Сметная стоимость материалов позиции — часть `cost` «Плановых работ» (`plan-23`), только с
  `plan.estimate.cost`; стоимость ресурса бывает не у каждой сметы — `not-in-estimate`.

## Goals / Non-Goals

**Goals:** сравнение по номенклатуре стройки с двумя числами факта; честные состояния сметной колонки;
та же арифметика денег, что у «Затрат по стройке».

**Non-Goals:**
- сравнение количеств (сколько метров по смете и сколько купили) — материалы сметы с количествами уже
  видны в заявке (`plan-26`); здесь деньги;
- взгляд «на момент закрытия» — отчёт считает «с исправлениями»;
- сравнение работ (не материалов) с затратами — разноски на позицию перечня нет (`COST-14`).

## Decisions

- **Строки.** Объединение номенклатуры из сметы (`plan-23`, часть `cost`, по действующим редакциям) и из
  разнесённых на стройку строк счетов. Строка без пары остаётся (`COST-21`).
- **Факт.** «Разнесено» — доли строк счетов в учёте (без черновиков и отклонённых) на стройку или раздел;
  «оплачено» — из них доли оплаченных; оба — путём `CostViews`, как «Затраты по стройке» и
  «Фактические затраты» (`plan-24`). Строки счёта без номенклатуры — одной строкой «без позиции
  номенклатуры», а не пропадают.
- **Расхождение** — «разнесено − смета», только когда обе стороны — числа; иначе пусто с причиной
  состояния.
- **Состояния сметной колонки** (D17): `hidden` с кодом `plan.estimate.cost`; `not-connected` («модуль
  „Планирование“ не подключён»); у строки — `not-in-estimate`. Сумма колонки при `hidden` не отдаётся.
- **Ворота.** Адрес под `costs.report.read` за воротами модуля `costs`; только читает — `If-Match` не
  нужен. Выгрузка XLSX выгружает видимое, скрытое правами не выгружается (`CORE-33`).
- **Экран.** Вкладка «План против факта» отчёта «Затраты по стройке»; макеты — общий раунд П6 с
  `plan-26`; таблица — `DataGrid`.
- **Сторож.** `EstimateVsCostsTests`: смета — кабель 100 000, разнесено 120 000, оплачено 90 000 —
  расхождение +20 000; закупленный материал вне сметы — строка со сметой пусто; сметный без закупки —
  строка с фактом 0; без `plan.estimate.cost` — колонка `hidden`, сумм сметы в ответе нет; `plan`
  выключен — `not-connected`; ресурс без стоимости — `not-in-estimate`; без `costs.report.read` — 403.
- **Чем ломается.** Сравнение по оплаченному — смонтированный неоплаченный кабель показан экономией.
  Пропуск строк без пары — лишняя закупка не видна.

## Risks / Trade-offs

- [Отчёт целиком виден немногим] → `costs.report.read` и `plan.estimate.cost` вместе по умолчанию есть
  только у «Руководителя» и «Администратора». «Бухгалтер» видит факт без сметы. Если отчёт нужен ещё
  кому-то — это выдача права, а не правка отчёта; вопрос владельцу отмечен в отчёте нарезки.
- [Номенклатура сметы сопоставлена не так, как в счетах] → обе стороны ссылаются на номенклатуру ядра
  (`CORE-9`); расхождение сопоставления видно парой строк без пары.
