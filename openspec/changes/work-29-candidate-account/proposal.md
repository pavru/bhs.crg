# Proposal

## Why

Панель «Назначения» (change `work-12-assignments-ui`) обязана помечать у выбора сотрудника «нет учётной записи»
по полю ответа сервера ([WORK-47]: монтажник — это сотрудник учётной записи; без связи он не введёт отчёт
сам). Кандидат `GET /api/work/assignments/candidates` этого поля не несёт: у вида «менеджер» отсутствие связи
видно только как причина `eligible: false`, у вида «монтажник» — не видно ничего. Состояние связи порт
сотрудников модуля уже отдаёт вместе с поиском — не хватает только выдачи.

## What Changes

- Кандидат назначения несёт `account: { state }`, где `state` — `linked`, `none` или `deleted`: те же
  значения, что у связи на карточке сотрудника (`GET /api/employees`, change `work-01-employee-account`).
- `deleted` («учётную запись удалили, связь осталась») выдаётся отдельно от `none` («связи нет»): экран,
  получивший `none` вместо `deleted`, предложил бы связать сотрудника, которого никто не отвязывал.
- Годность кандидата (`eligible`, `reason`) не меняется: поле — пометка, а не новая причина отказа.
- Менеджер, чью учётную запись удалили, отвергается прежним образом, но причина теперь «учётная запись
  сотрудника удалена», а не «сотрудник не связан с учётной записью»: иначе кандидат нёс бы `deleted` и
  причину «не связан» одновременно. Так же — в признаке `canChange` строки назначения.
- Клиент получает тип кандидата с этим полем в `src/client/src/shared/api/work.ts`; панель и выбор —
  забота `work-12`.
