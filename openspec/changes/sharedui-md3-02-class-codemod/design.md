# Design: перевод классов перезапускаемым кодмодом

Общая архитектура — `../sharedui-md3-00-epic/design.md`: кодмод (D3), псевдонимы (D2), сторожа (D11).
Словарь и псевдонимы — `../sharedui-md3-01-tokens/design.md`. Макетов нет (D10).

## Context

- Счёт классов — 5302 вхождения в 339 файлах (31 — в тестах), разбор `colorCandidates` из
  `color-classes-lib.mjs` (разбор Архитектора 27.10.2026, §1.3). Один к одному переводится ~3,5 тыс.
- Классы живут не только в `className`: карты вариантов (`Button.tsx:48-59`), `clsx`, шаблоны,
  константы (`DEPTH_COLORS`), ожидания тестов (12 файлов). Отрицательных ожиданий с именами цвета — 10
  (`rg 'not\.(toContain|toHaveClass)'` по тестам клиента).
- Граница класса уже описана регуляркой `CANDIDATE` (`color-classes-lib.mjs:33`): перед классом — начало,
  пробел, кавычка, `:` варианта; после — конец, пробел, кавычка, скобка. `stripComments` отделяет
  комментарии с сохранением номеров строк.
- После 01 в коде нет `--f-*`, но они могут прийти из чужой ветки; `var(--color-brand)` — 8 мест.

## Goals / Non-Goals

**Goals:** весь перевод без изменения вида — одной командой, повторяемой на любой ветке.

**Non-Goals:** неоднозначные имена (04 — серые и текст на контейнерах, 05 — наведение и отключённое);
радиусы, тени, текст (06, 07 — они дописывают карту); значки (03).

## Decisions

### Карта
`src/client/scripts/md3-class-map.json`, три раздела:
- `names` — имя цвета для любой цветовой утилиты (`COLOR_UTILITIES`): `fg1 → on-surface`, `fg2 →
  on-surface-variant`, `base → surface-container-low`, `muted → surface-container`, `muted-hover →
  surface-container-high`, `stroke → outline-variant`, `stroke-strong → outline`, `brand → primary`,
  `brand-subtle → primary-container`, `on-brand(-subtle) → on-primary(-container)`, `tonal`/`on-tonal` →
  `secondary-container`/`on-secondary-container`, `tertiary-subtle`/`on-tertiary-subtle` →
  `tertiary-container`/`on-tertiary-container`, `danger*` → `error*`, `success-subtle`/`warning-subtle` →
  `*-container`. Каждое имя помечено `same: true` — «вид не меняется», это проверяет тест.
- `classes` — полный класс, перекрывающий `names` для одной утилиты. Здесь же пометка `skip` для
  неоднозначного: `text-stroke-strong`, `text-base`. Сюда дописывают 06 и 07 (`rounded-md → rounded-sm`).
- `vars` — переменная: `--f-shadow4/16/28 → --md-sys-elevation-level1/2/3`, `--f-brand →
  --md-sys-color-primary` и прочие строки таблицы 01; `--color-<старое> → --color-<роль>`.
- Неоднозначные имена (`fg3`, `fg4`, `fg-disabled`, `brand-hover`, `brand-pressed`, `warning-border`,
  `stroke-subtle`) в карту не входят и перечисляются отчётом. Перечень берётся из описания темы:
  псевдоним с `legacy`-значением или без пары в карте — неоднозначен.
- **Отвергнуто — выводить карту из `aliases` описания темы целиком.** Тогда `text-stroke-strong` (обводка
  как цвет текста) перевёлся бы в `text-outline` — один к одному по пикселям, но против MD3; исключения
  по утилите живут только в карте.

### Скрипт
- Токенизатор — `CANDIDATE` с вариантами (`hover:`, `dark:`, `data-[…]:`, `group-hover:`), `/opacity`,
  `!` в начале и в конце; переменные — отдельная регулярка `--[a-z0-9-]+`. Каждое найденное имя
  заменяется по карте **один раз**, по исходному тексту: строка собирается из кусков, а не правится
  повторно.
- Проходы: код (меняет) и комментарии (меняет то же, отдельной строкой отчёта): иначе комментарий
  советовал бы старое имя, а сторож велит называть класс в комментарии целиком.
- **Отрицательные ожидания:** в тестах строка, где в той же цепочке вызова стоит `.not.`, не меняется и
  попадает в отчёт. Их ~10 — переписываются руками, и ревью проверяет, что каждое снова может упасть
  (временно вставить запрещённый класс).
- Отчёт: замены по парам, файлы, неоднозначное с `файл:строка`. `--check` — режим без записи: код выхода 1,
  если есть что менять (для проверки чужой ветки и для теста идемпотентности).
- Только `typescript` уже в проекте; `ts-morph`/`jscodeshift` не нужны (D3).

### Тесты
- `scripts/md3-migrate.test.mjs`:
  - фикстуры: варианты, прозрачность, `!`, строка вне `className`, комментарий, отрицательное ожидание,
    `text-base`, цепная карта `a → b`, `b → c`;
  - идемпотентность: второй прогон по выходу первого — без изменений;
  - **пары карты:** для каждой пары с `same: true` `candidatesToCss` старого и нового класса × утилиты с
    разрешёнными переменными равны в обеих темах (разбор переменных — общий с `md3-theme.test.mjs` 01).
- Тест пар живёт, пока живы псевдонимы; финал (20) снимает его вместе с ними.

### Что меняется рядом
- `ui-baseline.json`: уровень `legacy-class` — `npm run ui:ratchet:update` после прогона.
- `white-on-fill`: `ROLE` уже знает роли MD3 (01); фикстуры `ui-ratchet.test.mjs` переводятся на роли,
  старые имена остаются одной фикстурой, пока живы псевдонимы.
- `color-classes.test.mjs` и `ui-ratchet.test.mjs` в `scripts/` команда не обходит (вне `src/`): их
  фикстуры правятся руками в том же PR.

### Как обновить ветку
- Ветка, начатая до перевода: (1) слить master до коммита перевода обычным порядком — настоящие
  конфликты решаются как всегда; (2) слить сам коммит перевода, в конфликтах взяв версию ВЕТКИ
  (`git merge -X ours <перевод>`): в этом слиянии master только переименовывает; (3) `npm run md3:migrate`
  переводит старые имена ветки, коммит; `--check` — код 0.
- **Отвергнуто — «принять master в конфликтах»** (так было в планировании). Проверено на живой ветке
  (3.1): строка, где ветка дописала класс рядом со старым именем, после `-X theirs` приходит из master без
  правки ветки — молча, слияние и все проверки зелёные.

### Что уточнила реализация
- `fg4 → outline` — в `names` (`same: true`, значения равны), `text-fg4` — `classes.skip`: текст цветом
  обводки ждёт 04, а `bg-fg4`, `decoration-fg4` переводятся один к одному.
- `vars` — только `--f-*` с ролью того же значения; `--f-fg3`, `--f-fg4`, `--f-fg-disabled`,
  `--f-stroke3`, `--f-brand-hover/pressed`, `--f-warning-stroke`, `--f-r-*`, `--f-font-mono` — в отчёт
  (у радиусов и моноширинного под `@theme inline` переменной в рантайме может не быть). `var(--color-<старое>)`
  переводится по `names`, отдельных строк не требует.
- Токенизатор берёт любой класс, не только цветовой: `classes` дописывают радиусы (06). Граница шире
  `CANDIDATE`: перед классом и `.` (селектор `span.bg-brand-subtle`), после — `.`, `:` (`.bg-brand:hover`)
  и `\` (`\'bg-brand\'` в строке внутри строки). Без `.` два теста искали класс селектором и упали.
- Отрицательное ожидание — строка теста, где есть `.not.`; все пять таких в клиенте однострочные.
- `src/theme/` не обходится: там сами псевдонимы (`--color-fg1: …` перевёлся бы в роль).
- Разбор объявлений с разрешёнными переменными — `loadDeclarations` в `color-classes-lib.mjs`, общий с
  `md3-theme.test.mjs`.

## Risks / Trade-offs

- [PR на ~330 файлов конфликтует со всеми открытыми ветками] → один PR, слить сразу после зелёного CI;
  обновлять ветки после коммита бота; команда в описании PR.
- [Тест пар не видит смысла: `text-on-surface-variant` на месте `text-fg2` может быть не той ролью по
  MD3] → смысл — дело компонентов 10–16 и экранов 17; кодмод переводит словарь, не раскладку.
- [Отрицательное ожидание переписали, а упасть оно больше не может] → проверка временной вставкой, список
  в описании PR.
