# Design: подключение подсказок — шаг «Новая позиция», формы, ячейки, флажок

Общая архитектура — `../suggest-00-epic/design.md` (D3, D4, D9, D10, D12); компонент —
`../archive/2026-10-23-suggest-03-field/design.md`. Здесь только решения этого change.

## Context

- Шаг «Новая позиция» (`features/costs/NewNomenclatureStep.tsx`): поле — свой `<input>` на `:162`
  (в issue — `:147`), значения по ключам поля описания двери; набор уже идёт с задержкой 250 мс к поиску
  похожих (`:95-103`). Описание двери `GET /api/nomenclature/intake` под `core.nomenclature.edit`
  (`NomenclatureIntakeEndpoints.cs:27`): у поля ключ, подпись, обязательность, `identity`, варианты,
  тэг — **ни вида поля, ни типа-владельца** (`FieldDto`, `:81`). В описание попадают поля `string` и
  `text` (`NomenclatureIntake.cs:125,220`).
- `PrimitiveInput.tsx` рисует `TextField` (форма с подписью) или голый `<input>` (`:125-133`); его зовут
  `RequisitesTab`, `ComplexFields`, `catalog/index.tsx`, `QualityDocForm.tsx` **и
  `features/costs/InvoiceExtraFields.tsx`** — последний подключать нельзя (D9).
- `TableCell` (`ComplexCells.tsx:59-120`) получает `scope`/`scopeId`, но не тип-владелец; текстовая
  ячейка — `<input>` без `aria-label` (`:110-118`).
- `FieldBuilder.tsx`: «Вычисляемое (формула)» — нативный флажок на `:456-468`; тэги поля — чипами в
  свёрнутой карточке (`:337-340`) и в списке выбора (`fieldTags`, `:305`).
- Храповик размера: `FieldBuilder.tsx` 654, `RequisitesTab.tsx` 653, `ComplexFields.tsx` 779 строк кода
  (`src/file-size-baseline.json`) — расти им нельзя.
- e2e — `src/client/e2e/*.mjs` на общем `harness.mjs`; новый сценарий вписывается в список живых
  прогонов CI.

## Goals / Non-Goals

**Goals:** подсказка в трёх точках по одному правилу; ни одного вызова адреса там, где правило
говорит «нет» или нет контекста типа; флажок без чипа; e2e на свежей базе.

**Non-Goals:** `InvoiceExtraFields` (D9); вложенный источник (`suggest-04`); переопределение флажка в
наследнике; перевод «Вычисляемое» на `Checkbox` (это #1414 — здесь только если правка задевает строку).

## Decisions

- **`identity` — не тэг однозначности (решение владельца 23.10.2026, вопрос из реализации).** Сверкой
  выяснилось: у заказчика «Номенклатура → Производитель» несёт `identity:2` — это компонент составного
  ключа, и правило `suggest-01` его не подсказывало бы, то есть главный выигрыш замера #1528 пропадал.
  Вторая грань — поиск похожих в шаге берёт только поля ключа: подстановка неключевого поля его не
  запускает, и требование «подстановка запускает поиск похожих» было невыполнимо. Решение: код `identity`
  из правила убран (C#, TS, общий файл случаев, перепись тэгов — `identity` в «не однозначных» с
  причиной), требование TYPE-2 в `types-and-tags` — MODIFIED. Однозначными остаются `org.inn`,
  `doc.number`, `employee.personnelNumber`, `nomenclature.article`, `org.name`, `employee.account`.
  Повтор ключа целиком ловят «такая уже есть» в шаге и сверка двойников. Отвергнуто: «однозначен только
  ключ из одного поля» (правилу понадобилась бы вся схема, а не поле — меняются обе сигнатуры и форма
  передаёт соседей) и «оставить как есть» (снять `identity` с поля — сменить ключи всех материалов и
  порвать связки с документами качества).
- **Контекст типа-владельца — `fields/suggestContext.tsx`.** `SuggestContext = { type, scope?, scopeId? }`
  и провайдер. Ставят его: `RequisitesTab` (тип документа, область комплекта), `ComplexFields` (тип
  составного поля — переопределяет внешний), `ArrayTableModal` (тип строки массива), форма записи
  каталога (тип записи и её область), `QualityDocForm`, шаг «Новая позиция» (тип вида, уровень «вся
  система»). `PrimitiveInput` и `TableCell` читают контекст и `Suggestable` поля: нет контекста или код не
  «подсказывается» — обычный `TextField`/`<input>`, адрес не зовётся. Так `InvoiceExtraFields` остаётся
  без подсказок без единой проверки «это счёт».
- **Тип в контексте** — тип записи (или составного/строки), а не объявивший поле предок: решение В-2
  зонтика, рекомендация (а). Если В-2 решён иначе — контекст получает тип-владелец по полю через
  `resolveEffectiveFields` с запоминанием предка, а дверь — поле `owner`.
- **Шаг «Новая позиция».** Описание двери получает у поля `suggest` — код причины `Suggestable`,
  вычисленный сервером (у шага нет схемы, и разбирать её он не должен). Поле с кодом «подсказывается» —
  `SuggestField` в контексте `{ type: kind.typeId, scope: System }`; подстановка выбранного идёт тем же
  `type(key, value)`, то есть запускает поиск похожих, как набор (поле ключа: после решения про
  `identity` «Производитель» подсказывается). Поле — `SuggestField compact`: шаг рисует подпись над полем
  сам, и вид поля не меняется; список открывается вводом и Alt+↓. Право — по решению В-1: при (а) адрес
  открыт держателю `core.nomenclature.edit`, клиент ничего не проверяет; при (б) поле подсказки
  показывается только с `core.catalog.read` (`useCan`).
- **Флажок — `settings/SuggestFlag.tsx`.** Принимает поле и `onChange`; по коду `Suggestable`: «да» или
  `manual` — `Checkbox` «Подсказывать введённое ранее» с `description` «Поле предлагает значения,
  введённые в нём в других записях. Снимите, если значения уникальны», снятие добавляет
  `input.noSuggest`, установка убирает; `type`, `computed` — ничего; прочие — строка `text-caption
  text-fg3` с причиной (тексты по коду — в `shared/api/suggestable.ts`). В `FieldBuilder` — одна строка
  вызова рядом с «Вычисляемое»; `input.noSuggest` исключается из чипов карточки и из списка выбора тэгов
  (`fieldTags`) — одним фильтром в `shared/api/tags.ts`, а не в `FieldBuilder`.
- **Макет флажка.** Положение и текст заданы разбором Дизайнера (#1533), но строка причины вместо флажка
  — новое на экране; макет — вместе с макетами `suggest-03`, выбор владельца.

  **Выбрано владельцем 23.10.2026 — вариант В «Как А, плюс пометка „без подсказки“ в шапке карточки»**
  (макет «Флажок подсказки в карточке поля»,
  https://claude.ai/design/p/a6a517a8-bbfd-43d2-93b3-05ff36d4a886?file=%D0%A4%D0%BB%D0%B0%D0%B6%D0%BE%D0%BA+%D0%BF%D0%BE%D0%B4%D1%81%D0%BA%D0%B0%D0%B7%D0%BA%D0%B8+%D0%B2+%D0%BA%D0%B0%D1%80%D1%82%D0%BE%D1%87%D0%BA%D0%B5+%D0%BF%D0%BE%D0%BB%D1%8F.html).
  Отвергнуты А (то же без пометки — снятый флажок не виден без раскрытия) и Б (строка «Подсказка:» в сетке
  настроек, пояснение в Tooltip). Что это значит для кода: раскрытая карточка — `Checkbox` с `description`
  под «Вычисляемое (формула)», у кода однозначности на его месте строка причины `text-caption text-fg3`;
  в шапке карточки при `manual` — `StatusBadge tone="quiet"` «без подсказки» рядом с типом поля (чипа
  тэга по-прежнему нет). В макете строка причины нарисована у `identity` — после решения выше у этого
  тэга причины нет, вид тот же для `article`, `inn` и прочих.
- **`aria-label` у текстовой ячейки** — `field.title`, попутно.
- **Документы.** `USER_GUIDE` — как работает подсказка (свои сверху, «С других строек», Tab не
  принимает); `ADMIN_GUIDE` — флажок поля и причины; оглавления — `npm run toc` в `docs/tools`.
- **Чем ломается.** Подключение в `PrimitiveInput` без условия контекста — e2e «дописанные поля счёта —
  запросов нет» краснеет. Чип тэга в карточке — e2e флажка краснеет. Рост `FieldBuilder.tsx` —
  `FileSizeRatchet`.

## Risks / Trade-offs

- [Подстановка в шаге запускает поиск похожих дважды — от набора и от выбора] → один `type(...)`;
  задержка поиска похожих та же, лишний запрос гасится отменой.
- [Контекст «протекает» во вложенное составное с чужим типом] → каждый `ComplexFields` и
  `ArrayTableModal` переопределяет `type`; тест — подсказка поля составного зовёт адрес с типом
  составного, а не документа.
