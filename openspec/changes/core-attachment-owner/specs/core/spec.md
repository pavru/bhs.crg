# Spec Delta: core

## ADDED Requirements

### Requirement: [CORE-37.2] У файла хранилища есть владелец
Каждая запись реестра файлов SHALL называть владельца: ядро или код модуля. Владельца назначает тот,
кто кладёт файл, и после записи он не меняется. Модуль MUST класть файлы только своим портом, который
подставляет код модуля сам; назвать чужой код модуль не может.

#### Scenario: Файл кладёт ядро
- **WHEN** пользователь загружает вложение адресом `POST /api/attachments`
- **THEN** запись реестра называет владельцем ядро

#### Scenario: Файл кладёт модуль
- **WHEN** модуль `costs` кладёт скан счёта своим портом
- **THEN** запись реестра называет владельцем `costs`

#### Scenario: Файлы, лежавшие до перехода
- **WHEN** экземпляр обновляется до версии с владельцем
- **THEN** разовый сбор называет владельцем модуль, в схеме которого найден путь, а остальным — ядро
- **AND** повторный старт сбор не повторяет

### Requirement: [CORE-37.2] [WORK-39] Общий адрес выдаёт только файлы ядра
`GET /api/attachments` и материализация картинок при генерации документа SHALL выдавать только файлы,
владелец которых — ядро. На файл модуля они MUST отвечать так же, как на незнакомый путь: 404 без
причины, по которой файл модуля отличим от отсутствующего.

#### Scenario: Файл модуля общим адресом
- **WHEN** пользователь с `core.files.use` запрашивает общим адресом путь файла модуля
- **THEN** ответ — 404, такой же, как на незнакомый путь

#### Scenario: Путь файла модуля в реквизитах документа
- **WHEN** в поле-картинку реквизитов вписан путь файла модуля и документ генерируется
- **THEN** картинка не материализуется, генерация называет поле, файл которого недоступен

#### Scenario: Вложение ядра
- **WHEN** пользователь с `core.files.use` запрашивает путь вложения ядра
- **THEN** файл отдаётся, как прежде

#### Scenario: Без права на файлы
- **WHEN** пользователь без `core.files.use` обращается к общему адресу
- **THEN** ответ — 403

### Requirement: [CORE-37.2] Модуль читает только свои файлы
Порт файлов модуля SHALL открывать, измерять и удалять только файлы, владелец которых — этот модуль.
На чужой файл порт MUST отвечать как на отсутствующий. Служебные читатели ядра (резервная копия,
читаемый образ офисного файла) MUST называть владельца явно; читать «без владельца» MUST NOT ни один
путь, кроме резервной копии.

#### Scenario: Модуль открывает чужой файл
- **WHEN** модуль `work` открывает своим портом путь файла `costs`
- **THEN** порт отвечает «файла нет»

#### Scenario: Читаемый образ скана счёта
- **WHEN** ядро строит читаемый образ офисного файла счёта
- **THEN** оно читает файл от имени `costs`, и образ строится, как прежде

#### Scenario: Резервная копия
- **WHEN** снимается резервная копия экземпляра с модулями `costs` и `work`
- **THEN** в архив попадают файлы ядра и обоих модулей, а восстановление возвращает каждому его владельца
