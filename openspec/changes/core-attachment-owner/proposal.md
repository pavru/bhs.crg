# Proposal: владелец у файла хранилища

Самостоятельный change ядра. Условие для `work-17-photos` (см. `../work-00-epic/design.md`, Risks).

## Why

В реестре файлов (`blob_registry`) записано, что файл создало приложение, но не записано, кому он
принадлежит. Пока все пользователи — сотрудники с равным допуском (#675), этого хватало. Модуль `work`
изолирует отчёты построчно (`WORK-39`): чужой отчёт отвечает 404, и фото его строк не должны читаться
ни одним путём, кроме адреса модуля с его проверкой доступа. Условие безопасности — локальный отчёт
аудита, раздел 2.

## What Changes

- У записи реестра появляется **владелец**: ядро или код модуля. Владельца назначает тот, кто кладёт
  файл; модуль кладёт файл только своим портом, и тот подставляет код модуля сам.
- **Общий адрес файлов ядра** (`GET /api/attachments`) и **материализация картинок при генерации**
  выдают только файлы ядра. Файл модуля там отвечает так же, как незнакомый путь.
- **Порт модуля** `IModuleBlobs` открывает и удаляет только файлы своего модуля.
- **Служебные читатели ядра** называют владельца явно: резервная копия читает всё, читаемый образ
  офисного файла счёта читает файл `costs` от его имени.
- Разовый сбор владельцев для уже лежащих файлов — миграцией, по схеме колонки, где путь найден.
- Право `core.files.use` остаётся воротами общего адреса, его смысл в ТЗ (`CORE-37.2`) переписан.

## Capabilities

### New Capabilities
- Нет.

### Modified Capabilities
- `core`: владелец файла хранилища, выдача по владельцу.

## Impact

- **Сервер:**
  - `Domain/Storage/BlobRegistryEntry.cs`, `Infrastructure/Storage/RegisteredBlobStorage.cs`,
    `Application/Common/IBlobStorage.cs`;
  - `Api/Modules/Ports/ModuleBlobsPort.cs` и `ModulePorts.cs`;
  - `Api/Renditions/RenditionStore.cs`, `Infrastructure/Backup/*`;
  - миграция ядра со сбором владельцев.
- **Модуль `costs`:** получает порт с кодом модуля. Поведение экранов не меняется: скан счёта уже
  читается адресом модуля (`invoices.ts`, `loadInvoiceScan`).
- **Клиент:** не меняется.
- **Документы:** `docs/tz/10-ядро.md` (`CORE-37.2`), `docs/DEV_NOTES.md`.
