# Proposal: «по смете — фактически» и выработка

Дочерний change зонтика `work-00-epic`, общая архитектура — `../work-00-epic/design.md` (D4, D13, D15, D17).

> **Показ выработки рядом с работой графика** (`PLAN-16`) — тоже здесь, вкладом `work` в экран графика
> `plan` вместе с контрактом «Выработка» (решение нарезки этапа 3 от 22.10.2026, D18 зонтика). Контракт
> «Плановые работы» с правом `plan.labor.read` строит `plan-23-planned-works-contract`.

## Why

Вариант Б по `WORK-Q4`: «Ход работ» стройки показывает сметные чел.-ч на принятый объём против
фактических часов принятых отчётов (`WORK-42`). Так видно, где работы идут дольше сметы, без своих норм
и без денег. Выработка по виду работ (`WORK-43`) нужна графику (`PLAN-16`) как поправка будущего
планирования. Но честна она только по отчётам с одним видом работ (`WORK-Q6`). Часы из модуля не
выходят (`WORK-57`, Е4): считает сам `work`, сметные нормы он берёт контрактом «Плановые работы» под
узким правом `plan.labor.read` (Е3), а наружу отдаёт только производное.

## What Changes

- **PR 1, сервер.**
  - `GET /api/work/labor/estimate-vs-actual` — по стройке за период:
    - сметные чел.-ч на принятый объём, фактические часы принятых отчётов;
    - отдельной строкой — работы без позиции сметы и часы без сметных работ.
  - Отбор по разделу — только разнесением часов отчёта по сметной трудоёмкости, с пометкой
    `distributed`.
  - `GET /api/work/labor/productivity` — выработка по виду работ по месяцам:
    - только по отчётам с одним видом работ, с размером выборки;
    - порог «данных мало» задаёт сервер, отброшенное названо;
    - по стройке, разделу и сотруднику — процент к сметной норме.
  - Состояния с сервера: `not-connected`, `hidden` (с кодом права), `no-accepted`, `too-little-data`, `ok`.
  - Изоляция (D4): чужая стройка — 404, сотрудники — только своих строек.
  - Контракт «Выработка» в `BHS.CRG.Modules/Exchange` для графика (`PLAN-16`): объём на час с размером
    выборки, без часов и людей.
- **PR 2 (макеты Р6).**
  - Полоса «по смете — фактически» над таблицей «Хода работ» (`PLAN-21`) — вкладом модуля `work`
    контрактом «Колонка Хода работ» (`plan-25`): полоса с состоянием, рисует её ядро. Состояния — строкой с
    причиной.
  - Выработка у работы графика (`PLAN-16`): ответ графика `plan` читает контракт «Выработка», экран
    графика показывает её рядом с объёмом работы — по образцу факта у работы (`plan-25`, `PLAN-18`).

## Capabilities

### New Capabilities
- Нет.

### Modified Capabilities
- `work`: «по смете — фактически», выработка по виду работ, их состояния, изоляция и контракт выработки
  для графика.
- `plan`: выработка у работы графика (`PLAN-16`) — вклад этого change в экран графика (D18 зонтика).

## Impact

- **Сервер:** модуль `work` — `Labor/*` и адреса; `BHS.CRG.Modules/Exchange/IWorkProductivity.cs` (новый
  контракт); потребитель контракта «Плановые работы» этапа 3.
- **Клиент:** полоса в «Ходе работ» рисуется ядром из вклада контракта (`plan-25`); выработка у работы —
  экран графика `plan` (`plan-20`).
- **Сервер `plan`:** ответ графика (`plan-19`) — поле выработки из контракта «Выработка».
- **Этап 3:** право `plan.labor.read` (чел.-ч на единицу, без денег) у «Менеджера проекта» — записано в
  `PLAN-23` и объявляется `plan-23-planned-works-contract`.
- **Документы:** `docs/USER_GUIDE.md` — полоса и её оговорки.
