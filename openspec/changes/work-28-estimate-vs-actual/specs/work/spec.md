# Spec Delta: work

## ADDED Requirements

### Requirement: [WORK-42] «По смете — фактически» по стройке
Адрес `GET /api/work/labor/estimate-vs-actual` SHALL отдавать по стройке за период `estimatedHours`
(сумма «принятый объём × чел.-ч на единицу позиции сметы») и `actualHours` (часы принятых отчётов).
Отдельной строкой `offEstimate` MUST идти объём работ без позиции сметы и часы отчётов, где нет ни одной
сметной работы. Непринятые отчёты не считаются. Сравнения по отдельной работе нет.

#### Scenario: Стройка за месяц
- **WHEN** за октябрь на стройке принято 120 м кабеля по норме 0,5 чел.-ч/м в отчётах на 70 ч
- **THEN** ответ несёт `estimatedHours: 60` и `actualHours: 70`

#### Scenario: Несметная работа
- **WHEN** в принятом отчёте на 8 ч есть только работа, чья позиция перечня не связана со сметой
- **THEN** её объём и эти 8 ч стоят в `offEstimate`, а не теряются и не попадают в сравнение

#### Scenario: Отчёт ждёт приёмки
- **WHEN** отчёт подан, но не принят
- **THEN** ни его объём, ни его часы в ответ не входят

### Requirement: [WORK-42] [WORK-Q5] По разделу — только разнесением
При отборе по разделу сервер SHALL делить часы каждого принятого отчёта между его сметными работами
пропорционально «объём × чел.-ч на единицу» и помечать ответ `distributed: true` («расчётная»). Работы
без нормы MUST идти в `offEstimate` и в деление не входить. Сумма разнесённых часов по всем разделам
MUST равняться часам этих отчётов.

#### Scenario: Отчёт на два раздела
- **WHEN** в отчёте на 10 ч две работы: в корпусе 1 на 6 сметных чел.-ч и в корпусе 2 на 2 сметных чел.-ч
- **THEN** при отборе «корпус 1» `actualHours` равно 7,5 с `distributed: true`, а при отборе «корпус 2» — 2,5

### Requirement: [WORK-43] [WORK-Q6] Выработка по виду работ — только по отчётам с одним видом
Адрес `GET /api/work/labor/productivity` SHALL считать выработку вида работ (объём на час, по месяцам)
только по принятым отчётам, где все строки — этот вид работ в одной единице. Ответ MUST нести размер
выборки — число отчётов и строек — и порог `minSample`. Ниже порога вместо числа приходит
`state: too-little-data`. Отброшенное MUST быть названо счётчиками: смешанные отчёты, другая единица.

#### Scenario: Достаточная выборка
- **WHEN** за квартал принято 14 отчётов с одной прокладкой кабеля на 3 стройках, а порог — 10
- **THEN** ответ несёт выработку «м/ч» по месяцам и выборку «14 отчётов, 3 стройки»

#### Scenario: Данных мало
- **WHEN** отчётов с одним видом работ 4 при пороге 10
- **THEN** приходит `state: too-little-data` без числа, а выборка названа

#### Scenario: Смешанный отчёт
- **WHEN** в отчёте прокладка кабеля и монтаж коробок
- **THEN** отчёт в выработку не входит, и счётчик `discarded.mixedReports` его называет

### Requirement: [WORK-43] Процент к сметной норме по стройке, разделу и сотруднику
Тот же адрес SHALL отдавать по стройке, разделу или сотруднику процент `estimatedHours / actualHours`
по правилам `WORK-42`, с пометкой `distributed` там, где применено разнесение. Измерения «бригада» MUST
NOT быть (`WORK-Q7`). Сотрудники называются только по стройкам, доступным спрашивающему.

#### Scenario: По сотруднику
- **WHEN** менеджер запрашивает процент к норме по сотрудникам своей стройки
- **THEN** приходят только сотрудники с принятыми отчётами этой стройки, у каждого — процент и `distributed: true`

### Requirement: [WORK-42] [WORK-43] [CORE-34] Состояния ответа
Оба адреса SHALL нести `state`:
- `ok`;
- `not-connected` — модуль `plan` выключен;
- `hidden` — нет права, с кодом права (`plan.labor.read`);
- `no-accepted` — за период нет принятых отчётов;
- `too-little-data` — для выработки ниже порога.

Пустой ответ без `state` MUST NOT приходить.

#### Scenario: Планирование выключено
- **WHEN** модуль `plan` выключен
- **THEN** `estimate-vs-actual` приходит с `state: not-connected`, фактические часы не показываются без сметы

#### Scenario: Нет узкого права на нормы
- **WHEN** у менеджера нет `plan.labor.read`
- **THEN** ответ приходит с `state: hidden` и кодом `plan.labor.read`, а не с нулём сметных чел.-ч

#### Scenario: Нет принятых
- **WHEN** за период на стройке нет ни одного принятого отчёта
- **THEN** ответ приходит с `state: no-accepted`

### Requirement: [WORK-39] [WORK-57] Изоляция и ворота адресов трудозатрат
Адреса трудозатрат SHALL стоять за воротами модуля и под правом `work.report.review` или
`work.report.read.all`. Менеджеру они отвечают только по стройкам его действующих назначений «менеджер»
(или любым при `work.sites.all`). По чужой стройке ответ MUST быть 404. Монтажнику адреса закрыты.

#### Scenario: Чужая стройка
- **WHEN** менеджер запрашивает «по смете — фактически» по стройке, где не назначен
- **THEN** ответ — 404, а не 403

#### Scenario: Монтажник
- **WHEN** пользователь только с `work.report.own` вызывает адрес выработки
- **THEN** ответ — 403

#### Scenario: Модуль выключен
- **WHEN** модуль `work` выключен
- **THEN** адреса трудозатрат отвечают отказом выключенного модуля (501)

### Requirement: [PLAN-16] [WORK-57] Контракт «Выработка» для графика
Модуль SHALL отдавать другим модулям выработку вида работ контрактом: объём на час по месяцам, размер
выборки и состояние, по тем же правилам, что адрес выработки. Часов, отчётов и сотрудников контракт MUST
NOT отдавать. Отвечает он в правах спрашивающего, правом контракта `work.facts.read`.

#### Scenario: График спрашивает выработку
- **WHEN** модуль `plan` запрашивает выработку прокладки кабеля для работы графика
- **THEN** ответ несёт «м/ч» и «по 14 отчётам, 3 стройки», но ни одного часа, отчёта или имени

#### Scenario: Учёт работ выключен
- **WHEN** модуль `work` выключен
- **THEN** реализации контракта нет, и потребитель показывает «не подключено»

### Requirement: [WORK-42] [PLAN-21] Полоса «по смете — фактически» в «Ходе работ»
Модуль `work` SHALL отдавать в «Ход работ» стройки вкладом контракта «Колонка Хода работ» полосу «по
смете N чел.-ч — фактически M ч» за выбранный период, а при отборе по разделу — с пометкой «расчётная». Строку несметных работ полоса MUST
показывать рядом. Каждое состояние, кроме `ok`, MUST показываться строкой с причиной из ответа сервера, а
не прочерком.

#### Scenario: Отбор по разделу
- **WHEN** менеджер выбирает в «Ходе работ» раздел «корпус 1»
- **THEN** полоса показывает разнесённые часы с пометкой «расчётная»

#### Scenario: Скрыто правами
- **WHEN** ответ пришёл с `state: hidden` и кодом `plan.labor.read`
- **THEN** вместо чисел полоса пишет «сметные нормы скрыты: нужно право plan.labor.read»
