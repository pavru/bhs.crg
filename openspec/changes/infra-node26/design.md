# Design

## Context

Мотивация — proposal.md, «Why». Состояние на 04.11.2026:

- Версия Node названа в четырёх местах и нигде не сверяется: `ci.yml` — `node-version: '22'` в работах
  «Frontend» и «Живые прогоны» (вторая ставит Node для vite preview и Playwright), `deploy/Dockerfile.web`
  — `FROM node:22.23.3-alpine`, `src/client/package.json` — `engines.node >=22.22.0` (порог react-router 8)
  при `engine-strict=true` в `src/client/.npmrc`, у `docs/tools` границы нет вовсе.
- Тег `node:26.13.0-alpine` в Docker Hub есть (amd64 и arm64, выложен 28.10.2026).
- На Node 26.13.0 зелёные `tsc -b`, `npm run build`, оба храповика; `npm test` — 5 файлов красные
  (`ModuleSettingsSections`, `BrandIconLinks`, `PdfViewer`, `PdfViewer.swap`, `ImageView`; 49 тестов):
  `localStorage` Node 26 — свойство-геттер на `globalThis`, без `--localstorage-file` отдаёт
  `undefined`, и среда jsdom vitest своё хранилище поверх уже имеющегося свойства не ставит. С
  `--no-webstorage` свойства нет вовсе (`'localStorage' in globalThis === false`) — проверено.
- Сторож [UI-21] — `src/shared/ui/viewer/pdfEngine.test.ts`: настоящий pdf.js в Node, worker в Node
  поддельный — тот же поток и те же встроенные объекты. Заплатки (`pdfPolyfills.ts`) ставятся при
  импорте `pdfEngine` и только там, где функции нет (`patch` смотрит `name in target`); `IMPLS` —
  сами заплатки, для сверки.

## Goals / Non-Goals

**Goals:**
- Одна версия — `26.13.0` — у разработчика, в CI и в образе `web`; расхождение ловит тест в обязательной
  проверке «Frontend».
- Сторож заплаток работает на любой версии Node и сам доказывает, что граница наступила.

**Non-Goals:**
- Граница браузеров просмотрщика (Chrome/Firefox 126, Safari 18, D5 `viewer-00-epic`) не меняется,
  заплатки остаются все.
- Node в `.github` для действий (`runs.using: node24` у actions) — это рантайм раннера, не наш.
- Версия .NET, Typst и прочих образов — не трогаем.

## Decisions

### D1. Источник — `.nvmrc` в корне, полная версия `26.13.0`

`actions/setup-node` читает его сам (`node-version-file: .nvmrc`), nvm/fnm/volta — тоже. Полная
версия, а не `26`: «одна версия» значит одна сборка, а `26` у setup-node — свежайшая 26.x на день
прогона, и CI уехал бы вперёд образа.

Dockerfile `.nvmrc` прочитать не может (`FROM` — литерал; `ARG` из файла — только через аргумент
сборки, который пришлось бы передавать в трёх местах: release, оверлей compose, CI). Поэтому в
`FROM` версия пишется литералом, а совпадение сверяет тест (D4). Так же — нижняя граница `engines`:
npm её из файла не берёт.

**Альтернатива — `engines` как источник** (setup-node умеет `node-version-file: package.json`):
отвергнута — диапазон `>=26.13.0` setup-node разрешил бы в свежайшую, а не в 26.13.0.

### D2. Нижняя граница `engines` равна версии источника

`>=26.13.0` и у клиента, и у `docs/tools`. Порог react-router 8 (22.22) больше не определяющий —
комментарий `//engines` и `.npmrc` говорят теперь «граница = `.nvmrc`». У `docs/tools` нет
`engine-strict`, там граница — предупреждение; заводить `.npmrc` ради инструмента сборки PDF не
будем, но в сверку D4 он входит, чтобы не отстал молча.

### D3. dependabot: мажор Node по-прежнему руками; патч и минор — красным PR

Бот обновлений образов `deploy/` предложит `node:26.13.1-alpine` и т. п. Такой PR покраснеет на
сверке D4 с подсказкой «поднимите `.nvmrc` и `engines` тем же PR» — это и нужно: бот сообщает о
выпуске, человек поднимает версию во всех местах. Игнорировать патчи Node целиком нельзя — о
заплатках безопасности сообщать больше некому. Комментарий у правила `ignore` переписывается.

### D4. Сверка версий — тест vitest в клиенте

`src/client/nodeVersion.test.ts`, рядом с `viteSupport.test.ts` (тот же приём: читает файлы
репозитория через `node:fs`). Едет в обязательной проверке «Frontend». Сверяет:
- `.nvmrc` — одна строка `X.Y.Z`;
- `deploy/Dockerfile.web` — `FROM node:X.Y.Z-alpine` (суффикс `-alpine` обязателен);
- `src/client/package.json` и `docs/tools/package.json` — `engines.node === ">=X.Y.Z"`;
- `ci.yml` — у каждого `actions/setup-node` есть `node-version-file: .nvmrc` и нет `node-version:`.

Отказ называет файл, найденное и ожидаемое. **Почему не шаг в «Скрипт обновления (логика)»**:
bash-сверка повторила бы разбор JSON и YAML грепом; в клиенте `package.json` читается как JSON.

### D5. vitest — воркеры без webstorage Node

`test.execArgv: ['--no-webstorage']` в `vite.config.ts` (vitest 4, пул `forks` по умолчанию —
аргументы доходят до процессов воркеров). Это устраняет причину: у Node нет хранилища, и jsdom ставит
своё, как в браузере. `npm test` и CI одинаковы без `NODE_OPTIONS`.

**Альтернатива — файл setupFiles, подменяющий `globalThis.localStorage` хранилищем jsdom**:
отвергнута — зависит от среды файла, в среде `node` подменять нечем, и ещё один слой поверх причины.

### D6. Сторож заплаток сам делает границу (решение владельца 04.11.2026)

**Поверхность границы записана файлом.** `src/client/src/shared/ui/viewer/browserBorder.json` —
собственные ключи (строковые и известные символы) встроенных объектов ES на границе: конструкторы и
их прототипы (`Object`, `Array`, `String`, `Number`, `Map`, `WeakMap`, `Set`, `WeakSet`, `Promise`,
`ArrayBuffer`, `DataView`, все типизированные массивы и `%TypedArray%`, `Iterator`, `RegExp`, `Date`,
`Error`…), пространства (`Math`, `JSON`, `Reflect`, `Atomics`, `Intl`) и имена глобального объекта.
Снимается генератором `src/client/scripts/browser-border.mjs` на `node:22.23.3-alpine` (команда — в
шапке генератора и в DEV_NOTES). Node 22 — V8 12.4, Chrome 126 — V8 12.6: снятая поверхность не
шире границы, то есть строже её (лишний красный возможен, пропуск — нет). Это ровно та защита, что
была при CI на Node 22, только записанная.

**Помощник границы.** `src/client/src/shared/ui/viewer/browserBorder.ts` (только для тестов): для
каждого объекта из файла удаляет собственные свойства, которых в записи нет; у глобального объекта —
только неперечисляемые и без `__` в начале: служебные глобалы vitest (`__vitest_worker__`,
`__vitest_mocker__`, `__vitest_index__`) тоже неперечисляемые, и с ними vitest «теряет своё
состояние» (найдено при реализации).
Возвращает список удалённого.

**Порядок в тесте.** Первым импортом `pdfEngine.test.ts` — модуль, вызывающий помощник; затем
`pdfEngine` (ставит заплатки). Отдельный тест проверяет, что граница наступила: для каждой функции
из `IMPLS` на её месте — заплатка (`Map.prototype.getOrInsertComputed === IMPLS.getOrInsertComputed`
и т. д.). На Node 22 это верно и без помощника, на 26 — только с ним; если помощник перестанет
срабатывать, тест красный (сторож обязан срабатывать).

Процесс воркера vitest на файл свой (пул `forks`, `isolate`), удаление не утекает в другие тесты.
Внутренности Node берут встроенное из примордиалов, снятых при старте, и удалением не ломаются.

**Альтернативы**: отдельный шаг CI на Node 22 — вторая версия, против решения; поднять границу
браузеров и снять заплатки — меняет D5 зонтика viewer; убрать сторож — пропуск ловится только руками.
Выбор владельца — первый вариант из предложенных («тест сам делает границу»).

### D7. Тексты

Комментарии `ci.yml` («22, а не свежайший…» → «версия из `.nvmrc` — та же, что у образа»),
`Dockerfile.web`, `.npmrc`, `package.json` (`//engines`), dependabot (оба места), шапки
`pdfPolyfills.ts` и `pdfEngine.test.ts`, DEV_NOTES (граница браузеров; новый абзац «Одна версия
Node»), CLAUDE.md «Node в CI — той же версии, что в `deploy/Dockerfile.web`» → «одна версия — `.nvmrc`»
— и AGENTS.md тем же коммитом (`AgentRulesCopyTests`). Исторический комментарий `release.yml` о
плавающих образах `node:22-alpine` — история, не трогаем.

## Risks / Trade-offs

- [Удаление встроенного ломает сам vitest или pdf.js в Node, а не «границу»] → помощник трогает
  только объекты из записи и неперечисляемые глобалы без `__`; если сломается — увидим сразу (тест красный
  непонятной ошибкой), а не молча. Проверяется в задаче 3.
- [Запись поверхности стареет: граница поднимется — запись надо переснять] → граница — решение
  владельца, событие редкое; команда переснятия в шапке генератора и в DEV_NOTES.
- [Разработчик на Node 26.x ниже/выше 26.13.0] → ниже — `npm ci` отказывает (так задумано); выше —
  ставится (граница нижняя), расхождение возможно; принимаем, CI и образ остаются на `.nvmrc`.
- [Патч-PR dependabot по образу node красный] → задуман (D3): красный с подсказкой, что поднять.

Найдено при реализации: в Node 26.13 из функций заплаток нет только `Math.sumPrecise` (Chrome 147);
остальные (`getOrInsert*`, `Promise.try`, `Uint8Array.toBase64/fromBase64/toHex`) свои. Проверено
руками: без помощника границы тест «граница наступила» красный; без заплатки `getOrInsertComputed`
красный и настоящий движок на эталонном PDF.

## Migration Plan

Один PR. Разработчику — ничего: у владельца уже 26.13.0. Откат — revert PR (все места в одном PR).
