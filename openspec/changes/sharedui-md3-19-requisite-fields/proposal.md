# Proposal: значение реквизита из источника и под замком — поле MD3, а не сырой `<input>`

Дочерний change зонтика `sharedui-md3-00-epic`, общая архитектура — `../sharedui-md3-00-epic/design.md`
(D9 — вид через `shared/ui`, D10 — макеты при новой раскладке, D11 — правила в ноль). Вынесен из
`sharedui-md3-17-screens` решением владельца 05.11.2026: в заметке к задаче 3.1 md3-17 записано «не
переведено — `fieldInputClass`».

## Why

В форме реквизитов документа значение, привязанное к источнику данных или запертое модулем, рисуется
**сырым `<input>` / `<textarea>`** с классом из `fieldInputClass` (`features/document-sets/fields/constants.ts:20`):
своя рамка 1 px, свой отступ, **подложка `surface-container`** у только-для-чтения. Это прямо расходится с
[UI-69] «Поле только для чтения — контур без подложки» и со сценарием «Запертое поле модуля» требования
[UI-81] change md3-17 (`TextField readOnly` со знаком замка в хвосте). Храповик `raw-field` этих мест **не
видит**: в разметке стоит `className={cls}`, а `cls` — результат вызова функции из другого модуля. Уровень
правила по разделу document-sets нулевой, хотя самоделок там пять. Такая дыра закроется, только если
правило научится видеть класс, вынесенный из разметки.

## What Changes

Что найдено в коде (на `009ee1c2`):
- `PrimitiveInput` (`features/document-sets/fields/PrimitiveInput.tsx`) рисует сырое поле с
  `fieldInputClass` в **пяти** ветках — все при `label` не переданном:
  1. `text` → `<textarea>` (строка 54);
  2. `enum` только для чтения → `<input readOnly>` с подписью варианта (строка 87);
  3. `primitive` не-дата → `<input type=number|text>` (строка 127);
  4. подсказка по введённому (`source && !readOnly`) → `SuggestField compact` с `className={cls}` (строка 143);
  5. `string` / `number` → `<input>` (строка 150).
- Без подписи `PrimitiveInput` зовёт **только** `RequisitesTab`, и только для значения **из источника или
  под замком** (`readOnly`): широкий текст — строка 572 (`label` снят при `bound || locked`), простые поля —
  строка 625. Подпись в обоих случаях рисует вызывающий — **строкой над полем** (`<label>` `body-small`
  с замком, звёздочкой, именем примитива и знаком происхождения), а не колонкой слева.
- Редактируемые реквизиты уже на `TextField` / `TextAreaField` с подписью в вырезе (строка 640). Остальные
  потребители (`ComplexFields`, `QualityDocForm`, каталог, `InvoiceExtraFields`) подпись передают всегда:
  `InvoiceExtraFields` — `field.title || field.key`, без подписи он поле не зовёт.
- Следствие: ветки 4 и нередактируемая часть `fieldInputClass` (фокус, рамка ошибки) сегодня **не
  достижимы**: без подписи поле всегда только для чтения.

Что меняется:
- **Раздел 0 — макеты и выбор владельца** (`docs/UI.md#новый-экран-порядок`): вид значения из источника и
  под замком в форме реквизитов меняется заметно, поэтому сначала разбор Дизайнера, три варианта в Claude
  Design и выбор владельца. Варианты на стол:
  - **A. Подпись в вырезе** — `TextField readOnly` / `TextAreaField readOnly` с подписью-именем поля в
    вырезе рамки; замок и знак происхождения — в хвосте поля, имя примитива — подсказкой под полем. Так
    уже устроены `LockedFieldValue` (Р3 md3-17) и редактируемые реквизиты; подпись над полем уходит.
  - **Б. Плотное поле под своей подписью** — подпись остаётся строкой над полем, поле —
    `TextField` / `TextAreaField` `density="dense"` только для чтения, имя — `aria-label`. Раскладка формы не
    меняется, но высота значения 40 против 56 у соседних редактируемых.
  - **В. Исключение** — `fieldInputClass` остаётся как есть, но объявленным исключением правила, которое
    класс видит (уровень 5 с причиной), и с подложкой, снятой по [UI-69].
- **Перевод `PrimitiveInput`** по выбранному варианту: ни одной ветки с сырым полем; `fieldInputClass`
  удаляется (при варианте В — остаётся объявленным исключением).
- **`raw-field` видит класс, вынесенный из разметки**: значение `className` раскрывается через вызов
  функции (`const cls = fieldInputClass(…)`) и через импорт константы или функции из другого модуля
  проекта. Общая коробка отбора `FIELD_CLS` (`shared/filter/fieldClass.ts`), невидимая сегодня по
  случайности, становится **явным** исключением правила с причиной.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `sharedui`: [UI-69] «Самодельное поле — под храповиком» — правило считает и класс, вынесенный в
  функцию или в другой модуль; добавлено [UI-86] — значение реквизита из источника и под замком рисует
  поле `shared/ui` по выбранному в разделе 0 варианту.

## Impact

- Клиент: `features/document-sets/fields/PrimitiveInput.tsx`, `fields/constants.ts`
  (`fieldInputClass`), `editor/RequisitesTab.tsx` (подписи над полем у строк 496 и 609 уходят — выбран
  вариант А, 05.11.2026; файл в `file-size-baseline.json` на 648 — расти ему нельзя), `editor/FieldSourceBinding.tsx`
  и `SourceBindingTrigger.tsx` (кнопка привязки в хвосте поля, слитая со знаком происхождения).
- `shared/ui` (PR 0): `TextAreaField.tsx` (`trailing`), `fieldBox.ts` (второй размер хвоста), `TextField.tsx`;
  после — `/design-sync`.
- Храповик: `scripts/ui-ratchet-inputs.mjs` и его тест, `ui-baseline.json`; `docs/UI.md` — абзац о
  `raw-field` (сегодня в нём «константа другого модуля правилу не видна»).
- Живые прогоны: `fields-smoke`, `document-preview-checks`, `pages-smoke` — вид привязанного и запертого
  реквизита; весь `npm run -s test:e2e:ci` (правка общего поля формы).
- Сервер, API, данные — без изменений. Связь: сценарий «Запертое поле модуля» [UI-81] md3-17 в форме
  реквизитов выполняется этим change.
