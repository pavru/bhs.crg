# Design: веб-ввод отчёта

Общая архитектура — `../work-00-epic/design.md` (D7, D8, D15, D17). Здесь только решения этого change.

## Context

Сервер готов до этого change:
- «мои стройки» с `today` и `boundary` — `GET /api/work/sites/mine` (`work-11`);
- модель, свои отчёты, `If-Match`, конфликт четвёрки, `assignedOnDate` — `work-13`;
- автор ввода отдельно от исполнителя — `work-14`;
- окно подачи, момент автоподачи, обязательность места и материалов на переходе «подан» — `work-15`;
- фото: `PUT /api/work/reports/{id}/lines/{lineId}/photos/{photoId}` без версии, `DELETE` с версией,
  `GET /api/work/photos/{photoId}` и `/preview`, `photosPending` — `work-17`;
- вид работы с признаками и варианты — `work-06`.

«Сегодня» в клиенте сейчас одно — день компании: `companyToday()` в
`src/client/src/shared/ui/Calendar.tsx:55`. Его же зовут стрелки года в
`src/client/src/shared/ui/dateSegmentModel.ts:60`.

## Goals / Non-Goals

**Goals:** монтажник вводит и подаёт отчёт в вебе по тем же правилам, что у будущего приложения;
менеджер вводит отчёт за сотрудника; ночная смена после полуночи не путается с днём.

**Non-Goals:**
- ярусы подсказки материалов — `work-26` (после этапа 3);
- поля заказчика «нужно к приёмке» — `work-24`;
- отчёт «объекта нет в списке» — этап 5 (`WORK-58`);
- сверка бригад — `work-18`.

## Decisions

- **Макеты:** раунд Р3, выбор владельца — вписать сюда ссылку. Код — после выбора (D17). Р3 решает и
  форму строк: `EditGrid` с раскрытием строки или карточки строк.
- **Состав PR.**
  - **PR 1 — список и шапка.**
    - `src/client/src/shared/api/workReports.ts` — свои отчёты, черновик, правка и подача с `If-Match`.
    - `features/work/entry/MyReportsPage.tsx` — `PageHeader`, `DataGrid`, «Новый отчёт» —
      `PrimaryActionButton` и запись в `PALETTE_ACTIONS` с приёмом `usePaletteIntent`.
    - `features/work/entry/ReportForm.tsx` — страница отчёта со своим адресом, охрана ухода —
      `useDirtyGuard`.
    - `src/client/src/shared/ui/SitePicker.tsx` — выбор стройки из назначенных.
    - `src/client/src/shared/ui/ShiftDateHeader.tsx` — `DateField` и «День | Ночь» на `Tabs segmented`,
      знак ☾.
    - «Ввести за сотрудника» — `EmployeePicker` (`work-12`).
    - Пункт «Мои отчёты» — в `navConfig.ts`, раздел и ранг входа — из `work-03`.
  - **PR 2 — строки, вид работы, материалы.**
    - `features/work/entry/ReportLines.tsx` — по форме Р3.
    - `src/client/src/shared/ui/WorkTypePicker.tsx` — вид работы с признаками `requires*` и вариантами.
    - `src/client/src/shared/ui/MaterialPicker.tsx` — выбор материала. Ярус пока один: справочник
      номенклатуры. Место под ярусы `work-26` закладывается. `NomenclaturePicker` счётов
      (`features/costs/NomenclaturePicker.tsx`) не берётся: он привязан к строке счёта.
    - Участники бригады — выбор из адреса `work-18`; до его слияния есть только признак бригады.
  - **PR 3 — фото и галерея.**
    - `features/work/entry/LinePhotos.tsx` — загрузка с `crypto.randomUUID()` как `photoId`, повтор
      тем же идентификатором.
    - `src/client/src/shared/ui/PhotoGallery.tsx` — общая галерея на `Modal fullScreen`, превью и
      оригинал адресами модуля.
- **«Сегодня» стройки — проп календаря.** `Calendar` получает необязательный `today` (ISO).
  `DateInput` и `DateField` передают его насквозь. Нет пропа — `companyToday()`, как сейчас: прочие
  поля даты не меняются.
  - Значение берётся из `today` стройки в ответе `work-11`. Клиент пояса стройки не считает.
  - Стрелки года в `dateSegmentModel.ts:60` получают то же значение через `useSegmentField`.
  - Сторож — тест `Calendar.test.tsx`: Владивосток в 20:00 по Москве подсвечивает завтрашний день, а
    без пропа подсветка прежняя.
- **Пара «дата · смена» нового отчёта — с сервера (D8).** Подпись «Ночная смена 16.09» и пара
  открытия приходят полем ответа `work-15`, клиент окно не вычисляет. Если `work-15` такого поля не
  отдаёт, оно дописывается туда до слияния PR 1.
- **Галерея.** Галерея — общий компонент из PR 3. Если карточка `work-21` уходит раньше, галерея
  строится там, а PR 3 берёт готовую (решение записано и в `../work-21-review-ui/design.md`). Листание,
  масштаб и клавиатура сверяются с просмотрщиком PDF эпика #1489. Вторая логика «листать и
  приближать» не заводится.
- **Носители (D15).** Все из ответа сервера, клиент ни одно не вычисляет:
  - `today` и граница выдачи стройки;
  - предлагаемая пара и подпись;
  - момент автоподачи;
  - конфликт четвёрки с идентификатором существующего отчёта;
  - признаки вида работы;
  - отказ подачи со строками и полями;
  - предел фото и `photosPending`.

  Пометка «нужно для ИД» — сочетание признака вида из ответа и пустого поля формы. Это состояние
  черновика на экране; окончательно решает отказ сервера на подаче.
- ⚠️ **Адрес «ввести за сотрудника» не заведён ни одним серверным change.**
  - `work-13` даёт только свои отчёты под `work.report.own`. `work-14` хранит автора ввода. `work-16`
    уже читает `enteredBy`.
  - Нужны адрес заведения отчёта за сотрудника под `work.report.review` (ворота стройки — назначение
    «менеджер» или `work.sites.all`) и кандидаты.
  - Он дописывается в `work-13` до слияния PR 1. Иначе действие «Ввести за сотрудника» в PR 1 не
    входит.
- **Без новых пишущих адресов.** If-Match и ворота — у `work-13`, `work-15`, `work-17`. Здесь —
  отправка версии и разбор 400/403/404/409/413 словами.
- **Сторож.**
  - vitest: без `reason` кнопка «Новый отчёт» есть, с `not-assigned` — нет; «Ночная смена 16.09» — из
    ответа; вариант исчезает у вида без вариантов; 413 показан у фото.
  - Живой прогон `work-entry-smoke.mjs`: монтажник заводит и подаёт отчёт; повтор той же четвёрки даёт
    «Открыть»; менеджер вводит за сотрудника.
- **Чем ломается.**
  - «Сегодня» из `companyToday()` — у стройки во Владивостоке вечером по Москве отчёт заводится
    вчерашним днём.
  - Окно ночной смены считает клиент — веб и телефон расходятся в сутках.
  - Фото ждут загрузки до подачи — отчёт висит на медленной сети.
- **Зависимости:** `work-11`, `work-13`, `work-14`, `work-15`, `work-03`, `work-12` (`EmployeePicker`);
  PR 2 — `work-06`; PR 3 — `work-17`, `work-05`. Этап 3 не нужен (ярусы — `work-26`).

## Risks / Trade-offs

- [Проп `today` у общего календаря забудут передать в новом поле отчёта] → поле даты отчёта одно,
  `ShiftDateHeader`, и тест на нём проверяет подсветку по стройке.
- [Форма строк по Р3 окажется карточками, а не сеткой] → `EditGrid` не берётся, `ui:ratchet` это не
  трогает; клавиатурный переход по полям тогда — забота карточки, тест на него — в PR 2.
