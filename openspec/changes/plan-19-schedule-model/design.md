# Design: график — работы, построение из редакции, зависимости

Дочерний change зонтика `plan-00-epic`, общая архитектура — `../plan-00-epic/design.md` (D3, D7, D9, D14,
D15, D17). Здесь только решения этого change.

## Context

- Позиции перечня — `WorkPlanItem` (`Domain/Documents/WorkPlanItem.cs:34`), «найди или создай» строит
  `plan-04`; ссылка модуля на позицию — `ReferenceTarget.WorkPlanItem` (`BHS.CRG.Modules/Data/ModuleReference.cs:9`).
- Редакции, их фиксация и строки — `plan-06`; распределение и его отпечаток — `plan-10`; рабочие дни
  стройки и права графиков — `plan-18`; порт сотрудников и видов работ — `plan-03`.
- Запись в общую таблицу модуль умеет только для своих справочников «по названию» (`IModuleOwnCatalog`,
  `BHS.CRG.Modules/Ports/IModuleOwnCatalog.cs`): полей и уровня стройки этот порт не пишет.

## Goals / Non-Goals

**Goals:** график из редакции за одно действие; работы ссылаются на позицию перечня; зависимости и
предупреждения видны; цикл не сохраняется.

**Non-Goals:**
- пересчёт сроков и выравнивание ресурсов (`PLAN-19`, `STG-14`);
- связи «начало → начало», «окончание → окончание» (`PLAN-16.1`) — вид хранится, но не принимается;
- перенос графика на новую редакцию (`plan-16`, Non-Goals);
- факт по графику — `plan-25`; выработка — `work-28`.

## Decisions

- **Шапка графика — запись модуля (предложено, ждёт решения В-14).** `CORE-20.1` и `PLAN-Q7` оставляют
  шапку документом общего типа «ради печати». Печать записи модуля строит `plan-15`, и довод уходит; а
  шапка в общей таблице потребовала бы нового пишущего порта ядра (поля, уровень стройки, ссылка на
  редакцию — запись модуля) ради записи без единого закрытого сведения. Рекомендация — шапка в схеме
  `plan`. Если владелец оставит документ общего типа, добавляется порт записи документа модуля в общую
  таблицу, а таблица `schedules` хранит только ссылку на него.
- **Хранение** (схема `plan`):
  - `schedules` — стройка, название, исходная редакция (необязательна: график может быть только из ручных
    работ), отпечаток распределения при построении, версия строки;
  - `schedule_works` — график, позиция перечня (обязательна), строка редакции (если из сметы), раздел или
    «по стройке в целом», объём, начало и окончание (`date`, могут быть пусты), «вручную», версия строки;
  - `schedule_work_assignees` — работа, сотрудник (ссылка `CORE-34.1`, новая ссылка на архивного —
    отказ, `CORE-34.4`);
  - `schedule_links` — предшественник, последователь, вид (`fs` | `ss` | `ff` | `sf`, принимается только
    `fs`), задержка (целое, рабочие дни), версия строки.
  Ссылки на позицию, стройку, раздел и сотрудника объявлены `CORE-34.1`.
- **Построение** `POST /api/plan/schedules` (`plan.schedule.edit`, создание — без `If-Match`):
  - по каждой сопоставленной строке редакции — работа на каждую часть распределения и на остаток «по
    стройке в целом»; позиция части — портом `plan-04` по ключу с разделом части (D7);
  - несопоставленные строки — `skipped: { unmapped: N }` в ответе;
  - редакция фиксируется тем же действием (`plan-06`); построение и фиксация безопасны при повторе:
    ключ построения у графика, повтор возвращает тот же график.
- **«Распределение изменено после построения».** Отпечаток распределения редакции сравнивается с
  сохранённым; расхождение — пометка `distribution-changed` у графика (D17). Перестроение — предпросмотр
  (`added`, `removed`, `changed` объём, `fingerprint`) и действие с `If-Match` графика и отпечатком.
  Совпавшая часть (строка + раздел) сохраняет сроки и исполнителей.
- **Работы** — правка сроков, объёма, исполнителей: `PUT /api/plan/schedules/{id}/works/{workId}` с
  `If-Match`; ручная работа — `POST …/works` (вид работы, раздел, единица → позиция портом `plan-04`).
  Работа, построенная из сметы, сменить позицию не может — только удалиться и быть добавленной вручную.
- **Связи** — `POST …/links` (без версии, заведение) и `PUT`/`DELETE …/links/{id}` с `If-Match`:
  - вид не `fs` — 422 «пока поддерживается только „окончание → начало“»;
  - работа другой стройки — 422; другого графика той же стройки — допустимо (`PLAN-16.1`);
  - цикл — 422 с перечнем работ цикла: проверка `CycleCheck` по графу связей всей стройки, в одной
    транзакции с вставкой (блокировка графиков стройки на запись), чтобы два параллельных сохранения не
    замкнули цикл вдвоём.
- **Предупреждения** (`ScheduleWarnings`, D14, D17) у работы и списком у графика: `starts-before-predecessor`
  (начало раньше «окончание предшественника + задержка» в рабочих днях стройки — у обеих работ),
  `ends-on-day-off`, `calendar-missing`, `no-dates`. Сроки не двигаются никогда.
- **Сторож.**
  - PR 1: редакция с распределением 700 + 500 и остатком 200 даёт три работы; несопоставленная строка не
    входит и посчитана; повтор построения — тот же график; построение фиксирует редакцию; перестроение с
    устаревшим отпечатком — 409.
  - PR 2: цикл из трёх работ двух графиков — отказ с перечнем; параллельная вставка двух связей,
    замыкающих цикл, — одна отвергнута; задержка −2 рабочих дня; связь на другую стройку — 422; отказы
    `If-Match` (400/409), без права — 403, модуль выключен — отказ.
- **Чем ломается.** Работы массивом в документе — «срок по графику» по позиции не находится; проверка
  цикла только внутри графика — цикл через соседний график стройки проходит; пересчёт сроков на сервере —
  сдвиг, о котором человек не просил.

## Risks / Trade-offs

- [В-14 решится «документ общего типа»] → добавляется порт записи документа модуля; работы и связи не
  меняются.
- [Большая смета — сотни работ] → построение одной операцией модуля; предупреждения считаются по графу
  стройки за один проход с календарём из `plan-18`.
- [Ручные даты при перестроении] → сохраняются у совпавших частей, снятые работы названы в предпросмотре.
