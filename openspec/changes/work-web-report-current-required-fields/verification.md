## Живой цикл 28.11.2026

Четыре черновика созданы через API с пустым полем во второй строке. Штатный такт автоподачи
подал их в конце окна, указанном в ответе черновика. В очереди и карточках появились текущие
пропуски. Менеджер вернул все отчёты в открытом периоде. Счётчик `required-missing` в очереди
изменился с 4 на 0.

При повторном открытии браузер получил отдельный ответ `catalog/work-types`. Версия отчёта
совпала с версией после возврата. До ручной подачи `requiredMissing` содержал исходный
пропуск, а форма не показывала красную ошибку и не фокусировала поле.

| Режим | Поле | Требование | Ручная подача | Тестовый отчёт |
|---|---|---|---|---|
| `own` | Место работ | Снято | HTTP 200, пометка исчезла, поле осталось пустым | `70f122cd-67b6-45a4-8f1d-d4d64713318e` |
| `entry` | Материалы | Снято | HTTP 200, пометка исчезла, список остался пустым | `7893b752-3d49-4035-8e95-8cd02bbb7d47` |
| `own` | Материалы | Сохранено | HTTP 422, раскрыта строка 2, фокус на «Добавить материал» | `11d0b7d9-a363-4280-abcf-bd6972e1fd55` |
| `entry` | Место работ | Сохранено | HTTP 422, раскрыта строка 2, фокус на «Место работ» | `2d53a077-55f1-4cca-b46d-d82a2c3aea47` |

Ответы HTTP 200 перевели отчёты в `submitted` с `submittedBy: manual` и пустым
`requiredMissing`. Они появились в очереди без пометки о пропусках. Ответы HTTP 422 назвали
номер, идентификатор строки и код поля, статус остался `returned`. В журнале каждого
отчёта сохранилась одна запись `auto-submitted` от «Система» с исходным пропуском.

Прогон продолжили на тех же отчётах после тайм-аута чтения PostgreSQL. Контрольные формы
повторно открыли по прямым адресам. В отдельной проверке возврат через историю браузера
дал новый HTTP 200 на справочник в обоих режимах, когда сценарий дождался закрытия формы
перед переходом назад. Случай со свежим кэшем прежних признаков проверен также компонентными
тестами, включая обновление сохранённого вида из `selected`.
