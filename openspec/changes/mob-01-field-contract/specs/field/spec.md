# Постоянные адреса полевого API и контракт v1

## Purpose

Заказчику нужен один публикуемый вход для телефона. Установленный APK должен узнать сервер и свою совместимость после обновления экземпляра.

## ADDED Requirements

### Requirement: [MOB-13] [MOB-14] Публичный контур

Экземпляр SHALL обслуживать сведения о сервере, подключение, обновление токена и проверку связи под постоянным префиксом `/api/field/`. Версионный обмен MUST находиться под `/api/field/v1/`. Внешнему прокси достаточно публиковать `/api/field/` и `/m/`.

#### Scenario: Публичный контур в работе

- **WHEN** Прокси публикует только два префикса
- **THEN** телефон получает сведения об организации и проходит полевой путь, офисные экраны остаются внутренними адресами.

### Requirement: [MOB-14] [MOB-22] Совместимость

Сервер SHALL сохранять форму постоянных адресов и поддерживать только совместимые добавления в v1. Отказ протокола MUST содержать машинно-читаемую причину.

#### Scenario: Совместимость в работе

- **WHEN** обновлённый сервер обслуживает клиент с предыдущими контрактными примерами
- **THEN** старые запросы и обязательные поля ответов сохраняют смысл, новый клиент может читать дополнительные поля.
