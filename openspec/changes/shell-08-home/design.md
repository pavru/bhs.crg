# Design: Главная «Продолжить работу»

Общая архитектура — `../shell-00-epic/design.md` (D1 — макет, D2 — решения владельца, D5 — пересечение с
`plan-02`, D6 — живые прогоны). Макет — артборд «B · Главная „Продолжить работу“» канваса варианта B;
выбран решением владельца 17.10.2026. Раздел «Главная» — новый раздел рейла в `shared/ui`: по `docs/UI.md`
(«Новый экран: порядок», шаг 1) до кода — разбор с Архитектором (новый вид раздела без подпанели) и
Дизайнером (что не покрывает макет: телефон, пустые состояния).

## Context

Сверено по коду ветки от master `c9586405`; пересверено 11.11.2026 по `6dec4de6` (кроме экрана счетов).

- **Маршрут.** Индекс — `<EntryRedirect />` (`App.tsx:126`, `shared/ui/EntryRedirect.tsx`): адрес даёт
  `entryPage` (`shared/ui/entryPage.ts`, `plan-02` PR 2, #1588) — пункт с наименьшим рангом входа, при
  равных — порядок рейла; без пунктов — страница `AUTH-15`. Ранг Главной `HOME_ENTRY_RANK = 100`, пункт
  Главной узнаёт `isHomeItem` (пункт ядра с этим рангом), сторож `entryRankProblems` запрещает пункту ядра
  ранг ниже Главной и две «Главные». Пока пункта Главной нет, её ранг в расчёт не входит.
- **Рейл.** `RailId = 'constructions' | 'data' | 'costs' | 'plan' | 'system'` (`navConfig.ts:50`; «Планы» —
  `plan-02`, «Учёт» подписан «Затраты»); раздел без
  страниц не показывается (`buildRail`, `railSections.ts:25`), «куда ведёт раздел» — первая страница
  (`home`). Раздела без подпанели вовсе нет: есть только `panelOnlyAt` (подпанель лишь на одной странице).
  Пункта «Главная» нет — #1429 его не завёл.
- **Очереди счетов** (`features/costs/invoiceQueues.ts`, `shared/api/invoiceQueues.ts`):
  - «Разобрать» — `GET /api/costs/invoices/queues/parsing` (`useParsingCount`), спрашивается у каждого,
    кто видит список (`costs.invoice.read`);
  - «Не распознано», «Удалённые записи», «В архиве» — одним ответом `GET /api/costs/invoices/queues`
    (`useInvoiceQueues`); сервер закрывает его чтением, а клиент спрашивает только при
    `costs.invoice.edit` (`InvoicesPage.tsx:96`): «число без выхода было бы упрёком»;
  - у чисел есть оговорка «проверено не всё» (`doubt`) и «число не пришло» ≠ ноль (`queueChip`).
- **Что выяснилось сверкой:** отбор очереди живёт только в состоянии страницы
  (`useState<InvoiceQueue | 'upload' | null>`, `InvoicesPage.tsx:83`) — адресом очередь не открыть, и
  карточке Главной вести некуда. Нужен параметр `queue` (дельта `costs`).
- **Фоновые задачи** — `useActiveJobs()` (`shared/api/jobs.ts:29`) и строка `JobRow`
  (`features/jobs/JobRow`) — тот же источник у `ActivityCenter` (#1431).
- **Личные настройки** — `UserSettingKeys` (`src/server/BHS.CRG.Application/Settings/UserSettingKeys.cs`),
  ключи с проверкой формы; длинные значения бывают (`workspaces` — 16 000). Зеркало в браузере —
  `useSyncedPreference`, загрузка ничего не отправляет (`CORE-25.3`).
- **Экран записи по коду типа** — `RECORD_ROUTES` (`shared/ui/recordRoutes.ts`): там только счёт; рядом —
  `CATALOG_RECORD` (запись общих данных, `/common-data?entry=`, #1517), но не по коду типа.
- **История открытий** не хранится нигде.
- **Пересечение:** страница входа по рангу пункта (`entryPage.ts`) построена `plan-02` на том же
  индекс-маршруте; `work-03-navigation` назначает ранги своим пунктам.
- **Телефон** (найдено сверкой `work-03`, C2): `phoneChrome` (`shared/ui/phoneChrome.ts:22`) отбирает
  разделы нижней навигации по `!unscoped` — так он убирает «Систему». Раздел Главной с `unscoped: true`
  ушёл бы с телефона тем же правилом. По выбору владельца в `work-03` (11.11.2026) нижняя строка станет
  тремя местами «Главная · Закреплённые · Меню» — её перестраивает `work-03`/`work-04`, не этот change.

## Goals / Non-Goals

**Goals:** человек после входа видит свои очереди, недавние записи, идущие задачи и три неочевидных
умения; Главная не знает о счетах; ни одного числа, посчитанного вторым способом.

**Non-Goals:**
- очереди других модулей и ядра (подключаются тем же объявлением, когда появятся);
- «закреплённые» записи и избранное на Главной;
- лента событий и уведомления на Главной (у них место — кнопка активности).

## Decisions

### Макет: сверка с MD3 — «годен с правками» (решение владельца 12.11.2026)
Артборд нарисован до перехода на чистый MD3 (`sharedui-md3-00`, закрыт 10.11.2026): состав, порядок блоков и
тексты держатся, а ручная разметка переводится в компоненты `shared/ui`. Хром макета (рейл, шапка) построен
отдельно — от артборда берётся только область содержимого.
- Заголовок — `PageHeader` (`title-large` 22), не 28 px: `headline-medium` по `docs/UI.md` — только экран входа.
- Карточка очереди — кликабельная `Card` (радиус 12): `title` — имя цели и идёт первым, поэтому порядок
  «подпись → число → пояснение»; число — `headline-small`. Подпись — как у чипа экрана счетов
  (`QUEUE_LABEL`: «Разобрать», «Не распознано», «Удалённые записи», «В архиве»), под ней строка модуля
  «Счета»; четыре карточки (на артборде три). Знак и тон — как у чипа (`InvoiceQueueChips.tsx`):
  `Checklist`; `DocumentScanner` warning; `Warning` error, при сомнении — `Help` warning; `Archive`.
- «Полезно знать» — `Card variant="filled"`, а не пунктир: пунктир в `docs/UI.md` — место броска файла.
  «Скрыть» — кнопка text; знак-лампочка добавляется в набор значков; пометка «файл» → знак `UploadFile`;
  клавиши — `kbd` в виде строки поиска шапки (`AppShell.tsx:240`). Общий `Kbd` — не этот change.
- «Выполняется» — `JobRow` (своего кольца нет); «Недавние» — `ListItem` в `Card flush`, без черт между строками.
- Рейл и телефон — по коду: «Затраты» и «Планы» уже есть, подпись одним весом и залитый знак выбранного
  ([UI-60]); нижняя строка — пять мест.

### Раздел «Главная» без подпанели (0.2 — Архитектор 12.11.2026, [комментарий к #1436](https://github.com/pavru/bhs.crg/issues/1436#issuecomment-6807308413))
`RailId` += `'home'`, первым в `railSections`, первым рабочим разделом. Пункт
`{ to: '/home', label: 'Главная', rail: 'home', entry: HOME_ENTRY_RANK }` без права и модуля — открыт
каждому вошедшему, `isHomeItem` его узнаёт (В-4: адрес Главной — `/home`, `/` остаётся расчётом входа).
Пространство Главную не сужает без всякого признака: пункт без `module` и `section` входит в любое
пространство (`inWorkspace`, `workspaces.ts:181`).
- **Признак `unscoped` → `admin`.** Имя врёт: по нему рейл ставит раздел под черту и не рисует строку
  «вне пространства» (`SectionRail.tsx:35,133`), телефон убирает раздел с нижней строки и ИЩЕТ им пункт
  «Администрирование» меню профиля (`phoneChrome.ts:22–26`), а `railSections.test.ts` сверяет
  «`workNav` ⇔ не `unscoped`». Главная с ним ушла бы под черту и стала бы «Администрированием».
  Переименование — чистое, во всех читателях тем же PR; Главной признак не нужен, и `phoneChrome` по
  существу не меняется.
- **Подпанель — одним полем** `panel?: false | { onlyAt: string }` вместо `panelOnlyAt` (иначе
  бессмысленное сочетание двух полей): `false` — подпанели нет нигде (Главная), `{ onlyAt }` — только на
  одной странице (карточка стройки), поля нет — всегда. Читатель один — `panelAt` (`railSections.ts:64`);
  отсюда `AppShell` без подпанели, на телефоне нет меню раздела и кнопки «Показать панель».
- **Логотип** рейла и шапки («на главную», `SectionRail.tsx:67`, `AppShell.tsx:211`) ведёт на `/home`, а
  не на `/`: подпись обещает Главную, а `/` — расчёт входа, монтажника он уведёт в «Мои отчёты». `/`
  остаётся адресом входа и закладок.
- Раскладку сверяет `railSections.test.ts` (Главная первой, рабочим разделом, `panelAt` — нет);
  правило «Подпанель есть только у разделов со списками» в `docs/UI.md` дополняется: «Главная — раздел
  без подпанели». На телефоне — первый пункт `BottomNav` (пять мест — предел MD3: Главная, Стройки,
  Данные, Затраты, Планы; строку из трёх мест потом заводит `work-03`).

### Вход без прав — Главная не работа (Архитектор 12.11.2026)
Главная видна каждому, и `entryPage` больше не вернул бы «никуда» — страница «доступ не выдан»
(`AUTH-15`) пропала бы у того, кому не открыто ничего. Правило: **расчёт входа спрашивает «есть ли
работа», а Главная — не работа.** Показанных пунктов, кроме Главной, нет — ответ `null`, и `EntryRedirect`
рисует `NoAccessPage` (`AUTH-15`), как сейчас; ранжирование — по-прежнему по всем показанным. Сама
`/home`, открытая рейлом или адресом при «работы нет», первым блоком рисует тот же текст `NoAccessPage`
тем же предикатом из `entryPage.ts` (одно правило на двоих): Главная остаётся открытой каждому (`UI-33`)
и не притворяется рабочим местом. Отвергнуто: прятать Главную от навигации — ломает `UI-33`, а `/home`
адресом всё равно открывается. Дельта `auth` — `specs/auth/spec.md`; сценарий `UI-33` «Пользователь без
модулей» уточнён: без прав на модули, **с правами ядра**.

### «Ждут вас» — по решению В-2 (вариант Б, 11.11.2026; форма — 0.1a, Архитектор 12.11.2026)
- **Объявление — в манифесте модуля:** `IAppModule.HomeQueues => []`, запись
  `ModuleHomeQueue(Code, Title, Hint, Requires, Quiet = false)` с `Problems()` в `BHS.CRG.Modules/Home/` —
  близнец готового отбора таблицы `ModuleTableShortcut` (`Quiet` — «В архиве» тише соседей). Читается у
  всех модулей сборки (перепись, файл-сверка с клиентом), предлагается — у включённых.
- **Число — контрактом со многими поставщиками** (`plan-22`):
  `[ModuleContract("Очереди Главной", Many = true)] IHomeQueueCounts.CountAsync(ModuleReader, codes, ct)` →
  `HomeQueueCount(Code, int? Count, string? Doubt, string? Refused)`; реализация в модуле —
  `<Module>HomeQueueCounts`. Отвергнуто: только свойство манифеста со своим счётчиком (область на запрос,
  отбор включённых и «одна реализация» писались бы заново) и только контракт (нет перечня для сверки с
  клиентом, `Refusal` даёт «любое из», а нужно «все», и право обязан помнить каждый поставщик).
- **Права — один путь, у ядра.** `GET /api/home/queues` предлагает очередь, если модуль открыт
  (`reader.Allows(module)`) и есть **все** ключи `Requires` — формула ворот адреса модуля. Поставщику
  передаются только открытые коды; `ContractAnswer.Hidden` контракт не использует — названное в доке
  интерфейса исключение: право здесь — объявленные данные, а не суждение поставщика. Ключи счетов:
  «Разобрать» — `costs.invoice.read`; «Не распознано», «Удалённые записи», «В архиве» — `read` **и**
  `edit`: `UsuallyWith` — подсказка, а не зависимость, и с одним `edit` карточка вела бы на закрытый
  `/invoices`.
- **Тот же счётчик буквально.** Служба costs `InvoiceQueueCounts` (на запрос): `ParsingAsync` — тело
  `InvoiceListEndpoint.ParsingCountAsync`, `TroublesAsync` — тело `InvoiceListMarks.QueuesAsync`. Адреса
  `/queues` и `/queues/parsing` (`InvoiceEndpoints.cs:52`) становятся обёртками над ней,
  `CostsHomeQueueCounts` зовёт её же. «Разобрать» считается отдельно: отказ опроса ссылок ядра даёт
  `refused` трём очередям, а «Разобрать» приходит с числом (причина разделения адресов, ревью #1302).
- **Сбой одного модуля.** Ядро зовёт каждого поставщика в своей области (`CreateAsyncScope`) со своим
  пределом времени (около 3 с, в одном месте настроек), параллельно; исключение или таймаут —
  `refused` всем открытым кодам модуля и предупреждение в журнал, отмена самого запроса пробрасывается.
  Выключенный модуль отсеивает `GetAll`. Ответ — `{ module, id, label, hint, quiet, count, doubt?, refused? }`.
- **Перепись при старте** (`HomeQueueCatalog`): коды уникальны в модуле, `Requires` непуст и состоит из
  объявленных прав; у модуля с `HomeQueues` есть поставщик, и наоборот.
- **Общее с поиском `shell-05`** (первый рабочий Many-контракт, вероятно, наш): помощник ядра
  `BHS.CRG.Api/Modules/Ports/ModuleContributions.AskEachAsync` (область, предел, журнал, `refused`) — один
  на оба контракта; отказ на проводе — `refused?: string` словами; имена `Modules/Home/IHomeQueueCounts` и
  `Modules/Search/IRecordSearch`; правило прав: **право известно до вызова — его объявляют, проверяет
  ядро; право зависит от данных поставщика — `Hidden`**.
- **Клиент.** Карточка — из ответа; адрес экрана очереди знает клиент (сервер адресов клиента не знает,
  `recordRoutes.ts`) — таблица `(module, id) → href` в `shared/ui/homeQueueRoutes.ts`. Объявления сервера
  сверяются с ней через файл-перепись `src/client/src/shared/ui/homeQueues.json` (как
  `invoiceLineCases.json`): серверный тест сверяет `HomeQueues` всех модулей сборки с файлом,
  `homeQueues.test.ts` — что у каждой записи есть адрес и экран принимает её `queue`. Карточку без адреса
  не показываем.
- **Правило числа** («ноль не рисуем», «?» при `doubt`, «не посчитано» при отказе) поднимается из
  `features/costs/invoiceQueues.ts` в `shared/` — им пользуются и чип экрана счетов, и карточка Главной;
  иначе Главной пришлось бы импортировать costs или держать вторую копию.

### «Недавние» — по решению В-3 (вариант Б, 11.11.2026)
- Сервер: своя таблица ядра `user_recent_records` (`UserId`, `RecordType`, `RecordId`, `OpenedAt`, ключ —
  первые три; не больше 20 на пользователя, вытеснение старых при записи). Адреса `POST /api/account/recent`
  (`{ recordType, id }`, ответ 204) и `GET /api/account/recent`. Только свои: идентификатора пользователя
  адрес не принимает.
- Чтение разрешает записи владельцем типа: тип ядра — ядро, тип модуля — модуль через объявление «карточка
  записи по идентификатору в правах спрашивающего» (название, раздел, стройка). Это тот же контракт
  «Поиск записей» со многими поставщиками, что отвечает поиску палитры (`shell-05`, В-1 — Б): одно
  объявление «найти» и «показать по id», а не два.
  Нет записи или нет права — пропускается. Выключенный модуль — его записи пропускаются, в таблице
  остаются (включат — вернутся).
- **Исключение из правила `If-Match`, названное:** `POST /api/account/recent` пишет личную отметку
  пользователя, а не запись модуля или общих данных; потерянного обновления нет (последнее открытие —
  всегда верно), запись модуля не меняется. Так же устроены личные настройки (`PUT /api/account/settings`).
- Клиент: хук `useRecentTouch(recordType, id)` на экранах, у которых есть `RECORD_ROUTES` (счёт; дописать
  стройку, комплект, набор данных, шаблон) — зовётся, когда запись показана, не чаще раза на открытие.
  Перепись: каждый экран из `RECORD_ROUTES` отмечает открытие.

### «Выполняется» и «Полезно знать»
- «Выполняется» — `useActiveJobs()` и `JobRow` в некликабельной `Card flush`, без второго запроса; блок
  пропадает, когда список пуст.
- «Полезно знать» — три строки по правам (сканы — `costs.invoice.edit`); «Скрыть» пишет новый ключ
  `UserSettingKeys.HomeTips` (`home.tips`, значения `shown`/`hidden`) через `useSyncedPreference`.
  Вернуть блок — тем же ключом в профиле («Показывать подсказки на Главной»), иначе «насовсем» было бы
  без выхода.

### Интерфейс: что не нарисовано на макете (0.2 — Дизайнер 12.11.2026, комментарий к #1436)
- **Раскладка PR 1** (без «Недавних») — одна колонка: «Ждут вас», ниже «Выполняется» и «Полезно знать»;
  ширина — как у страницы смет (`mx-auto max-w-5xl px-6 py-5`, `EstimatesPage.tsx`). Две колонки придут с
  «Недавними». Заголовки блоков — `h2` вне карточек.
- **Телефон (375/390):** карточки очередей в две колонки (контейнерный запрос: в одну четыре карточки
  займут экран), пояснение очереди — не длиннее ~50 знаков (тест на объявления); порядок блоков тот же;
  над заголовком ничего, плавающей кнопки нет — основного действия у Главной нет; в «Полезно знать» одна
  строка — о поиске (Ctrl K, «?» и перетаскивание на касании не работают).
- **Пустые и промежуточные состояния «Ждут вас»:** открытых очередей нет — блока нет; все пусты — строка
  `body-medium` «Сейчас ничего не ждёт» (не `EmptyState`: его пунктир — место броска файла); ответ в пути —

- [Живые прогоны и закладки ждут `/` → «Стройки»] → прогоны, начинавшие с `/`, переводятся на явный
  адрес в том же PR; в `docs/USER_GUIDE.md` — что открывается после входа.

### В-2. Как модуль объявляет очередь Главной — решение Архитектора, до кода PR 1
- **А. Клиентский реестр** `shared/ui/homeQueues.ts`, описатели в части модуля (см. Decisions). «+» числа
  — буквально те же хуки, что у очереди; адреса экранов знает только клиент (`recordRoutes.ts`: «модуль
  на сервере адресов клиента не знает»); сервер не меняется. «−» новая очередь — правка клиента (как и
  новый экран).
- **Б. Серверное объявление** `IAppModule.Queues` + адрес ядра `GET /api/home/queues`, который зовёт счётчик
  модуля. «+» модуль объявляет себя на сервере, один запрос. «−» числа идут вторым путём, если адрес
  очереди не зовёт тот же счётчик; клиент всё равно сопоставляет очередь с экраном; права — дважды.
- **Рекомендация — А.**
- **✅ Решено владельцем 11.11.2026 — вариант Б, очереди счетов — тоже.** Decisions переписаны по нему;
  форма серверного объявления (свойство модуля или контракт `plan-22`) — уточнение Архитектора до кода.

### В-3. Где хранить «Недавние» и как проверять удалённые и закрытые — решение Архитектора, до кода PR 2
- **А. Личная настройка** — ключ `recent` в `UserSettingKeys` (JSON до 20 записей). «+» без нового адреса и
  таблицы. «−» сервер настроек значения не читает (как избранное, `FavoritesAreNotApiParameterTests`) —
  удалённые и закрытые отсеять некому, кроме клиента, а он не знает об удалённых.
- **Б. Своя таблица ядра и разрешение через владельца типа** (см. Decisions). «+» удалённые и закрытые
  отсеивает сервер в правах спрашивающего; то же объявление служит поиску палитры. «−» таблица, миграция
  ядра, порт модуля.
- **В. Только браузер.** «+» проще всего. «−» на другом устройстве пусто (issue предпочитает сервер);
  удалённые остаются.
- **Рекомендация — Б.** Decisions и дельта `core` написаны по ней; при ответе А дельта `core` сужается до
  ключа настройки, а сценарий «удалённая и закрытая» уходит на клиент.
- **✅ Решено владельцем 11.11.2026 — вариант Б.** Decisions и дельта `core` — без изменений.
