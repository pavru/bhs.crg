# Proposal: исправление накладной закрытого периода

Самостоятельный change модуля `costs` — хвост этапа 2 (E2b). Опирается на базовый тип версии записи из
`../plan-12-record-versions/` (ещё не реализован) — зависимость названа ниже.

## Why

Issue #1340 (E2b; выделено из E2 #1100 решением владельца 15.10.2026). Проведённую накладную, запертую
закрытым периодом, сегодня нельзя ни вернуть в черновик, ни исправить: связка записи `WaybillDesk`
отказывает и предлагает только отменить закрытие периода. ТЗ (`COST-16`) требует для документа закрытого
периода новую версию с обязательной причиной; прежняя остаётся видна (`CORE-36`). Для счёта это построено
книгой исправлений E2 (#1100 закрыт, PR 1–6d, #1357…#1397); накладная по решению владельца исправляется
«отдельной задачей на том же приёме версий».

## What Changes

- **Исправление накладной** `POST /api/costs/waybills/{id}/correction`: причина и всё содержимое накладной
  одним телом (шапка и строки, включая позиции номенклатуры), `If-Match`, своё право исправления, ворота
  модуля. Действующее содержимое уходит в версию, накладная остаётся проведённой.
- **Версии накладной** — таблица наследника `ModuleRecordVersion` (`plan-12`); чтение
  `GET /api/costs/waybills/{id}/versions` под `costs.waybill.read`. Книги проводок нет: денег у накладной
  нет (`Data/Waybill.cs`, доккомментарий класса).
- **Карточка** — список версий с причинами; **список накладных** — пометка «исправлена после закрытия».
- Запертая накладная **мимо исправления** по-прежнему отказывает — с выходом через исправление вместо
  «отмените закрытие»; диалог закрытия периода говорит, что такие накладные правятся только исправлением.
- Перечень «Материалы на объекте» читает только действующее содержимое (`CORE-36`).
- **До кода — решение владельца** (design, Open Questions): нужен ли накладной второй взгляд «на момент
  закрытия» (рекомендация — нет), какое право исправляет накладную (рекомендация — своё
  `costs.waybill.correct`, а не `costs.invoice.correct`), запирает ли версия накладную после отмены
  закрытия (рекомендация — нет).

## Capabilities

### New Capabilities
- Нет.

### Modified Capabilities
- `costs`: исправление накладной закрытого периода новой версией с причиной; версии и пометка накладной.

## Impact

- **Зависит от:** `plan-12-record-versions` (базовый тип `ModuleRecordVersion` и перепись
  `RecordVersionInventoryTests`) — PR этого change сливается после него. Если `plan-12` ещё не слит к
  старту, накладная становится **первым** наследником базового типа вместо версий КП (`plan-13`) —
  отметить в `plan-12` и зонтике `plan-00-epic`.
- **Сервер (`Modules.Costs`):** `Data/WaybillVersion.cs`, `Data/Waybill.cs` (`CurrentVersion`),
  `Endpoints/WaybillDesk.cs` (выход через исправление), новый `Endpoints/WaybillCorrection.cs`,
  `Endpoints/WaybillActions.cs` (событие журнала), `Data/WaybillClosingLines.cs` (слова), `CostsModule.cs`
  (право — по решению 0.1); миграция `CostsDbContext`.
- **Клиент:** `features/costs/WaybillForm.tsx`, `WaybillsPage.tsx`, `shared/api` накладных — по выбранному
  макету.
- **Тесты:** `WaybillCorrectionTests`, `RecordVersionInventoryTests`, `InvoiceWritePathTests` (запись
  накладной мимо связки), состав прав по ролям.
- **Документы:** `docs/USER_GUIDE.md` (исправление накладной), `docs/tz/55-счета-и-накладные.md`
  (`COST-16`: «накладная исправляется отдельной задачей» — построено).
