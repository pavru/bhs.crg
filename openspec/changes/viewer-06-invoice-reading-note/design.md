# Design: строка-оговорка вида для чтения в одну строку

Общая архитектура — `../viewer-00-epic/design.md` (D6, D10). Здесь только решения этого change.

## Context

- **`BuiltImage`** (`features/costs/InvoiceFileImage.tsx:59`), блок `data-testid="image-caveat"` (`:90`),
  сейчас в нём три этажа:
  1. фраза в `Tooltip`: построен когда и из чего, плюс `layoutHint`; рядом «Перестроить»;
  2. `LayoutChooser` (`Chip menu` + `Popover`) — только если `canEdit && canChooseProfile` (профилей
     больше одного, `layout === 'profile'`);
  3. список `<ul>`: `layoutNotice` (`changed` / `deleted` / `none`, только `canEdit`,
     `data-testid="layout-notice"`) и все `image.notes`.
- **Тексты** — `features/costs/invoiceImageLayout.ts`: `layoutHint`, `layoutNotice`, `layoutChipLabel`,
  `rebuiltMessage`.
- **Сверка: клиент не отличает пометку о раскладке от прочих.** `notes` — плоский список строк, в нём
  перемешаны:
  - пометки конвертера;
  - `ExcelPageLayout.AppliedNote(profile, sheets)` — четыре формы с именем профиля внутри
    (`ExcelPageLayout.cs:102–108`);
  - `ExcelPageLayout.FailedNote` (`:100`);
  - пометки `OfficeRenditionBuilder` (`SmallTextNote`, `SheetsNote`, `UncheckedNote`).
  В записи (`RenditionRecord.Notes`) они лежат одним списком. Отделить пометку о раскладке на клиенте
  можно только разбором текста с подставленным именем профиля. Значит, нужна правка сервера — issue её
  не называл.
- **Образец отделения при чтении** — `ModuleRenditionsPort.NotesOf` (`:88`): к пометке о потерянном
  тексте дописывается фраза по префиксу `RenditionPostconditions.LostTextNote`. Раскладка уже идёт
  отдельно — `ModuleRenditionLayout` (`IModuleRenditions.cs:90`), в ответе `InvoiceImageView.Layout`,
  `Profile`, `ProfileState`.

## Goals / Non-Goals

**Goals:** одна строка-оговорка; ни одного потерянного текста состояния; пометка о раскладке отделена
сервером.

**Non-Goals:**
- Состав строки файла («Открыть во вкладке», «Оригинал») — `viewer-01`.
- Строка-оговорка у читателя без чипа: issue сводит дубль только при показанном чипе.
- Хранение пометок раздельно в `RenditionRecord`: миграции нет.

## Decisions

### Сервер: `layoutNote` при чтении
- `ExcelPageLayout.IsLayoutNote(string)` узнаёт свои пометки: четыре формы `AppliedNote` и `FailedNote`.
  Тексты генерирует этот же класс, поэтому знание остаётся в одном месте. Тест: для каждой формы
  (`FitWidth` × один или несколько листов) и для `FailedNote` — `true`; для `SmallTextNote`, `SheetsNote`,
  `UncheckedNote`, пометки о потерянном тексте — `false`.
- `ModuleRenditionsPort` (там уже есть `NotesOf`) отделяет пометку о раскладке: она уходит в новый член
  `ModuleRenditionLayout.Note`, а `Notes` её больше не содержит.
- Отделение при чтении, а не в записи: так поле получают и виды, построенные до изменения (тот же довод,
  что у `NotesOf`).
- `InvoiceImageView` получает `LayoutNote` (`string?`). Адрес только читает — If-Match не нужен, ворота
  модуля и права `costs.invoice.*` прежние.
- Это правка контракта `BHS.CRG.Modules`, поэтому до кода — разбор с Архитектором, вывод — в описании PR.
  `ModuleBoundaryTests` не затронут: модуль не получает ссылки на `Infrastructure`.
- **Альтернатива** — клиент узнаёт пометку по шаблону текста. Отвергнута: имя профиля подставлено
  внутрь, и правка формулировки на сервере молча вернула бы дубль.

### Клиент
- **Строка** — `flex flex-wrap items-center gap-x-2 gap-y-1`, в контейнере `@container`:
  - фраза (`truncate` в широкой колонке, перенос в узкой);
  - чип;
  - «Перестроить» (`variant="text"`).
  `< 420 px` — чип и «Перестроить» уходят на вторую строку целиком, без разрыва внутри.
- **Подсказка чипа** — `Tooltip` вокруг `Popover.Trigger`, по правилу UI.md «Триггер меню оборачивают
  целиком». Состав: `layoutNotice` (если есть) + `layoutNote` + фраза «Выбрать профиль — по нажатию».
- **Без чипа** (`!canEdit` или профиль один): `layoutNotice` и `layoutNote` остаются строками списка,
  как сейчас.
- `layoutHint` в подсказке фразы остаётся: он про то, по чему разложен вид, и читатель без чипа узнаёт
  это только из него.
- `data-testid="layout-notice"` остаётся на тексте состояния, где бы он ни стоял (строка или подсказка).
  На нём держатся тест `InvoiceFileImage.test.tsx:57–79` и живой прогон `invoice-layout-checks.mjs`
  (`image-caveat`, `layout-chip`). Оба переписываются в этом PR.

### Макеты
Раскладка строки меняется — по правилу UI.md нужны три варианта в Claude Design и выбор владельца (D10
зонтика). Владелец задал форму («одна строка»), но не порядок, не перенос и не место текстов состояний.
Варианты, например:
- (а) фраза — чип — «Перестроить»;
- (б) короткая фраза «Вид для чтения · N стр.» со значком сведений вместо полного текста оговорки;
- (в) чип перед фразой.

Ограничение для всех: слова «документ — оригинал» остаются на виду, а не в подсказке (`IMAGE_CAVEAT`,
issue #1270).

## Risks / Trade-offs

- [Молча потерять текст состояния #1456] → тест компонента проходит все состояния:
  - `changed`, `deleted`, `none`;
  - «профиль не применён» (`FailedNote`);
  - `file` (раскладка из файла — в подсказке фразы);
  - не книга (чипа и текстов нет).
- [Тексты, которые человек видел сразу, теперь в подсказке] → это решение владельца («в чипе или его
  подсказке»). Метка чипа и так называет удалённый профиль и «до профилей».
- [Пометка о раскладке у видов, построенных ДО #1453, другой формулировкой] → `IsLayoutNote` её не
  узнает, и она останется строкой: дубль, но не потеря. Тест: незнакомая пометка остаётся в `notes`.
