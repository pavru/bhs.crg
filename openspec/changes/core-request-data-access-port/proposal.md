# Подменяемое формирование доступа для таблиц, наборов и MCP

## Why

Тестовому хосту Work-25 нужна возможность изменить параметр доступа, который получают настоящие
обработчики HTTP и MCP. Таблицы и снимки сейчас запрашивают его у конкретного `DataAccessResolver`,
поэтому подмена контракта фоновых заданий или `IModuleReaders` до этих обработчиков не доходит.

## What Changes

- Ввести в `BHS.CRG.Api/Auth` интерфейс формирования `DataAccess` для запроса и зарегистрировать
  за ним существующий резолвер. HTTP и MCP передают ему принципал текущего запроса.
- Подключить к интерфейсу обработчики таблиц, источников и снимков, которые уже запрашивают
  `DataAccess`. Сохранить штатное вычисление прав, модульные ворота и границы выдачи
  ([AUTH-6], [AUTH-8], [AUTH-9], [AUTH-12.1], [CORE-24.1], [WORK-40]).
- Проверить штатный и подменённый резолвер на изолированном тестовом хосте с настоящими HTTP и MCP
  обработчиками. Описать точку регистрации для дальнейших тестов.

## Capabilities

### New Capabilities

Существующих возможностей ядра достаточно.

### Modified Capabilities

`skip_specs: true` в `.openspec.yaml`: рефакторинг сохраняет поведение, заданное спецификациями
`core`, `auth` и `work`.

## Impact

Область изменения охватывает DI и адаптеры API/MCP, интеграционные тесты и заметку разработчика.
Контракт `IDataAccessResolver.ForUserAsync` для фоновых задач, контракты модулей, схема БД и
форматы ответов сохраняются.

Это предпосылка задач 1.1, 1.5 и 1.6
[Work-25](../work-25-roles-e2e-violation/tasks.md) ([STG-6], [WORK-39], [WORK-40]).
Критерии этих задач, включая положительный контроль всех путей и красный прогон с восстановлением,
действуют в полном объёме. Проверку охватов собственных и менеджерских отчётов завершает Work-25.
