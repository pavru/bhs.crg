# Spec Delta: auth

## MODIFIED Requirements

### Requirement: [AUTH-12.1] [AUTH-12.2] MCP в правах владельца токена
Инструменты, ресурсы и промпты MCP SHALL объявлять ворота атрибутами `[McpPermission]` / `[McpModule]`
на методе (не на классе); они строят те же политики `perm:` / `module:`, что и адреса. Список
инструментов MUST собираться по правам пользователя; прямой вызов недоступного — отказ с кодом.
Право инструмента равно праву его адреса.

#### Scenario: Монтажник подключает агента
- **WHEN** пользователь с ролью «Монтажник» запрашивает `tools/list`
- **THEN** в списке нет инструментов, на которые у него нет права (`McpToolGateTests`)

#### Scenario: Инструмент без ворот
- **WHEN** в MCP добавлен инструмент без ворот и без записи в списке личных
- **THEN** `McpGateInventoryTests` падает

#### Scenario: Новый класс примитивов вне списков
- **WHEN** зарегистрирован новый класс инструментов, ресурсов или промптов — в том числе в сборке модуля — и ни в один список тестов он не вписан
- **THEN** опись ворот видит его примитивы: перечень берётся из регистрации MCP-сервера, а не из списка классов

#### Scenario: Опись расходится с регистрацией
- **WHEN** примитив зарегистрирован, но опись не нашла его метод, или метод с атрибутом SDK есть, а класс не зарегистрирован
- **THEN** `McpGateInventoryTests` падает и называет примитив

#### Scenario: Отозванное право
- **WHEN** у пользователя отозвали право
- **THEN** инструмент закрыт на следующем же вызове, без переподключения агента

#### Scenario: Фильтры авторизации не зарегистрированы
- **WHEN** из запуска убран `AddAuthorizationFilters()`
- **THEN** MCP отказывается перечислять инструменты вообще, а не открывается всем
