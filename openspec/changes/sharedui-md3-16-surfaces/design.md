# Design: просмотрщик PDF, календарь и редактор кода по MD3

Общая архитектура — `../sharedui-md3-00-epic/design.md`: D5 (значки), D6 (слой состояния), D7
(плотность), D8 (отступления: «Очистить / Сегодня», сегменты времени), D10 (три макета), D11 (правка
сторожей и ожиданий), D12 (документы и дизайн-система). Требования — `specs/sharedui/spec.md`.

## Goals / Non-Goals

**Goals:** три поверхности говорят ролями и шкалами MD3; отступления названы; редактор кода больше не
«чужой» в обеих темах.

**Non-Goals:**
- Поведение просмотрщика ([UI-10]…[UI-27] кроме [UI-11], [UI-18]) — без изменений; плавающая панель
  поверх листа — только если её выберут в макетах (тогда `/opsx:update` [UI-11]).
- Модальный выбор даты на телефоне — #1522, отдельно.
- Подсветка синтаксиса Typst (`typstLanguage.ts`) — цвета токенов языка берутся из тех же ролей, но
  грамматика не меняется.
- Печать и профили печати — документ Typst, не интерфейс.

## Decisions

### Просмотрщик
- **Панель остаётся закреплённой у нижнего края** — решение варианта В. Высота — по выбранному макету:
  кнопки 40 требуют панели не ниже 48. Docked toolbar M3 Expressive — 64; брать ли Expressive — выбор
  владельца, зонтик его по умолчанию не берёт (Non-Goals зонтика).
- **Масштаб — чип с меню** (`Chip menu` из `sharedui-md3-10-actions`), слой — `Menu dense`
  (`sharedui-md3-13-containers`). Отдельной поверхности меню у просмотрщика больше нет.
- **Поле номера** — плотное поле 40 из `sharedui-md3-11-inputs`, ширина по числу знаков.
- **Лист** — светлая тема: `shadow-elevation-1`; тёмная: `outline-variant`. Переключение — через роль
  темы (`data-theme`), а не через вариант `dark:`: его снимает `sharedui-md3-05-state-motion`.

### Календарь
- Размеры — docked date picker: 360 / 40 / 48. Шапка 48, месяц и год — текстовые кнопки с `arrow_drop_down`.
- Лента периода — `secondary-container` под клетками (`BAND` в `Calendar.tsx`), концы — круги `primary`.
- **Строка «Очистить / Сегодня» остаётся** — отступление D8. «Отмена / OK» не вводятся: выбор не
  подтверждается (щелчок ставит дату).
- **Отвергнуто — оставить 288.** Клетка 36 меньше цели 48, а календарь — слой над окном (#1521), и
  ширина окна его не ограничивает.
  Ширину проверяют уровень `fixed-width` и живой прогон календаря в окне «Оплата».

### Время
- `TimeField` получает роли и шкалы (текст поля по В6), сегменты остаются. Отступление названо в
  `docs/UI.md`.

### Редактор кода
- **Одна тема `bhs`** через `monaco.editor.defineTheme`: значения читаются из вычисленных стилей
  `--md-sys-color-*` при загрузке Monaco и при смене темы приложения. Хук `useMonacoTheme()` в
  `shared/ui` отдаёт имя темы; пять мест берут его вместо `vs` / `vs-dark`.
- Смена темы — `monaco.editor.setTheme` по событию `ThemeProvider`, без пересоздания редактора.
- **Отвергнуто — значения темы в JSON рядом с палитрой.** Тогда тема Monaco разошлась бы с палитрой при
  перегенерации (D4). Чтение из CSS держит один источник.
- Тест: цвет фона темы `bhs` равен вычисленной роли `surface` в обеих темах.

## Risks / Trade-offs

- [Панель 40 → 48…64 съедает высоту листа в узкой колонке счёта] → три макета на экране счёта с
  просмотрщиком на 1366×768; `pdf-viewer-checks` меряет новую высоту.
- [Календарь 360 шире поля в узкой колонке] → слой над окном и сдвиг по `collisionPadding` (#1521)
  уже есть; живой прогон в окне «Оплата».
- [Тема Monaco мигает при первой загрузке] → тема определяется до создания редактора (в загрузчике
  `MonacoEditor.tsx`).
