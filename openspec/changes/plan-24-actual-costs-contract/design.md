# Design: контракт «Фактические затраты»

Дочерний change зонтика `plan-00-epic`, общая архитектура — `../plan-00-epic/design.md` (D10 — контракты,
D11 — право контракта, D12 — права с первым адресом, D16 — «Ход работ»). Здесь только решения этого change.

## Context

Сверено по коду master `6b81e51e`.

- «Затраты по стройке» — `GET /api/costs/site-costs` под `costs.report.read`
  (`Modules.Costs/Endpoints/SiteCostsEndpoints.cs:91-93`), ответ `SiteCostsView` (`:49-54`): затраты — по
  оплаченным счетам, «к оплате» — отдельно, разделы — второй срез. Деньги считает `CostViews`
  (`Data/CostViews.cs:31`), и спецификация требует, чтобы деньги книги считал только он (`costs`,
  «Деньги книги считает только `CostViews`»).
- Доля разноски (`Data/InvoiceAllocation.cs:48-63`) — стройка, раздел или статья; ссылки на позицию
  перечня нет: `COST-14` не построен.
- `costs.report.read` объявлено с `ReadAllMark.In` — «Руководитель» его получает через «читать всё».

## Goals / Non-Goals

**Goals:** два итога стройки контрактом; право контракта для полосы; честное «не ведётся» у доли по
работам.

**Non-Goals:**
- полоса на экране — `plan-25`;
- разноска на позицию перечня (`COST-14`) — вне нарезки этапа 3, отдельное решение владельца;
- «план против факта» материалов — `plan-27`;
- взгляд «на момент закрытия» — контракт считает «с исправлениями», как реестр.

## Decisions

- **Интерфейс.** `[ModuleContract("costs", "Фактические затраты")]`
  `IActualCosts.ReadAsync(ModuleReader, Guid constructionId, Guid? sectionId, ct)` →
  `Totals(allocated, paid, currency, linkedToWorks: State)` | `Hidden(permission)`. `linkedToWorks` —
  `not-tracked` до `COST-14`.
- **Счёт итогов — тот же, что у отчёта.** Провайдер не заводит второго расчёта денег: «оплачено» берётся
  тем же путём `CostViews`, что «Затраты» `SiteCosts`, за всё время; «разнесено» — тот же путь без
  отбора по оплате, без черновиков и отклонённых. Сторож — равенство чисел отчёту на одном посеве.
- **Право.** `costs.totals.read` — право контракта (`plan-21`), `ReadAllMark.Out("выдача другим
  модулям")`: «Руководителю» итоги и так открыты через `costs.report.read`. Контракт отвечает носителю
  любого из двух. «Менеджер проекта» получает `costs.totals.read` в `SystemRoles` (ждёт решения В-3; при
  ответе (а) право не объявляется, при (в) «Менеджер проекта» получает `costs.report.read`).
- **If-Match и ворота.** Нового HTTP-адреса и пишущего API нет. Ворота `module:costs` правом контракта
  не открываются — проверка тестом состава доступа.
- **Сторож.** `ActualCostsContractTests`: два счёта стройки, один оплачен — `allocated` = сумма обоих,
  `paid` = оплаченный и равен «Затратам» отчёта за всё время; черновик не входит; отбор по разделу;
  только `costs.totals.read` — итоги есть; без прав — `Hidden`; система — отказ. Тест состава
  `/api/account/access`: у «Менеджера проекта» модуль `costs` открыт его прежними правами
  (`costs.request.*`), а у роли только с `costs.totals.read` — нет. `CostsOnlyHostTests` — число прав.
- **Чем ломается.** Свой расчёт денег в провайдере — полоса расходится с отчётом на первой корректировке
  закрытого периода. Ноль в доле «по работам» — читается как «ничего не потрачено на работы».

## Risks / Trade-offs

- [Полоса без доли «по работам» беднее `PLAN-21.1`] → носитель `not-tracked` говорит причину; `COST-14`
  — вопрос владельцу о возвращении, отмечен в отчёте нарезки.
- [В-3 решится иначе] → правка объявления одного права и одной строки состава роли.
