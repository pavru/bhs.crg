# Spec Delta: core

## ADDED Requirements

### Requirement: [CORE-5] [WORK-8] Модуль видит действующий пояс стройки
Стройка, которую ядро отдаёт модулю, SHALL нести действующий часовой пояс (IANA): свой пояс стройки, а
если он не задан — пояс компании с признаком «унаследован». Модуль MUST NOT читать настройки ядра, чтобы
узнать пояс сам.

#### Scenario: Пояс не задан у стройки
- **WHEN** у стройки пояс не задан, а пояс компании — `Europe/Moscow`
- **THEN** модуль получает у стройки `Europe/Moscow` с признаком «унаследован от компании»

#### Scenario: Свой пояс стройки
- **WHEN** у стройки задан `Asia/Vladivostok`
- **THEN** модуль получает `Asia/Vladivostok` без признака наследования

### Requirement: [CORE-5] [WORK-8] «Сегодня на стройке»
Ядро SHALL отвечать модулю, какая сегодня дата на названной стройке — по её действующему поясу, — и какая
дата стройки соответствует данному мгновению. «Сегодня» компании MUST оставаться отдельным вопросом с
прежним ответом. Незнакомая стройка — отказ, а не дата по поясу компании.

#### Scenario: Полночь наступила на стройке раньше
- **WHEN** сейчас 20:00 31.10 по Москве, компания в Москве, стройка во Владивостоке
- **THEN** «сегодня на стройке» — 01.11, «сегодня компании» — 31.10

#### Scenario: Граница проверяется без ожидания полуночи
- **WHEN** тест подставляет часы ядра на 23:59:59 и на 00:00:00 по поясу стройки
- **THEN** ответы различаются на одни сутки

#### Scenario: Удалённая стройка
- **WHEN** модуль спрашивает «сегодня» у стройки, которой больше нет
- **THEN** ответ — «стройки нет», а не дата по поясу компании

### Requirement: [CORE-7] [CORE-20.4] Связь с учётной записью в порту сотрудника
Порт сотрудников ядра SHALL отдавать модулю у сотрудника состояние связи с учётной записью — связан (с
идентификатором и именем учётной записи), не связан или учётная запись удалена. Состояние MUST браться
из таблицы связи ядра, а не из поля карточки.

#### Scenario: Связанный сотрудник
- **WHEN** модуль читает сотрудника, связанного с учётной записью
- **THEN** у сотрудника состояние «связан» с идентификатором и именем учётной записи

#### Scenario: Учётная запись удалена
- **WHEN** учётная запись, связанная с сотрудником, удалена
- **THEN** модуль получает у сотрудника состояние связи «удалена», а не «не связан»

#### Scenario: Поле карточки против таблицы связи
- **WHEN** в карточке сотрудника в поле `УчётнаяЗапись` стоит значение, а в таблице связи связи нет
- **THEN** порт отдаёт «не связан»
