# Design: экраны без самоделок

Общая архитектура — `../sharedui-md3-00-epic/design.md`: D2 (псевдонимы до 20), D8 (banner — расширение),
D9 (вид через `shared/ui`), D10 (макеты только при новой раскладке), D11 (правила в ноль). Требования —
`specs/sharedui/spec.md`.

## Context

- Компоненты уже есть: `Banner`, `StatusText` (12), `Card`, `SideSheet`, `Menu` (13), `Chip` (10),
  `TextField` / `TextAreaField` / плотное поле (11), шкалы формы, возвышения и текста (06, 07).
- Правила с уровнем по файлам (на 03.11.2026): `notice-plaque` 32 в 25 (весь `src/`), `hand-card` 67 в 49
  (только `features/`), `raw-field` 77 в 43, `legacy-radius` 6, `legacy-shadow` 1, `legacy-type` 39 в 31
  (все три — весь `src/`).
- Перечень всех 145 мест пяти правил с пометкой «компонент» / «макет» — разбор Дизайнера (лист «00 Разбор
  и вопрос» проекта 4f525fa0, задача 0.2): 97 мест сводятся к готовому компоненту или ступени, 32 меняют
  раскладку и сведены в девять развилок Р1–Р9, 16 — файлы экрана счёта. `raw-field` в разбор не входил:
  это перевод на готовое поле, макеты ему не нужны (`docs/UI.md`, «Макеты не нужны»).
- Половина «карточек руками» — не карточки: заметки (`SupplierMatchNote`, `ArchiveParts`), поля только
  для чтения (`LockedFieldMarks`, `FileProfilesDialog:95`), плитки значений (`RefTile`, `DocRefField`),
  миниатюры (`PdfGroupingEditor`, `BrandingSection`, `ImageField`), липкие панели выделения.
- `RereadFailedNotice`, `SegmentProblemMark`, `EmptyState`, `ArchivedMark`, `StaleSourceAction` пять правил
  не нарушают: первые два уже переведены в 12, остальные чистые.
- Экран счёта меняют `costs-invoice-screen-10…13`: 11 сам сводит `StaleInvoiceNotice` и заметки счёта к
  листу состояния.

## Goals / Non-Goals

**Goals:** шесть правил — на нуле; экраны берут вид только из `shared/ui` и шкал.

**Non-Goals:**
- Новые раскладки сверх выбранного варианта. Где замена её меняет — макеты, а не решение исполнителя.
- Экран счёта по варианту Г — его change. Здесь только то, что он оставил.
- Голые `Dialog.Root` → `Modal` — отдельный вопрос логики закрытия, вне эпика.
- Удаление псевдонимов цвета — `sharedui-md3-20-legacy-removal`.

### PR 0: компоненты до экранов (разбор Архитектора)

- **Контекстная шапка выбора** — новый компонент `shared/ui` (рабочее имя `SelectionBar`; `count`,
  `onClear`, действия, `note` — строка предупреждения под полосой). Два потребителя (`BulkSelectionBar`,
  `QualityDocLinks`); прочие «Выбрано: N» (`usePurgeBatchControls`, `ComplexFields:353`, `ArrayTableModal`)
  панелями не являются. Нового правила не нужно: `hand-card` не пустит самоделку в `features/`.
- **Состояния `Card`**: `dragged` (перетаскиваемая — `FieldBuilder:195`, это не цель), `dropTarget` (цель —
  `GroupedFieldsEditor:283`), `invalid` (рамка `error` — `IntegrationSettingsSection:162`); плюс проброс
  обработчиков перетаскивания и режим без внутренних отступов (шапки-строки конструктора полей через
  `title` не ложатся). Приглушение выключенного движка свойством не делается — внутри живой флажок; вид —
  ролью текста. Утилита `drop-mark-*` не годится: это черта места вставки, а не подсветка карточки.
- **`SideSheet` в окне**: свойство без автофокуса (в окне выбора фокус остаётся в поиске) и Esc листа,
  который закрывает сначала лист, а не окно (Radix слушает Esc на документе в фазе захвата — лист внутри
  `Modal` обязан остановить его сам). Предпросмотру документа — шлюз `xl`: сохранённое «открыто» иначе
  откроет лист во весь экран на телефоне. Ширина — 400, как в макете А; широкого листа не заводим.
- **Флажок 2 px** — `skip: ['shared/ui/Checkbox.tsx']` у `legacy-radius`, по образцу `skip` других правил:
  сейчас «исключение» — единица уровня, и второй `rounded-[…]` в `Checkbox` прошёл бы молча. Токен формы в
  теме отвергнут: генератор держит пять ступеней MD3, и `rounded-checkbox` разрешил бы 2 px всем.
- **Отвергнуто — `SupportingText` и `ValueTile`.** Нужны были вариантам Б и В (текст у причины вне поля,
  плитка-поле); в А сообщение о поле — подсказка поля, плитка — чип.

### Порядок и границы PR

- **По разделу на PR**, а не по правилу: правка экрана читает экран целиком один раз, а ревью сверяет
  один раздел. Перед экранами — PR 0 с компонентами и `/design-sync`.
- **Уровень опускается в каждом PR** (храповик просит сам). Последний PR (`shared/`) доводит до нуля и
  проверяет пустой уровень шести правил.
- **Плашка или текст поля.** Сообщение о состоянии области — `Banner`. Сообщение об одном поле — подсказка
  или ошибка поля. Пометка состояния строки — `StatusText`.
- **Экран счёта** — 16 мест в `InvoiceForm`, `InvoiceLinesTable`, `InvoiceScanPanel`, `InvoicePayment`,
  `InvoiceRecognitionNote`, `InvoicePartyNote`, `InvoiceTwinNotes`, `InvoiceDeleteDialog`,
  `LostReferencesNote`, `SupplierMatchNote`, `StaleInvoiceNotice`, которые правят `costs-invoice-screen-10…13`
  (сверка — по их `tasks.md` в начале PR 4), — в PR 5 после их архива. В PR 4 остаются полосы исправления
  (`CorrectionBar`, `WaybillCorrectionBar` → `Banner warning`), `WaybillForm`, `CorrectionPreviewDialog`,
  `IssuedMaterialsDialog`, `CostViewsBand`, `CorrectionHistory`, `LayoutChooser`.
- **Тест пустого уровня** — новым файлом рядом с `ui-ratchet-*.test.mjs`: `compare({}, …)` по фикстурам
  шести правил. `ui-ratchet.test.mjs` (497 строк кода) и `ui-ratchet-lib.mjs` (498) стоят у порога 500 и в
  `file-size-baseline.json` не значатся — дописывать в них нельзя.
- **Отвергнуто — один PR на все экраны.** Тысячи строк в одном диффе без снимков; ревью сравнивать не с чем.
- **Отвергнуто — оставить уровни правил ненулевыми до 20.** Тогда финал удалял бы псевдонимы под живыми
  классами, а «гибрид» возвращался бы через ненулевой уровень.

## Risks / Trade-offs

- [Конфликты с параллельными экранами этапов 3–4] → раздел, где идёт крупная ветка, ставится последним
  в очередь; ветки обновляются перезапуском кодмода (D3).
- [`sharedui-md3-18-lists` правит те же файлы] → кто сливается вторым, обновляет ветку; правила обоих
  change с уровнем не дают одному вернуть самоделку другого.
- [Экран счёта по Г ещё не слит к PR 4] → его файлы ждут PR 5; PR 5 ждёт архива `costs-invoice-screen-10…13`.
- [Banner вверху уводит сообщение от причины] → принято владельцем (Р1-А); причина в одном поле — подсказкой
  поля, у самой причины.
- [Предпросмотр PDF в 400 мелок] → принято владельцем (Р9-А): форме прибавляется 166 px.
- [Действия стройки уходят с карточки] → страница стройки получает их в шапку в том же PR 3; прогон
  `pages-smoke` / `rail-checks` правится вместе.
- [Скрытая плашка: константа классов вне разметки (`BROKEN_PLATE`, `BrokenRef.tsx:14`) правила не видят] →
  в конце PR 3 — ручной поиск таких констант.

## Migration Plan

Шесть PR в порядке: PR 0 (`shared/ui`), `settings`, `datasets`/`templates`/`tables`, `document-sets`,
`costs`, `shared/` с экраном счёта. Откат — ревёрт PR; псевдонимы держат старое до 20.
