# Design: экраны без самоделок

Общая архитектура — `../sharedui-md3-00-epic/design.md`: D2 (псевдонимы до 20), D8 (banner — расширение),
D9 (вид через `shared/ui`), D10 (макеты только при новой раскладке), D11 (правила в ноль). Требования —
`specs/sharedui/spec.md`.

## Context

- Компоненты уже есть: `Banner`, `StatusText` (12), `Card`, `SideSheet` (13), шкалы формы, возвышения и
  текста (06, 07).
- Правила с уровнем по файлам: `notice-plaque` (заводит 12), `hand-card` (13), `legacy-radius`,
  `legacy-shadow` (06), `legacy-type` (07). Числа уровня на момент старта — из `ui-baseline.json`; оценка
  разбора Дизайнера: плашек 46 строк в 31 файле, карточек 40 строк в 35 файлах.
- Неоднозначные места кодмодов 06 и 07 перечислены их отчётами (D3) — это вход раздела, а не повторный
  поиск.
- Плашки-компоненты в `shared/ui`: `RereadFailedNotice`, `StaleSourceAction`, `SegmentProblemMark` — и
  экранные (`StaleInvoiceNotice`, `CorrectionBar`, `SchemaLevelBanner`…).
- Экран счёта меняет свой change по варианту Г. Строки счёта — пять change `costs-invoice-lines-*`.

## Goals / Non-Goals

**Goals:** пять правил — на нуле; экраны берут вид только из `shared/ui` и шкал.

**Non-Goals:**
- Новые раскладки экранов. Где замена её меняет — макеты, а не решение исполнителя.
- Экран счёта по варианту Г — его change. Здесь только то, что он не тронул.
- Голые `Dialog.Root` → `Modal` — отдельный вопрос логики закрытия, вне эпика.
- Удаление псевдонимов цвета — `sharedui-md3-20-legacy-removal`.

## Decisions

- **По разделу на PR**, а не по правилу: правка экрана читает экран целиком один раз, а ревью сверяет
  один раздел. Разделы объединены по числу файлов: `costs` (53) с соседями по учёту; `document-sets` (78)
  с качеством и каталогом; `settings` (50) с учётной записью; наборы данных, шаблоны и таблицы; `shared/`
  последним.
- **Уровень опускается в каждом PR** (храповик просит сам). Последний PR (`shared/`) доводит до нуля и
  проверяет пустой уровень пяти правил.
- **Плашка или supporting text.** Сообщение о состоянии экрана — `Banner`. Сообщение об одном поле —
  supporting text поля. Пометка состояния строки — `StatusText`.
- **Макеты по месту.** Перед PR раздела исполнитель перечисляет места, где замена меняет раскладку
  (баннер вверху вместо плашки в середине, лист вместо своей панели). Нет таких мест — макеты не нужны
  (`docs/UI.md`). Есть — три макета на эти места и выбор владельца до кода.
- **Отвергнуто — один PR на все экраны.** Тысячи строк в одном диффе без попиксельных снимков; ревью
  сравнивать не с чем.
- **Отвергнуто — оставить уровни правил ненулевыми до 20.** Тогда финал удалял бы псевдонимы под живыми
  классами, а «гибрид» возвращался бы через ненулевой уровень.

## Risks / Trade-offs

- [Конфликты с параллельными экранами этапов 3–4] → раздел, где идёт крупная ветка, ставится последним
  в очередь; ветки обновляются перезапуском кодмода (D3).
- [Экран счёта по Г ещё не слит к PR `costs`] → PR `costs` обходит файлы экрана счёта и строк счёта,
  они доводятся в последнем PR.
- [Banner вверху содержимого уводит сообщение от места причины] → такие места — по макетам.

## Migration Plan

Пять PR в порядке: `settings`, `datasets`/`templates`/`tables`, `document-sets`, `costs`, `shared/`.
Первыми — разделы без параллельных крупных веток. Откат — ревёрт PR; псевдонимы держат старое до 20.
