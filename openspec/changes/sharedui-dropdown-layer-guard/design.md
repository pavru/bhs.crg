# Design: «+ Вставить поле» — слой с порталом; сторож ручных выпадающих списков

## Context

- `features/settings/FieldBuilder.tsx:141–176` — блок формулы расчётного поля: кнопка «+ Вставить
  поле» в `<div className="relative">`, список по `pickOpen && (<div className="absolute right-0
  top-full mt-1 z-50 w-64 … shadow-lg">)` с полем фильтра (`autoFocus`) и пунктами-кнопками;
  `insertRef` вставляет `get("<ключ>")` в позицию курсора `textarea` и возвращает ему фокус.
- `docs/UI.md`, «Слои над окном» (#1521): портал в body без `container`, вид `bg-surface` /
  `border-stroke` / `shadow16`, Esc и щелчок мимо закрывают слой, фокус — к якорю; «Самодельные
  выпадающие списки (`absolute top-full` без портала) не заводятся» — без машинной проверки.
- Храповик: правила по дереву (`countPortalContainers`, `countNativeCheckboxes`) и `dirs`
  (`portal-container` — `['features', 'shared']`).

### Что выяснилось сверкой (22.10.2026)

- Строка в issue верна: `FieldBuilder.tsx:156`, открывающее условие — `:155` (`pickOpen && (`).
- **«Перенести в группу» (`PdfGroupingEditor.tsx:214`) — без `top-full`:** `absolute z-10 mt-1 w-52`.
  Признак «`absolute` + `top-full` / `bottom-full`» из issue его не поймал бы, а правило обязано
  сработать на всех четырёх местах. Отсюда форма правила — по условию «открыт» (D2).
- Поиск по `src/` (условный элемент с `absolute`): кроме четырёх мест — наложения при перетаскивании
  (`DataSetsResource.tsx:340` — `dragOver &&`, `InvoiceScanDrop.tsx:52,55` — `dragging &&`), кнопки в
  углу поля (`RequisitesTab.tsx:483,597` — `isContainer &&`), вопрос окна (`Modal.tsx:327` — `asking &&`),
  слои `OutlinedField.tsx:118,131`. Ни у одного условие не названо «open» — признак их не задевает.
- Живой прогон `types` расчётное поле не проверяет; образец проверки `elementFromPoint` —
  `invoice-payment-smoke.mjs:215`.

### Что выяснилось при реализации (30.10.2026)

- **Мест сегодня три, а не четыре.** Меню «Сохранить как новую версию…» в `EditorPanel` ушло на
  `SplitButton` (#1696, `sharedui-split-button`). Правило находит `FieldBuilder` (1), `EditorPanel` (1,
  «Реквизит»), `PdfGroupingEditor` (1); уровень после перевода — два места. Форма прежнего меню
  сохранения осталась в тесте храповика: правило обязано её видеть.
- **`FieldBuilder` расти не может** (уровень размера — 643 строки кода), а поповер длиннее прежнего
  списка. Редактор формулы — самостоятельный компонент (`ComputedFieldEditor`: формула, проверка,
  «Проверить на образце»), он уходит в свой файл — D5.
- **Имена вида слоя** — роли MD3: `bg-surface`, `border-outline-variant`, `shadow-elevation-2`
  («Слои над окном» после эпика `sharedui-md3`); `border-stroke` и `shadow16` — прежние имена.
- **`ui-ratchet-lib.mjs` — на пороге 500 строк кода:** предикат правила — отдельным модулем
  `ui-ratchet-layers.mjs`, как `ui-ratchet-pills.mjs` и `ui-ratchet-buttons.mjs`; в перечне — запись.

## Goals / Non-Goals

**Goals:** «+ Вставить поле» не режется окном и закрывается Esc без окна; новый ручной список не
появится незамеченным.

**Non-Goals:**
- три меню страниц (`EditorPanel`, `PdfGroupingEditor`) — change `sharedui-page-menus-radix` (#1538),
  здесь они только стоят в уровне;
- клавиатура стрелками по пунктам списка «+ Вставить поле» — issue её не просит; Tab ходит по
  пунктам, Enter выбирает. Понадобятся стрелки — отдельной правкой.

## Decisions

- **D1. Поповер, а не меню.** В списке поле фильтра: у `DropdownMenu` ввод текста перехватывается
  поиском по первой букве пунктов, и фильтр печатать нельзя. `Popover.Root` (`open`/`onOpenChange` —
  прежний `pickOpen`), `Popover.Trigger asChild` — кнопка, `Popover.Portal` без `container`,
  `Popover.Content align="end" sideOffset={4} collisionPadding={8}`, вид слоя по «Слоям над окном».
  Фокус при открытии — в фильтр (`onOpenAutoFocus` → поле), при закрытии — на кнопку (поведение Radix
  по умолчанию). После выбора поля фокус уходит в `textarea`, как сегодня: возврат к кнопке тогда
  отменяется (`onCloseAutoFocus` с `preventDefault`), иначе `insertRef` проиграл бы ему.
- **D2. Форма правила `manual-dropdown`.** По синтаксическому дереву: элемент разметки (тег со
  строчной буквы), у которого в `className` есть класс `absolute`, стоит правой частью `&&`, а левая
  часть — идентификатор `open` или `…Open` (или цепочка `&&`, оканчивающаяся им). Признак `top-full`
  — не обязателен (см. сверку). Область — `dirs: ['features', 'shared']`: меню и поля `shared/` —
  первые, с кого ошибка расходится. `instead`: «выпадающий список — Radix `Popover` (с полем ввода)
  или `DropdownMenu` (пункты-действия), портал в body без `container` (docs/UI.md, «Слои над окном»)».
  - Альтернатива — «`absolute` + `top-full`/`bottom-full`» (issue) — отклонена: пропускает
    `PdfGroupingEditor`. Альтернатива — «`absolute` + `z-*` + `bg-surface`» — отклонена: ловит наложения
    при перетаскивании.
  - По разбору Архитектора (комментарий к #1537) закрыты два дешёвых обхода, оба — ноль срабатываний
    на сегодняшнем дереве: **`fixed`** наравне с `absolute` (первый способ «починить» обрезку, а в окне
    с `transform` он режется так же) и **тернарник** `open ? <div absolute> : null` (ветвь «да»).
  - ⚠️ Не видит список, открытый условием с другим именем (`showList &&`), слой во фрагменте или в
    отдельном компоненте. Это записывается в комментарий правила и в «Кто сторожит»; такие ловит ревью.
- **D3. Уровень.** После перевода `FieldBuilder` — два места: `features/templates/EditorPanel.tsx` (1),
  `features/datasets/PdfGroupingEditor.tsx` (1). До нуля его опускает #1538.
- **D4. Макетов нет.** Вид и место списка не меняются — меняются слой и клавиатура по уже принятому
  правилу «Слои над окном». Форма нового правила храповика — разбор с Архитектором комментарием к
  issue (правило — слой компонентов, `docs/UI.md`, «Новый экран: порядок», шаг 1), до PR.
- **D5. Редактор формулы — свой файл.** `ComputedFieldEditor` переезжает из `FieldBuilder.tsx` в
  `features/settings/ComputedFieldEditor.tsx` как есть, с поповером; `FieldBuilder` худеет, и уровень
  размера опускается по факту. Тест компонента — `ComputedFieldEditor.test.tsx`.
- **Сторож.**
  - `ui-ratchet.test.mjs`: формы сегодняшних мест и прежнего меню сохранения считаются (в том числе
    без `top-full`), как и цепочка `a && xxxOpen &&`, тернарник и `fixed`; `dragOver && <div
    className="absolute inset-0 …">`, `dragging &&`, `asking && …`, `md:absolute`, компонент с
    `absolute` — нет.
  - Живой прогон `types`: окно «Новый тип документа» → шесть полей, последнее расчётное → кнопка «+
    Вставить поле» у нижнего края видимой части тела окна → `elementFromPoint` в центре последнего
    пункта попадает в сам список; Esc — список закрыт, окно открыто, фокус на кнопке. Проверено, что
    на прежнем `absolute`-списке проверка красная обрезкой (в точке — затемнение под окном).
- **Чем ломается.** Список внутри окна снова в `container` — правило `portal-container`. Esc закрыл окно —
  живой прогон. Правило перестало видеть меню без `top-full` — тест храповика.

## Risks / Trade-offs

- [Поповер в портале, а щелчок по пункту — вне окна в DOM: окно сочтёт его промахом] → не сочтёт:
  слой лежит в дереве React окна, единственная копия слоёв Radix (`radix-single-copy.test.mjs`) — так
  работают `Select` и календарь в окне.
- [Признак по имени условия обходится переименованием] → цель правила — остановить привычный способ, а
  не злой умысел; ревью видит `absolute` у списка.
- [`FieldBuilder` правят и другие change (пометки — `sharedui-chip-badge-tabs-screens`, флаги строки
  поля — `work-24-customer-fields`)] → флажки и кнопки-иконки уже слиты; блок формулы уходит в свой
  файл целиком, остальные правят другие строки `FieldBuilder`.
