# Design: часть счёта раскрывается щелчком по всей шапке

Issue #1869. Решения D1–D5 — за владельцем. Их записывают сюда с датой ДО кода (tasks 0.1). Если выбран
не рекомендованный вариант, delta-спецификация и tasks правятся через `/opsx:update`.

## Context

`InvoicePart` (`features/costs/InvoicePart.tsx`) — карточка outlined без своей шапки (решение Э6,
06.11.2026). Шапку рисует сама часть, в одну строку:

```
[номер] [h3 заголовок] [строка-итог, flex-1, обрезается] [действия] [IconButton-шеврон]
```

- Переключает только `IconButton` с именем «Развернуть «…»» / «Свернуть «…»», `aria-expanded` и
  `aria-controls` на тело.
- Действия (`actions`) — свои кнопки части: «Сохранить» у «Сроков и оплаты», кнопка оплаты, «Всё
  верно (N)» у «Строк». Они видны и у свёрнутой части.
- В узкой части (`@container` уже `@md`) действия уходят строкой ниже (`order-last w-full`), а шеврон
  остаётся у заголовка.
- Тело свёрнутой части прячется (`hidden`), а не размонтируется: в нём живёт черновик строк.

Образец — `shared/ui/ListGroupHeader`: `<button aria-expanded>` на всю строку со `state-layer
state-layer-row`, шеврон внутри кнопки, действие группы (`action`) — сосед кнопки.

## Goals / Non-Goals

**Goals:**
- Любое место шапки, кроме действий, раскрывает и сворачивает часть.
- Видно, что шапка нажимаемая: слой состояния, курсор, фокус.
- Для диктора и клавиатуры — одна цель с прежним именем и `aria-expanded`.

**Non-Goals:**
- Не меняем раскладку шапки, состав частей, правила «какая часть открыта» и строки-итоги.
- Не заводим общий компонент в `shared/ui`: у `InvoicePart` пока один потребитель (как и в Э6).
- Не меняем `ListGroupHeader`.

## Decisions

### D1. Устройство цели — ОТКРЫТ, решает владелец

Рекомендация — **шаблон аккордеона WAI-ARIA с растянутой кнопкой**:

```
<section aria-label={title}>
  <div class="relative state-layer …">               ← слой состояния на всей шапке
    <h3>
      <button aria-expanded aria-controls={body} aria-describedby={line}
              class="… after:absolute after:inset-0">  ← ::after растягивает цель на всю шапку
        [номер] [заголовок]
      </button>
    </h3>
    <span id={line}>[строка-итог]</span>                ← под ::after: щелчок попадает в кнопку
    <div class="relative z-10">[действия]</div>        ← над ::after: щелчок — своему действию
    <Icon шеврон aria-hidden />                         ← декоративный, под ::after
  </div>
  <div id={body} hidden={!open}>…</div>
</section>
```

Почему так:
- `<button>` внутри `<h3>` — канонический аккордеон WAI-ARIA. Заголовок части остаётся заголовком для
  навигации диктора, а `<h3>` внутри `<button>` недопустим: в кнопке только строчное содержимое.
- Растянутый `::after` даёт цель во всю шапку, не трогая раскладку. Действия стоят над ним (`z-10`) и не
  вложены в кнопку: нажимаемое в нажимаемом запрещено и HTML, и MD3.
- В узкой части строка действий тоже оказывается под `::after`: щелчок мимо кнопок действий переключает
  часть. Это ожидаемо — вся плашка одна цель.

Отвергнутые варианты:
- **Вся строка — `<button>`, как в `ListGroupHeader`.** Шеврон тогда стоит перед действиями, а не у края,
  и раскладка меняется. А `<h3>` пришлось бы вынуть из кнопки.
- **`onClick` на `<div>` шапки + `IconButton` как сейчас.** Две цели одного действия: щелчок мышью
  по `div`, клавиатура — по шеврону. Обработчик на `div` должен отсеивать щелчки по действиям, а
  храповик `raw-state` и правила доступности такой `div` не пропускают.

### D2. Свёртка раскрытой части щелчком по шапке — ОТКРЫТ, решает владелец

Рекомендация — **да, симметрично**: щелчок по шапке раскрытой части её сворачивает. Так работает
`ListGroupHeader` и любой аккордеон. Данные не теряются: тело прячется, а не размонтируется.

Вариант — сворачивать только шевроном, а шапкой только раскрывать. Отвергается: одна цель с разным
поведением в двух состояниях — то, от чего уходим.

### D3. Имя и описание для диктора — ОТКРЫТ, решает владелец

Рекомендация — **имя прежнее**: «Развернуть «<заголовок>»» / «Свернуть «<заголовок>»» через
`aria-label`, строка-итог — описанием (`aria-describedby`). Видимый текст заголовка входит в имя (WCAG
2.5.3 «Label in Name»). Живые прогоны (`harness.mjs`, `invoice-screen-layout-checks`,
`invoice-terms-collapse-checks`) ищут кнопку по этому имени и не ломаются.

Вариант — имя по содержимому («1 Кто и сколько») и только `aria-expanded`. Так в `ListGroupHeader`.
Минус — правка всех прогонов и теста, и пропадает глагол, который сейчас слышит диктор.

### D4. Выделение текста строки-итога — ОТКРЫТ, решает владелец

Строка-итог окажется под растянутой целью, и выделить из неё текст мышью (номер счёта, сумму) станет
нельзя: щелчок переключает часть. Рекомендация — **принять**. Те же данные есть в полях части, а
полный текст обрезанной строки по-прежнему показывает подсказка (`fullTextIfCut` — на наведение, оно
не мешает).

### D5. Макеты — ОТКРЫТ, решает владелец

Правило `docs/UI.md` («Новый экран: порядок»): заметная переделка взаимодействия — три макета и выбор
владельца до кода. Рекомендация — **без макетов**: вид шапки не меняется (добавляется только слой
состояния), а взаимодействие повторяет готовый образец `ListGroupHeader`. Если владелец хочет макет —
один, состояния шапки: покой, наведение, фокус, нажатие; свёрнутая и раскрытая; широкая и узкая.

## Risks / Trade-offs

- **Нечаянная свёртка.** Щелчок мимо кнопки действия свернёт часть. Тело не размонтируется, набранное
  сохраняется — повторный щелчок возвращает как было.
- **Узкая часть.** Строка действий под растянутой целью: промахи мимо кнопок переключают часть. Проверить
  на 1024×768 рядом с файлом (tasks 1.3).
- **Слой состояния над действиями.** Наведение на кнопку действия подсвечивает и шапку. Проверить, что
  у кнопки действия свой слой виден поверх (tasks 1.3); если нет — слой шапки гасится при наведении на
  действия.
- **Параллельный change `costs-pay-action-label`** правит подпись кнопки оплаты в шапке «Сроков и оплаты».
  Файлы разные (`InvoicePayment.tsx` против `InvoicePart.tsx`), конфликта в коде нет. В спецификации
  этот change только ДОБАВЛЯЕТ требование и требование о свёртке не трогает.
