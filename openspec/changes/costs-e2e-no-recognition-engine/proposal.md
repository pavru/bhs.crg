# Proposal: живой прогон счетов не ходит к движку распознавания

Самостоятельный change модуля `costs`. Маленький: серверная половина задачи уже построена #1343.

## Why

Issue #1344 (живой прогон счетов отправляет поддельные PDF в настоящий движок распознавания; решение
владельца 15.10.2026 — задача вне этапа 2). `src/client/e2e/invoices-smoke.mjs` заводит из файлов шесть
счетов, внутри которых строка `%PDF-1.4 не настоящий …`, и на стенде с настроенным движком каждый уходил
настоящему Gemini: на дев-стенде с 8 октября накопилось около 280 ошибок «Распознавание недоступно:
Gemini ответил 400», похожих на сбой доступа к Gemini.

#1343 (PR #1398) построил проверку файла до движка (`Infrastructure/Recognition/RecognitionFileCheck.cs`):
нечитаемый PDF отказывает причиной `BadFile` словами `RecognitionFileCheck.Unreadable`, к движку не
уходит. Сверка показала, что «Готово» issue этим ещё не достигнуто:

- в модуле `costs` проверка файла стоит **после** проверки готовности: `InvoiceScanRecognition.StartAsync`
  сначала зовёт `IModuleRecognition.EnsureReadyAsync`, и на стенде без движка (CI) исход —
  `NotConfigured`, а не отказ о файле. Сторож issue («отказ — именно о файле, на любом стенде») так не
  выполним;
- на стенде с движком `EnsureReadyAsync` зовёт предполётную проверку ядра, а она умеет пробу зрения
  (`VisionProbe.IfUnknown`) — запрос к движку ради заведомо нечитаемого файла;
- проверка 9 прогона («счёт в Excel») нажимает «Распознать файл» на **исправном** PDF-образе книги — на
  стенде с движком это настоящий платный запрос;
- прогон сверяет «любой отказ» (`/Файл не распознан: /`), а не отказ о файле.

## What Changes

- **Сервер, `costs`.** Запуск распознавания проверяет файл **первым** — до проверки готовности движков:
  нечитаемый PDF даёт исход `BadFile` при любых настройках, и ни предполётной проверки, ни движка не
  трогает. Проверку модуль получает портом ядра (`IModuleRecognition`), правило — то же
  `RecognitionFileCheck`.
- **Прогон, проверка 7** («счёт из скана»): форма называет именно отказ о файле («сам файл не
  читается»), строка списка — «файл не читается»; слов «не настроено» и «недоступно» на форме нет.
- **Прогон, проверки 8 и 8а** (пачка, повтор): содержимое не проверяется, но исход каждого черновика —
  тот же отказ о файле, а не запрос к движку; отдельной сверки слов не нужно.
- **Прогон, проверка 9** («счёт в Excel»): на стенде с настроенным движком «Распознать файл» не
  нажимается — пропуск назван строкой прогона; на стенде без движка (CI) проверка прежняя.
- Остальные прогоны, заводящие счета из файла, сверены: запуска распознавания у них нет (см. design).

## Capabilities

### New Capabilities
- Нет.

### Modified Capabilities
- `costs`: требование `[COST-8]` получает сценарий «нечитаемый файл — отказ о файле до движков и до
  проверки их готовности».

## Impact

- **Сервер:** `Modules.Costs/Endpoints/InvoiceScanRecognition.cs` (порядок в `StartAsync`),
  `BHS.CRG.Modules/Ports/IModuleRecognition.cs` и `Api/Modules/Ports/ModuleRecognitionPort.cs` (проверка
  файла портом).
- **Тесты:** `Integration/InvoiceFromScanTests.cs` — нечитаемый PDF при ненастроенном движке даёт `BadFile`;
  `Integration/ModuleRecognitionPortTests.cs`.
- **Прогон:** `src/client/e2e/invoices-smoke.mjs`, проверки 7–9.
- **Клиент приложения:** не меняется (`features/costs/recognition.ts` уже знает `BadFile`).
- Накопленные ошибки в колокольчике дев-стенда — не задача кода (issue, «Чем ломается»).
