# Proposal: карточка позиции не сдвигает список окна выбора

## Why

Находка ревью PR #1760 (`sharedui-md3-17-screens`, PR 4, развилка Р9), оставленная там без правки: её
решает макет, а значит, владелец. Issue нет, change заведён по решению владельца вынести находку с
исследованием.

На столе карточка позиции в окне выбора номенклатуры (`NomenclaturePicker.tsx`) — `SideSheet standard`
шириной 400. Лист открывается по выделенной строке, а строку выделяют и стрелки, и мышь: достаточно
постоять над строкой около 150 мс (`HOVER_REST`). Без листа список во всю ширину окна, около 896 px. С
листом список сужается до 496: строки переносятся, и под неподвижным курсором оказывается другая строка.
Малейшее движение мыши выделяет уже её, и лист показывает не ту позицию, которую человек читал. Закрытие
листа крестиком снова раздвигает список, и следующее движение мыши открывает лист заново.

Макет md3-17 (Claude Design, проект `4f525fa0`, вариант А «MD3 буквально») показывает только состояние с
открытым листом. Переход между состояниями в нём не нарисован, поэтому скачок прошёл и выбор владельца, и
ревью.

## What Changes

- **Исследование (раздел 0 задач)** сравнивает:
  - что предписывает MD3 для list-detail и side sheet;
  - как устроено выделение в окне (`usePickerSelection`, `dismissed`);
  - варианты: лист только по явному действию, место под лист всегда, лист поверх списка, «оставить как
    есть», сторож наведения, строки в одну линию, окно, растущее на ширину листа.

  Разбор — в `design.md`.
- **Три макета в Claude Design** — три разных решения: рекомендованное и два сильнейших других. Выбирает
  владелец (`docs/UI.md`, «Новый экран: порядок»). Код пишется только после выбора.
- **Инвариант, общий для всех рассматриваемых решений**, кроме «оставить как есть», записан требованием
  [COST-7]. Строка под мышью не сменяется сама, когда карточка открывается или закрывается. Подробности
  выбранного варианта вносятся `/opsx:update` после выбора.
- **Код** — одна правка окна выбора на столе по выбранному макету, с тестами выделения. Узкое окно, где
  карточка открывается шагом `WindowStep`, не меняется.
- Если владелец оставит как есть, change закрывается без кода. Требование и задачи кода тогда снимаются
  `/opsx:update`, а в `docs/UI.md` записывается, почему скачок принят.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `costs`: добавлено требование [COST-7] о том, что карточка позиции в окне выбора не уводит строку из-под
  мыши. Если выбран вариант, меняющий сценарий «Карточка номенклатуры» требования [UI-81] (лист без
  крестика или не side sheet), в change добавляется дельта `sharedui`. Её вносят `/opsx:update` после архива
  `sharedui-md3-17-screens`: до архива требования [UI-81] нет в `openspec/specs/sharedui/spec.md`, и
  изменять его нечем.

## Impact

- Клиент:
  - `src/client/src/features/costs/NomenclaturePicker.tsx` — раскладка тела окна и условие открытия листа;
  - `pickerSelection.ts` — выделение наведением;
  - `PickerRows.tsx` — строка списка;
  - тесты `pickerSelection.test.ts` и e2e окна выбора, если вариант их касается.
- `shared/ui` — только если выбран вариант с постоянной панелью без крестика или с окном шире `max-w-4xl`.
  Тогда в разборе участвует Архитектор (`docs/UI.md`, шаг 1).
- Сервер, API и база не затронуты.
- PR кода — с метками `version:minor` и `ui`. PR этого планирования — с меткой `ui`. `<Version>` не
  трогаем.
