# Design: загрузка выгрузки 1С файлом и папкой — заготовка

Change-заготовка по issue #1084 (D3 этапа 2). Отложен решением владельца 05.10.2026. Здесь — граница,
решения и известное по коду; разбор формата не проектируется до образцов (задача 0.1).

## Context

Сверено по коду ветки `openspec/open-issues-changes` (master `c9586405`), 22.10.2026.

**Решения, которые этот change переносит без потерь.**
- `COST-Q12`, решено 18.09.2026 — вариант А+Б: выгрузка 1С файлом (XML или XLSX, вручную или по
  расписанию) — основной путь накладных своего склада; распознавание остаётся для сканов; второй профиль
  распознавания «Расходная накладная» вынесен в `STG-14` (возвращается, когда появятся сканы накладных,
  которых 1С не отдаёт).
- `COST-4.1`: у документа и у позиции номенклатуры — необязательный внешний идентификатор (система и
  код); повторная загрузка по нему не создаёт дубликат; номер и дата хранятся как в источнике.
- `COST-8`, Ревизия 18.09.2026: загрузка вручную файлом или из заданной папки на сервере (по расписанию —
  если так настроено при установке); накладная из 1С — сразу проведённая, с источником в журнале; итог —
  «загружено / пропущено / без номенклатуры»; сбой по расписанию — уведомлением.
- `COST-16`: накладная, загруженная из 1С после закрытия с датой отпуска в закрытом месяце, получает
  учётным периодом первый открытый день и пометку «введена после закрытия»; в итоге загрузки такие
  накладные — отдельной строкой.
- **Решение владельца 05.10.2026** (комментарий issue): задача отложена; накладные вводятся только вручную
  (D1, #1083); правило «из 1С — проведённой, с несопоставленными строками» в коде уже учтено и остаётся
  заделом; ключи настроек «папка и расписание загрузки 1С» (M1, #1070) уходят вместе с задачей; поиск и
  постраничность списка накладных на сервере (предел 300 с предупреждением) отдельной задачи не имеют.
- **Решение владельца 18.10.2026** (комментарий issue, эпик #1496): сумма строки счёта в системе всегда
  с НДС в обоих режимах, сумма с бумаги — отдельно (`net_amount`). Выгрузке по умолчанию отдавать суммы с
  НДС и НДС строк («сумма включает НДС» = да) — режим ей знать не нужно; бумажный вид без НДС — только по
  просьбе бухгалтерии заказчика. Относится к обмену счетами с 1С, если интеграция его получит.

**Что выяснилось сверкой.**
- `docs/tz/90-этапы.md`, `STG-14`: «загрузка файла выгрузки 1С входит в этап 2, `COST-8`» — устарело после
  решения 05.10.2026 (статус того же файла уже пишет #1084 хвостом этапа 2). Задача 0.3.
- **Внешнего идентификатора нет нигде, кроме стройки.** `Construction.ExternalSystem/ExternalCode`
  (`Domain/Documents/Construction.cs:34`, `COST-Q11`, `CORE-5`) есть; у `Waybill`, `Invoice` и записи
  номенклатуры — нет. `COST-4.1` требовал «сразу», построено только для стройки.
- **Задел проведённой накладной есть:** `Waybill.Match` — «единственная правка строки, разрешённая
  проведённой накладной: накладная из 1С приходит проведённой и с несопоставленными строками»
  (`Data/Waybill.cs:213-220`); `WaybillEndpoints.cs:22` — то же исключение у адреса сопоставления.
- **Право уже обещает загрузку:** описание `costs.waybill.edit` — «вводить, проводить и удалять накладные…,
  загружать машиночитаемую выгрузку 1С» (`CostsModule.cs:155-160`), а загрузки нет. Человек, ставящий
  галку, читает обещание несуществующего.
- **Порта расписания у модуля нет** (`BHS.CRG.Modules/Ports/`: `IModuleJobs` — фоновая задача, без
  расписания); `IModuleNotifications` есть.
- Учётная дата и замок периода у накладной построены (`WaybillLock`, решение 11.10.2026) — загрузка
  получает их даром.

## Goals / Non-Goals

**Goals:** записать границу и решения так, чтобы задача стартовала с образцов, а не с пересказа issue;
зафиксировать требования, не зависящие от формата.

**Non-Goals:**
- формат выгрузки, разбор XML/XLSX, сопоставление кодов номенклатуры 1С — до образцов (0.1);
- полная интеграция с 1С:УНФ/УНСФ (номенклатура, счета, стройки, обмен в обе стороны) — `STG-14`;
- второй профиль распознавания «Расходная накладная» — `STG-14`;
- поиск и постраничность списка накладных на сервере — отдельной задачи нет (решение 05.10.2026).

## Decisions

- **D1. Формат не выдумывается.** Ни одной задачи по разбору до образцов XML и XLSX от заказчика. Образцы
  ложатся в тестовые данные (по примеру `src/server/BHS.CRG.Tests/TestData/GrandSmeta/`, `PLAN-Q19`), разбор
  проектируется по ним; неизвестная версия формата — отказ с названием, а не пустой результат (как
  `STG-12` у ГРАНД-Сметы).
- **D2. Идемпотентность — по внешнему идентификатору документа**, уникальному в паре «система, код»
  (как у стройки: `IX_constructions_ExternalSystem_ExternalCode`). Не по имени файла и не по пути: один
  документ приходит и файлом, и из папки.
- **D3. Итог — три числа с документами** («загружено / пропущено / без номенклатуры»); «введены после
  закрытия» — отдельной строкой (`COST-16`). Итог долгой загрузки — исход фоновой задачи (`IModuleJobs`),
  ход — поллингом `GET /api/jobs/active`.
- **D4. Сбой по расписанию — уведомление** через `IModuleNotifications` получателям с правом загрузки.
  Порт расписания модуля — работа ядра этой задачи (или этапа интеграции).
- **D5. Ворота.** Право — `costs.waybill.edit` (его описание уже называет загрузку) или своё у модуля
  интеграции — по решению 0.2. `If-Match` не нужен: загрузка заводит новые записи, повтор сторожит
  внешний идентификатор (названное исключение правила config.yaml).
- **D6. Где живёт загрузка — решение 0.2.** (а) модуль `costs`: накладная и её замок там, ничего не
  передаётся через контракт; (б) отдельный модуль интеграции с 1С, обслуживающий и номенклатуру, и
  счета, и стройки (`COST-8`: «возможно отдельным модулем, который обслуживает все остальные»): `costs`
  получает накладные контрактом. Рекомендация — решать вместе с составом этапа интеграции: если в нём
  только накладные — (а); если номенклатура и счета тоже — (б).

## Risks / Trade-offs

- [Обещание в описании `costs.waybill.edit` читается как готовое] → убрать слова о выгрузке из описания
  права до появления загрузки (задача 0.4) — отдельной мелкой правкой, независимо от этапа.
- [Внешний идентификатор заводится позже, чем приходят первые данные из 1С] → колонки идентификатора у
  накладной и номенклатуры — первая задача реализации, до разбора.
- [Образцы одной версии конфигурации 1С] → версия формата пишется с загрузкой; другая версия — отказ.

## Open Questions

  (EnterpriseData / свой), XLSX, оба. Без ответа задача не стартует.
- **В-2 (0.2).** Модуль `costs` или отдельный модуль интеграции (D6). Рекомендация — по составу этапа.
