# Spec Delta: types-and-tags

## MODIFIED Requirements

### Requirement: Схема типа
Схема SHALL быть объектом `{ "fields": [...], "groups": [...] }`. У поля — ключ, подпись, вид
(`string`, `text`, `number`, `date`, `boolean`, `enum`, `primitive`, `file`, `image`, `complex`,
`array`, `doc-ref`, `doc-array`), ссылка на тип (`typeId`), обязательность, тэги, при необходимости
расчётность (`computed` с выражением), признак «нужно к приёмке» (`forAcceptance`) и метки `origin` /
`locked`. Куски схемы MUST сравниваться по смыслу, а не текстом.

#### Scenario: Схема из jsonb и из тела запроса
- **WHEN** сохраняется схема, прочитанная из `jsonb` с пробелами Postgres, против компактной из тела запроса
- **THEN** одинаковые по смыслу поля не считаются изменёнными

## ADDED Requirements

### Requirement: [WORK-53] [CORE-19] Признак поля «нужно к приёмке»
Признак `forAcceptance` SHALL ставиться только на поле заказчика у типа, чей модуль объявил приёмку;
такой тип отдаёт в ответе чтения `acceptanceFields: true`. Признак MUST NOT делать поле обязательным и
MUST NOT мешать сохранению черновика. На расширяемом уровне его можно ставить и снимать у своих полей.
Признак у поля модуля, у расчётного поля или у типа без приёмки — отказ сохранения схемы с названием
поля.

#### Scenario: Поле заказчика в сведениях строки
- **WHEN** администратор добавляет в `СтрокаРаботы.Сведения` необязательное поле «Номер акта скрытых работ» с `forAcceptance: true`
- **THEN** схема сохраняется, а поле остаётся необязательным

#### Scenario: Признак у поля модуля
- **WHEN** администратор ставит `forAcceptance` полю, заведённому модулем
- **THEN** сохранение отклоняется: признак полей модуля задаёт модуль

#### Scenario: Тип без приёмки
- **WHEN** администратор ставит `forAcceptance` полю типа `СчётНаОплату` или типа документа ИД
- **THEN** сохранение отклоняется с причиной «у типа нет приёмки», а не принимается молча

#### Scenario: Расчётное поле
- **WHEN** у поля с `computed: true` стоит `forAcceptance`
- **THEN** сохранение отклоняется: расчётное поле не заполняют

#### Scenario: Закрытый тип
- **WHEN** у типа уровня `Closed` администратор меняет `forAcceptance` у любого поля
- **THEN** сохранение отклоняется: в закрытом типе администратору остаётся подпись

#### Scenario: Носитель для редактора
- **WHEN** редактор типов читает `СтрокаРаботы.Сведения` и `Сотрудник`
- **THEN** у первого `acceptanceFields: true`, у второго `false`, и колонка признака рисуется только у первого
