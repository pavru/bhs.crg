# Обмен своими отчётами и фактическая доставка

## Context

Полевые операции v1, существующие ReportWriter, ReportDesk, ReviewMarks, журнал отчёта и очередь приёмки. Опоры и границы описаны в [эпике](../mob-00-epic/design.md). Условие старта — [mob-02-device-sessions](../archive/2026-11-28-mob-02-device-sessions/tasks.md).

## Goals / Non-Goals

Офис должен увидеть один отчёт после повторной отправки и различать момент работы и доставки. На телефоне нужен результат приёмки, возврата или ввода за монтажника. Объём и наблюдаемый результат закреплены в [дельте field](specs/field/spec.md).

## Decisions

Использовать существующие id отчёта и строк, changeId, версию и серверную последовательность Work. Проверять повтор до конфликта версии после проверки владельца. Подтверждённая правка записи менеджера использует текущую версию и сохраняет авторство в журнале. Пометки времени выводить из обеих временных отметок и окна подачи, показывать причину и величину отклонения.

Перед вызовом ReportWriter полевой адаптер сопоставляет строки по id и сохраняет текущие Details, которые отсутствуют в мобильном договоре. Проверка If-Match и запись проходят в одной операции, повтор changeId сохраняет существующий договор. Полевая правка не передаёт null как команду очистки веб-полей. Дополнительно проверяется минимальная версия приложения из сведений MOB-01 с отдельным кодом client-outdated.

## Risks / Trade-offs

Новый запрос со старой версией и повтор уже применённого действия различать до записи. Проверить последовательность после веб-правки и конкурирующей доставки.
