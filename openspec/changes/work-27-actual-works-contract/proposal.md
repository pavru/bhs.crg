# Proposal: контракт «Фактические работы» — поставщик `work`

Дочерний change зонтика `work-00-epic`, общая архитектура — `../work-00-epic/design.md` (D3, D4, D13).
Стартует после этапа 3.

## Why

Принятые объёмы нужны графику (`PLAN-18`), «Ходу работ» (`PLAN-21`), а позже ИД и ОЖР. Модули не
ссылаются друг на друга (`CORE-2`), поэтому объёмы идут контрактом ядра (`CORE-34`). Этот контракт
обязан не выпустить из модуля две вещи:
- часы и людей (`WORK-57`): часы указаны на отчёт целиком, и по позиции они были бы выдумкой (`WORK-7`);
- удвоенный бригадный объём (`WORK-19`).

Право `work.facts.read` по `WORK-45` есть у «Менеджера проекта», а в составе роли его нет
(`SystemRoles.cs:66-72`). Объявленное обычным правом, оно открыло бы Инженеру ИД пустой «Учёт работ».

## What Changes

- Модуль `work` реализует контракт «Фактические работы»:
  - принятые объёмы по позиции перечня, дате, смене и разделу;
  - бригадная работа — итогом записи группы (`work-18`);
  - без часов и без сотрудников;
  - не вошедшее названо числом: ждут приёмки, бригадные группы не сверены.
- Объявляется `work.facts.read` — **право контракта** (D3, `work-02`). Право получают Инженер ИД,
  Производитель работ и Менеджер проекта; последнему его дописывают в состав роли. Модуль `work` оно
  не открывает.
- Факты отдаются по всем стройкам, без построчной изоляции: изолируются отчёты, а не принятый факт
  (`WORK-39`).
- Колонка «факт по учёту» в «Ходе работ» — часть `work` по механизму колонок этапа 3 (`PLAN-21`).

## Capabilities

### New Capabilities
- Нет.

### Modified Capabilities
- `core`: контракт «Фактические работы» — форма ответа без часов и людей, «не подключено», «скрыто
  правами».
- `work`: поставщик контракта, право контракта `work.facts.read`, колонка «Хода работ».

## Impact

- **Контракты:** `src/server/BHS.CRG.Modules/Exchange/IActualWorks.cs` — интерфейс и форма ответа.
  Каталог `Exchange/` заводит этап 3 или `work-09` (D13).
- **Сервер:** `src/server/BHS.CRG.Modules.Work/Exchange/ActualWorksProvider.cs`, регистрация в
  `WorkModule.RegisterServices`; объявление права; `src/server/BHS.CRG.Api/Auth/SystemRoles.cs`
  (состав «Менеджера проекта»).
- **Тесты:** `src/server/BHS.CRG.Tests/Work/ActualWorks*`, тест состава `/api/account/access` по ролям.
- **Зависит от:** этап 3 (механизм контракта, позиции перечня, экран «Ход работ»), `work-02` (право
  контракта), `work-13`, `work-16` (принятые), `work-18` (итог группы), `work-19` (действующая версия).
