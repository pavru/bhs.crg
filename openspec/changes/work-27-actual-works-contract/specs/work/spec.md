# Spec Delta: work

## ADDED Requirements

### Requirement: [CORE-34] [PLAN-18] Модуль `work` — поставщик «Фактических работ»
Включённый модуль `work` SHALL реализовывать контракт «Фактические работы». В ответ входят только строки
принятых отчётов, в их действующей версии, сгруппированные по позиции перечня, дате, смене и разделу.
Дата строки — дата отчёта по поясу стройки, а не момент доставки.

#### Scenario: Только принятые
- **WHEN** на стройке за день один отчёт принят, один подан и один черновик
- **THEN** контракт отдаёт объёмы только принятого отчёта

#### Scenario: Ночная смена
- **WHEN** отчёт ночной смены 31.10 принят, а доставлен 01.11
- **THEN** его объём приходит с датой 31.10 и сменой «ночь»

#### Scenario: Исправление закрытого периода
- **WHEN** принятый отчёт закрытого периода исправлен новой версией с причиной
- **THEN** контракт отдаёт объём действующей версии, а не сумму версий

### Requirement: [WORK-19] Бригадная работа — итогом группы
Бригадные строки SHALL входить в ответ один раз на группу — утверждённым итогом записи группы, а не
суммой строк участников. Группа без утверждённого итога или с итогом, требующим решения, MUST NOT давать
объёма.

#### Scenario: Группа из трёх строк
- **WHEN** в бригадной группе три принятые строки 120, 120 и 100 м, а утверждённый итог — 120 м
- **THEN** контракт отдаёт по этой позиции, дате и смене один объём 120 м

#### Scenario: Итог не утверждён
- **WHEN** у группы с принятыми строками итога нет
- **THEN** объёма группы в ответе нет, а группа учтена в «не включены»

### Requirement: [WORK-57] [CORE-34] Не вошедшее названо числом
Ответ SHALL нести по запрошенному отбору счётчики того, что не вошло: отчётов, ждущих приёмки,
бригадных групп без утверждённого итога и принятых строк без позиции перечня. Счётчики MUST считаться контрактом по всему отбору и MUST NOT
называть сотрудников.

#### Scenario: Занижение видно
- **WHEN** график спрашивает факты стройки за октябрь, где 5 отчётов ждут приёмки и 2 группы не сверены
- **THEN** ответ несёт «не включены: 5 ждут приёмки, 2 бригадные работы не сверены» без имён

### Requirement: [WORK-48] [AUTH-8.1] `work.facts.read` — право контракта
Модуль SHALL объявлять `work.facts.read` как право контракта с объяснением «принятые объёмы по всем
стройкам, без часов и сотрудников». Право MUST NOT открывать модуль `work`: ни ворота, ни навигацию, ни
адреса `/api/work`. Право получают Инженер ИД, Производитель работ и Менеджер проекта.

#### Scenario: Инженер ИД
- **WHEN** пользователь с ролью «Инженер ИД» запрашивает `/api/account/access`
- **THEN** у него есть `work.facts.read`, а модуль `work` приходит с `available: false`

#### Scenario: Адрес модуля
- **WHEN** пользователь только с `work.facts.read` вызывает любой адрес `/api/work`
- **THEN** ответ 403, как у пользователя без прав модуля

#### Scenario: Состав ролей
- **WHEN** экземпляр стартует с модулем `work`
- **THEN** «Менеджер проекта» получает `work.facts.read` вместе со своими правами модуля, состав остальных ролей по `/api/account/access` совпадает с ожидаемым

### Requirement: [WORK-39] Факты — без построчной изоляции
Держатель `work.facts.read` SHALL получать принятые объёмы всех строек одинаково, независимо от своих
назначений. Изоляция отчётов MUST NOT применяться к ответу контракта, потому что в нём нет ни отчётов,
ни людей.

#### Scenario: Менеджер чужой стройки
- **WHEN** менеджер, назначенный только на стройку А, спрашивает факты стройки Б через «Ход работ»
- **THEN** объёмы стройки Б приходят, а отчёты стройки Б ему по-прежнему не видны (404)
