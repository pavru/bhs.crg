# Spec Delta: core

## ADDED Requirements

### Requirement: [CORE-34] [WORK-57] Контракт «Фактические работы»
Ядро SHALL объявлять в контрактах модулей контракт «Фактические работы»: принятые объёмы по позиции
перечня, дате, смене и разделу стройки, с единицей. Форма ответа MUST NOT содержать ни часов, ни
сотрудников, ни других сведений, по которым их можно восстановить. Потребитель получает контракт без
ссылки на модуль-поставщик.

#### Scenario: Форма ответа
- **WHEN** потребитель читает строку ответа контракта
- **THEN** в ней позиция перечня, дата, смена, раздел, объём и единица — и нет полей часов, сотрудника, автора или отчёта

#### Scenario: Ссылка на поставщика
- **WHEN** проект потребителя ссылается на проект модуля `work`, чтобы получить факты
- **THEN** `ModuleBoundaryTests` падает

### Requirement: [CORE-34] [PLAN-18] Поставщик выключен — «не подключено»
Если модуль-поставщик выключен, контракт SHALL отвечать состоянием «не подключено», а не пустым списком.
Потребитель MUST показывать это словами, а не нулями.

#### Scenario: Экземпляр без учёта работ
- **WHEN** модуль `work` выключен, а график спрашивает факты стройки
- **THEN** контракт отвечает «не подключено», и график говорит «учёт работ не подключён», а не «факт: 0»

### Requirement: [CORE-34] Контракт отвечает в правах спрашивающего
Контракт SHALL принимать явный параметр доступа того, кто спрашивает, и отвечать в его правах. Без
права `work.facts.read` ответ MUST быть состоянием «скрыто правами», а не пустым списком или нулями.

#### Scenario: Сметчик без права на факты
- **WHEN** пользователь без `work.facts.read` открывает экран, который спрашивает факты
- **THEN** контракт отвечает «скрыто правами», экран пишет «часть данных скрыта правами»

#### Scenario: Фоновое задание
- **WHEN** контракт вызывает задание от имени системы
- **THEN** параметр доступа несёт «система» с причиной, а не права случайного пользователя
