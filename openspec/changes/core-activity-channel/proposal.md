# Proposal: канал действия в журнале — интерфейс или агент через MCP

## Why

Issue #1336 (найдено Архитектором 15.10.2026; решение владельца — задача вне этапа 2, готовит почву
ИИ-ассистенту). Журнал действий не говорит, каким путём сделано действие: у `ActivityRecord` есть кто,
что, над чем и «было/стало», но нет канала. MCP открыт уже сейчас (`docs/ADMIN_GUIDE.md` §10): внешний
агент с токеном сотрудника действует от его имени, и потом не разобрать, что сделал человек, а что —
агент.

Сверка с кодом уточняет картину. Ни один из семи меняющих инструментов MCP (`generate_document`,
`assemble_document_set`, `recognize_dataset`, `recognize_source`, `report_observation`,
`retract_observation`, `propose_alias`) **в журнал не пишет вовсе** — ни из MCP, ни из интерфейса:
выпуска PDF, распознавания, замечаний и алиасов нет в каталоге `ActivityActions`. Значит, одной колонки
канала мало: действие агента в журнале сегодня не видно ни с каким каналом. Что именно о нём
записывать, решил владелец 22.10.2026 — вариант А (design, «Открытые вопросы», В1).

## What Changes

- **Канал у каждой записи журнала:** `ui` (интерфейс и API по токену), `mcp` (агент через MCP),
  `system` (сам экземпляр: старт, расписание, задача без заказчика). Позже — «ассистент».
- **Канал знает контекст, а не параметр вызова.**
  - Писатель журнала канал не передаёт. `IActivityActor` определяет его по адресу запроса: метаданные
    адреса `/mcp` означают канал `mcp`.
  - Фоновая задача несёт канал и автора того запроса, который её поставил, и в своей области
    выполнения пишет журнал от его имени.
  - Новый писатель забыть канал не может.
- **Действие агента видно в журнале** — вариант А (решение владельца 22.10.2026): одна
  запись на каждый удавшийся вызов меняющего инструмента MCP пишется одним фильтром вызовов
  MCP-сервера, с названием инструмента и целью.
- **Отбор журнала по каналу:** `GET /api/activity?channel=…`. На экране `/activity` — второй отбор
  рядом с отбором по действию и пометка «через агента (MCP)» у записи.
- **Старые записи** получают канал миграцией по автору: без автора — `system`, с автором — `ui`. Это
  не догадка: до этого change ни один путь MCP журнал не писал (сверено по коду).
- **Копия переносит канал.** Запись копии старой версии без канала читается тем же правилом, что и
  миграция.

## Capabilities

### New Capabilities
- Нет.

### Modified Capabilities
- `core`: запись журнала действий несёт канал; отбор по каналу; действие агента через MCP видно в журнале.

## Impact

- **Сервер:**
  - `Domain/Activity/ActivityRecord.cs` — колонка `Channel`;
  - `Application/Activity/IActivityActor.cs` — `ActivityActor` с каналом;
  - `Api/Activity/HttpContextActivityActor.cs`;
  - `Api/Configuration/EndpointMap.cs:55` — метаданные канала на `MapMcp`;
  - `Infrastructure/Activity/ActivityLog.cs` — запись, отбор, импорт;
  - `Api/Endpoints/Activity/ActivityEndpoints.cs`;
  - `Domain/Jobs/Job.cs` и `Infrastructure/Jobs/JobService.cs`, `JobBackgroundService.cs` — канал и
    автор задачи;
  - при варианте А — фильтр вызовов в регистрации MCP (`ServiceRegistration.Domain.cs`) и действие
    `core.mcp.tool.called` в `ActivityActions`.
- **Миграции ядра (`AppDbContext`):** `activity_log."Channel"` с заполнением по автору; `jobs."Channel"`.
- **Копия:** `BackupActivityRecord` получает `Channel`, сторож — `BackupManifestCoverageTests`.
- **Клиент:** `features/settings/ActivityPage.tsx`, `shared/api` (тип записи, параметр отбора).
- **Зависит от** `core-mcp-gate-inventory`: сторож перечисляет меняющие инструменты его описью.
