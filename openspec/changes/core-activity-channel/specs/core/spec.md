# Spec Delta: core

## MODIFIED Requirements

### Requirement: [CORE-28] [CORE-28.1] Журнал действий
Журнал действий SHALL быть одной службой ядра (`activity`, адреса `/api/activity` под правом
`core.audit.read`). Запись несёт время, код действия из каталога, автора и цель снимком имени, прежнее
и новое значение и канал: `ui` (интерфейс и API), `mcp` (агент через MCP) или `system` (сам экземпляр).
Канал служба берёт из контекста действия, а не у вызывающего; записи MUST только дописываться.

#### Scenario: Попытка правки записи
- **WHEN** код пытается изменить или удалить запись журнала
- **THEN** `SaveChanges` отвергает это, а обращения к набору перечисляет `ActivityLogInventoryTests`

#### Scenario: Смена ролей
- **WHEN** администратор меняет роли пользователя
- **THEN** после удавшегося действия журнал получает запись с прежним составом ролей

#### Scenario: Действие в интерфейсе
- **WHEN** сотрудник меняет роль пользователя в интерфейсе
- **THEN** запись журнала несёт канал `ui` и его имя автором

#### Scenario: Действие системы
- **WHEN** при старте замечена смена состава модулей
- **THEN** запись журнала несёт канал `system` и автора «Система»

#### Scenario: Фоновая задача
- **WHEN** фоновая задача, поставленная запросом через MCP, пишет журнал
- **THEN** запись несёт канал `mcp` и автором — сотрудника, от имени которого задачу поставили

#### Scenario: Записи до появления канала
- **WHEN** экземпляр обновляется до версии с каналом, или восстанавливается копия, снятая до неё
- **THEN** записи без автора получают канал `system`, остальные — `ui`

## ADDED Requirements

### Requirement: [CORE-23] [CORE-28] Действие агента через MCP видно в журнале
Каждый удавшийся вызов меняющего инструмента MCP SHALL оставлять запись журнала с каналом `mcp`,
автором — владельцем токена, и названием инструмента. Запись MUST делать один общий механизм
MCP-сервера, а не код каждого инструмента. Неудавшийся вызов записи не оставляет.

#### Scenario: Агент выпускает документ
- **WHEN** агент с токеном сотрудника вызывает `generate_document`, и выпуск удаётся
- **THEN** журнал получает запись с каналом `mcp`, автором — этим сотрудником и названием инструмента

#### Scenario: Новый меняющий инструмент
- **WHEN** в MCP зарегистрирован новый инструмент без пометки «только чтение»
- **THEN** его удавшийся вызов пишет журнал без правки кода инструмента, и сторож, берущий перечень из регистрации, это проверяет

#### Scenario: Читающий инструмент
- **WHEN** агент вызывает инструмент с пометкой «только чтение»
- **THEN** журнал не пишется

#### Scenario: Вызов отказал
- **WHEN** меняющий инструмент отвечает ошибкой или отказом прав
- **THEN** журнал не пишется

### Requirement: [CORE-28] Отбор журнала по каналу
`GET /api/activity` SHALL принимать необязательный отбор `channel` (`ui`, `mcp`, `system`) вместе с
отбором по действию и отдавать канал в каждой записи. Экран журнала MUST показывать отбор по каналу и
помечать записи, сделанные агентом.

#### Scenario: Только действия агента
- **WHEN** пользователь с `core.audit.read` запрашивает журнал с `channel=mcp`
- **THEN** в ответе только записи канала `mcp`, а счётчик записей считает по тому же отбору

#### Scenario: Неизвестный канал
- **WHEN** запрос называет канал, которого нет
- **THEN** ответ — 400 с перечнем допустимых значений

#### Scenario: Без права на журнал
- **WHEN** пользователь без `core.audit.read` запрашивает журнал с отбором по каналу
- **THEN** ответ — 403
