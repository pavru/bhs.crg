# Proposal: межмодульный контракт и «Материалы на объекте» у `costs`

Дочерний change зонтика `work-00-epic`, общая архитектура — `../work-00-epic/design.md` (D13, D3, D4).

## Why

Модули читают данные друг друга только через контракты ядра, и при выключенном поставщике потребитель
говорит «не подключено», а не показывает пустоту (`CORE-34`, `OVW-12`). Первый контракт этапа —
«Материалы на объекте»: монтажнику в поле «применённые материалы» предлагается отпущенное на его
стройку (`WORK-5.1`, `COST-18`), узким правом `costs.materials.hint` — номенклатура без количеств и без
набора данных (`WORK-48`, Р-3). Сегодня перечень — внутренняя модель `costs`
(`Modules.Costs/Data/IssuedMaterials.cs`), наружу она не выходит, а право `costs.materials.read`
сознательно не объявлено «до первого потребителя» (`Modules.Costs/CostsModule.cs:79-83`), хотя уже
стоит в составах «Инженера ИД» и «Менеджера проекта» (`Api/Auth/SystemRoles.cs:59,72`). Без контракта
потребитель позвал бы `GET /api/costs/materials` по HTTP — мимо прав и мимо «не подключено».

**Условие.** Механизм естественно рождается в этапе 3 («Плановые работы» берёт `costs`). Если этап 3 его
завёл, PR 1 отпадает, а core-дельта сверяется с его спецификацией.

## What Changes

- **PR 1 — механизм** (если его нет). Интерфейс контракта — в `BHS.CRG.Modules/Exchange/*` с названием
  модуля-поставщика; реализацию регистрирует поставщик в своём `RegisterServices`. Потребитель получает
  контракт портом ядра: «не подключено» — ответом, а не исключением. Контракт принимает явный параметр
  доступа (`work-07`) и отвечает в правах спрашивающего. Сторожа при старте: не больше одного поставщика
  на контракт; включённый поставщик без реализации — отказ; реализацию регистрирует только названный
  модуль.
- **PR 2 — поставщик `costs`.** Контракт «Материалы на объекте» над `IssuedMaterials`: по
  `costs.materials.read` — позиции с количествами, датами и числом не вошедших строк; по
  `costs.materials.hint` — только позиции номенклатуры. Оба права объявляются **правами контракта**
  (`work-02`): модуль `costs` и его навигацию они не открывают. «Монтажник» получает
  `costs.materials.hint`.

## Capabilities

### New Capabilities
- Нет.

### Modified Capabilities
- `core`: межмодульный контракт — объявление, регистрация у поставщика, «не подключено», ответ в
  правах спрашивающего.
- `costs`: поставщик «Материалы на объекте»; права `costs.materials.read` и `costs.materials.hint` как
  права контракта.

## Impact

- **Сервер:** новые `BHS.CRG.Modules/Exchange/ModuleContractAttribute.cs`, `IModuleContracts.cs`,
  `MaterialsOnSite.cs`; `Api/Modules/ModuleContractCatalog.cs` (проверка при старте);
  `Modules.Costs/Exchange/MaterialsOnSiteContract.cs`, `CostsModule.cs` (права, регистрация);
  `Api/Auth/SystemRoles.cs:64` («Монтажник»).
- **Тесты:** `ModuleContractCatalogTests`, `MaterialsOnSiteContractTests`, тест состава
  `/api/account/access` по ролям, `ModuleBoundaryTests`, `CostsOnlyHostTests`, живой хост `work` без `costs`.
- **Документы:** `docs/ADMIN_GUIDE.md` — права контракта у ролей; `docs/DEV_NOTES.md` — как завести контракт.
- Адрес `GET /api/costs/materials` не меняется.
