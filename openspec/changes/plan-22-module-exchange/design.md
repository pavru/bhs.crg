# Design: межмодульный контракт и параметр доступа контракта

Дочерний change зонтика `plan-00-epic`, общая архитектура — `../plan-00-epic/design.md` (D10 — контракт,
D2 — что забрано у этапа 4). Устройство повторяет PR 1 `work-09-module-exchange`; отличия — параметр
доступа заводится здесь и контракт со многими поставщиками.

## Context

Сверено по коду master `6b81e51e`.

- Каталога `BHS.CRG.Modules/Exchange` нет; ссылок модуль → модуль нет и быть не может
  (`ModuleBoundaryTests`).
- `IAppModule.RegisterServices` (`BHS.CRG.Modules/IAppModule.cs:43`) зовётся только у включённого модуля:
  отсутствие реализации и есть «не подключено».
- Что знает модуль о спрашивающем: `IModuleUser` (`BHS.CRG.Modules/Ports/IModuleUser.cs:21`) — `Id`
  (`null` вне запроса), `Name`, `HasAsync`, `PermissionsAsync`. Фоновая операция несёт поставившего в
  `ModuleJobRun.UserId` (`Ports/IModuleJobHandler.cs:13`).
- `work-07` проектирует `BHS.CRG.Modules/Access/ModuleReader.cs` (`UserId?`, `Who`, `Keys`, `SystemReason`,
  `IsSystem`) как зеркало `DataAccess`. Здесь заводится та же форма без охвата строк: тип один, `work-07`

## Goals / Non-Goals

**Goals:** механизм контракта со сторожами старта; параметр доступа контракта; контракт со многими
поставщиками для вкладов в экран.

**Non-Goals:**
- рабочие контракты — «Плановые работы» (`plan-23`), «Фактические затраты» (`plan-24`), «Колонка Хода
  работ» и интерфейс «Фактических работ» (`plan-25`), «Материалы на объекте» (`work-09`);
- охват строк («свои / стройки / все») — `work-07`;
- право контракта — `plan-21`.

## Decisions

- **Объявление.** `[ModuleContract("plan", "Плановые работы")]` на интерфейсе: поставщик назван у
  контракта, а не выведен из регистрации. Для вкладов — `[ModuleContract(Many = true, "Колонка Хода
  работ")]`: поставщиком может быть любой модуль.
- **Регистрация.** `services.AddModuleContract<IContract, Impl>(moduleCode)` в `RegisterServices`
  поставщика.
- **Порт потребителю** `IModuleContracts`:
  - `Get<T>()` → `ModuleContractAnswer<T>` — `Connected(T)` | `NotConnected(provider, title)`;
  - `GetAll<T>()` для контракта со многими поставщиками — список реализаций включённых модулей.
  Прямой запрос интерфейса контракта из DI ловит перепись по исходникам: иначе выключенный поставщик —
  исключение разрешения служб, а не «не подключено».
- **Параметр доступа** `ModuleReader(UserId?, Who, Keys, SystemReason?)`, `IsSystem => UserId is null`.
  Строит его `Api`: в запросе — из `IUserPermissions`, в фоновой операции — от имени поставившего, иначе
  «система» с причиной задания. Тип лежит в `BHS.CRG.Modules/Access`, ни на что не ссылается.
- **Общие ответы** в `Exchange/ContractAnswer.cs`: `Hidden(permission)` — «скрыто правами» с кодом
  права; `SystemRefused(reason)` — отказ системе. Каждый контракт говорит одинаково, и потребитель
  рисует состояние одним компонентом (D17 зонтика).
- **Проверка при старте** `Api/Modules/ModuleContractCatalog.cs`: интерфейсы с атрибутом в сборке
  контрактов; у обычного контракта и включённого поставщика — ровно одна реализация; реализацию
  зарегистрировал названный модуль; больше одной — отказ; у контракта `Many` — не больше одной реализации
  на модуль. Причина называет контракт и модули.
- **If-Match и ворота.** Нового пишущего API нет: контракт — вызов в процессе. Ворота модуля
  потребителя стоят на его адресах, как прежде.
- **Сторож.** `ModuleContractCatalogTests` на пробных модулях: поставщик без реализации, два
  поставщика, чужая регистрация — отказ старта с названиями; выключенный поставщик — `NotConnected`;
  контракт `Many` с двумя модулями — оба в `GetAll`. `ModuleContractAnswerTests`: без права — `Hidden`,
  система — `SystemRefused`. `ModuleBoundaryTests`.
- **Чем ломается.** Потребитель зовёт адрес чужого модуля по HTTP: без права модуля — 403, у
  выключенного — 501 вместо «не подключено». Потребитель берёт интерфейс из DI — при выключенном
  поставщике падает разрешение служб.
- **Зависимости.** После `plan-21` (ответ «скрыто правами» ссылается на право контракта). Потребители —
  `plan-23`, `plan-24`, `plan-25`; этап 4 — `work-09` PR 2, `work-26`, `work-27`, `work-28`.

## Risks / Trade-offs

- [`work-07` захочет иную форму параметра] → форма взята из его же design; расширение — новыми
  полями, не переименованием.
- [Контракт `Many` станет лазейкой для обычных] → атрибут явный, перепись старта называет каждый
  контракт `Many`; сегодня он один.
