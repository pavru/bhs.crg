# Proposal: межмодульный контракт и параметр доступа контракта

Дочерний change зонтика `plan-00-epic`, общая архитектура — `../plan-00-epic/design.md` (D2, D10, D11).
Забирает PR 1 из `work-09-module-exchange` этапа 4.

## Why

Модули читают данные друг друга только через контракты ядра, и при выключенном поставщике потребитель
говорит «не подключено», а не показывает пустоту (`CORE-34`, `OVW-12`). Каталога
`BHS.CRG.Modules/Exchange` в коде нет: механизма контрактов нет вовсе. Этап 3 — первый, у кого есть
настоящие потребители:
- заявки `costs` берут материалы позиций сметы («Плановые работы», `COST-5.1`);
- «Ход работ» берёт затраты `costs` («Фактические затраты», `PLAN-21.1`) и вклады модулей в экран
  («Колонка Хода работ», `PLAN-21`).

Без контракта потребитель позвал бы адрес чужого модуля по HTTP — мимо прав спрашивающего и мимо «не
подключено». Этап 4 записал механизм себе с условием «если этап 3 не завёл» (`work-09`); по правилу
«поддержка едет с первым потребителем» его строит этап 3.

## What Changes

- Интерфейс контракта — в `BHS.CRG.Modules/Exchange/*`, с названием модуля-поставщика на атрибуте;
  реализацию регистрирует поставщик в своём `RegisterServices`. Потребитель получает контракт портом
  ядра: «не подключено» — ответом, а не исключением.
- Параметр доступа контракта `ModuleReader`: кто спрашивает, его права, «система с причиной». Контракт
  отвечает в правах спрашивающего; без права — «скрыто правами» с кодом права; от имени системы —
  отказом с причиной. Изоляцию строк («свои / стройки / все») в тот же тип добавит `work-07`.
- Проверка при старте: у обычного контракта ровно одна реализация у включённого поставщика; реализацию
  регистрирует только названный модуль. Контракт, объявленный «со многими поставщиками», допускает
  реализацию у каждого включённого модуля и ни одной — у выключенных.
- Нового HTTP-адреса нет: контракт — вызов в процессе. Ни одного рабочего контракта change не заводит —
  их приносят `plan-23`, `plan-24`, `plan-25`; сторожа проверяются на пробных модулях.

## Capabilities

### New Capabilities
- Нет.

### Modified Capabilities
- `core`: межмодульный контракт — объявление, регистрация у поставщика, «не подключено», контракт со
  многими поставщиками, ответ в правах спрашивающего.

## Impact

- **Сервер:** новые `BHS.CRG.Modules/Exchange/ModuleContractAttribute.cs`, `IModuleContracts.cs`,
  `ContractAnswer.cs` (общие «скрыто правами», отказ системы), `BHS.CRG.Modules/Access/ModuleReader.cs`;
  `Api/Modules/ModuleContractCatalog.cs` (проверка при старте), построение `ModuleReader` в `Api`.
- **Тесты:** `ModuleContractCatalogTests`, `ModuleContractAnswerTests`, `ModuleBoundaryTests`, перепись
  прямого запроса интерфейса контракта из DI.
- **Документы:** `docs/DEV_NOTES.md` — как завести контракт, почему поставщик назван у интерфейса.
- **Этап 4:** у `work-09` остаётся только поставщик «Материалы на объекте»; `work-07` расширяет
  `ModuleReader`, а не заводит его.
