# Design: модель сметы

Дочерний change зонтика `plan-00-epic`, общая архитектура — `../plan-00-epic/design.md` (D3 — смета →
редакция → строка, D4 — деньги закрыты правом, D12 — права, D17 — носители). Здесь только решения этого
change.

## Context

Сверено по коду master `6b81e51e`.

- Образец записи модуля с версией строки и 409 — `Modules.Costs/Data/CostsDbContext.cs` и `Invoice*`;
  `SeenVersion` (`BHS.CRG.Modules/SeenVersion.cs:12`) — версия из `If-Match`.
- `IAppModule` объявляет `RecordTypes` (`BHS.CRG.Modules/IAppModule.cs:80`), `Tags` (`:132`), `Tables`
  (`:188`), ссылки `References`; журнал — `IModuleActivityLog` (`Ports/IModuleActivityLog.cs:79`), действия
  объявляются заранее (`IModuleActivityActions`).
- Строки счёта `costs` — своя таблица без схемы (`CostsRecordTypes.cs`, комментарий о строках); у сметы
  строки несут ещё поля заказчика по схеме (`PLAN-3`) — отличие названо ниже.
- В `types-and-tags` тип `ПозицияСметы` и тэги `estimate.*` значатся «этапы 3–7, не реализованы».

## Goals / Non-Goals

**Goals:** модель, которой импорт (`plan-07`) пишет редакции, сопоставление (`plan-08`) — позиции, КП и
график (`plan-13`, `plan-19`) — фиксацию; чтение под правами без утечки денег.

**Non-Goals:**
- импорт и разбор файла — `plan-05`, `plan-07`; сопоставление — `plan-08`; распределение — `plan-10`;
- экраны — `plan-09`; конъюнктурный анализ — `plan-11`;
- поставка плана другим модулям — `plan-23`; таблицы `CORE-33` и наборы — `plan-28`.

## Decisions

- **Таблицы схемы `plan`.**
  - `estimates` — `construction_id`, `section_id?`, `name`, `kind` (`main` | `additional`),
    `current_revision_id?`, `xmin`.
  - `estimate_revisions` — `estimate_id`, `number` (растёт в смете), `source_blob`, `schema_version`,
    `import_key`, `imported_at`, `imported_by`, `frozen_at?`, `frozen_reason?` (код и ссылка на
    производную), `xmin`.
  - `estimate_rows` — `revision_id`, `order`, `lsr_section` (код и наименование раздела ЛСР),
    `number_in_section`, `rate_code`, `name`, `source_volume`, `source_unit` (текст из файла),
    `work_type_id?`, `unit_id?`, `factor?`, `volume?` (в единице классификатора), `plan_item_id?`,
    `unit_cost`, `total`, `data jsonb` (схема `ПозицияСметы`).
  - `estimate_row_materials` — `row_id`, `nomenclature_id?`, `source_name`, `source_code?`, `source_unit`,
    `quantity`, `unit_price?`, `amount?` (сметная стоимость ресурса, если файл её несёт; под
    `plan.estimate.cost`) — её читают «план против факта» материалов (`plan-27`) и денежная часть
    «Плановых работ» (`plan-23`); `estimate_row_labor` — `row_id`, `man_hours`.
  - Строка редакции после импорта не правится, кроме полей сопоставления (`plan-08`) — их заполняет
    сопоставление, и правило зафиксированной редакции для них — В-6.
- **Деньги и сметное наполнение — колонки и блок под правом.** `unit_cost`, `total` — колонки: их читают
  код КП, итоги и контракт (`CORE-15`). Данные `ПозицияСметы` (расценка, коэффициенты, поля заказчика) —
  целиком «сметное наполнение» и отдаются только с `plan.estimate.cost`. Без права ответ строки — скелет
  (вид, объём, единица, раздел ЛСР, шифр, наименование, ресурсы без цен) и `hidden: [{code: "cost",
  permission: "plan.estimate.cost"}]`. Пометка денежных полей схемы тэгом отвергнута: заказчик добавит поле
  без тэга, и оно утечёт молча.
- **Тип `ПозицияСметы`** — `RecordTypes` модуля, открытый (`CORE-19`), составной; в нём только поля
  заказчика. Тэги `estimate.rate`, `estimate.unitCost`, `estimate.total` не объявляются: их читали бы из
  JSON, а код опирается на колонки. Строка `types-and-tags` «Ожидает будущих этапов» для `ПозицияСметы`
  снимается этим change.
- **Действующая редакция.** `POST /api/plan/estimates/{id}/current-revision {revisionId}` с `If-Match`
  версии сметы. Первая редакция становится действующей сама; следующие — только действием (решение В-5).
  Смена пишется в журнал действий ядра: «смета …: действующая редакция 2 → 3».
- **Фиксация.** Метод модели `Freeze(revision, reason)` — его зовут `plan-13` и `plan-19` при создании
  производной. Правка и удаление зафиксированной редакции — 409 «редакция зафиксирована: из неё сделан …».
  Действующую редакцию удалить нельзя — 409 «сначала сделайте действующей другую».
- **Адреса** (группа `/api/plan`, ворота модуля):
  - под `plan.estimate.read`: `GET /estimates?constructionId=…`, `GET /estimates/{id}` (с редакциями и
    признаками фиксации), `GET /revisions/{id}/rows?cursor=…` (строки с ресурсами, страницами);
  - под `plan.estimate.edit`: `POST /estimates`, `PUT /estimates/{id}`, `DELETE /estimates/{id}` (без
    редакций), `DELETE /revisions/{id}`, `POST /estimates/{id}/current-revision`; все, кроме `POST
    /estimates`, — с `If-Match`.
- **Право `plan.estimate.cost`** объявляется здесь: объяснение «себестоимость сметы — стоимость строк,
  итоги, расценки», `ReadAllMark.In`. «Сметчик» получает его по `plan-01`; «Менеджер проекта» — нет
  (решение В-1).
- **Ссылки `CORE-34.1`:** `estimates.construction_id`, `section_id`; `estimate_rows.plan_item_id`,
  `work_type_id`, `unit_id`; `estimate_row_materials.nomenclature_id`. Новая ссылка на архивную запись —
  отказ (`CORE-34.4`).
- **Охрана «план — по действующим»** (D3 зонтика): строки для сумм читаются только методом
  `PlanRows.Current(constructionId)`; перепись по исходникам ловит прямое чтение `estimate_rows` для сумм
  вне одного файла (по образцу `InvoiceBookInventoryTests`). Метод заводится здесь, потребители — `plan-23`,
  `plan-25`.
- **Сторож.**
  - `EstimateCostVisibilityTests`: ответ строк без `plan.estimate.cost` не содержит ни одного денежного поля и
    ни одного поля `data` — проверка по JSON ответа целиком, а не по известным ключам.
  - `EstimateRevisionTests`: правка и удаление зафиксированной — 409 с производной; удаление действующей —
    409; смена действующей пишет журнал; `If-Match` — 400 без заголовка, 409 устаревший.
  - Тест ворот: «Инженер ИД» — 403 на каждом адресе; `plan.estimate.read` без `.edit` — 403 на пишущих.
  - `PlanRowsInventoryTests` — прямое чтение строк для сумм вне `PlanRows` краснеет.
- **Чем ломается.** Цены строки лежат полями схемы и отдаются целиком — сметчик без права их видит; «план»
  считается по всем редакциям — дополнительная смета удваивает объём.
- **Зависимости.** `plan-01`. Потребители — `plan-07`…`plan-10`, `plan-13`, `plan-19`, `plan-23`.

## Risks / Trade-offs

- [Скрытое сметное наполнение мешает сметчику без права на деньги видеть коэффициенты] → такой роли в
  поставке нет («Сметчик» получает `.cost`); если появится — поле схемы с пометкой «не деньги» можно
  будет открыть отдельно, без смены модели.
- [Строки сотни тысяч на крупной стройке] → чтение страницами по курсору; итоги — запросом базы, а не
  загрузкой строк.
