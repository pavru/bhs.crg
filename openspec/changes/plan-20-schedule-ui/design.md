# Design: экраны графика — список, диаграмма, зависимости, печать

Дочерний change зонтика `plan-00-epic`, общая архитектура — `../plan-00-epic/design.md` (D13, D14, D17,
D18). Здесь только решения этого change.

## Context

Сервер — `plan-19` (графики, работы, связи, предупреждения, перестроение) и `plan-18` (календари, рабочие
дни). Панели карточки стройки и пункты рейла — `plan-02` (сегодня панели перечислены вручную,
`features/document-sets/ConstructionDetail.tsx:31,112-118`). Печать записи модуля — `plan-15`. В
`shared/ui` есть `DataGrid`, `EditGrid`, `DateField`, `NumberInput`, `Modal`, `ConfirmDialog`, `Tabs`,
`Tooltip`, `EmptyState`; диаграммы Ганта и библиотек таймлайнов в клиенте нет. Общего выбора сотрудника
нет: его планировал `work-12` этапа 4 — первым потребителем становится этот change.

## Goals / Non-Goals

**Goals:** менеджер строит график из сметы, назначает сроки и исполнителей, связывает работы и видит
нарушения; список работает с клавиатуры и печатается; диаграмма — второй вид.

**Non-Goals:**
- правка на диаграмме перетаскиванием — сначала список (`PLAN-17`); перетаскивание — после макета и
  спроса;
- факт по работам — `plan-25` (колонка добавляется вкладом «Хода работ» в график);
- выработка рядом с объёмом — `work-28`;
- печать диаграммы (ждёт решения В-10).

## Decisions

- **Макеты:** раунд П4 (часть «график»), три варианта, выбор владельца — вписать сюда ссылку. Код — после
  выбора (D18). Раунд решает: переключение «список / диаграмма» (вкладки или раздельный экран), где живут
  предшественники (колонка или боковая панель строки), вид предупреждений.
- **PR 1.**
  - `SchedulesPanel.tsx` — панель «График» стройки (механизм `plan-02`): список графиков (`DataGrid`),
    «Построить из сметы» (`Modal` 512 px: смета, редакция, «не вошло: N несопоставленных строк» из ответа),
    «Новый график».
  - `ScheduleWorksGrid.tsx` на `EditGrid`: даты — `DateField`, объём — `NumberInput`, исполнители —
    `EmployeePicker`; длительность в рабочих днях и предупреждения — поля ответа сервера, клиент рабочих
    дней не считает (D14). Раздел без распределения — «по стройке в целом».
  - Сводка предупреждений над списком: «нарушений зависимостей: N ▸», «окончание на выходном: N ▸»,
    «календарь на 2027 год не заполнен» — отбор строк по коду.
  - `RebuildByDistributionDialog.tsx` (`Modal wide`) — предпросмотр перестроения; 409 по отпечатку —
    перечитать.
  - `shared/ui/EmployeePicker.tsx` — поиск сотрудника портом ядра (`plan-03`), пометка архивных; `work-12`
    расширит кандидатами и причинами исключения, не меняя вызова.
- **PR 2.**
  - `ScheduleLinksCell.tsx` — предшественники в строке: выбор работы (свои и графиков той же стройки,
    сгруппированы по графику), задержка; отказ сервера при цикле — перечнем работ цикла словами.
  - `ScheduleGantt.tsx` — SVG поверх тех же строк, что список (одна модель данных): шкала по дням
    календаря стройки, нерабочие дни затенены токеном поверхности, полосы работ, стрелки связей,
    предупреждения тем же знаком, что в списке. Щелчок — переход к строке списка. Цвета — токенами
    (`ui:ratchet`), своей `<table>` нет. Минимальная ширина — 1280; на телефоне диаграммы нет, список есть.
- **PR 3.**
  - Печатная форма списка работ — `Printing/ScheduleWorksPrintContext.cs`, право `plan.schedule.read`,
    шаблон по умолчанию; кнопка «Печать» карточки графика (ждёт решения В-10).
  - Живой прогон `e2e/plan-schedule-smoke.mjs`: построить из посеянной редакции → связать две работы с
    задержкой → нарушение видно у обеих → печать отдаёт PDF.
- **Сторож.** vitest: длительность и предупреждения берутся из ответа (подменённый ответ с
  `starts-before-predecessor` даёт знак у обеих строк); отказ цикла показывает перечень; без
  `plan.schedule.edit` ячеек правки нет. Живой прогон под ролью «Менеджер проекта».
- **Чем ломается.** Клиент считает рабочие дни сам — диаграмма и печать расходятся с сервером; диаграмма
  единственным видом — на телефоне и в печати графика нет.

## Risks / Trade-offs

- [Своя диаграмма дороже готовой библиотеки] → только просмотр, одна модель со списком; библиотека — если
  макет П4 потребует правки на диаграмме, решением с владельцем.
- [Сотни работ в списке] → `DataGrid` с виртуализацией строк, отбор по разделу и по предупреждению.
- [`EmployeePicker` появляется раньше, чем его спроектировал `work-12`] → вызов без кандидатов и причин;
  `work-12` добавляет их необязательными свойствами.
