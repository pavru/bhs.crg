# Design: экраны графика — список, диаграмма, зависимости, печать

Дочерний change зонтика `plan-00-epic`, общая архитектура — `../plan-00-epic/design.md` (D13, D14, D17,
D18). Здесь только решения этого change.

## Context

Сервер — `plan-19` (графики, работы, связи, предупреждения, перестроение) и `plan-18` (календари, рабочие
дни). Панель стройки уже зарегистрирована как `schedule` в `shared/ui/constructionPanels.ts`.
`features/document-sets/scopePanels.tsx` открывает на этом адресе календарь стройки. Печать записи
модуля — `plan-15`. В
`shared/ui` есть `DataGrid`, `EditGrid`, `DateField`, `NumberInput`, `Modal`, `ConfirmDialog`, `Tabs`,
`Tooltip`, `EmptyState`. `work-12` уже добавил `shared/ui/EmployeePicker`: график передаёт данные в его
существующем формате и использует те же поиск, выбор и пометку архива.

## Goals / Non-Goals

**Goals:** менеджер строит график из сметы, назначает сроки и исполнителей, связывает работы и видит
нарушения; список работает с клавиатуры и печатается; диаграмма — второй вид.

**Non-Goals:**
- правка на диаграмме перетаскиванием — сначала список (`PLAN-17`); перетаскивание — после макета и
  спроса;
- факт по работам — `plan-25` (колонка добавляется вкладом «Хода работ» в график);
- выработка рядом с объёмом — `work-28`;
- печать диаграммы (решение В-10).

## Decisions

- **Макеты:** три варианта раунда П4 для графика приведены ниже. Реализация экрана начинается после
  выбора владельца (D18).
- **PR 1.**
  - `SchedulesPanel.tsx` — панель «График» стройки (механизм `plan-02`): список графиков (`DataGrid`),
    «Построить из сметы» (`Modal` 512 px: смета, редакция, «не вошло: N несопоставленных строк» из ответа),
    «Новый график».
  - `ScheduleWorksGrid.tsx` на `EditGrid`: даты — `DateInput` размера клетки, объём — `NumberInput`, исполнители —
    `EmployeePicker`; длительность в рабочих днях и предупреждения — поля ответа сервера, клиент рабочих
    дней не считает (D14). Раздел без распределения — «по стройке в целом».
  - Сводка предупреждений над списком: «нарушений зависимостей: N ▸», «окончание на выходном: N ▸»,
    «календарь на 2027 год не заполнен» — отбор строк по коду.
  - `RebuildByDistributionDialog.tsx` (`Modal wide`) — предпросмотр перестроения; 409 по отпечатку —
    перечитать.
  - `EmployeePicker` принимает кандидатов и причину запрета. Архивного сотрудника нельзя добавить
    вручную, прежняя ссылка может сохраняться по правилам API.
- **PR 2.**
  - Редактор предшественников: выбор работы (свои и графиков той же стройки,
    сгруппированы по графику), задержка; отказ сервера при цикле — перечнем работ цикла словами.
    После конфликта версии редактор сохраняет изменённые поля и перечитывает остальные. После отказа
    удаления по версии или отсутствию связи перечитывается график.
  - `ScheduleGantt.tsx` — SVG поверх тех же строк, что список (одна модель данных): шкала по дням
    календаря стройки, нерабочие дни затенены токеном поверхности, полосы работ, стрелки связей,
    предупреждения тем же знаком, что в списке. Диаграмма показывает 31 календарный день. Если один
    конец связи за границей периода или в другом графике, стрелка ведёт к границе и подписываются
    обе работы. Щелчок — переход к строке списка. Цвета — токенами
    (`ui:ratchet`), своей `<table>` нет. Минимальная ширина — 1280; на телефоне диаграммы нет, список есть.
- **PR 3.**
  - Печатная форма списка работ — `Printing/ScheduleWorksPrintContext.cs`, право `plan.schedule.read`,
    шаблон по умолчанию; кнопка «Печать» карточки графика (решение В-10).
  - Живой прогон `e2e/plan-schedule-smoke.mjs`: построить из посеянной редакции → связать две работы с
    задержкой → нарушение видно у обеих → печать отдаёт PDF.
- **Сторож.** vitest: длительность и предупреждения берутся из ответа (подменённый ответ с
  `starts-before-predecessor` даёт знак у обеих строк); отказ цикла показывает перечень; без
  `plan.schedule.edit` ячеек правки нет. Живой прогон под ролью «Менеджер проекта».
- **Чем ломается.** Клиент считает рабочие дни сам — диаграмма и печать расходятся с сервером; диаграмма
  единственным видом — на телефоне и в печати графика нет.

## Risks / Trade-offs

- [Своя диаграмма дороже готовой библиотеки] → только просмотр, одна модель со списком; библиотека — если
  макет П4 потребует правки на диаграмме, решением с владельцем.
- [Сотни работ в списке] → `DataGrid` с виртуализацией строк, отбор по разделу и по предупреждению.

## Раунд П4

Ссылки открывают варианты в локальном каталоге BHS.CRG UI.

- [А · Рабочая таблица](http://127.0.0.1:5200/?section=mockups&project=plan-20-schedule-ui&page=a).
  Сроки и объём правятся в выбранной строке. Связи открываются из своей колонки. Подходит для
  сравнения работ по срокам, объёмам и исполнителям. На телефоне широкая таблица прокручивается внутри.
- [Б · Список и карточка работы](http://127.0.0.1:5200/?section=mockups&project=plan-20-schedule-ui&page=b).
  Слева общая очередь, справа сроки, объём, исполнители, предупреждения и предшественники выбранной
  работы. На телефоне карточка появляется под списком.
- [В · Работы по разделам](http://127.0.0.1:5200/?section=mockups&project=plan-20-schedule-ui&page=c).
  Список сгруппирован по разделам. В каждой карточке видны сроки, длительность, объём и исполнители.
  Правка и работа со связями открываются из карточки. Колонки карточек складываются в один ряд на узком экране.

Разбор интерфейса подготовлен исполнителем. Рекомендуемый вариант А соответствует ежедневной
работе со сроками: колонки позволяют сразу сопоставить несколько работ и перейти к правке с клавиатуры.
Вариант Б удобен для разбора зависимостей одной работы, В — для последовательного обхода по разделам
на телефоне. Диаграмма во всех вариантах сохраняет отбор списка и возвращает к выбранной строке.
В сценариях доступны чтение без правки, конфликт версии, новый предпросмотр, цикл и пробел календаря.
Все данные макета демонстрационные. 24.11.2026 владелец выбрал
[А · Рабочая таблица](http://127.0.0.1:5200/?section=mockups&project=plan-20-schedule-ui&page=a).

## Носители API

Сверено на `d7775884f`, версия приложения `2.139.1`.

- `GET /api/plan/schedules?constructionId=…` отдаёт список графиков и версии. Карточка по
  `GET /api/plan/schedules/{id}` несёт `skipped.unmapped`, `marks` с `distribution-changed`,
  `works[].warnings`, общий `warnings` и входящие/исходящие `links`. Коды календаря и зависимостей
  включают `calendar-missing` с годом, `no-dates`, `ends-on-day-off`, `starts-before-predecessor`
  и `lag-out-of-range` для задержек обоих знаков.
- Построение и ручной график используют `POST /api/plan/schedules` с `creationKey`. Повтор того же
  запроса возвращает тот же график. Построение фиксирует редакцию. По В-6 в фиксированной редакции
  можно впервые сопоставить ранее несопоставленную строку.
- `PUT/DELETE …/{id}/works/{workId}` используют версию работы. `POST …/{id}/links` создаёт
  связь без версии, `PUT/DELETE …/{id}/links/{linkId}` используют версию связи. Связь принадлежит графику
  последователя. Отказ цикла — 422 с `code`, `error` и `cycle` (работы с графиками).
  Для подписей на диаграмме и в редакторе `GET` карточки отдаёт `predecessor` и `successor`
  в существующем формате `ScheduleWorkRef`. Работы графика для нового предшественника читаются
  при выборе этого графика.
- `GET …/{id}/rebuild-preview` возвращает `version`, `fingerprint`, `added`, `removed`,
  `changed`, `skipped.unmapped` и `removedLinks` с обеими работами и графиками. `POST …/{id}/rebuild`
  сверяет `If-Match` графика и отпечаток. Ответ 409 по отпечатку содержит новый `preview`, в том
  числе после изменений удаляемой связи между графиками. Ответ 409 по версии требует заново
  прочитать предпросмотр. У совпавших частей сроки и исполнители сохраняются.
- **PR 1:** `ScheduleWorkDto` сейчас не содержит длительности. Добавляется `durationWorkingDays`
  из `WorkingDays.WorkingDaysBetween` с обеими границами включительно. При отсутствии любой даты
  значение `null`. По действующему [PLAN-19.1] за незаполненный год используется правило недели
  и передаётся `calendar-missing` с годом. Сроки при расчёте сохраняются.
- **PR 2:** календарные `GET /api/plan/calendars/company/{year}` и
  `GET /api/plan/calendars/constructions/{id}` сейчас отдают настройки и исключения. Добавляется
  `GET /api/plan/calendars/constructions/{id}/non-working-days?from=YYYY-MM-DD&to=YYYY-MM-DD` под
  `plan.schedule.read` и воротами `plan`. Принимает включительный период до 366 календарных дней.
  Даты классифицирует `WorkingDays`. Ответ несёт `nonWorkingDays` и `gaps`. Диаграмма использует
  ответ для отметок, а календарные даты — для координат.
- **PR 3:** общие адреса — `POST /api/print/{typeCode}/{recordId}` для скачивания и
  `POST /api/print/{typeCode}/{recordId}/preview` для просмотра. Модуль зарегистрирует контекст
  графика, форму с правом `plan.schedule.read` и шаблон списка по умолчанию.

## Права на связанные справочники

Решение владельца от 24.11.2026. Карточка графика отдаёт имена уже связанных исполнителей и
обозначения единиц через порты ядра. Ответ содержит только данные, нужные для чтения графика.
Новые списки выбора под правом графика не вводятся.

| Действие в графике | Действующие права |
|---|---|
| Читать карточку и печатать список | `plan.schedule.read` |
| Создать ручной график, править сроки или объём существующей работы | `plan.schedule.read`, `plan.schedule.edit` |
| Добавить ручную работу с видом классификатора | Права правки графика и `core.catalog.read` |
| Выбрать новых исполнителей | Права правки графика и `core.employees.read` |
| Построить из сметы | Права правки графика и `plan.estimate.read` |

Проверяется фактическое наличие прав. Редактор без доступа к справочникам сохраняет существующих
исполнителей при правке других полей. На месте выбора экран сообщает, какого доступа не хватает.
Запросы к недоступным справочникам не выполняются. Архивный сотрудник виден в существующей ссылке и
недоступен для новой.
