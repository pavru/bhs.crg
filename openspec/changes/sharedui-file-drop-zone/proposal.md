# Proposal: площадка выбора и броска файла в `shared/ui`

Самостоятельный change общих компонентов интерфейса (домен `sharedui`). Его ждёт PR 2 у
`costs-invoice-screen-14-file-drop` (эпик `costs-invoice-screen-00-epic`, задача 2.4a, решение Э8 владельца
от 08.11.2026).

## Why

Окну, куда кладут один файл, нужна площадка: «перетащите сюда или выберите». В `shared/ui` её нет — есть
только помощники `fileDrop.ts` (`carriesFiles`, `droppedFiles`, `useFileDragActive`, `useDropMissGuard`). Поэтому
единственная площадка в системе написана экраном для себя: `FilePick` в
`features/planning/estimates/ImportDialog.tsx` — пунктирная рамка, свой счёт входов и выходов, своё «один
файл — по одному», а отказа по виду файла нет вовсе: брошенный `.pdf` уходит на сервер.

Ребёнок 14 заводит ещё две такие площадки: окна «Приложить файл…» и «⋮ → Заменить файл…» (design D6 у 14,
[COST-6.7]). Без общего компонента это вторая самодельная площадка с другим поведением: та же рамка, другие
слова, другие отказы. Владелец решил по Э8 поднять площадку в `shared/ui` отдельным change до PR 2 у 14.

## What Changes

- **Новый компонент `FileDropZone`** в `src/client/src/shared/ui`. Он принимает файл двумя путями — броском
  и кнопкой выбора — и отдаёт его экрану. Свой захват броска ему не нужен: React-обработчик площадки
  отменяет действие по умолчанию раньше стража окна `useDropMissGuard`.
- **Состояния площадки:**
  - покой;
  - «наготове» — над окном тащат файл;
  - «отпустите» — файл над площадкой;
  - выбранный файл — имя и размер, кнопка «Другой файл»;
  - отказ;
  - «идёт загрузка» — бросок не принимается, кнопка выключена;
  - выключена.
- **Отказ — словами и на месте**, а не снэкбаром и не молча. Площадка называет причину сама: папка,
  несколько файлов там, где ждут один, пустой файл, не тот вид (по `accept`), больше предела (`maxBytes`).
  Остальное экран добавляет своей проверкой. Отказ по виду или размеру `onFiles` не зовёт.
- **Вид и раскладка — по выбору владельца** из трёх макетов (docs/UI.md, «Новый экран: порядок»; #1545).
  Выбор записывается в `design.md` этого change до кода.
- **`ImportDialog` переходит на `FileDropZone`**, его `FilePick` удаляется. Имя поля для e2e остаётся
  прежним — «Файл сметы». Заодно бросок не того вида (не `.gsfx` / `.xml`) получает отказ на месте, а не с
  сервера. Это видимая правка поведения окна.
- **Правило в `docs/UI.md`:** новый раздел о площадке файла — когда площадка, когда кнопка в меню
  (`ScanFileInput`), когда цель на всё окно (захват 14, D1).

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `sharedui`: добавляется требование [UI-89] о площадке выбора и броска файла — пути, состояния, отказы,
  доступ с клавиатуры и для диктора, совместимость со стражем окна.

## Impact

- **Код клиента:** новый `src/client/src/shared/ui/FileDropZone.tsx` и тест `FileDropZone.test.tsx`; проверка
  вида и размера — в `fileDrop.ts` (рядом с `droppedFiles`) с тестом; `features/planning/estimates/ImportDialog.tsx`
  — `FilePick` уходит, окно худеет.
- **Живые прогоны:** `e2e/planning-estimates-smoke.mjs` — выбор файла по имени «Файл сметы» (не меняется),
  отказ по виду. Нужен модуль `plan` на стенде.
- **Документы:** `docs/UI.md` — раздел о площадке файла.
- **Сервер, API, база** — не меняются.
- **Не входит:**
  - окна «Приложить файл…» и «Заменить файл…» — это PR 2 у 14;
  - захват броска окном (`claimWindowDrop`) — 14, D1;
  - цели на целую часть экрана: колонка списка счетов (`InvoiceScanDrop`, её снимает 14) и источник набора
    данных (`DataSetsResource`). Это другой рисунок — покрытие поверх содержимого, а не площадка в окне;
  - правило храповика на самодельную площадку (см. design, «Отвергнуто»).
