# Design: площадка выбора и броска файла (`FileDropZone`)

## Context

Мотивация — `proposal.md`. Требования — `specs/sharedui/spec.md` ([UI-89]). Решение Э8 и место в порядке
эпика — `../costs-invoice-screen-00-epic/design.md` (D8, Migration Plan) и `tasks.md` (2.4a).

Как устроено сегодня:
- **`shared/ui/fileDrop.ts`** (#1093) даёт:
  - `carriesFiles` — тащат ли файлы;
  - `useDropMissGuard` — страж окна, ставится в `App`: отклоняет промах `dropEffect = 'none'`, если цель
    не отменила действие сама;
  - `useFileDragActive` — над окном тащат файл;
  - `droppedFiles` — файлы и, отдельно, папки по имени.

  Компонента площадки нет.
- **`FilePick`** в `features/planning/estimates/ImportDialog.tsx` (строки ~277–318):
  - пунктирная рамка `border-2 border-dashed`, свой флаг «над площадкой»;
  - «одна загрузка — один файл» — своей строкой;
  - скрытый `input` с `aria-label="Файл сметы"`; по нему e2e `planning-estimates-smoke.mjs` кладёт файл;
  - `accept=".gsfx,.xml"` — только у окна выбора, бросок вид не проверяет.
- **Ребёнок 14** (D6) открывает окна «Приложить файл…» и «⋮ → Заменить файл…» с площадкой и кнопкой выбора.
  Захват броска окном (`claimWindowDrop`, D1) молчит, пока открыт модальный слой. Значит, бросок в окне ловит
  сама площадка: её React-обработчик отменяет действие раньше стража.
- **Дизайн-система в Claude** заморожена на 2.74.0, `/design-sync` туда не пишет (`docs/UI.md`, «Новый экран:
  порядок»). Макеты нарисованы разметкой на токенах «BHS.CRG UI». Бандл компонентов в холсте не монтируется:
  он собран под React 19, а у холста React 18.

## Goals / Non-Goals

**Goals:**
- Один компонент на все окна, куда кладут один файл. Одно поведение: состояния, отказы, загрузка.
- `ImportDialog` переходит на него без потери имени поля «Файл сметы» и без правки e2e выбора.
- 14 получает площадку для PR 2 готовой: ему остаётся передать `accept`, слова вида и предел.

**Non-Goals:**
- Несколько файлов в одной площадке (`multiple`). Пакет у 14 идёт броском на окно, а не площадкой. Понадобится
  — отдельной правкой: с ним меняются слова отказа и вопрос «что отдать, если часть не годна».
- Захват броска окном и покрытие поверх страницы — это 14, D1.
- Цели на целую часть экрана: колонка списка счетов (`InvoiceScanDrop`) и источник набора данных
  (`DataSetsResource`).
- Отправка файла. Площадка отдаёт `File`, отправляет экран; ход загрузки площадка только показывает.

## Decisions

### D1. Вид — вариант Б «Площадка» (выбор владельца 08.11.2026)

Макет — холст «Площадка файла · FileDropZone»: https://claude.ai/artifact/DkC1pS2r15uGtos1SS5m56. Лист «0» —
общее и сравнение, дальше листы А, Б, В по восемь состояний и два окна. Выбран **Б**, рекомендация автора.

**Покой.** Пунктир `outline` 1 px, радиус `rounded-md` (12), высота не меньше 184. По центру столбиком:
- знак `UploadFile` 40, `on-surface-variant`;
- `title-medium` «Перетащите файл сюда» — слова задаёт экран;
- `body-medium` «или»;
- `Button variant="tonal"` «Выбрать файл»;
- `body-small` — вид и предел.

**Наготове** (над окном тащат файл). Пунктир 2 px `primary`, знак `primary`, заголовок «Бросьте файл сюда».

**Отпустите** (файл над площадкой). Сплошная обводка 2 px `primary`, заливка `primary-container`, текст
`on-primary-container`: «Отпустите — возьмём файл». Кнопки нет: бросок уже идёт.

**Выбран.** Площадка сворачивается в строку файла 72: обводка `outline-variant`, фон `surface`, знак
`Description` 24, имя (`body-medium`) и размер (`body-small`), `Button variant="text"` «Другой файл». Строка
принимает бросок и сама: наготове и «отпустите» рисуются на ней теми же цветами, а брошенный файл заменяет
выбранный.

**Отказ.** Под площадкой — строка `body-small text-error` со знаком ошибки 18, `role="alert"`. Обводку
площадки отказ не красит: состояние несёт знак и текст, а не рамка (правило `docs/UI.md` о плашках).

**Загрузка.** `CircularProgress` 40 на месте знака, заголовок — текст хода от экрана («Загружаем «Счёт
1021.pdf»»), под ним «Бросок примем после неё». Кнопка выключена, на бросок — курсор «нельзя».

**Выключена.** Цвета `on-surface` 38 % и 12 % у обводки. Вместо заголовка — причина от экрана, например
«Сначала выберите стройку».

**Телефон** (`(pointer: coarse)`). Перетаскивать нечем, поэтому:
- нет «Перетащите…» и «или»;
- площадка ниже — от 120;
- кнопка называет файл: «Выбрать файл сметы» — подпись от экрана.

*Отвергнуто — А «Строка в форме»*: цель броска 72 px, а окна 14, где кроме площадки ничего нет, выглядят
пустыми. *Отвергнуто — В «Поле файла»*: в покое бросок не виден. Ещё поле, которое не печатается, похоже на
текстовое.

### D2. Устройство: компонент поверх `fileDrop.ts`, без своего захвата окна

```ts
interface FileDropZoneProps {
  label: string;            // имя скрытого поля: «Файл сметы» — для диктора и e2e
  onFile: (file: File) => void;
  accept?: string;          // как у <input accept>: расширения и типы (`acceptOf` из fileKinds)
  kinds?: string;           // слова вида для подсказки и отказа: «.gsfx или .xml», «PDF, PNG и JPEG»
  kindNoun?: string;        // «файл сметы» → «счёт.pdf — не файл сметы: нужен .gsfx или .xml»
  maxBytes?: number;        // предел; в подсказке и в отказе — `formatBytes`
  check?: (file: File) => string | null; // своя проверка экрана — тем же отказом
  file?: { name: string; size: number } | null; // выбранный: площадка свёрнута в строку
  prompt?: string;          // «Перетащите файл счёта сюда»; по умолчанию «Перетащите файл сюда»
  pickLabel?: string;       // подпись кнопки на телефоне: «Выбрать файл сметы»
  busy?: string;            // идёт загрузка: текст хода; площадка файл не принимает
  disabled?: boolean | string; // строка — причина вместо заголовка
}
```

Внутри:
- **Наготове** — `useFileDragActive()`. **«Над площадкой»** — счётчик входов на самом элементе, как у
  стража окна: вход в дочерний элемент приходит раньше выхода из родителя, флаг мигал бы.
- **`onDragOver` / `onDrop` площадки** отменяют действие по умолчанию сами, поэтому `useDropMissGuard` их
  не трогает. В загрузке и выключенной площадке `dropEffect = 'none'`: файл не отдаётся, браузер его не
  открывает, начатое не прерывается.
- **Проверка** — чистая функция `refusalOf(dropped, rules)` в `fileDrop.ts`, рядом с `droppedFiles`. Её
  проверяет свой vitest. Порядок причин: папка → несколько → пустой → вид → размер → `check`. Первая найденная
  и называется.
- **Вид по `accept`** — `matchesAccept(file, accept)`:
  - `.ext` — по концу имени, без учёта регистра;
  - `type/*` — по началу типа;
  - иное — точным типом.

  Пустой `accept` пропускает всё. Окно выбора проверяется той же функцией: фильтр «Все файлы» — подсказка,
  а не проверка.
- **Скрытый `input type="file"`** без `multiple`, `aria-label={label}`. Значение сбрасывается после выбора:
  тот же файл второй раз даёт событие (как у `ScanFileInput`).
- **Отказ — состояние площадки.** Его снимает следующий принятый файл. Экрану отказ не отдаётся: это слова
  площадки, а не событие экрана. Нужен будет экрану — отдельной правкой, по потребителю.

*Отвергнуто:* площадка со своим `claimWindowDrop`. Захват — механизм цели на всё окно (14). Внутри модального
слоя обработчик элемента и так срабатывает раньше стража, а второй захват на окно спорил бы с захватом
страницы (14, D1).

*Отвергнуто:* `multiple` с отказом части файлов. Потребителя нет (см. Non-Goals).

### D3. `ImportDialog` — перевод без правки шагов

`FilePick` удаляется. На его месте:

```tsx
<FileDropZone label="Файл сметы" accept=".gsfx,.xml" kinds=".gsfx или .xml" kindNoun="файл сметы"
  prompt="Перетащите файл сметы сюда" pickLabel="Выбрать файл сметы" file={file} onFile={setFile} />
```

Шаги окна («Файл и цель → Разбор → Отчёт») и `isDirty` не меняются. Видимых правок три:
- площадка выше строки до выбора и сворачивается в строку после;
- бросок не того вида получает отказ на месте;
- бросок нескольких — отказ словами площадки вместо своей строки.

Загрузки на площадке у `ImportDialog` нет: после «Загрузить» окно уходит на шаг разбора. `busy` здесь не
передаётся.

### D4. Правила — `docs/UI.md`, без нового правила храповика

В `docs/UI.md` появляется строка таблицы компонентов и короткий раздел «Площадка файла»:
- когда площадка;
- когда пункт меню со скрытым выбором (`ScanFileInput`);
- когда цель на всё окно (14).

*Отвергнуто:* правило `ui:ratchet` на самодельную площадку. Лексический признак (`border-dashed` вместе с
`onDrop`) ловит и законные цели на часть экрана — `InvoiceScanDrop` и `DataSetsResource`. Новое правило
храповика по `docs/UI.md` требует разбора Архитектора. После перевода `ImportDialog` самодельных площадок в
`features/` не остаётся, и считать нечего.

## Risks / Trade-offs

- [Б выше строки до выбора и удлиняет окно ImportDialog на ~110 px] → после выбора площадка сворачивается в
  строку 72, а окно `Modal wide` прокручивается телом. Проверка — живой прогон `planning-estimates` на
  1280×720.
- [`(pointer: coarse)` у ноутбука с сенсорным экраном и мышью] → `coarse` значит, что основной указатель
  грубый. Ноутбук с мышью остаётся `fine`, и слова «перетащите» на нём видны.
- [Браузер не даёт тип у `.gsfx`] → проверка по расширению. Тип сверяется, только если он назван в `accept`.
- [Скрытый `input` с `display: none` нельзя выбрать клавиатурой] → фокус получает кнопка, а не поле. Поле
  вызывается через `click()`. Имя поля нужно e2e и диктору: оно читается в цепочке «кнопка → окно выбора».
- [Бандл дизайн-системы отстаёт] → `FileDropZone` попадёт в «BHS.CRG UI», когда заработает `/design-sync`.
  Макет опирается на код и `.d.ts` (`docs/UI.md`).

## Migration Plan

Один PR кода после слияния planning PR:
1. `fileDrop.ts` — `matchesAccept` и `refusalOf` с тестом.
2. `FileDropZone.tsx` с тестом.
3. `ImportDialog` переходит на компонент.
4. `docs/UI.md`.
5. e2e `planning-estimates-smoke.mjs` — отказ по виду.

Откат — revert PR: сервер, API и данные не затронуты. Потом архив отдельным PR и отметка 2.4a в зонтике.
После слияния 14 начинает PR 2 на готовой площадке.
