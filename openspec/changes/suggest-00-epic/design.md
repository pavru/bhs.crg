# Design: подсказки по ранее введённому, общая архитектура

Документ общий для дочерних change `suggest-01`…`suggest-05`: каждый ссылается сюда и не повторяет
сказанного. Мотивация — `proposal.md`. Решения 1–9 согласованы Архитектором и Дизайнером 19.10.2026
(issue #1527) и записаны здесь как D1–D9; D10 — общий контракт адреса.

## Goals / Non-Goals

**Goals:**
- «Номенклатура → Производитель» в шаге «Новая позиция» подсказывает введённое ранее — главный
  потребитель по замеру.
- Поля форм и ячейки, нарисованные по схеме, подсказывают по тому же адресу и правилу.
- Ни один ответ не раскрывает больше, чем значение: без id записей, имён, частот и дат.
- Отказ выглядит отказом: таймаут — 503, а не пустой список.

**Non-Goals** («Не входит», из эпика):
- **Производная таблица значений** — только если p95 адреса > 150 мс при пределах D2, адрес упирается в
  таймаут или понадобится весь архив, а не окно. По замеру #1528 условие не выполнено ни на копии, ни на
  синтетике. Контракт адреса при переходе не меняется.
- Подсказки в многострочных `text`: по замеру повторов нет (2 значения на всю копию).
- Постоянные поля документов («Публикатор», «Раздел», «Шифр», «Тип документации») — #1540.
- Подсказки в строковых `primitive` и в дописанных полях счёта.
- Экран администратора «не предлагать это значение».
- Строковые поля, которые по смыслу должны быть ссылками («Проект», «Адрес»), — переводятся на ссылку
  (#1540), а не получают подсказку.

## Decisions

### D1. Адресация — тип-владелец + ключ поля
Не путь от корня документа: путь привязан к одному типу документа, ломается от переименования
родительского поля и не даёт значениям переходить между документами. Семью типа по наследованию сервер
находит сам (`IsSameOrDescendant`); потомок, перекрывший ключ своим полем, из семьи выпадает. Как клиент
узнаёт тип-владелец — В-2.

### D2. Чтение на лету из JSONB, без своей таблицы
Ограничители (уточнены замером #1528):
- индекс `(CompositeTypeId, UpdatedAt DESC) WHERE ArchivedAt IS NULL` — без него каждая буква
  распаковывает картинки всех записей типа;
- окно — последние записи семьи по `UpdatedAt`, пока сумма `pg_column_size("Data")` ≤ 8 МБ, и не больше
  1000; у строк массивов — ещё и не больше ~10 000 строк (`suggest-04`);
- `statement_timeout` около 300 мс.
На копии ответ меньше 1 мс, на синтетике с этими пределами p95 не выше 65 мс. Производная таблица
потребовала бы хуков во всех писателей данных, пересборки при правке схемы и при восстановлении копии —
переход на неё только по условию из Non-Goals.

### D3. Что подсказывается — решает одно правило на сервере
`Suggestable` с зеркалом на клиенте и общим файлом случаев. Подсказывается только `string`. Не
подсказываются: `text`, `primitive` (в них ИНН, КПП, телефоны), вычисляемые, запертые, поля с тэгами
однозначности (`identity`, `org.inn`, `doc.number`, `employee.personnelNumber`) и выключенные вручную.
Правило возвращает **код причины**, а не да/нет: редактор типа показывает её вместо флажка.
`work.producesId` из списка согласования выпал сверкой: поле с ним — `boolean`, его отсекает `type`.

### D4. Ручное выключение — функциональный тэг `input.noSuggest`
Не свойство `SchemaField`: новые свойства поля трижды терялись на круге «разобрали → сохранили» (#1004,
#1008, `moduleTitle`), а тэги этот путь проходят давно. В редакторе типа тэг показывается флажком
«Подсказывать введённое ранее», не чипом. Умолчание вычисляется, не хранится: флажка «включить» нет.

### D5. Права читателя — в службе
Источники отбираются по правам читателя приёмом `DataAccess`: значения из документов — с
`id.document.read` и включённым модулем `id`, из общих данных — с `core.catalog.read`. Без обоих — 403.
Значение с другой стройки по инварианту #675 утечкой не считается, но подсказки вписываются в `CLAUDE.md`
в перечень «Условие пересмотра» инварианта `CatalogScope` и в перечень мест `STG-11` (видимость типов,
`TYPE-5`). Право в шаге «Новая позиция» — В-1.

### D6. Архив — «больше не предлагать»
Значения архивных записей не подсказываются: чтение — `RecordsFor.Choice`, новое место чтения — строкой
«выбор» в `ArchiveReadInventoryTests` с живым тестом в `ArchiveReadPurposeTests`.

### D7. `_baseRef` — только свои значения записи
Унаследованная копия частоту основы не поднимает: `_baseRef` при чтении не разрешается.

### D8. Удаления «ошибочной подсказки» нет
Это был бы второй источник истины. Вместо него — порог (со своей стройки от 1 записи, с чужих от 2) и
склейка близнецов. Ошибку исправляют в самой записи — подсказка уходит сама.

### D9. Данные модуля счетов — вне эпика; шаг «Новая позиция» — в эпике
Дописанные поля счёта лежат в `costs.invoices."Data"`, за границей модуля: ядро их читать не вправе
(`InvoiceExtraFields` не подключается). Шаг «Новая позиция» — экран модуля, но заводит он запись
справочника ядра через дверь ядра, и подсказка берёт значения из записей номенклатуры ядра. Поведение
модуля `costs` не меняется: дельты `costs` в эпике нет.

### D10. Контракт адреса (общий для всех задач)
`GET /api/field-suggestions?type=&field=&q=&scope=&scopeId=&limit=8` → `{ items: [{ value, here }] }`,
уже в порядке показа.
- `scope`/`scopeId` — как у `/api/common-data/for-scope`; стройку по ним находит сервер. `here` —
  значение со своей стройки.
- Нормализация на сервере: регистр, ё→е, пробелы. Совпадение — с начала любого слова. Близнецы
  склеиваются. Значение, равное набранному целиком, не отдаётся. Частота — по разным записям, а не по
  вхождениям.
- Пустой `q` — самые частые значения поля.
- Поле, которое не подсказывается, — **200 и пустой список**. Неизвестный тип или поле — 400. Таймаут —
  **503, а не «пусто»**.
- В ответе нет id записей, имён, частот и дат.
- Клиент зовёт адрес не на фокус, а после ввода от 1 символа с задержкой 200 мс, отменяя прошлый
  запрос; кеш 60 с.

### D11. Где живёт код (решение Архитектора, #1530)
Запрос и чистая функция плана источников `SuggestionSources.For(...)` — `Application/Objects/
FieldSuggestions/`; узкий порт `IFieldSuggestionReader` с реализацией в `Infrastructure` — не очередной
partial `DomainObjectRepository`; адрес — `Api/Endpoints/Core`. Порт для модулей не заводится.

### D12. Порядок (поправлен по замеру #1528)
`suggest-01` (#1529) → `suggest-02` (#1530) → `suggest-05` (#1533); `suggest-03` (#1531) — параллельно с
`suggest-02`, до `suggest-05`: от сервера ему нужен только контракт D10. `suggest-04` (#1532) — потом и
необязательно: в строках массивов, набранных руками, повторов почти нет (сбережено 1 из 25), основной
выигрыш — номенклатура, верхний уровень. `suggest-05` подключает ячейки массивов сразу: ответ для них
наполнится, когда появится `suggest-04`.

## Risks / Trade-offs

- [Неверная форма запроса даёт тот же ответ, только в 30 раз дольше] → тест на план, а не на ответ
  (`suggest-02`): EXPLAIN — Limit над Index Scan нового индекса, записи вне окна не читаются.
- [Подсказка с чужой стройки станет утечкой, когда учётную запись выдадут вне компании] → место в
  «Условии пересмотра» `CatalogScope` и в перечне `STG-11`.
- [Ячейки с подсказкой перестанут водить ↑↓ по строкам] → `EditGrid` уступает стрелки только
  `aria-expanded="true"` — первым шагом `suggest-03`.
- [Правило на сервере и на клиенте разойдутся] → общий файл случаев, случай на каждый код причины.
- [Файлы в храповике размера] → флажок, контекст и подключение — в своих файлах.
