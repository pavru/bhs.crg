# Proposal: носители экранов смет — чего не хватает серверу по макету П1

Дочерний change зонтика `plan-00-epic`, общая архитектура — `../plan-00-epic/design.md` (D4, D7, D8, D9,
D17). Серверная часть `plan-09-estimate-ui`: идёт перед его первым PR.

## Why

Раунд макетов П1 (`plan-09`, задача 1.1, выбор владельца 26.10.2026) и сверка носителей с ответами
сервера (задача 1.2, `../plan-09-estimate-ui/design.md`, «Носители макета») показали: выбранный экран
опирается на признаки, которых сервер не отдаёт. По D17 клиент их не вычисляет — иначе «не сопоставлено»
на экране и в плане стройки однажды разойдутся. Сервер смет, импорта и сопоставления строили
`plan-06`…`plan-08`; они в архиве, поэтому дописываем здесь.

Важнее прочих — позиции-материалы ЛСР (ФССЦ, ТЦ, по КА). Сейчас каждая ложится строкой без вида работы
и помечается «не сопоставлена»; в живой ЛСР ЭОМ таких позиций треть и больше, и счётчик «не сопоставлено»
вырастает с 17 до сотни. Решение владельца 26.10.2026: это строка-материал — вида работы не требует, в
«не сопоставлено» не входит, с номенклатурой сопоставляется как материал.

## What Changes

- **Строка сметы** несёт сквозной № п/п из файла (`number`, только для показа — ключ переноса остаётся
  номером в разделе, D9), признак подчинённой позиции и вид позиции: `work` или `material`
  [PLAN-4] [PLAN-7].
- **Неактивная позиция ЛСР не импортируется** (решение владельца 26.10.2026): строки нет, отчёт называет
  её пропущенной, согласия на частичный импорт она не требует [PLAN-7]. Строка-материал не помечается `unmatched` и в план не входит, её материал
  сопоставляется с номенклатурой [PLAN-9.1].
- **Редакция** несёт счётчики «материалов без номенклатуры» и «единица изменилась», ссылку на импорт и
  признак «частично N из M» [PLAN-7] [PLAN-6.1].
- **Разделы ЛСР редакции** — адрес с числом строк, несопоставленных и единицами расценки по разделу
  [PLAN-6.1].
- **Общий список смет** — `GET /api/plan/estimates` без стройки отдаёт сметы всех строек страницами
  [PLAN-20].
- **Предпросмотр смены действующей** — «было → станет» по видам работ, деньги — с `plan.estimate.cost`
  [PLAN-5.2].
- **Коэффициент до записи** — предложение сервера по двум единицам, без правки строк [PLAN-6.1].
- **Массовое сопоставление сверх раздела** — выбранные строки или несколько разделов одним запросом
  [PLAN-6.1].
- **Материалы по материалу** — перечень материалов редакции, сгруппированный по материалу файла, и
  сопоставление группы одним решением [PLAN-9.1].
