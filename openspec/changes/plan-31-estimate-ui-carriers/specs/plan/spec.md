# Spec Delta: plan

## MODIFIED Requirements

### Requirement: [PLAN-1] [PLAN-3] [PLAN-4] Смета, редакции и строки сметы
Смета SHALL составляться на стройку или её раздел и существовать в редакциях. Строка редакции SHALL нести
скелет колонками — позицию перечня, вид работы, объём в единице классификатора, единицу, порядок, раздел
ЛСР, шифр расценки, номер в разделе, номер позиции в файле, вид позиции (работа или материал), признак
подчинённой позиции, стоимость единицы и итог — и сметное наполнение по схеме типа `ПозицияСметы`.
Строка-работа без вида работы и позиции перечня MUST помечаться «не сопоставлена» и MUST NOT попадать в
план, «Ход работ» и график. Строка-материал (позиция ЛСР без работы: материал по КА или по сборнику цен
материалов) вида работы MUST NOT требовать: она не помечается «не сопоставлена», в план не входит, а её
материал сопоставляется с номенклатурой.

#### Scenario: Смета стройки с редакциями
- **WHEN** пользователь с `plan.estimate.read` читает сметы стройки
- **THEN** ответ несёт каждую смету с её редакциями, номером действующей и признаком фиксации у каждой

#### Scenario: Несопоставленная строка
- **WHEN** у строки-работы редакции нет вида работы
- **THEN** строка отдаётся с пометкой `unmatched` и не входит в план стройки

#### Scenario: Позиция-материал
- **WHEN** импортирована ЛСР, в которой позиция — материал по КА
- **THEN** строка отдаётся с видом `material`, без пометки `unmatched`, в счётчик «не сопоставлено» не входит,
  а её материал без номенклатуры помечен «не сопоставлен»

#### Scenario: Вид работы для материала
- **WHEN** сметчик сопоставляет строку-материал с видом работы
- **THEN** ответ 400 «это материал, а не работа», строка не меняется

#### Scenario: Номер позиции
- **WHEN** читаются строки редакции, импортированной из файла с позициями «13» и «13.1»
- **THEN** строки несут номера «13» и «13.1» как в файле, а у «13.1» — признак подчинённой позиции

## ADDED Requirements

### Requirement: [PLAN-7] Неактивная позиция ЛСР не импортируется
Позиция, отмеченная в файле неактивной, SHALL NOT становиться строкой редакции. Отчёт импорта MUST
называть её пропущенной с местом в файле — отдельно от не разобранных: «разобрано N из M» она не уменьшает
и согласия на частичный импорт не требует.

#### Scenario: Расчёт с неактивной позицией
- **WHEN** импортирована ЛСР из 300 позиций, одна из которых неактивна
- **THEN** отчёт говорит «разобрано 300 из 300» и называет одну пропущенную неактивную, редакция создаётся из
  299 строк без подтверждения частичного импорта

### Requirement: [PLAN-7] [PLAN-6.1] Счётчики редакции и её импорт
Редакция SHALL нести, кроме числа строк и несопоставленных, число материалов без номенклатуры, число строк
с изменившейся единицей, ссылку на импорт, из которого создана, и признак «частично N из M», если редакция
создана из неполного разбора. Счётчики MUST считаться сервером.

#### Scenario: Частичная редакция
- **WHEN** редакция создана из импорта «280 из 300» с согласием на частичный
- **THEN** у редакции есть `partial` с числами 280 и 300 и ссылка на импорт — у читающего с `plan.estimate.read`

#### Scenario: Материалы без номенклатуры
- **WHEN** у редакции 9 материалов без номенклатуры
- **THEN** редакция несёт `materialsUnmatched: 9`

### Requirement: [PLAN-6.1] Разделы ЛСР редакции
Адрес `GET /api/plan/revisions/{id}/sections` SHALL отдавать разделы ЛСР редакции в порядке файла с числом
строк, несопоставленных строк, материалов без номенклатуры и единицами расценки раздела — под
`plan.estimate.read`, за воротами модуля.

#### Scenario: Свёрнутые разделы
- **WHEN** экран читает разделы редакции из 30 разделов и 300 строк
- **THEN** один ответ несёт 30 разделов со счётчиками, строки не читаются

### Requirement: [PLAN-20] Общий список смет
`GET /api/plan/estimates` без стройки SHALL отдавать сметы всех строек страницами, с курсором, стройкой и
разделом у каждой сметы; без `plan.estimate.cost` — без денег, с носителем «скрыто правами».

#### Scenario: Сметы всех строек
- **WHEN** пользователь с `plan.estimate.read` читает список без `constructionId`
- **THEN** ответ — страница смет разных строек и курсор следующей, а не 400

### Requirement: [PLAN-5.2] Предпросмотр смены действующей редакции
Адрес `GET /api/plan/estimates/{id}/current-revision/preview?revisionId=` SHALL отдавать без правки только
изменившиеся объёмы плана по видам работ «было → станет», число несопоставленных строк новой редакции и
версию сметы — под `plan.estimate.edit`. Деньги «было → станет» MUST отдаваться только с
`plan.estimate.cost`.

#### Scenario: Предпросмотр
- **WHEN** сметчик смотрит смену действующей с редакции 2 на 3
- **THEN** ответ называет виды работ, у которых объём меняется, с обоими объёмами, а действующая остаётся 2

#### Scenario: Без права на себестоимость
- **WHEN** предпросмотр читает пользователь с `plan.estimate.edit` без `plan.estimate.cost`
- **THEN** в ответе нет денег, есть `hidden` с правом `plan.estimate.cost`

#### Scenario: Только чтение
- **WHEN** предпросмотр вызывает пользователь с одним `plan.estimate.read`
- **THEN** ответ 403

### Requirement: [PLAN-6.1] Коэффициент пересчёта до записи
Адрес `GET /api/plan/unit-factor?sourceUnit=&unitId=` SHALL предлагать коэффициент из единицы расценки в
единицу классификатора тем же правилом, что сопоставление, и ничего не записывать. Не выводимый
коэффициент MUST отдаваться пустым с причиной, а не единицей.

#### Scenario: Укрупнённая единица
- **WHEN** спрошен коэффициент из «100 шт» в «шт»
- **THEN** ответ — 100 и обе единицы

#### Scenario: Несоизмеримые единицы
- **WHEN** спрошен коэффициент из «м» в «шт»
- **THEN** коэффициента нет, причина названа

### Requirement: [PLAN-6.1] Массовое сопоставление строк
Адрес `POST /api/plan/revisions/{id}/lines/match` SHALL сопоставлять выбранные строки или несколько
разделов ЛСР одним запросом и одной фиксацией, отвечая числом сопоставленных и пропущенными с причиной.
Строки-материалы MUST пропускаться с причиной. Адрес стоит под `plan.estimate.edit` за воротами модуля и
MUST требовать `If-Match` с версией редакции.

#### Scenario: Два раздела
- **WHEN** сметчик сопоставляет два раздела ЛСР одним видом работы
- **THEN** ответ называет число сопоставленных строк обоих разделов и пропущенные с причиной, версия редакции
  сдвинута один раз

#### Scenario: Без версии
- **WHEN** запрос пришёл без `If-Match`
- **THEN** ответ 400, строки не меняются

#### Scenario: По устаревшей версии
- **WHEN** редакцию тем временем изменили
- **THEN** ответ 409 «редакцию тем временем изменили», ни одна строка не сопоставлена

#### Scenario: Только чтение
- **WHEN** запрос шлёт пользователь с одним `plan.estimate.read`
- **THEN** ответ 403

#### Scenario: Пользователь без модуля
- **WHEN** «Инженер ИД» вызывает адрес
- **THEN** ответ — отказ ворот модуля

### Requirement: [PLAN-9.1] Материалы редакции по материалу
Адрес `GET /api/plan/revisions/{id}/materials` SHALL отдавать материалы редакции группами по материалу файла
(шифр, наименование, единица) с числом строк, суммой количества и номенклатурой; цена — только с
`plan.estimate.cost`. Адрес `PUT /api/plan/revisions/{id}/materials/match` SHALL сопоставлять все ресурсы
группы с позицией номенклатуры одной фиксацией — под `plan.estimate.edit`, за воротами модуля, с
`If-Match` версии редакции.

#### Scenario: Один материал во многих строках
- **WHEN** кабель ВВГнг 3×2,5 стоит в 14 строках, и сметчик сопоставляет его группу
- **THEN** все 14 ресурсов получают позицию номенклатуры, ответ называет их число

#### Scenario: Без версии
- **WHEN** сопоставление группы пришло без `If-Match`
- **THEN** ответ 400, ресурсы не меняются

#### Scenario: По устаревшей версии
- **WHEN** редакцию тем временем изменили
- **THEN** ответ 409, ни один ресурс группы не сопоставлен

#### Scenario: Только чтение
- **WHEN** сопоставление группы шлёт пользователь с одним `plan.estimate.read`
- **THEN** ответ 403
