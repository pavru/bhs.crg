# Spec Delta: work

## ADDED Requirements

### Requirement: [WORK-28] Очередь приёмки с пометками сервера
Страница «Приёмка» SHALL показывать отчёты, ждущие решения, с отбором по стройке, дате и сотруднику.
Пометки строки MUST браться из `marks` ответа, а чипы отбора — из счётчиков сервера по кодам; клиент
пометок не вычисляет. Чип с нулём не рисуется. Код, которого клиент не знает, показывается текстом
сервера.

#### Scenario: Пометки строки
- **WHEN** у строки очереди в ответе `marks` стоят «правка после подачи» и «ввёл и принял один человек»
- **THEN** строка показывает обе пометки текстом сервера

#### Scenario: Нулевой счётчик
- **WHEN** счётчик кода «расхождение в бригаде» в ответе равен 0
- **THEN** чипа этого кода над очередью нет

#### Scenario: Отбор по коду
- **WHEN** менеджер нажимает чип «фото не догружены 3»
- **THEN** очередь перечитывается с сервера с отбором по этому коду и показывает три отчёта

#### Scenario: Новый код до обновления клиента
- **WHEN** сервер прислал код пометки, которого нет в каталоге клиента
- **THEN** пометка и чип показываются текстом сервера, а не пропадают

### Requirement: [WORK-28] [WORK-39] [CORE-24.3] Граница выдачи и пустая очередь
Очередь SHALL показывать границу выдачи из ответа («отчёты ваших строек (4)», «все стройки»). Пустая
очередь MUST называть причину по полю `reason`: `not-assigned` — «вы не назначены ни на одну
стройку», `nothing-pending` — «ждущих решения нет», `filtered-out` — «отбор скрыл все отчёты» со
сбросом отбора.

#### Scenario: Менеджер без назначений
- **WHEN** у менеджера нет ни одного действующего назначения «менеджер», и сервер отвечает `reason: not-assigned`
- **THEN** вместо сетки страница говорит «вы не назначены ни на одну стройку»

#### Scenario: Отбор исключил всё
- **WHEN** сервер отвечает пустым списком с `reason: filtered-out`
- **THEN** страница говорит, что отбор скрыл все ждущие отчёты, и предлагает сбросить отбор

#### Scenario: Руководитель
- **WHEN** очередь открывает пользователь только с `work.report.read.all`, и у строк `actions` пуст
- **THEN** граница выдачи говорит «все стройки», а действий приёмки у строк нет

### Requirement: [WORK-30] [WORK-39] Карточка отчёта и отказ 404
Карточка SHALL показывать шапку «сотрудник · стройка · дата · смена» (ночная — со знаком ☾), часы на
отчёт, строки, фото и ленту журнала. Отчёт вне доступа MUST давать фразу «Отчёт не найден: его нет,
или он вне ваших строек» — одинаковую для несуществующего и чужого, по ответу 404.

#### Scenario: Отчёт чужой стройки по ссылке
- **WHEN** менеджер открывает ссылку на отчёт стройки, на которую не назначен
- **THEN** сервер отвечает 404, и карточка показывает «Отчёт не найден: его нет, или он вне ваших строек»

#### Scenario: Ночная смена
- **WHEN** открыт отчёт ночной смены
- **THEN** шапка показывает дату начала смены и знак ☾

#### Scenario: Фото ещё не догружены
- **WHEN** ответ карточки говорит, что двух фото строки нет на сервере
- **THEN** строка показывает «фото не загружены: 2», а кнопка «Принять» доступна

### Requirement: [WORK-13] [WORK-31.1] Приёмка и возврат
«Принять» и «Вернуть» SHALL открывать окна 512 px и отправлять версию отчёта из чтения. Возврат MUST
требовать комментарий. При истинном `acceptWouldMark` окно заранее говорит об отметке «ввёл и принял
один человек». Отказ 409 по версии — «отчёт тем временем изменили — перечитайте», по статусу —
состояние из тела отказа («отчёт уже принят»).

#### Scenario: Возврат без комментария
- **WHEN** менеджер нажимает «Вернуть» и не пишет комментарий
- **THEN** кнопка записи окна неактивна, и подсказка называет, чего не хватает

#### Scenario: Принимает тот, кто ввёл
- **WHEN** в ответе карточки `acceptWouldMark` истинно
- **THEN** рядом с «Принять» и в окне приёмки видна подпись об отметке «ввёл и принял один человек»

#### Scenario: Отчёт уже принят соседом
- **WHEN** второй менеджер принял отчёт, и сервер отвечает 409 с `status` «принят»
- **THEN** окно говорит «отчёт уже принят» и после закрытия показывает карточку в новом статусе

#### Scenario: Досылка под открытым окном
- **WHEN** монтажник дослал правку, пока окно приёмки было открыто, и менеджер принимает
- **THEN** сервер отвечает 409, окно остаётся открытым и предлагает перечитать отчёт

### Requirement: [WORK-14] [WORK-30] Действия — только разрешённые сервером
Карточка SHALL рисовать «Принять», «Вернуть» и правку строк, только если их называет ответ сервера.
Без действий кнопок MUST не быть вовсе, а не неактивных. Правка строк менеджером — пункт меню
карточки, а не главная кнопка: основной ход — возврат.

#### Scenario: Руководитель открывает отчёт
- **WHEN** карточку открывает пользователь только с `work.report.read.all`
- **THEN** в карточке нет ни «Принять», ни «Вернуть», ни правки строк

#### Scenario: Правка строк менеджером
- **WHEN** менеджер выбирает в меню карточки «Править строки» и сохраняет
- **THEN** правка уходит с версией отчёта, а после ответа строка показывает пометку «правка менеджером» из ответа

### Requirement: [WORK-54] Черновик менеджеру — наличием
Карточка черновика у менеджера SHALL показывать только «черновик» и момент автоподачи из ответа, без
строк, часов и фото. Содержимое MUST появляться после подачи.

#### Scenario: Менеджер открывает черновик
- **WHEN** менеджер открывает отчёт в статусе «черновик»
- **THEN** карточка говорит «черновик, автоподача 23.10 в 23:59 по времени стройки» и строк не показывает

### Requirement: [WORK-15] Версии отчёта закрытого периода
Если ответ карточки называет версии отчёта, карточка SHALL показывать переключатель версий: по
умолчанию — действующая, у прошлых — причина исправления и кто его сделал. Прошлая версия MUST
показываться только для чтения.

#### Scenario: Отчёт исправлен после закрытия
- **WHEN** у отчёта в ответе две версии
- **THEN** карточка открывается на действующей, а переключатель показывает прошлую с причиной исправления
