# Proposal: очередь приёмки и карточка отчёта

Дочерний change зонтика `work-00-epic`, общая архитектура — `../work-00-epic/design.md` (D11, D15, D17).

## Why

Сервер приёмки (`work-16`) отдаёт очередь с пометками, счётчики по кодам, `acceptWouldMark` и действия
приёмки. Без экрана менеджер не примет ни одного отчёта, а значит, ни один объём не дойдёт до
первички и закрытия периода (`WORK-28`, `WORK-30`). Отметка «ввёл и принял один человек» обязана быть
видна в очереди и в карточке, а не только в журнале (`WORK-31.1`): журнал никто не открывает, пока не
случилось плохое.

## What Changes

**PR 1 — очередь.**
- Страница «Приёмка» в разделе рейла модуля (`work-03`): отчёты, ждущие решения, отбор по стройке,
  дате и сотруднику.
- Пометки строки — из `marks: [{code, text}]` сервера; чипы отбора по кодам со счётчиками сервера.
  Чип с нулём не рисуется.
- Граница выдачи «отчёты ваших строек (N)» и пустые состояния с причиной, в том числе «вы не назначены
  ни на одну стройку» (`reason: not-assigned`).
- Клиентский каталог кодов пометок; код, которого клиент не знает, показывается текстом сервера.

**PR 2 — карточка.**
- Карточка отчёта: шапка «сотрудник · стройка · дата · смена» с ☾, часы, строки, фото, лента журнала.
- «Принять» и «Вернуть» — окна `Modal` 512 px. Возврат — с обязательным комментарием. Рядом с
  «Принять» — подпись по `acceptWouldMark`.
- Правка строк менеджером — запасным ходом, из меню, а не главной кнопкой (`WORK-14`).
- Переключатель версий отчёта закрытого периода (`work-19`).
- Отказ 404 — фразой «Отчёт не найден: его нет, или он вне ваших строек». Без права на действия
  кнопок нет вовсе: «Руководитель» видит карточку только для чтения.
- Черновик менеджеру — наличием и моментом автоподачи, без содержимого (`WORK-54`).

Печать отчёта и табеля в change не входит; вопрос владельцу задаётся в раунде Р4.
