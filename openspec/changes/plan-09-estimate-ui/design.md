## Goals / Non-Goals

**Goals:** сметчик без инструкции проходит путь «файл → редакция → сопоставление → действующая»; ни одно
отсутствие (денег, сопоставления, разбора) не выглядит пустотой.

**Non-Goals:** распределение (`plan-10`, макеты П2); КП и производные под сметой (`plan-16`, `plan-17`);
конъюнктурный анализ (`plan-11`).

## Макеты П1

Проект Claude Design — [«П1 · Экраны смет»](https://claude.ai/design/p/03f60dfc-de8c-4660-ae27-5fdc8b271a42?file=%D0%AD%D0%BA%D1%80%D0%B0%D0%BD%D1%8B+%D1%81%D0%BC%D0%B5%D1%82.html),
файл «Экраны смет.html»: лист 0 — общее, носители, отказы импорта, вопросы; варианты 1 «смета в карточке
стройки, работа — окнами», 2 «рабочее место во всю ширину», 3 «очередь: что ждёт решения». Разбор
Дизайнера — `_designer-report.md`, §75 (до макетов — A…D, после — E).

**Выбор владельца 26.10.2026 — смесь по рекомендации Дизайнера:**

- **Основа — вариант 1.** Смета на месте в карточке стройки (824 px, П0 в силе), редакции вкладками,
  работа в окнах `Modal wide`. Видны действующая и последние редакции, остальные — в «ещё N» (у живой
  сметы их 5–10). Ширина таблице — за счёт неё самой: колонки «Пометки» нет (пометка — в клетке вида
  работы), шифр в одну строку с обрезкой, разделы ЛСР по умолчанию свёрнуты. Страница во всю ширину
  (вариант 2) — запасной ход до П4.
- **Из варианта 3 — «что ждёт», без окна во весь экран.** Полоса чипов над таблицей: «не сопоставлено ▸ ·
  без номенклатуры ▸ · ед. изменилась ▸ · частично 280 из 300 ▸», чип ставит отбор. В окне раздела —
  «применить и к следующему разделу». Материалы — по материалу (один материал во многих строках — одно
  решение), а не по строке. Пометка «частично» остаётся у редакции.
- **Из варианта 2 — отчёт импорта.** Причины не разобранного сгруппированы; частичная редакция
  создаётся кнопкой, называющей последствие («Создать редакцию без 20 строк…»), и подтверждением.

| «Запомнить» | включено по умолчанию; ошибку исправляют в списке запомненного |

**Найдено разбором и обязательно при коде** (Дизайнер, §75 E): тон «не действующая» — neutral, а не
warning; в окне раздела — чипы единиц и пример коэффициента («2,16 × 100 шт = 216 шт»); права `read`,
`edit`, `cost` независимы, недоступное скрыто; флажки и переключатели — `Checkbox` и `Switch` из
`shared/ui`, а не самодельные; без `color-mix` и своих ширин экрана.

## Decisions

- **Порядок.** Разбор с Дизайнером → три макета П1 в Claude Design → выбор владельца → код. Выбор — в
  «Макеты П1» выше. Код PR 1 стартует после слияния `plan-31-estimate-ui-carriers`.
- **Носители — с сервера** (D17). Клиент не вычисляет:
  - «зафиксирована» и чем — поле редакции;
  - `unmatched`, «запомнено», `unit-changed` — пометки строки кодом;
  - «скрыто правами» — `hidden: ["cost"]` с кодом права; колонка стоимости — в состоянии «нет права»
    у `DataGrid` (CORE-33), как в таблицах других модулей (решение владельца 26.10.2026);
  - счётчики «не сопоставлено: N», «без номенклатуры: N», по разделам ЛСР — полями ответа
    (`plan-31`).
- **Действующая редакция** (решение В-5 (а)): первая редакция становится действующей
  сама; «сделать действующей» у следующих — окно с расхождениями «план по виду работ: было → станет»,
  которые считает сервер.
- **Импорт** (решение В-12 (а)): человек выбирает «новая редакция сметы X» или «новая
  смета». Разбор — фоновая операция (`plan-07`), ход — поллингом `GET /api/jobs/active`, как прочие долгие
  операции. Отчёт «N из M» — с раскрытием не разобранных строк и причин; «создать редакцию» доступно и при
  неполном разборе, но только явным выбором.
- **Сопоставление** — по разделам ЛСР: раздел целиком одним действием, исключения — построчно.
  Коэффициент предлагается сервером из единиц, поле показывает обе единицы («100 м → м, × 100»). «Новый
  вид работы» видно только при `core.worktypes.edit` — невыполнимое действие скрывается.
- **Запросы.** `shared/api/planningEstimates.ts`, `planningMatches.ts`: правки с `If-Match`, разбор 400,
  403, 409 («редакцию тем временем изменили — перечитайте»), набранное в окне при 409 сохраняется.
- **Живой прогон** `e2e/planning-estimates-smoke.mjs`: посев — смета с двумя редакциями, одна строка без
  сопоставления; «Сметчик» видит стоимость, пользователь с одним `plan.estimate.read` — «скрыто правами».

## Risks / Trade-offs

- [300 строк в одной таблице] → группировка по разделу ЛСР и отбор «только несопоставленные» — в макете.
- [Пометок много, таблица шумит] → пометки — чипами из `shared/ui` (`ui:ratchet`, #1416), набор и
  порядок — по макету.
- [Сервер не отдаёт нужный макету признак] → дописывается в серверный change до кода экрана, а не
  вычисляется на клиенте: перечень «нет» выше — `plan-31-estimate-ui-carriers`.
