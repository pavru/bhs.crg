## Goals / Non-Goals

**Goals:** сметчик без инструкции проходит путь «файл → редакция → сопоставление → действующая»; ни одно
отсутствие (денег, сопоставления, разбора) не выглядит пустотой.

**Non-Goals:** распределение (`plan-10`, макеты П2); КП и производные под сметой (`plan-16`, `plan-17`);
конъюнктурный анализ (`plan-11`).

## Decisions

- **Порядок.** Разбор с Дизайнером → три макета П1 в Claude Design → выбор владельца → код. Выбор — в
  «Макеты П1» выше. Код PR 1 стартует после слияния `plan-31-estimate-ui-carriers`.
- **Носители — с сервера** (D17). Клиент не вычисляет:
  - «зафиксирована» и чем — поле редакции;
  - `unmatched`, «запомнено», `unit-changed` — пометки строки кодом;
  - «скрыто правами» — `hidden: ["cost"]` с кодом права; колонка стоимости — в состоянии «нет права»
    у `DataGrid` (CORE-33), как в таблицах других модулей (решение владельца 26.10.2026);
  - счётчики «не сопоставлено: N», «без номенклатуры: N», по разделам ЛСР — полями ответа
    (`plan-31`).
- **Действующая редакция** (решение В-5 (а)): первая редакция становится действующей
  сама; «сделать действующей» у следующих — окно с расхождениями «план по виду работ: было → станет»,
  которые считает сервер.
- **Импорт** (решение В-12 (а)): человек выбирает «новая редакция сметы X» или «новая
  смета». Разбор — фоновая операция (`plan-07`), ход — поллингом `GET /api/jobs/active`, как прочие долгие
  операции. Отчёт «N из M» — с раскрытием не разобранных строк и причин; «создать редакцию» доступно и при
  неполном разборе, но только явным выбором.
- **Сопоставление** — по разделам ЛСР: раздел целиком одним действием, исключения — построчно.
  Коэффициент предлагается сервером из единиц, поле показывает обе единицы («100 м → м, × 100»). «Новый
  вид работы» видно только при `core.worktypes.edit` — невыполнимое действие скрывается.
- **Запросы.** `shared/api/planningEstimates.ts`, `planningMatches.ts`: правки с `If-Match`, разбор 400,
  403, 409 («редакцию тем временем изменили — перечитайте»), набранное в окне при 409 сохраняется.
- **Живой прогон** `e2e/planning-estimates-smoke.mjs`: посев — смета с двумя редакциями, одна строка без
  сопоставления; «Сметчик» видит стоимость, пользователь с одним `plan.estimate.read` — «скрыто правами».

## Решения при коде (PR 1)

Мелкие, по ходу реализации группы 2; заметных (поведение, тексты, отказ) среди них нет — кроме последнего пункта,
вынесенного вопросом.

- **Имя права у колонки «нет права».** Каталог прав (`/api/roles/permissions`) читающему смету закрыт правом на
  пользователей, а «имя права — из каталога, без кода». Поэтому носитель `hidden` несёт и имя: `{code, permission,
  name}`, `name` — `PlanModule.EstimateCostGives`, та же строка, что объявляет право. Сетка получила
  `DataGridColumn.unavailableHint` — причина закрытой колонки словами экрана в подсказке шапки и клетки.
- **Строки редакции читаются целиком** (страницами по 1000, предел сервера): разделы, отбор и поиск — по всем
  строкам; неполный ответ показал бы раздел «всё сопоставлено», не дочитав его.
- **Отбор чипом раскрывает разделы**, где есть подходящие строки, и прячет остальные; без отбора разделы свёрнуты
  (макет). Чипы «что ждёт» по строкам — по счётчикам редакции (`unmatched`, `unitChanged`); пустой чип не
  показывается. Число на чипе — всегда число СТРОК, которые он покажет (ревью PR #1648): поэтому «Без номенклатуры»
  и «Запомнено» (макеты 1 и 3: неверно запомненное очередь прячет) считаются по пометкам прочитанных строк —
  счётчик `materialsUnmatched` считает материалы, и «3» при одной строке под чипом искали бы глазами. Отбор — по
  пометкам сервера (D17), а не по полям: «без номенклатуры» — пометка `unmatched` у материала строки, «Запомнено» —
  пометка `remembered` у строки ИЛИ у её материала (материал запоминается своим ключом); пометка «запомнено»
  в клетке вида работы — по тому же правилу, и у позиции-материала тоже. Заголовок раздела по-прежнему называет
  число материалов без номенклатуры (`materialsUnmatched` раздела).
- **Вкладок редакций — четыре**: действующая, последние по номеру и открытая из «ещё N».
- **«Частично N из M»** — пометкой в полосе редакции; переход к отчёту импорта — с экраном импорта (PR 2).
- **Список смет стройки**: «Ждут» — несопоставленные строки последней редакции (её и разбирают), «Себестоимость» —
  итог действующей. На уровне стройки видны все её сметы, у сметы раздела — имя раздела; на странице раздела —
  только сметы раздела.
- **Общий список смет ждёт «Избранные стройки»**: пока фильтр грузится — «Читаем сметы…», а не пустая сетка
  «Отбор ничего не нашёл» со «скрыто N» (ревью PR #1648).
- **Смета из глобального раздела открывается в нём же** — `/estimates/{id}`, рейл остаётся «Планы»; из карточки
  стройки — адресом панели `…/estimates/{id}`.
- **«Сметы» — панель по умолчанию** у человека с правом: первая видимая блока «Работы» (правило `plan-02`).
- **Телефон — только чтение**: «Сделать действующей» скрыта ниже 768 px (`useMedia(WIDE)`), как и без права.
- **Смена действующей при 409** — окно остаётся открытым на той же редакции, отказ назван над кнопкой, предпросмотр
  перечитывается (его ключ под ключом сметы), повтор идёт по новой версии.
- **Общий список смет урезается «Избранными стройками»** (#1432), как все списки по стройкам: отбор «Стройки» над
  таблицей, число скрытых — по прочитанным страницам. В макете отбора нет — вопрос владельцу, если нужно иначе.

## Решения при коде (PR 2)

Мелкие, по ходу реализации группы 3.

- **Окно загрузки — шаги одного окна** `Modal wide` «Файл и цель → Разбор → Отчёт» (макет 1в). Цели по умолчанию нет:
  без выбранной сметы или имени новой «Загрузить» недоступна и называет, чего не хватает. Из карточки сметы цель —
  её новая редакция, выбора нет; на странице раздела новая смета ложится в этот раздел, если не выбрать другой.
- **Ход разбора в окне** — перечитыванием отчёта импорта раз в секунду, пока `parsing`: его `progress` — слова той же
  задачи очереди, что показывает общий индикатор фоновых задач (`/api/jobs/active`). Конец задачи в индикаторе
  перечитывает импорты стройки — полоса «ждёт решения» меняет «разбирается» на исход.
- **Частичная редакция** — кнопкой «Создать редакцию без N строк…» и подтверждением шагом окна (`WindowStep`), а не
  флажком из 1в: смесь берёт отчёт из варианта 2. Подтверждение называет, сколько войдёт, и что недостающее
  добавляется только новой загрузкой.
- **Закрыть без решения** — крестиком: импорт остаётся полосой «ждёт решения». «Закрыть» в подвале — только там, где
  решать нечего (отказ разбора, не ЛСР).
- **«Ждёт решения»** — списком над сметами стройки (на странице раздела — его сметы и новые сметы раздела) и над
  карточкой сметы — её импорты; только с `plan.estimate.edit`. В общем разделе полосы нет: импорты сервер отдаёт
  по стройке, а закрытый там импорт виден в панели «Сметы» его стройки.
- **Общий раздел** — «Загрузить смету» со стройкой в окне; список строек — с «Избранными» первыми (#1432).
- **После «Создать редакцию»** — карточка сметы на созданной редакции, с отбором «не сопоставлено», если оно есть
  (ответ листа 0), и уведомление «Ред. N … создана» — «и стала действующей», если это первая.
- **ВОР и КА до `plan-11`** (решение владельца 26.10.2026): отчёт называет вид документа, «Создать редакцию» нет, есть
  «Убрать импорт». Приложить файл к смете пока некуда, поэтому отказ сервера (`NotEstimate`, он же пометка
  `notEstimate`) говорит убрать импорт, а не «приложите файл к смете» — сценарий «Загружена ВОР» изменён дельтой.
  Кнопку «Приложить к смете» и прежнюю фразу возвращает `plan-11` вместе с хранилищем.
- **Неактивные позиции** — свёрнутым списком «строками не станут»: в «N из M» они разобранные. Итог без права —
  «итог скрыт: нужно право «…»», а не пустое место.

## Risks / Trade-offs

- [300 строк в одной таблице] → группировка по разделу ЛСР и отбор «только несопоставленные» — в макете.
- [Пометок много, таблица шумит] → пометки — чипами из `shared/ui` (`ui:ratchet`, #1416), набор и
  порядок — по макету.
- [Сервер не отдаёт нужный макету признак] → дописывается в серверный change до кода экрана, а не
  вычисляется на клиенте: перечень «нет» выше — `plan-31-estimate-ui-carriers`.
