# Proposal: «Ход работ» стройки и факт в графике

Дочерний change зонтика `plan-00-epic`, общая архитектура — `../plan-00-epic/design.md` (D10, D16, D17, D18, D2).

> **Корректировка 26.11.2026.** Полную форму `IActualWorks` и настоящего поставщика атомарно
> поставляет `work-27-actual-works-contract`. Этот change начинается после слияния его кода и архива.
> 26.11.2026 владелец отдельной командой возобновил Plan-25 после подтверждения кода и архива Work-27.

## Why

Экран «Ход работ» на странице стройки — ради него три модуля и делят позицию перечня: строка — вид
работы, колонки — план по смете, срок по графику, факт по учёту, закрыто актом (`PLAN-21`). Строки без
пары не прячутся: работа без плана и план без факта — это и есть то, что нужно увидеть. Над таблицей —
полосы, без которых цифры врут: план не по той редакции, несопоставленные строки сметы, нераспределённый
план при отборе по разделу, затраты `costs` (`PLAN-21.1`), «учёт работ не подключён».

Экран собирает ядро: оно не знает модулей (`OVW-12`), а у каждой колонки свой владелец. Контракт
«Фактические работы» приходит из завершённого Work-27: включённый Work обязан иметь настоящего
поставщика уже при объявлении интерфейса (`CORE-34`). «Ход работ» проверяется и на настоящем Work,
и на синтетическом факте в отдельном тестовом составе (`STG-6.1`). Исключённые Work-27 бригадные
группы показываются с причинами: неполный факт нельзя представить полным или заменить нулём.

## What Changes

- **PR 1 — ядро и контракты.**
  - Потребление готового интерфейса «Фактических работ» из Work-27: действующие принятые объёмы,
    диагностика исключений и их охват, без часов, людей и идентификаторов отчётов.
  - Контракт «Колонка Хода работ» со многими поставщиками: модуль отдаёт свои колонки по позициям
    перечня и свои полосы с состоянием.
  - Адрес ядра `GET /api/constructions/{id}/progress?section=` под «любым из» прав колонок: строки по виду
    работы (через позиции перечня), колонки вкладов, факт — из «Фактических работ», полоса затрат — из
    «Фактических затрат» (`plan-24`). Колонка без права — «скрыто правами», без поставщика — «не
    подключено».
  - Раздел ядра `progress` и его объявления у `plan`, `costs` и `work` вместе с первым потребителем.
  - Настоящий Work в интеграционных тестах; синтетический поставщик в отдельном тестовом составе
    без второй регистрации поверх production Work; режим без Work сохраняется.
- **PR 2 — вклад `plan` и факт графика.**
  - Колонки «план по смете» (сумма действующих редакций, распределение при отборе по разделу) и «срок
    по графику»; полосы «план по: смета … ред. N», «строк сметы не сопоставлено: N ▸», «не распределено по
    разделам: … — план всей стройки ▸».
  - Факт в работах графика из «Фактических работ»; при выключенном `work` — состояние «учёт работ не
    подключён», а не нули (`PLAN-18`). При исключениях — неполный факт с причинами и охватом диагностики.
- **PR 3 — экран** (макеты П5). Панель «Ход работ» в карточке стройки (механизм `plan-02`), таблица на
  `DataGrid`, полосы с состояниями, отбор по разделу; колонка факта в списке графика (`plan-20`).
  Неполнота факта видна и при отборе по разделу; доступ к отчётам не следует из `work.facts.read`.

## Capabilities

### New Capabilities
- Нет.

### Modified Capabilities
- `core`: экран «Ход работ» — адрес, сборка из вкладов, состояния колонок и полос; контракт «Колонка
  Хода работ»; потребление формы «Фактических работ» и безопасной диагностики из Work-27.
- `plan`: вклад модуля в «Ход работ», факт в работах графика.

## Impact

- **Контракты:** новый `ProgressContribution.cs`; готовый `ActualWorks.cs` принадлежит Work-27.
- **Сервер:** ядро — `Api/Endpoints/Core/ConstructionProgressEndpoints.cs` и сборщик; модуль —
  `Modules.Plan/Exchange/PlanProgressContribution.cs`, факт в ответе графика.
- **Клиент:** `src/client/src/features/planning/progress/*`, `shared/api/progress.ts`, регистрация панели.
- **Тесты:** `src/server/BHS.CRG.Tests/Plan/ConstructionProgress*` с настоящим и отдельно пробным
  модулем `work`, живой прогон `e2e/progress-smoke.mjs` с Work и без него.
- **Документы:** `docs/USER_GUIDE.md` — «Ход работ», его полосы и оговорки.
- **Этап 4:** `work-27` поставляет интерфейс и реализацию до этого change; колонку факта рисует ядро, вклад `work` в колонки не
  нужен. Полоса «по смете — фактически» — вклад `work-28` тем же контрактом колонок.
- **Зависит от:** кода и архива `work-27`; `plan-02` (панель, «любое из»), `plan-04`, `plan-22`,
  `plan-23`, `plan-24`, `plan-19`. Три PR строго последовательны: следующий начинается после слияния
  предыдущего, подтверждённого бот-бампа и обновления базы.
