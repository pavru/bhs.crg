# Proposal: «Ход работ» стройки и факт в графике

Дочерний change зонтика `plan-00-epic`, общая архитектура — `../plan-00-epic/design.md` (D10, D16, D17, D18, D2).

## Why

Экран «Ход работ» на странице стройки — ради него три модуля и делят позицию перечня: строка — вид
работы, колонки — план по смете, срок по графику, факт по учёту, закрыто актом (`PLAN-21`). Строки без
пары не прячутся: работа без плана и план без факта — это и есть то, что нужно увидеть. Над таблицей —
полосы, без которых цифры врут: план не по той редакции, несопоставленные строки сметы, нераспределённый
план при отборе по разделу, затраты `costs` (`PLAN-21.1`), «учёт работ не подключён».

Экран собирает ядро: оно не знает модулей (`OVW-12`), а у каждой колонки свой владелец. Учёт работ
придёт этапом 4, а форма «Фактических работ» нужна сейчас — экрану и графику (`PLAN-18`). Поэтому
интерфейс контракта заводится здесь, а «Ход работ» проверяется на синтетическом факте, засеянном в CI,
а не на пустом (`STG-6.1`). Поставщика строит `work-27`.

## What Changes

- **PR 1 — ядро и контракты.**
  - Интерфейс «Фактических работ» (`BHS.CRG.Modules/Exchange/ActualWorks.cs`, поставщик `work`): принятые
    объёмы по позиции перечня, дате, смене и разделу — без часов и людей (`CORE-34`, `WORK-57`); не
    вошедшее — числом.
  - Контракт «Колонка Хода работ» со многими поставщиками: модуль отдаёт свои колонки по позициям
    перечня и свои полосы с состоянием.
  - Адрес ядра `GET /api/constructions/{id}/progress?section=` под «любым из» прав колонок: строки по виду
    работы (через позиции перечня), колонки вкладов, факт — из «Фактических работ», полоса затрат — из
    «Фактических затрат» (`plan-24`). Колонка без права — «скрыто правами», без поставщика — «не
    подключено».
  - Синтетический поставщик «Фактических работ» в тестах — пробный модуль с кодом `work`.
- **PR 2 — вклад `plan` и факт графика.**
  - Колонки «план по смете» (сумма действующих редакций, распределение при отборе по разделу) и «срок
    по графику»; полосы «план по: смета … ред. N», «строк сметы не сопоставлено: N ▸», «не распределено по
    разделам: … — план всей стройки ▸».
  - Факт в работах графика из «Фактических работ»; при выключенном `work` — состояние «учёт работ не
    подключён», а не нули (`PLAN-18`).
- **PR 3 — экран** (макеты П5). Панель «Ход работ» в карточке стройки (механизм `plan-02`), таблица на
  `DataGrid`, полосы с состояниями, отбор по разделу; колонка факта в списке графика (`plan-20`).

## Capabilities

### New Capabilities
- Нет.

### Modified Capabilities
- `core`: экран «Ход работ» — адрес, сборка из вкладов, состояния колонок и полос; контракт «Колонка
  Хода работ»; форма контракта «Фактические работы».
- `plan`: вклад модуля в «Ход работ», факт в работах графика.

## Impact

- **Контракты:** `src/server/BHS.CRG.Modules/Exchange/ActualWorks.cs`, `ProgressContribution.cs`.
- **Сервер:** ядро — `Api/Endpoints/Core/ConstructionProgressEndpoints.cs` и сборщик; модуль —
  `Modules.Plan/Exchange/PlanProgressContribution.cs`, факт в ответе графика.
- **Клиент:** `src/client/src/features/planning/progress/*`, `shared/api/progress.ts`, регистрация панели.
- **Тесты:** `src/server/BHS.CRG.Tests/Plan/ConstructionProgress*` с пробным модулем `work`, живой прогон
  `e2e/progress-smoke.mjs`.
- **Документы:** `docs/USER_GUIDE.md` — «Ход работ», его полосы и оговорки.
- **Этап 4:** `work-27` реализует готовый интерфейс; колонку факта рисует ядро, вклад `work` в колонки не
  нужен. Полоса «по смете — фактически» — вклад `work-28` тем же контрактом колонок.
- **Зависит от:** `plan-02` (панель, «любое из»), `plan-04`, `plan-22`, `plan-23`, `plan-24`, `plan-19`.
