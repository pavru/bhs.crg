# Spec Delta: core

## ADDED Requirements

### Requirement: [PLAN-21] Экран «Ход работ» собирает ядро из вкладов модулей
Ядро SHALL отдавать «Ход работ» стройки адресом `GET /api/constructions/{id}/progress` с необязательным
отбором по разделу. Строка — вид работы и единица (через позиции перечня), колонки — вклады модулей
контрактом «Колонка Хода работ», факт — из контракта «Фактические работы», полоса затрат — из контракта
«Фактические затраты». Строка, у которой есть только план или только факт, MUST показываться.
Адрес открыт носителю любого из прав колонок и только читает.

#### Scenario: Факт без плана
- **WHEN** у позиции перечня есть принятый факт, а в действующих редакциях смет её нет
- **THEN** строка вида работы показана с пустым планом и с фактом

#### Scenario: План без факта
- **WHEN** у позиции есть план, а факта нет
- **THEN** строка показана с планом и пустым фактом

#### Scenario: Без прав колонок
- **WHEN** адрес вызывает пользователь без единого права колонок «Хода работ»
- **THEN** ответ 403

### Requirement: [PLAN-21] [AUTH-8.2] Права ворот «Хода работ» собираются из вкладов
Список прав «любое из» адреса «Хода работ» SHALL собираться из вкладов включённых модулей: каждый
поставщик называет права, под которыми отдаёт данные. Ядро MUST NOT перечислять коды модулей литералом:
модуль, которого нет на экземпляре, в списке не участвует.

#### Scenario: Учёт работ не установлен
- **WHEN** экземпляр поднят без модуля `work`
- **THEN** приложение стартует, а `work.facts.read` в списке прав адреса нет

#### Scenario: Ни одного вклада
- **WHEN** ни один включённый модуль не вкладывает в «Ход работ»
- **THEN** адрес закрыт всем (403), а не роняет старт приложения

### Requirement: [PLAN-21] [CORE-34] Состояния колонок и полос «Хода работ»
Колонка или полоса, на которую у читающего нет права, SHALL приходить состоянием «скрыто правами» с
кодом права; у выключенного поставщика — «не подключено» с названием модуля из ответа контракта. Нули и
пустые колонки вместо состояний MUST NOT отдаваться. При выключенном учёте работ колонки факта нет, а
вместо неё — полоса «учёт работ не подключён».

#### Scenario: Учёт работ выключен
- **WHEN** на экземпляре нет модуля `work`
- **THEN** колонки факта в ответе нет, есть полоса «учёт работ не подключён»

#### Scenario: Нет права на сметы
- **WHEN** читает пользователь без `plan.estimate.read`
- **THEN** колонка «план по смете» приходит «скрыто правами» с кодом права, значений в ней нет

### Requirement: [CORE-34] [PLAN-21] Контракт «Колонка Хода работ»
Контракт «Колонка Хода работ» SHALL объявляться со многими поставщиками: каждый включённый модуль отдаёт
свои колонки по позициям перечня и свои полосы с состоянием, в правах читающего. Вклад выключенного
модуля MUST отсутствовать, не ломая экран.

#### Scenario: Два вклада
- **WHEN** колонки отдают два включённых модуля
- **THEN** экран показывает колонки обоих

#### Scenario: Совпадение локальных кодов
- **WHEN** два модуля отдают колонки с локальным кодом `fact`
- **THEN** их заголовки, состояния и значения раздельны между собой и с колонкой `fact` ядра

#### Scenario: Пустой объём
- **WHEN** ни одна позиция строки не содержит объёма для колонки
- **THEN** объём остаётся пустым, а явный числовой ноль при наличии значения сохраняется числом

### Requirement: [CORE-34] [WORK-57] [STG-6.1] «Ход работ» потребляет готовый контракт факта
Ядро SHALL читать контракт «Фактические работы», поставленный Work-27 вместе с настоящей реализацией.
Проверки потребителя MUST использовать настоящий Work и отдельный тестовый состав с синтетическим
фактом. Синтетический поставщик MUST NOT регистрироваться одновременно с настоящим Work.

#### Scenario: Синтетический факт
- **WHEN** тестовый поставщик «Фактических работ» засеял факт по позиции перечня
- **THEN** «Ход работ» показывает его в колонке факта этой позиции

#### Scenario: Настоящий поставщик
- **WHEN** у настоящего Work приняты три бригадных отчёта 120, 120 и 100 м по одной позиции, а актуальный итог — 120 м
- **THEN** «Ход работ» показывает один факт 120 м, без часов, людей и идентификаторов отчётов

### Requirement: [PLAN-21] [WORK-57] Неполный факт виден с охватом диагностики
«Ход работ» SHALL сохранять включённые объёмы и показывать причины исключений Work-27 отдельными
счётчиками отчётов, групп и строк. Диагностика MUST явно называть охват стройки и периода, в том числе
при отборе по разделу. Отсутствие включённых объёмов при исключениях MUST NOT означать достоверный ноль.

#### Scenario: Группа в двух разделах
- **WHEN** утверждённая бригадная группа относится к двум позициям, а открыт один из разделов
- **THEN** её объём не распределён автоматически, предупреждение сохранено с подписью «по всей стройке за период»

#### Scenario: Факт пока не принят целиком
- **WHEN** у группы утверждён итог, но часть текущих отчётов ещё ждёт приёмки
- **THEN** итог группы не включён, причина показана; число отчётов и число групп не складываются в один счётчик

#### Scenario: Неподанный участник
- **WHEN** актуальный итог по единственной позиции опубликован, а у группы есть неподанный участник
- **THEN** объём доступен с предупреждением о неподанном участнике, а состояние остаётся `ok`, если других исключений нет

#### Scenario: Только контрактное право
- **WHEN** читатель с `work.facts.read` не имеет доступа к отчётам Work
- **THEN** показаны безопасные счётчики и причины без ФИО, ID отчётов и ссылок в закрытые карточки
