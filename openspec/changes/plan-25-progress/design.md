# Design: «Ход работ» стройки и факт в графике

Дочерний change зонтика `plan-00-epic`, общая архитектура — `../plan-00-epic/design.md` (D16 — «Ход
работ», D10 — контракты, D17 — носители, D18 — макеты, D2 — интерфейс «Фактических работ» заводится
здесь). Здесь только решения этого change.

## Context

Сверено по коду master `6b81e51e`.

- Адреса стройки — группа `/api/constructions` под `core.constructions.read`
  (`Api/Endpoints/Core/ConstructionEndpoints.cs:38`). Экрана «Ход работ» нет.
- Позиция перечня — ключ «вид работы, стройка, раздел, единица» (`Domain/Documents/WorkPlanItem.cs:34`);
  чтение позиций по списку — порт `plan-04`.
- Механизм контракта, контракт со многими поставщиками и `ModuleReader` — `plan-22`; «Плановые работы» —
  `plan-23`; «Фактические затраты» — `plan-24`; «любое из прав» и панели карточки стройки — `plan-02`.
- Работы графика с позицией перечня и частью распределения — `plan-19`.

## Goals / Non-Goals

**Goals:** экран, собранный из вкладов, с честными состояниями; форма «Фактических работ» до поставщика;
факт в графике; проверка на синтетическом факте.

**Non-Goals:**
- поставщик «Фактических работ» — `work-27`;
- полоса «по смете — фактически» трудозатрат (`WORK-42`) — вклад `work-28`;
- колонка «закрыто актом» — модуль `id`, этап 6 (`ID-12`); до тех пор колонки нет, полосы о ней нет;
- сохранённые представления `CORE-33` — «Ход работ» свёрстанный экран, а не представление (`PLAN-21`).

## Decisions

- **«Фактические работы» — форма.** `[ModuleContract("work", "Фактические работы")]`
  `IActualWorks.ReadAsync(ModuleReader, ActualWorksQuery(constructionId, sectionId?, planItemIds?, from?,
  to?), ct)` → `Facts([{planItemId, date, shift, sectionId?, volume}], pending: int, crewUnreconciled:
  int)` | `Hidden(permission)`. Ни часов, ни сотрудников в типе нет — их нельзя положить (`WORK-57`).
  `work-27` может добавить поля, не меняя имеющихся.
- **«Колонка Хода работ».** `[ModuleContract(Many = true, "Колонка Хода работ")]`
  `IProgressContribution.ReadAsync(ModuleReader, constructionId, sectionId?, ct)` →
  `columns: [{code, title, kind, values: [{planItemId, value}] | Hidden | NotAvailable(reason)}]`,
  `strips: [{code, text, link?, state}]`, `planItems: [ids]` — позиции, о которых модуль знает.
- **Сборка ядром.** Строки — объединение позиций перечня всех вкладов и фактов, сгруппированных по виду
  работы и единице: строка без пары остаётся. Колонка факта — ядро само спрашивает «Фактические работы»;
  полоса затрат — «Фактические затраты». `NotConnected` даёт строку «учёт работ не подключён» вместо
  колонки факта (`PLAN-21`) и «затраты: модуль „Счета и накладные“ не подключён» — словами из ответа
  контракта, ядро имён модулей не знает.
- **Отбор по разделу.** Позиции с этим разделом; план — из распределения (`plan-23`, `plan-10`);
  нераспределённое — полосой `plan`, а не строками раздела (`PLAN-5.1`).
- **Вклад `plan`.** Колонка «план по смете» — объём из «Плановых работ» тем же провайдером, в правах
  читающего (`plan.estimate.read`); «срок по графику» — самое раннее начало и самое позднее окончание
  работ всех графиков стройки по позиции (`plan.schedule.read`). Полосы: «план по: смета „…“ ред. N» по
  каждой смете (`PLAN-5.2`), «строк сметы не сопоставлено: N ▸» (`PLAN-6.1`), «не распределено по
  разделам: N м по K работам — план всей стройки ▸» при отборе по разделу.
- **Факт в графике (`PLAN-18`).** Ответ графика (`plan-19`) получает у работы `fact: {volume, state}`:
  по позиции работы и её разделу, без часов. `state`: `ok` | `not-connected` | `hidden`.
- **Ворота.** `GET /api/constructions/{id}/progress` — «любое из»: `plan.estimate.read`,
  `plan.schedule.read`, `work.facts.read`, `costs.totals.read`, `costs.report.read` (`plan-02`; коды
  выключенных модулей в «любом из» не участвуют). Пункт «Ход работ» в карточке — то же «любое из».
  Адрес только читает: `If-Match` не нужен.
- **Синтетический факт (`STG-6.1`).** В тестах — пробный модуль с кодом `work`, регистрирующий
  `IActualWorks` с засеянными фактами; живой хост `plan` + пробный `work`. Живой прогон на стенде идёт без
  `work` и проверяет «учёт работ не подключён».
- **Экран (PR 3).** Макеты П5: три варианта, выбор владельца, ссылка — здесь. Таблица — `DataGrid`;
  полосы — общий компонент состояния (`hidden`, `not-connected`, `not-tracked`) из `shared/ui`; минимальная
  ширина 1280.
- **Сторож.** `ConstructionProgressTests`: пробный `work` с фактом по позиции без плана — строка есть,
  план пуст; позиция плана без факта — строка есть; `work` выключен — полоса «не подключено», колонки
  факта нет; без `plan.estimate.read` — колонка плана «скрыто правами»; отбор по разделу — полоса
  нераспределённого. `PlanProgressContributionTests` — действующая редакция в заголовке полосы, число
  несопоставленных.
- **Чем ломается.** Строки — только позиции плана: факт без плана пропадает. Колонка факта без
  поставщика — нули.

## Risks / Trade-offs

- [Форма «Фактических работ» придумана без реального факта] → она минимальна (объём по позиции, дате,
  смене, разделу) и названа требованиями `CORE-34` и `WORK-57`; `work-27` расширяет, не меняя.
- [Экран тяжёлый на большой стройке] → вклады читают агрегаты по позиции, а не строки; адрес без
  пагинации, потому что строк — виды работ стройки, а не документы.
