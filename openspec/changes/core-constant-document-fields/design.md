# Design: постоянные поля документов не набираются руками

Change по issue #1540; решения нет — варианты, рекомендации и условные блоки задач. Связан с эпиком
подсказок `suggest-00-epic` (#1527): там эти поля названы «не входит — закрывает #1540».

## Context

Сверено по коду ветки `openspec/open-issues-changes` (master `c9586405`), 22.10.2026.

- **Умолчание поля** — `SchemaField.defaultValue`, переопределение в потомке —
  `schema.fieldOverrides[key].defaultValue` (`client/src/shared/api/schema.ts:124,248-252`; сервер —
  `Application/Schema/DocumentTypeSchemaReader.cs:12,74`, #53).
- **Форма** засевает умолчания **копией** только в свежий документ с пустыми реквизитами
  (`features/document-sets/editor/RequisitesTab.tsx:113-119`, `getDefaultValues`); после сохранения это
  значение документа. `getDefaultValues` не рекурсивен; во встроенный составной умолчания подсевает
  `ComplexFields` при создании объекта.
- **Генерация** подставляет умолчания после экземпляра и привязок, только верхнеуровневые скалярные поля
  (`Infrastructure/Generation/EntityResolver.cs:113-123`, `ApplyDefaultsAsync`: «уже задано инстансом или
  биндингом — не перезаписываем»; составные и массивы — не трогает). «Публикатор» внутри встроенного
  «Проекта» умолчанием генерации сегодня не закрывается вовсе.
- **Профиль уровня** (#258) — объект общих данных профиль-типа на уровне (`LevelProfileService`,
  `Infrastructure/Generation/LevelProfileService.cs`); в контекст генерации — ключом
  `уровень.{стройка,раздел,комплект}` **до** умолчаний (`EntityResolver.cs:55-96`). Форма документа профиль
  не читает. Владелец профиля: `ПрофильСтройки`, `ПрофильРаздела` — ядро, `ПрофильКомплекта` — `id`
  (`openspec/specs/types-and-tags/spec.md`, «Действующие тэги ядра — типы, профили…», `CORE-30.2`).
- **Охрана умолчания:** `SchemaEditPolicy.cs:167,179` сравнивает `DefaultValue` — правка умолчания поля
  модуля запрещена (`CORE-19.2`). Правило круга схемы: свойство `SchemaField`, которое редактор не
  переносит, стирается при сохранении (#1004 — `origin`, #1008 — `locked`; сторож —
  `schemaRoundTrip.test.ts`).
- **Ссылка вместо копии.** Составное поле хранит встроенный объект или `$ref` на запись общих данных
  (механизм наследования `_baseRef` / `$ref`, `EntityResolver`). Перевод встроенной копии на ссылку —
  настройка типа плюс миграция реквизитов существующих документов.
- `docs/tz/80-типы-и-тэги.md`, `TYPE-1`: «переопределить … значение по умолчанию»; там же — «сослаться
  полем на стройку сегодня нельзя»: стройка не тип, с типом её связывает только профиль уровня. Вариант 2
  — ровно этот мост.

## Goals / Non-Goals

**Goals:** по каждому полю таблицы issue — вариант и рекомендация; решение записано (issue, «Готово»);
задачи выбранных вариантов — с границами к прогону.

**Non-Goals:**
- подсказки по ранее введённому (`suggest-*`);
- «Наименование документа» и «Номер приложения» — значение своё у каждого документа (issue: «по смыслу
  уникален»); автонумерация приложений — не эта задача;
- справочник адресов как новый тип — тип ядра `Адрес` уже есть.

## Decisions

Варианты — из issue; рекомендации — до разбора 0.1 и решения 0.2.

| Поле | Где объявлено | Рекомендация | Почему |
|---|---|---|---|
| «Публикатор» | «Документ» (абстрактный) | **2** — умолчание из `уровень.стройка.Публикатор` | значение одно на стройку, а не на тип: умолчание типа его не закроет; форма показывает, генерация подставляет |
| «Публикатор» | «Проект» (встроенный) | **ссылка** на запись проекта стройки | публикатор проекта — свойство проекта; повтор возникает из встроенной копии |
| «Раздел», «Шифр», «Тип документации» | «Проект» | **ссылка** на запись проекта стройки + миграция | то же: копия проекта в каждом документе |
| «Адрес» (встроенный) | составной | **ссылка** на запись `Адрес` общих данных + миграция | одно-два значения на копию — справочник; так же записано в `suggest-00-epic` |
| «Наименование документа» | «Документ проекта» | без изменений | своё у каждого документа |
| «Номер приложения» | «Приложение» | без изменений | уникален по смыслу |

- **D1. Вариант 2 — умолчание-ссылка, не копия.** Новое свойство поля (и переопределения) — путь в
  профиль уровня, например `defaultFrom: "уровень.стройка.Публикатор"`. Форма показывает значение профиля
  как умолчание с источником и **не пишет** его в реквизиты: правка профиля доезжает до всех документов с
  пустым полем. «Задать своё» в форме — обычное значение документа. Генерация — тем же порядком
  (`ApplyDefaultsAsync` после `InjectScopeProfilesAsync`). Свойство переносится кругом схемы
  (`schemaRoundTrip.test.ts`) и сравнивается `SchemaEditPolicy` вместе с `DefaultValue`.
  - *Против варианта 1:* «пустое поле, а в PDF что-то есть» — тот самый «отказ, переодетый в результат»
    для человека, проверяющего документ формой.
  - *Против варианта 3:* копия; правка источника в старые документы не доедет — для одного-на-стройку
    значения это неверно по смыслу.
- **D2. Перевод встроенных «Проекта» и «Адреса» на ссылки** — настройка типов (поле — ссылкой на запись) и
  разовая миграция реквизитов: одинаковые встроенные копии одной стройки сводятся к одной записи, документ
  получает `$ref`. Проверка — на копии базы заказчика до слияния, отчётом в описании PR (агрегаты).
  Шаблоны Typst, читающие встроенные поля, проверяются отладочным бандлом.
- **D3. Вложенные поля** (умолчание внутри составного) — вариант 2 распространяется на них, только если
  0.2 оставит «Публикатора» в «Проекте» встроенным; при переводе «Проекта» на ссылку не нужен.
- **D4. Домен.** Умолчание поля схемы и профиль уровня — `types-and-tags` (там описаны профили и их
  владельцы); миграция реквизитов документов — данные модуля `id`, отдельной дельты не требует (поведение
  документа не меняется, меняется форма хранения).

## Risks / Trade-offs

- [Новое свойство схемы стирается редактором] → сторож круга `schemaRoundTrip.test.ts` и сравнение в
  `SchemaEditPolicy`, тем же PR (#1004, #1008).
- [Миграция встроенных копий сводит разные значения в одну запись] → сводятся только совпадающие по
  смыслу копии в пределах стройки; расхождения — отчётом, а не молча.
- [Профиля стройки нет или поле не заведено] → форма называет «в профиле стройки не задано» (сценарий
  дельты), а не показывает пустое как заполненное.
- [Дельта написана под рекомендацию] → при ином решении 0.2 переписывается до кода (tasks.md, 0.3).
