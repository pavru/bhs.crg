# Design: роли модуля в посеве, живой прогон и проверка нарушением

Дочерний change зонтика `plan-00-epic`, общая архитектура — `../plan-00-epic/design.md` (D4 — деньги
правом, D5 — КП записью модуля, D12 — права и роли). Здесь только решения этого change; устройство
проверки повторяет `work-25` этапа 4 и проверку H1 этапа 2.

## Context

Сверено по коду master `6b81e51e`.

- Проверка по месту хранения этапа 2 — `Tests/Configuration/ModuleMoneyStorageTests.cs` (правило ядра о
  денежном тэге в общей таблице, перепись модулей с деньгами, обращения ядра к схеме модуля).
- Живые прогоны — `src/client/e2e/*.mjs` (`limited-smoke.mjs`, `costs-smoke.mjs`, посев `seed.mjs`,
  `seed-invoices.mjs`); в CI живые прогоны идут с `Modules__Enabled: id,costs` (`.github/workflows/ci.yml:550,602`).
- Пути чтения денег `plan`: адреса смет и КП (`plan-06`, `plan-13`), таблицы и наборы (`plan-28`), печать КП
  (`plan-15`), контракт «Плановые работы» (`plan-23`), «Ход работ» (`plan-25`), MCP поверх наборов, журнал
  действий модуля, уведомления; шапка графика — объект общей таблицы (D15 зонтика): денег в ней быть не
  должно.

## Goals / Non-Goals

**Goals:** проверка нарушением по месту хранения, которая сначала падает; посев сидений по ролям `PLAN-23`;
живой прогон под каждым.

**Non-Goals:**
- изоляция строк по стройкам — в `plan` её нет (инвариант #675);
- проверка денег `costs` — сделана этапом 2; здесь только деньги `plan`, в том числе в «Ходе работ».

## Decisions

- **Метки.** В посеве себестоимость строки — `1234567,89`, цена продажи строки КП — `7654321,01`: числа,
  которых нет нигде больше. Метка ищется в ответах и файлах как число в любом формате (с пробелами,
  запятой, точкой).
- **Перепись мест хранения.** Денежные колонки сущностей схемы `plan` перечислены по модели EF; каждая
  получает метку в посеве или названа с причиной («прайс-лист — цена продажи, метка 2»). Новая денежная
  колонка без метки — красный.
- **Обход.** Под каждым сиденьем без права — все `GET` адреса `/api/plan` и `/api/constructions/{id}/progress`
  (по переписи адресов, а не списком), таблицы и выгрузки XLSX, системные наборы и источники на них,
  инструменты MCP, `/api/common-data` (шапка графика), поиск, уведомления, журнал действий, печать КП,
  ответ контракта «Плановые работы». Ни один ответ не несёт метки.
- **Положительный контроль.** Тот же обход под «Руководителем» находит обе метки — иначе обход не
  доказывает ничего.
- **Сначала красный.** Первый коммит PR запускает проверку против хоста, где сметчику без права выдан
  `plan.estimate.cost` (расширенный доступ); CI краснеет, ссылка — в описании PR. Второй коммит
  возвращает права.
- **Посев и прогон.** `e2e/seed-plan.mjs` — сиденья и данные; `e2e/plan-smoke.mjs` — по сиденью: видимые
  экраны открываются, ни одного 403 на видимое действие, раздела «Планирование» нет у «Монтажника»,
  «Снабженца», «Инженера ИД». `ci.yml`: `Modules__Enabled: id,costs,plan` в обеих работах живых прогонов.
  Правка оболочки CI — весь список живых прогонов.
- **If-Match и ворота.** Новых адресов нет; проверка сама обходит ворота всех адресов модуля.
- **Чем ломается.** Шапка графика с итогом сметы в общей таблице — «Инженер ИД» находит метку через
  «Общие данные». Колонка денег без `Requires` в таблице — метка в XLSX сметчика без права.

## Risks / Trade-offs

- [Обход медленный] → один посев на класс, обход параллелится по сиденьям; идёт в обычном наборе backend.
- [Новый путь чтения появится после этого change] → обход строится по переписи адресов и инструментов,
  а не по списку; перепись мест хранения ловит новую денежную колонку.
