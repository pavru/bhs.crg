# Proposal: периодический такт модульных заданий

Дочерний change зонтика `work-00-epic`, общая архитектура — `../work-00-epic/design.md` (D12).

## Why

Автоподачу выполняет только сервер, по состоянию, а не по расписанию, и после простоя он догоняет
пропущенные дни (`WORK-10`). Фоновые службы модуля работают от имени системы с явной пометкой в журнале
(`WORK-41`). Сегодня у модуля есть очередь задач (`IModuleJobs`), но нет способа поставить задачу
периодически: свой `BackgroundService` в модуле был бы второй очередью, которой нет ни в индикаторе, ни
в остановке приложения (`BHS.CRG.Modules/Ports/IModuleJobs.cs`, комментарий порта). Образец «прошёл ли
срок и не ставили ли после него» в ядре уже есть — плановая копия (`BackupScheduleService.cs`).

## What Changes

- Модуль объявляет такт: код, название, операция своей очереди, период. Объявление — частью
  `IAppModule`, поэтому у выключенного модуля такта нет.
- Служба ядра раз в минуту проверяет такты включённых модулей: если срок прошёл и после него задачу не
  ставили — ставит задачу модуля через общую очередь с постоянной целью такта. Пока задача такта стоит
  в очереди или идёт, вторая не ставится.
- Догон после простоя — свойство запроса модуля («все черновики, чьё окно истекло»), а не такта: после
  недели простоя такт ставит одну задачу, а не тысячи.
- Задача такта идёт от имени системы: в журнале — «Система» с названием такта; опубликованных наборов
  не читает (`CORE-24.1`).
- Сторожа: такт без обработчика операции — отказ при старте; повтор кода такта в модуле — отказ.
- Первый потребитель — автоподача (`work-15`); здесь проверяется на пробном модуле.

## Capabilities

### New Capabilities
- Нет.

### Modified Capabilities
- `core`: периодический такт модульных заданий.

## Impact

- **Сервер:** `BHS.CRG.Modules/IAppModule.cs` (`Ticks`), новый `BHS.CRG.Modules/Ports/ModuleTick.cs`;
  новый `Api/Modules/ModuleTickService.cs`; `Api/Modules/Ports/ModuleWorkRunner.cs` (автор журнала у
  задачи такта); проверка объявлений при старте рядом с `ModuleWork.EnsureHandled`.
- **Тесты:** `ModuleTickServiceTests` (пробный модуль, `TimeProvider`), `ModuleTickDeclarationTests`.
- **Документы:** `docs/DEV_NOTES.md` — такт против своего фонового цикла модуля.
- Клиент не меняется; нового пишущего адреса нет.
