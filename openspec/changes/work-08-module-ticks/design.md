# Design: периодический такт модульных заданий

Общая архитектура — `../work-00-epic/design.md` (D12). Здесь только решения этого change.

## Context

Сверено по коду master `f8a8b222`.

- `Infrastructure/Backup/BackupScheduleService.cs` — образец: `PeriodicTimer` раз в минуту, пауза на
  старте, `TimeProvider`, правило «прошёл ли срок и не ставили ли после него», работу делает задачей
  той же очереди, что и кнопка.
- `Api/Modules/Ports/ModuleJobsPort.cs` — постановка задачи модуля: `ModuleWork.EnsureHandled` отказывает
  сразу, если обработчика нет; владелец вне запроса — `Guid.Empty`, отказ — общесистемным
  уведомлением. Дубль по цели ловит частичный уникальный индекс «одна активная задача на цель»
  (issue #900, сырым SQL — `Persistence/Configurations/JobConfiguration.cs:22`).
- Автор журнала вне запроса — `ActivityActor.System` («Система», `Application/Activity/IActivityActor.cs:10`),
  без указания, чем система занята.
- `IAppModule` (`BHS.CRG.Modules/IAppModule.cs`) — объявления модулем (таблицы, настройки, файлы); такта
  среди них нет.

Пересверено по master `5bfbbfe6` (после work-10, work-03, work-07):

- Параметр доступа модуля — `ModuleReader` (`BHS.CRG.Modules/Access`), его строит порт
  `IModuleReaders`. Фоновая операция берёт `ForJobAsync(run)`, а тот для задачи без владельца
  (`UserId = Guid.Empty`) отвечает системой с причиной «автора задачи больше нет: учётная запись … удалена»
  (`DataAccessResolver.ForUserAsync` не находит пользователя) — для такта причина ложная. Поэтому
  отказ «с названием такта» обязан дать именно этот порт.
- Обработчики операций у модулей — scoped (`CostsModule`, `PlanModule`): проверить «обработчик есть»
  можно только из собранного контейнера, в области служб, а не при `AddAppModules`.
- `IActivityActor` — синглтон по `HttpContext` (`Api/Activity/HttpContextActivityActor.cs`); у задачи вне
  запроса он отвечает `ActivityActor.System`. Подменить автора на время задачи можно только окружением
  вызова, а не областью служб.
- `Job.CreatedAt` ставят часы машины, а не `TimeProvider`; в поставке это одни часы.

## Goals / Non-Goals

**Goals:** модуль объявляет такт, ядро ставит одну задачу на цель; догон — запросом модуля; задача
такта подписана в журнале.

**Non-Goals:** автоподача и её запрос (`work-15`); сводка уведомлений за такт (`work-16`); серверные
«напоминания» (`WORK-41`, вынесены в `WORK-58`); расписание «в определённый час» — такт периодический.

## Decisions

- **Состав PR — один.**
  - `BHS.CRG.Modules/Ports/ModuleTick.cs` — `ModuleTick(Code, Title, Operation, Period)`;
    `IAppModule.Ticks => []`.
  - Проверка объявлений — в два шага, потому что видно их в разное время. Код уникален в модуле,
    `Period` не меньше минуты (шаг службы), операция начинается с кода ЭТОГО модуля — при сборке каталога
    тактов (`Api/Modules/ModuleTickCatalog.cs`, синглтон из реестра включённых модулей). Обработчик
    операции есть — тем же `ModuleWork.EnsureHandled`, в `StartupTasks`, из области служб: обработчики
    scoped. Оба отказа останавливают старт и называют модуль и такт.
  - `Api/Modules/ModuleTickService.cs` — `BackgroundService` по образцу `BackupScheduleService`: шаг
    минута, пауза на старте, `TimeProvider`. Живёт в `Api`, рядом с `ModuleWorkRunner`: инфраструктура о
    модулях не знает. Выключатель `ModuleTicks:Enabled` (по умолчанию включено) — ради тестового хоста,
    как `Backup:SchedulerEnabled`: такт первого потребителя (`work-15`) иначе ставил бы задачи посреди
    чужих тестов.
  - Ставит задачу портом `IModuleJobs` (D12 зонтика): тот же путь, что у модуля, с той же проверкой кода
    операции и обработчика; вне запроса владелец — `Guid.Empty`, отказ — общесистемным уведомлением.
  - Цель задачи такта — постоянный идентификатор из `модуль:код` (UUID v5): по нему индекс «одна активная
    задача на цель» не даёт второй, а «когда ставили последнюю» читается из той же таблицы задач
    (`IJobService.GetLatestModuleWorkAsync(target)` — последняя работа модуля по цели в любом статусе).
    Своей таблицы состояния такта нет: второе место правды разошлось бы с очередью.
  - «Уже выполняется» — по последней задаче (стоит или идёт) и по отказу индекса в гонке — штатный исход
    такта, не ошибка: в журнал сервера ошибкой не пишется.
  - `ModuleWorkRunner.cs`: задача такта узнаётся по цели и операции из каталога тактов и пустому
    владельцу. На время её выполнения автор журнала — `ActivityActor(null, "Система — <Title>")`
    (окружением вызова, `AsyncLocal`: автор — синглтон). Параметр доступа — `IModuleReaders.ForJobAsync`
    отвечает `ModuleReader.OfSystem(Title)`, поэтому контракт другого модуля отвечает отказом
    `SystemRefused` с названием такта; ядровый эквивалент того же — `DataAccess.OfSystem(Title)`
    (опубликованные наборы и `PerUser`-таблицы, `work-07`). Портом опубликованные наборы модулю не
    читаются вовсе — проверяется путь, который у модуля есть: контракт.
- **Догон — у модуля.** Такт не помнит пропущенных сроков: задача модуля выбирает по состоянию («все
  черновики, чьё окно истекло», `work-15`). Поэтому неделя простоя — одна задача.
- **Нового пишущего API нет** — If-Match и ворота модуля не применимы.
- **Сторож.** `ModuleTickDeclarationTests` — такт без обработчика, повтор кода, период короче минуты,
  чужая операция не стартуют. `ModuleTickServiceTests` на пробном модуле с поддельным `TimeProvider` (на
  своей базе, хост с исполнителем задач): срок прошёл — одна задача; задача идёт — вторая не ставится;
  сдвиг часов на неделю — одна задача; модуль выключен — ни одной; запись журнала из задачи — «Система —
  …», параметр доступа — система с названием такта. Часы теста отсчитываются от `CreatedAt` последней
  задачи: его ставят часы машины (см. Context).
- **Чем ломается.** Такт ставит задачу на каждом шаге без оглядки на прежнюю: после простоя очередь
  забита дублями (индекс спасает только от одновременных, а не от последовательных). Догон в такте:
  неделя простоя — две тысячи задач.
- **Зависимости.** Нет входящих; `work-07` даёт отказ системы у `PerUser`-таблиц. Потребитель — `work-15`.

## Risks / Trade-offs

- [Шаг такта — минута, период короче минуты невозможен] → для автоподачи достаточно; ограничение
  названо в объявлении (`Period` не меньше минуты — отказ старта).
- [Задача такта упала — следующая поставится через период, а не сразу] → это и есть «по состоянию»:
  следующий прогон заберёт то же; отказ виден общесистемным уведомлением.
