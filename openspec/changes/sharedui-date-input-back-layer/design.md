# Design: «Назад» на телефоне закрывает календарь поля даты

## Context

- `shared/ui/DateInput.tsx:240–254`: календарь — Radix `Popover` с порталом в body (#1521), `align="start"`,
  `collisionPadding={8}`, `hideWhenDetached`; `onCloseAutoFocus` и `onKeyDown` уводят Tab к следующему
  полю. `useHistoryLayer` у него нет.
- `shared/ui/historyLayers.ts:185` — `useHistoryLayer(open, onBack)`; его зовут `Modal`, `ConfirmDialog`,
  `AccountMenu`, `SectionMenu`, `CommandPalette`, `TypePicker`, `ActivityCenter`. На рабочем столе
  записей нет. Сторож — `shared/ui/windowsAreHistoryLayers.test.ts`.
- `docs/UI.md`, «Слои над окном»: «Календарь на телефоне пока такой же, как на рабочем столе… Модальный
  выбор даты для узкого экрана — #1522».

### Что выяснилось сверкой (22.10.2026)

- Зависимость (#1521, портал в body) слита — PR #1526. Сегодня календарь на телефоне в окне не
  обрезается: окно во весь экран совпадает с вьюпортом (довод Архитектора подтверждается кодом).
- «Назад» при открытом календаре действительно закрывает окно: у `DateInput` нет `useHistoryLayer`, а
  порядок слоёв #1418 («меню → шаг окна → окно») календарь не называет. Это расхождение с правилом, а не
  вопрос вкуса.

## Решение владельца (22.10.2026)

Вопрос «нужность и объём» (issue: «порядок и нужность — решение владельца») решён — **вариант А: только
«Назад»**, рекомендация принята. Отклонены: Б — «Назад» и модальный выбор (макет 2a + ещё два варианта,
второе поведение календаря с подтверждением «Выбрать»); В — отложить всё. Модальный выбор возвращается
отдельным change, если на живом телефоне ячейки 36 px или соседство с клавиатурой окажутся помехой.

## Goals / Non-Goals

**Goals:** «Назад» на телефоне закрывает календарь, окно остаётся.

**Non-Goals:** модальный выбор даты (решение владельца); открытие календаря при фокусе поля — ввод
сегментами остаётся основным; выбор времени (`TimeField`) — календаря у него нет.

## Decisions

- **D1. Календарь — слой истории.** `useHistoryLayer(pickerOpen, () => { setPickerOpen(false); return
  true; })` в `DateInput`; порядок #1418 в `docs/UI.md` дополняется календарём (он над окном, значит
  раньше окна). Цена — строка кода и строка правила. Макетов не требует: вид не меняется, меняется только
  «Назад» по уже записанному правилу.
- **Сторож.** Тест `DateInput`: на узком экране открытый календарь кладёт запись истории, «Назад»
  закрывает его и не закрывает окно; выбор дня снимает запись; на рабочем столе записи нет.
  `windowsAreHistoryLayers.test.ts` — без исключений.
- **Чем ломается.** Запись истории не снята после выбора дня — «Назад» «ничего не делает» один раз
  (тест D1).

## Risks / Trade-offs

- [Ячейки 36 px под палец тесноваты, клавиатура рядом] → не лечится этим change; это условие возврата к
  модальному выбору, названное владельцем.
