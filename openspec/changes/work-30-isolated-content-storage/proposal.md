# Proposal: Work-30 — содержимое отчёта остаётся в Work

## Why

Work-25 воспроизвёл копирование примеров строк в `DataSetSource.CachedSchema` при создании системных источников и свободного текста исправления в общий аудит. Код возврата также копирует комментарий в аудит и уведомление. Проверенные ответы REST/MCP не выдали метку чужим ролям, однако инвариант хранения [STG-6] [WORK-39] не выполнен. Владелец 24.11.2026 выбрал отдельное исправление с обработкой прежних копий, без исключений для Work-25.

## What Changes

- Изолированный системный источник сохраняет описание колонок без примеров значений, содержимого строк и числа строк конкретного пользователя; фактические данные получает по правам читающего [CORE-24.1] [CORE-24.2]. Покрываются обычное создание, мост таблицы и обновление метаданных.
- В общих аудите и уведомлении Work остаются метаданные события. Комментарий возврата и причина исправления сохраняются в действующих журнале отчёта и версиях с их охватом [WORK-11] [WORK-13] [WORK-15] [WORK-39]. Владелец отдельно подтвердил уведомление без комментария, со ссылкой на отчёт.
- Ранее сохранённые копии очищаются адресно и повторяемо, включая восстановление старой резервной копии. Для неизменяемого аудита описывается ограниченное исключение обслуживания данных, а не новое право редактировать журнал [CORE-28].
- Регрессии проверяют хранение и штатное чтение; Work-25 остаётся отдельной проверочной работой, которую возобновляют после слияния и архива исправления [STG-6].

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `core`: безопасные метаданные изолированных системных источников и адресная очистка прежних копий без общего разрешения менять аудит.
- `work`: свободные тексты возврата/исправления не копируются в общие аудит и уведомления, история отчёта сохраняется.

## Impact

- `BHS.CRG.Infrastructure/DataSets/DataSetSourceService.System.cs`, обновление кэша/схемы, `BHS.CRG.Api/Modules/Tables/ModuleTableDataProvider.cs`, существующие restore/инициализация и миграции `AppDbContext` при необходимости.
- `BHS.CRG.Modules.Work/Review/ReportReview.cs`, `ReturnNotice.cs`, `Endpoints/ReportCorrection.cs`, `ReportActions.cs`; порты ядра без зависимости ядра от проекта Work.
- PostgreSQL: метаданные изолированных источников, соответствующие записи `activity_log` и уведомлений; исходные отчёты, фото и журнал Work не удаляются.
- Один исправительный PR, затем отдельный архив; prerequisite для завершения Work-25. Новых API и экранов нет, версия вручную не меняется. Нет задачи на переработку произвольных пользовательских источников, архивных файлов резервных копий или системы прав.
