# Design: скан счёта (PDF и фото) и узкий экран

Общая архитектура — `../viewer-00-epic/design.md` (D4, D7–D9). Компонент — `../viewer-01-component/design.md`.
Здесь только решения этого change.

## Context

- `InvoiceScanPanel.OriginalFile` (`features/costs/InvoiceScanPanel.tsx:73`) по `fileShownAs` рисует:
  - PDF — `<iframe>` (`:129`);
  - картинку — `<img object-contain>` (`:132`);
  - для прочего — «показать нечем» или «не выяснили».
- «Во весь экран» — `window.open(url)` (`:116`).
- Байты даёт `useScan` (`:293`) через `loadInvoiceScan` (`shared/api/invoices.ts:750`): объектный
  адрес, тип из ответа.
- **`ScanTooNarrow`** (`:168`) — замена панели на экране уже 1280 px (`InvoicesPage.tsx:497`,
  `useWideEnoughForScan`, решение 28.09.2026). Обе кнопки открывают окно **после** `await`:
  - «Открыть вид для чтения» — `loadInvoiceImage`, затем `window.open` (`:203–204`);
  - «Открыть файл в отдельном окне» — `loadInvoiceScan`, затем `window.open` или скачивание
    (`:221–231`).
- `loadInvoiceScan` зовут ещё `OriginalButton` (`InvoiceFileImage.tsx:39`, скачивание через
  `saveScan(url, …)`) и `useScan`.
- Сверка: в issue строка `:204` указана верно. Кроме неё, окно после `await` открывается и на `:231`.
- Сверка: `invoices-smoke.mjs:243–251` ищет кнопку «Во весь экран» у скана. Issue этого не называет,
  но после переименования проверка покраснеет. Она переписывается в этом PR.

## Goals / Non-Goals

**Goals:** PDF и фото скана — в просмотрщике; на узком экране — поверх формы; ни одного окна после
`await`.

**Non-Goals:**
- Свой щипок на телефоне (зонтик, «Не входит»).
- Запоминание поворота скана на сервере.
- Ширина колонки скана (`w-[40%] max-w-[620px] min-w-[340px]`): остаётся как есть.

## Decisions

### Картинка — тем же просмотрщиком
- Публичный компонент получает `Blob` и решает по его типу:
  - `application/pdf` — лента pdf.js;
  - тип картинки из белого списка — режим картинки.
- **Режим картинки:**
  - `<img>` из объектного адреса (`img-src blob:` в CSP поставки есть);
  - масштаб — шириной, поворот — `transform` с пересчётом «по ширине» для 90° и 270°;
  - панель та же, без блока страниц.
- Движок pdf.js для картинки не грузится. Ctrl+P печатает картинку тем же фреймом печати.
- Альтернатива — отдельный `ImageViewer` рядом. Отвергнута: место решало бы вид само, а
  `ViewerToolbar` и `viewerState` всё равно общие.

### Загрузчик
- `loadInvoiceScan` возвращает `{ blob, mimeType }`, и объектный адрес никто не держит.
- `useScan` → `useScanBytes`: ключ прежний — `invoiceId|blobPath`, сверка «чужой ответ не
  показываем» сохраняется.
- `saveScan` принимает `Blob`: адрес делает сам и отзывает с отсрочкой.
- `OriginalButton` переводится тем же PR.
- `documentKey` — `invoiceId|blobPath`.

### Узкий экран
- `ScanTooNarrow` держит состояние «открыт поверх формы» и рисует `PdfViewer` в режиме поверх экрана.
  Байты грузятся **после** нажатия: открытие окна-слоя от жеста не зависит, блокировщика нет.
  - Поправка при реализации: `PdfViewer` с `overlay` рисует документ ещё и на месте, а здесь места
    нет. Поэтому слой вынесен отдельным экспортом `PdfViewerOverlay` (тот же слой, что у `overlay`, плюс
    строка места над листом — `note`); `PdfViewer` с `overlay` собран из него.
  - Пока байтов нет, вид неизвестен, и ленивый кусок pdf.js не грузится: иначе фото тянуло бы движок.
    Место, которое знает, что покажет PDF (вид для чтения), зовёт `preloadPdfViewer()`.
- Подписи кнопок: «Открыть файл» и «Открыть вид для чтения». Слов «в отдельном окне» больше нет.
- Вид для чтения поверх формы несёт оговорку `IMAGE_CAVEAT` строкой над листом: во вкладке её не было
  бы, а здесь она обязана быть (`COST-6.2`, issue #1270).
- **Файл, который показать нечем,** и случай «реестр видов не пришёл» скачиваются, как сейчас, с тем
  же тостом.
- Вид режима поверх экрана — по варианту, выбранному в `viewer-01` (0.1). Своих макетов нет (D10
  зонтика).

### Храповик
`InvoiceScanPanel.tsx` уходит из уровня `native-pdf-frame`.

## Risks / Trade-offs

- [Сканы CCITT, JBIG2, JPX в CI не проверяются: файлов заказчика в репозитории нет] → ручная проверка на
  трёх настоящих сканах. В описании PR — имена кодеков, без файлов и данных заказчика. Пустой лист без
  `wasm/` ловит сторож упаковки `viewer-01`.
- [Забыли `Blob` и оставили адрес] → в поставке пусто под CSP. Живые прогоны идут под CSP поставки
  (`viewer-01`, [UI-22]) и это видят.
- [Слой поверх формы прячет кнопки формы] → это окно с Esc. Форма и набранное остаются смонтированными
  (`Modal fullScreen`).
