# Work-25.1. Чувствительность проверок изоляции отчётов

## Why

[В #2096](https://github.com/pavru/bhs.crg/issues/2096) остались открыты пункты 1.1, 1.5 и 1.6
[архивного Work-25](../2026-11-25-work-25-roles-e2e-violation/tasks.md#1-проверка-нарушением-на-сервере).
Штатная выдача, изоляция хранения и сужение охвата отдельных путей уже покрыты. Для всего обхода
нужно подтвердить чувствительность к контролируемому отклонению на двух хостах и показать её
в истории GitHub CI.

## What Changes

- Запустить тот же обход на двух изолированных хостах приложения с модулем Work и эквивалентными
  синтетическими наборами данных. Второй хост задаёт контролируемый охват на входе в реальные
  службы чтения. [STG-6] [WORK-39] [WORK-40]
- Для каждого пути закрепить наблюдаемый результат по формату ответа. Проверять достижимость
  положительных сигналов, отсутствие данных Б в штатном обходе и диагностировать немые пути.
  [STG-6] [WORK-39] [WORK-40]
- В будущем PR реализации получить красный Backend на целевом утверждении и зелёный серверный
  прогон после восстановления штатной конфигурации основного хоста. Сохранить обе ссылки, SHA
  и имя теста в описании PR. [STG-6]

## Capabilities

### New Capabilities

- Новых возможностей продукта нет.

### Modified Capabilities

- `work`. При каждом прогоне подтверждается чувствительность сквозной проверки изоляции отчётов.

## Impact

Серверные интеграционные тесты Work, синтетический посев, тестовые регистрации служб и
документирование результатов GitHub CI. В `design.md` обоснована узкая внутренняя точка для чтения
своих отчётов, чтобы проверить полный охват и для этих двух адресов. Work-25.1 ведётся
самостоятельно. Ссылка на #2096 обозначает происхождение работы.
