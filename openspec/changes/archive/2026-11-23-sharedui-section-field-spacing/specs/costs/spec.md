# Spec Delta

## ADDED Requirements

### Requirement: [COST-6.2] Поля части счёта находятся вне цели шапки
В раскрытой части счёта поля и их плавающие подписи SHALL размещаться ниже шапки с отступом обычной секции [UI-77]. Обращение к полю, включая щелчок по видимой подписи, MUST NOT переключать часть. Шапка, её действия и сохранение содержимого при свёртке SHALL продолжать работать по действующим правилам.

#### Scenario: Первый ряд полей
- **WHEN** раскрыты части «Кто и сколько», «Сроки и оплата» или «Ещё», и первым элементом тела является ряд полей
- **THEN** поднятые подписи первого ряда целиком ниже шапки и не перекрываются её слоем состояния

#### Scenario: Щелчок по верхней части подписи
- **WHEN** пользователь щёлкает по верхней половине видимой подписи первого поля раскрытой части
- **THEN** часть остаётся раскрытой, нажатие не вызывает действие шапки и ранее введённое значение не теряется

#### Scenario: Работа с полем
- **WHEN** пользователь переводит фокус в первое поле клавиатурой, вводит значение или открывает его календарь либо список
- **THEN** часть остаётся раскрытой, подпись не попадает в область шапки и контрол работает по своим текущим правилам

#### Scenario: Перенос действий узкой части
- **WHEN** в части шириной 400 px действие «Внести оплату…» перенесено строкой ниже заголовка
- **THEN** поля и их подписи находятся ниже всей шапки с действиями; нажатие оплаты открывает диалог, а щелчок по полю не сворачивает часть

#### Scenario: Раскрытие по шапке
- **WHEN** пользователь щёлкает по шапке раскрытой части с несохранёнными правками и затем раскрывает её снова
- **THEN** часть переключается, а введённое содержимое сохраняется

#### Scenario: Первый этап на ноутбуке
- **WHEN** на 1366×650 открыт черновик с незаполненной первой частью, сбоем распознавания и двойником
- **THEN** поставщик, плательщик, номер, дата и сумма к оплате остаются видны и доступны без прокрутки по действующему требованию первого этапа, с читаемыми подписями вне шапки
