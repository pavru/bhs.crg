# Proposal: удаление строки счёта называет её разноску

## Why

Issue #1655. Строка счёта удаляется из черновика кнопкой `EditGrid` без подтверждения, а при
«Сохранить строки» её части разноски уходят каскадом (`OnDelete(Cascade)` по `LineId`,
`CostsDbContext.cs:469`). Каскад верен — разноска без строки есть деньги ниоткуда, — но удаление
проходит, не назвав последствия: строка, добавленная заново, получает новый id, и разноску не вернуть.
Правило проекта о безопасном удалении требует называть каскад до действия. Найдено при разборе
автосохранения строк (26.10.2026), где удаление стало бы записью сразу.

## What Changes

- Удаление строки, у которой есть сохранённая разноска, называет последствие до записи: на какие
  стройки, разделы, статьи разнесена строка и что эта разноска удалится вместе с ней.
- Форма — подтверждение, отложенное удаление с «Вернуть» или их сочетание — выбирается по трём
  макетам (задачи 0, D1).
- Строка без разноски и строка, ещё не сохранённая, удаляются как сейчас — одним действием.
- Сервер не меняется: каскад остаётся.

## Capabilities

### New Capabilities
- Нет.

### Modified Capabilities
- `costs`: новое требование об удалении строки счёта с разноской [COST-7] [COST-12].

## Impact

- **Клиент:** `features/costs/InvoiceLinesTable.tsx` (`remove`), `invoiceLineColumns.tsx` (подпись
  кнопки удаления), при отложенном удалении — `shared/ui/EditGrid.tsx` (строка-плашка на месте
  удалённой).
- **Документы:** `docs/UI.md` — правило удаления строки черновика, у которой есть зависимые записи.
- **Живые прогоны:** строки счёта — удаление разнесённой строки.
- **Сервер:** не меняется.
