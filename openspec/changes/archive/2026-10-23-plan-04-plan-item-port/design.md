# Design: порт «найди или создай» позиции перечня

Дочерний change зонтика `plan-00-epic`, общая архитектура — `../plan-00-epic/design.md` (D2 — что забрано у
этапа 4, D6 — порядок записи импорта, D7 — ключ позиции). Здесь только решения этого change.

## Context

Сверено по коду master `6b81e51e`.

- Сущность `WorkPlanItem` (`Domain/Documents/WorkPlanItem.cs:34`): четыре составляющие ключа без
  сеттеров, `Create` (`:69`) зовут только тесты; правила «найди или создай» нет (`:28-32`).
- Уникальный индекс по ключу с `NULLS NOT DISTINCT` (`WorkPlanItemConfiguration.cs:26-28`): пустой раздел
  — значение «стройка в целом». Вид работы и единица — `Restrict`, стройка и раздел — каскад
  (`:37-48`).
- Удаление — только командой с проверкой держателей (`Application/Documents/WorkPlanItems.cs:16`), адреса
  нет. Цель ссылки модуля — `ReferenceTarget.WorkPlanItem` (`BHS.CRG.Modules/Data/ModuleReference.cs:17`),
  разрешение цели — `Api/Modules/Ports/ModuleReferenceTargetsPort.cs:33`.

## Goals / Non-Goals

**Goals:** идемпотентное «найди или создай» без гонок; пакетный вызов для импорта на сотни строк; чтение
позиций по списку.

**Non-Goals:**
- импорт сметы и порядок «позиции до строк» — `plan-07`;
- распределение и позиции по разделам распределения — `plan-10`, `plan-19`, `plan-25` (D7 зонтика:
  позиции частей распределения заводятся при построении графика и в «Ходе работ», не при импорте);
- позиция из строки отчёта — `work-13`.

## Decisions

- **Состав PR — один.**
  - `BHS.CRG.Modules/Ports/IModulePlanItems.cs`: `PlanItemKey(WorkTypeId, ConstructionId, SectionId?,
    UnitId)`; `FindOrCreateAsync(key, ct)` → `PlanItemResult(Id, Created)` | отказ с составляющей;
    `FindOrCreateManyAsync(keys, ct)` → словарь «ключ → идентификатор» и перечень отказов; `GetAsync(ids, ct)`.
  - `Api/Modules/Ports/ModulePlanItemsPort.cs`: вставка `INSERT … ON CONFLICT DO NOTHING` по уникальному
    ключу, затем чтение по ключу — одним запросом на пакет. Конфликт решает база, а не «прочитал — не
    нашёл — вставил»: так два импорта одной стройки не получают двух позиций.
  - Проверки ключа до вставки: вид работы — запись типа `ВидРаботы`, единица — `ЕдиницаИзмерения`, обе не
    в архиве (`CORE-34.4`: новая ссылка на архивную запись — отказ); раздел принадлежит стройке. Пакет не
    отвергается целиком из-за одной плохой строки: отказы — поимённо, остальные позиции заведены.
- **Порт пишет в схему ядра своей транзакцией.** Позиции — «до строк» вызывающего (`STG-6.1`): упади
  модуль после порта, повтор найдёт те же позиции. Висячие позиции без держателей — допустимое
  состояние, чистить их нечем и незачем: они найдутся следующим импортом.
- **Без права.** Порт — служба ядра для модуля, который уже прошёл свои ворота; права проверяет адрес
  модуля. В журнал действий ядра заведение позиции не пишется: позиция — ключ, а не мнение, и действие
  человека (импорт) журнал получает от модуля.
- **Адреса нет.** `CORE-12`: интерфейс и телефон позиций не заводят. Перепись ворот это и проверяет:
  нового адреса нет.
- **Сторож.**
  - `ModulePlanItemsPortTests`: два параллельных `FindOrCreateAsync` с одним ключом — одна позиция; повтор —
    тот же идентификатор и `Created: false`; пустой раздел — одна позиция «стройка в целом»; архивный вид
    работы — отказ с составляющей; раздел чужой стройки — отказ; пакет из 300 ключей с одним плохим —
    299 позиций и один отказ.
  - `WorkPlanItemTests.В_позиции_ничего_кроме_ключа` — без изменений зелёный.
- **Чем ломается.** «Найди, потом создай» без уникального ключа — параллельный импорт даёт дубль, и план
  двух смет висит на разных позициях с одним смыслом.
- **Зависимости.** `plan-03` (порт видов работ — для проверки архива можно и без него, через общие
  данные; порядок не обязателен). Потребители — `plan-07`, `work-13`.

## Risks / Trade-offs

- [Позиции без держателей копятся после сбоев импорта] → они найдутся повтором; удаление незанятых
  позиций — отдельная работа, если появится спрос.
- [Пакет на тысячи ключей тяжёл для одного запроса] → порт режет пакет на части фиксированного размера;
  число частей — деталь реализации, а не контракта.
