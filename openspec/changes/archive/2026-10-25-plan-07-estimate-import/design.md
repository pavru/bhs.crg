# Design: импорт сметы

Дочерний change зонтика `plan-00-epic`, общая архитектура — `../plan-00-epic/design.md` (D3 — редакции,
D6 — импорт, D7 — позиции перечня). Здесь только решения этого change.

## Context

Сверено по коду master `6b81e51e`.

- Фоновые операции модуля — `IModuleJobs.EnqueueAsync(operation, targetId, title, payload)`
  (`BHS.CRG.Modules/Ports/IModuleJobs.cs:53-60`) и обработчик `IModuleJobHandler`; ход — поллингом
  `GET /api/jobs/active` (CLAUDE.md).
- Файлы — `IModuleBlobs.PutAsync` (`Ports/IModuleBlobs.cs:34`): путь модуль обязан сохранить у своей записи.
- Образца предпросмотра «импортировано N из M» в коде нет: загрузки выгрузки 1С в `costs` нет; ближайший
  образец фоновой операции над файлом — распознавание счёта (`InvoiceRecognitionJob`).
- Разбор — `plan-05`; модель редакции — `plan-06`; порт позиций — `plan-04`.

## Goals / Non-Goals

**Goals:** человек видит, что разобрано, до создания редакции; частичный файл не создаёт редакцию молча;
импорт безопасен к повтору и сбою между схемами.

**Non-Goals:**
- сопоставление строк с видами работ и материалов с номенклатурой — `plan-08` (здесь — точка расширения
  и пустая реализация: без `plan-08` все строки ложатся несопоставленными);
- перенос распределения на новую редакцию — `plan-10`;
- КА и ВОР приложением к смете — `plan-11`;
- экран импорта — `plan-09`.

## Decisions

- **Запись импорта** `estimate_imports`: `construction_id`, `target` (`estimate_id` или параметры новой
  сметы), `blob`, `file_name`, `state` (`parsing` | `parsed` | `rejected` | `committed`), `kind`,
  `schema_version`, `parsed jsonb` (модель разбора), `unparsed jsonb`, `revision_id?`, `xmin`. Модель разбора
  хранится до решения человека: коммит не разбирает файл второй раз и не видит другого результата.
- **Разбор — фоновой операцией.** `plan.import.parse` с целью «запись импорта»: смета на тысячи строк с
  проверкой по XSD не помещается в запрос. Ответ `POST` — запись импорта в состоянии `parsing`.
- **Куда — решает человек** (решение В-12 (а)): в запросе либо `estimateId` (новая
  редакция этой сметы), либо `newEstimate {name, sectionId?, kind}`. Совпадение реквизитов файла с
  последней редакцией выбранной сметы не проверяется молча: расхождение номера ЛСР показывается в отчёте
  как пометка `otherCalculation`, решение остаётся за человеком.
- **Не ЛСР.** Разбор ВОР или КА переводит импорт в `parsed` с `kind` и без сводки редакции; `commit` такого
  импорта — 409 «это … — приложите его к смете». Сам приём приложений — `plan-11` (ВОР — решение В-7).
- **Коммит.**
  - `If-Match` версии записи импорта: две вкладки не создадут две редакции.
  - `unparsed > 0` и нет `acceptPartial: true` — 409 «в файле K не разобранных строк: создать редакцию из
    N?». Ответ несёт числа, клиент спрашивает человека.
  - Шаг 1 — `IEstimateRowMatcher.Apply(rows)` (подстановка запомненных сопоставлений; реализация по
    умолчанию ничего не делает, `plan-08` её заменяет).
  - Шаг 2 — `IModulePlanItems.FindOrCreateManyAsync` для строк с видом работы и единицей. Отказ ключа
    (архивный вид) — строка ложится несопоставленной с причиной, а не роняет коммит.
  - Шаг 3 — смета (если новая), редакция с `import_key = import.Id` (уникальный индекс), строки и ресурсы,
    состояние импорта `committed` — одним `SaveChanges` модуля.
  - Повтор коммита после сбоя на шаге 3: позиции находятся те же (`plan-04`), редакция заводится заново.
    Повтор после успешного шага 3: уникальный `import_key` — ответ — уже созданная редакция, а не вторая.
  - Номер редакции — следующий в смете; первая редакция сметы становится действующей (решение В-5).
  - Журнал действий ядра — после сохранения.
- **Ворота и права.** Все адреса — `plan.estimate.edit` (импорт — правка сметы), ворота модуля. Сводка
  импорта несёт итог только с `plan.estimate.cost` (D4 зонтика). `DELETE` — с `If-Match`, только до коммита.
- **Сторож.**
  - `EstimateImportCommitTests`: файл с 20 не разобранными — без `acceptPartial` 409 с числами, с ним —
    редакция из 280 строк; сбой, внедрённый между шагами 2 и 3, и повтор — ни второй позиции, ни половинной
    редакции; двойной коммит — одна редакция.
  - `EstimateImportEndpointsTests`: неизвестная версия — состояние `rejected` с причиной; ВОР — 409 на
    коммите; 400 без `If-Match`, 409 устаревший; 403 без `plan.estimate.edit`; отказ ворот у «Инженера ИД».
- **Чем ломается.** Частичный файл молча создаёт редакцию — план стройки занижен, и никто не знает
  почему. Позиции заводятся после строк в той же операции — сбой оставляет строки без позиций.
- **Зависимости.** `plan-04`, `plan-05`, `plan-06`. Дальше — `plan-08` (подстановка), `plan-09` (экран),
  `plan-10` (перенос распределения).

## Risks / Trade-offs

- [Записи импорта и файлы копятся, если человек не решил] → отменённые и старые несостоявшиеся импорты
  видны в списке импорта сметы; уборка по сроку — отдельная работа при спросе.
- [Модель разбора в `jsonb` большая] → хранится до коммита; после коммита поле очищается, файл остаётся у
  редакции.
