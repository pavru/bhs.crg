# Design: экран счетов называет бросок файлов до броска

Общая архитектура — `../shell-00-epic/design.md` (D1 — макет, D6 — живые прогоны). Нового вида нет:
меняются слова двух существующих пустых состояний, поэтому макеты не нужны (правило трёх макетов —
для нового экрана, компонента или переделки взаимодействия).

## Context

Сверено по коду ветки от master `27981398` (13.11.2026).

- **Цель броска — всё окно** ([COST-6.7] [COST-31]). Бросок ловит захват окна (`shared/ui/fileDrop`),
  во время перетаскивания окно накрывает `DropCover` (`InvoiceDropCover.tsx`). Бросок, кнопку и палитру
  связывает `useInvoiceFileIntake`. Бросок на открытый счёт заводит новый черновик.
- **До броска** об умении говорят только кнопка и её подсказка: `fromFileTitle` («… Файлы можно
  перетащить в окно.») и `aria-label` у `FromFileButton` («Счёт из файла — или перетащите файл в окно»).
  Их видно лишь при наведении.
- **Правая часть без открытого счёта** — `EmptyState` «Выберите счёт», описание «Или заведите новый —
  черновик сохранится пустым.» (`InvoicesPage.tsx`, ветка `opened.kind === 'none'`). Она видна при
  ширине контейнера от `@2xl` (`ListDetailShell`), то есть на любом рабочем столе, и занимает большую
  часть окна. Описание не зависит от права: человек без `costs.invoice.edit` тоже читает «заведите
  новый».
- **Пустой список** — абзац с `emptyText(queue, query, queues)` (`invoiceQueues.ts`); без отбора и поиска —
  «Счетов пока нет.».
- Форматы: `readable = recognizedKinds(kinds.data)` из `useFileKinds()`, словами — `wordsOf(readable, last)`
  (сейчас «PDF, PNG, JPEG, Excel и Word»). Свой перечень завёл бы второй источник — `fileKinds.ts` это
  запрещает.
- `InvoicesPage.tsx` близок к порогу храповика размера (500 строк кода): тексты — в своём модуле, страница
  только зовёт их.

## Goals / Non-Goals

**Goals:** до броска умение видно без наведения там, куда смотрят, когда счёт не открыт; слова правдивы о
месте, форматах и фоне; человек без права не получает приглашения, которое кончится отказом.

**Non-Goals:**
- отдельная строка или плашка о броске (отвергнута, см. «Отвергнутое»);
- подсказка при открытом счёте: человек уже видел пустое состояние, а у кнопки в сводке есть своё
  `aria-label`;
- подсказка на экране накладных; новые виды файлов.

## Decisions

- **Описание «Выберите счёт»** — `selectHint(canEdit, kinds)`:
  - при праве: «Или перетащите сюда файлы счетов ({formats}) — из каждого заведём черновик и распознаем
    его в фоне. Новый счёт можно завести и пустым.»;
  - без форматов — без скобок;
  - без права — описания нет: заголовка «Выберите счёт» достаточно.

  «Сюда» — правда: правая часть входит в цель броска.
- **Звать ли** — один признак `dropInvited({ canEdit, coarse, info })` на оба места (ревью PR #1925):
  - право;
  - не касание (`useMedia(COARSE)`, `(pointer: coarse)` — тот же признак, что у `FileDropZone`; вынесен в
    `useMedia.ts`). Ширина не годится: планшет в 1024 px перетащить не даст, а правая часть видна по
    контейнеру (`@2xl`, 672 px), а не по `WIDE` (768);
  - реестр не сказал «распознаётся ничего»: тогда выбор файла пуст и брошенное отсеется. Не пришёл — звать
    можно, перечень допишется.
- **Пустой список** — `emptyText(queue, query, queues, drop)`: ветка `default` (нет отбора очереди и поиска)
  при `drop` говорит «Счетов пока нет. Перетащите файлы счетов в окно или нажмите «Счёт из файла».». Решение
  о пустоте живёт в одной функции. `drop` = `invited && selected === null`: при открытом счёте кнопки с
  подписью «Счёт из файла» нет (вход — значком), и «нажмите» звало бы к тому, чего не видно. Под отбором
  пустота говорит про отбор. Форматов здесь нет: в пустом списке рядом стоит правая часть с перечнем, а дважды
  перечислять ни к чему.
- **Модуль** `features/costs/invoiceDropWords.ts` — чистые функции без React, их проверяет vitest. Там же
  подсказка кнопки «Счёт из файла» (`fromFileTitle`): перечень форматов называется одним правилом, и подсказка
  с описанием не разойдутся. Слова подсказки и `aria-label` `FromFileButton` не меняются.

### Отвергнутое (13.11.2026)
- **Строка внизу колонки списка** (прежняя редакция, предложение координатора, макет «B · Счета» с
  пунктирной строкой). Владелец: «у нас в счетах уже весь экран drop-зона». Целью служит окно, а элемент у
  края колонки говорил бы о месте, которого нет.
- **Б — подзаголовок страницы.** Подзаголовок читают редко, а при открытом счёте шапки нет.
- **В — разовая богатая подсказка у «Счёт из файла»** при первом входе. Это новое поведение и настройка
  ради одной фразы, тогда как пустое состояние уже стоит на месте.
- **Г — ничего не делать.** Цель #1435 «умение видно до того, как о нём узнал» осталась бы не выполнена.

### Сторож и «чем ломается»
- Vitest `invoiceDropWords.test.ts`:
  - `dropInvited`: без права, на касании и при «распознаётся ничего» не зовём, без реестра — зовём;
  - с форматами — в скобках, без них — без скобок; не зовём — описания нет;
  - `emptyText` с `drop` и без, под отбором и поиском;
  - подсказка кнопки — тот же перечень.
- Живые прогоны:
  - `e2e/invoice-file-drop-checks.mjs`: без открытого счёта правая часть говорит «перетащите сюда файлы
    счетов (… PDF …)» — ждём текста уже с перечнем, — а бросок на неё заводит и открывает черновик;
  - `e2e/allocation-matrix-smoke.mjs`: руководителя без `costs.invoice.edit` правая часть не зовёт ни перетащить, ни
    завести.

  Плюс весь список живых прогонов (зонтик, D6).
- Ломается так:
  - перечень форматов расходится с тем, что принимает выбор файла;
  - человек без права читает «перетащите» или «заведите»;
  - экран касания говорит «перетащите»;
  - «нажмите «Счёт из файла»» при открытом счёте, где кнопки с этой подписью нет.

## Risks / Trade-offs

- [Кто уже знает, читает лишнее] → это описание пустого состояния, а не отдельная плашка; при открытом
  счёте его нет.
- [Пустой список виден редко] → главное место — правая часть; пустой список — для первого входа.
- [Текстовый конфликт с `costs-invoice-filter-row` в `InvoicesPage.tsx`] → правка страницы — две строки;
  кто сливается вторым, тот обновляет ветку.
