# Design: «план против факта» материалов

Дочерний change зонтика `plan-00-epic`, общая архитектура — `../../plan-00-epic/design.md` (D4 — деньги
правом, D10 — контракты, D17 — носители, D18 — макеты). Здесь только решения этого change.

## Context

Сверено по master `289437780` (2.142.13). Решения владельца от 27.11.2026.
28.11.2026 ветка обновлена от `6cc80ef49` после слияния плана предпосылки в PR #2139.

- «Затраты по стройке» — `GET /api/costs/site-costs` под `costs.report.read`
  (`Modules.Costs/Endpoints/SiteCostsEndpoints.cs:91-93`); деньги считает `CostViews`
  (`Data/CostViews.cs:31`). Срезов по номенклатуре в отчёте нет: есть стройки, разделы, поставщики.
- Строка счёта может ссылаться на номенклатуру (`COST-7`). В `InvoiceAllocation` доля хранит
  количество или сумму, а у разноски счёта целиком ссылка на строку пуста (`COST-10`, `COST-11`).
- Сметная стоимость материалов позиции — часть `cost` «Плановых работ» (`plan-23`), только с
  `plan.estimate.cost`; стоимость ресурса бывает не у каждой сметы — `not-in-estimate`.

### Предпосылка импорта

В эталоне `lsr-16.2.2-sks.etalon.json` у позиции 85 «Шайба М8» указаны 76 шт. и цена без НДС
5,01 ₽/шт. Произведение равно 380,76 ₽, а итог позиции с коэффициентом из формы — 388,38 ₽.
На первоначальной базе `EstimateImportRows.Drafts` сохранял итог на позиции, но оставлял у ресурса `Amount` пустым.
`PlannedWorksMath.Cost` возвращал для сопоставленного ресурса эту пустую стоимость.
Итог позиции с несколькими ресурсами не определяет стоимость каждого из них.

[plan-32-estimate-resource-costs](../2026-11-28-plan-32-estimate-resource-costs/proposal.md) отвечает
за сохранение стоимости ресурса при импорте, применение коэффициентов
и поведение ранее импортированных редакций. Plan-27 читает готовые суммы через `IPlannedWorks`.
Начало работ над кодом и интерфейсом — после слияния реализации предпосылки, подтверждения коммита
повышения версии на master и слияния архива предпосылки. PR публикуются последовательно.
Условие выполнено 28.11.2026 — код #2143/#2144, бот `e0ba60489` (2.142.17),
архив #2147 (`4ea1227fd`). Ветка обновлена от этого master с сохранением решений Plan-27.
План Plan-32 предлагает совместимое чтение старых редакций и повторный импорт новой редакцией.
Выбор порядка обновления данных остаётся в предпосылке.

## Goals / Non-Goals

**Goals:** сравнение по номенклатуре стройки с двумя числами факта; честные состояния сметной колонки;
та же арифметика денег, что у «Затрат по стройке».

**Non-Goals:**
- сравнение количеств (сколько метров по смете и сколько купили) — материалы сметы с количествами уже
  видны в заявке (`plan-26`); здесь деньги;
- взгляд «на момент закрытия» — отчёт считает «с исправлениями»;
- сравнение работ (не материалов) с затратами — разноски на позицию перечня нет (`COST-14`).

## Decisions

- **Строки.** Объединение номенклатуры из сметы (`plan-23`, часть `cost`, по действующим редакциям) и из
  разнесённых на стройку строк счетов. Строка без пары остаётся (`COST-21`).
  Названия уже сохранённых материалов читаются пакетным `RefsAsync`, включая архивные записи.
  Здесь нет выбора новой номенклатуры. Место чтения объявляется как `Seen` в `ArchiveReadInventoryTests`.
- **Факт.** Взгляд «с исправлениями», режим «без НДС». «Оплачено» равно затратам по учётным датам
  в календаре отчёта за всё время. «Разнесено» равно «оплачено» плюс «к оплате» (это слагаемое
  от периода не зависит). Для обоих чисел берутся доли выбранной стройки и, при отборе, раздела.
  Переиспользуются отборы `SiteCostsEndpoints.Paid/Unpaid`, читатель денег и арифметика `SiteCosts`.
  Черновик с подходящей долей входит, отклонённый счёт исключается. Учитываются количественные
  и суммовые доли с округлением действующей разноски. Доли счёта целиком и строки без ссылки
  на номенклатуру складываются в одну строку «Без позиции номенклатуры».
  Количественная доля черновика без цены несёт `PostedMoney.Amount=null`. В числовом факте остаётся
  сумма известных долей, совпадающая с Costs, с признаком неполноты у соответствующего показателя.
  Экран и XLSX называют её известной частью. Неизвестная доля сохраняет строку материала в отчёте,
  точное отклонение остаётся пустым.
- **Основа сравнения.** Смета и факт сопоставляются без НДС. При смете 100 ₽ и покупке за 120 ₽
  с известным НДС 20 ₽ разнесено 100 ₽, расхождение 0 ₽. Когда `SiteCosts.Net` возвращает
  `VatUnknown`, в соответствующем числе факта сохраняется сумма отчёта с оговоркой «НДС неизвестен,
  учтено полной суммой». Оговорка сохраняется при группировке таких долей и при выгрузке.
  По решению владельца от 28.11.2026 валюты проверяются отдельно. Стоимость ЛСР — в RUB,
  факт — в валюте экземпляра, прочитанной портом `IModuleAccountingCurrency`.
  При различии валют суммы показываются с кодами валют в заголовках, отклонение остаётся пустым.
  Это правило действует и для XLSX. Конвертация валют в расчёт не входит.
- **Расхождение** — «разнесено − смета» только при известной стоимости ресурса и известном НДС
  всех разнесённых долей строки, а также подтверждённой основе сметной суммы без НДС.
  Иначе расхождение пусто с причиной. Известная нулевая сумма
  остаётся числом. Отсутствие закупки даёт нулевой факт.
- **Денежный контракт Plan-32.** Для сравнения используется `Amount` и собственный признак его
  основы. Основа `UnitPrice` независима. Числовая смета с неизвестной основой показывается
  с предупреждением «Основа сметной суммы без НДС не подтверждена». Если хоть один вошедший
  ресурс номенклатуры не несёт суммы, итог этой группы пуст. При объединении групп разных позиций
  перечня по номенклатуре сохраняются оба правила. Предупреждение и пустое отклонение переходят в XLSX.
- **Состояния сметной колонки** (D17): `hidden` с кодом `plan.estimate.cost`; `not-connected` («модуль
  „Планирование“ не подключён»); у строки — `not-in-estimate`. Сумма колонки при `hidden` не отдаётся.
- **Ворота.** Адрес под `costs.report.read` за воротами модуля `costs`; только читает — `If-Match` не
  нужен. Выгрузка XLSX выгружает видимое, скрытое правами не выгружается (`CORE-33`).
  Общий `SpreadsheetExporter` доступен модулю через минимальный порт `IModuleSpreadsheets`
  и адаптер ядра. Колонки, разрешённые значения и пояснения формирует тот же отчёт Costs.
  Адрес `GET /api/costs/estimate-vs-costs/export` принимает те же стройку, раздел, поиск
  и отбор превышений, что экран. Денежные клетки записываются числами.
- **Экран.** Вкладка «План против факта» отчёта «Затраты по стройке» на `DataGrid`. Для этой
  вкладки — разбор с Дизайнером, а при изменении `shared/ui` и с Архитектором по `docs/UI.md`.
  Владелец выбирает один из трёх интерактивных вариантов в локальном каталоге «BHS.CRG UI».
  Ссылка на выбранную страницу вносится сюда до производственного интерфейса.
- **Сторож.** `EstimateVsCostsTests`: без НДС смета — кабель 100 000, разнесено 120 000, оплачено 90 000 —
  расхождение +20 000; закупленный материал вне сметы — строка со сметой пусто; сметный без закупки —
  строка с фактом 0; без `plan.estimate.cost` — колонка `hidden`, сумм сметы в ответе нет; `plan`
  выключен — `not-connected`; ресурс без стоимости — `not-in-estimate`; без `costs.report.read` — 403.
- **Чем ломается.** Сравнение по оплаченному — смонтированный неоплаченный кабель показан экономией.
  Пропуск строк без пары — лишняя закупка не видна.

## Risks / Trade-offs

- [Отчёт целиком виден немногим] → `costs.report.read` и `plan.estimate.cost` вместе по умолчанию есть
  только у «Руководителя» и «Администратора». «Бухгалтер» видит факт без сметы. Если отчёт нужен ещё
  кому-то — это выдача права, а не правка отчёта; вопрос владельцу отмечен в отчёте нарезки.
- [Номенклатура сметы сопоставлена не так, как в счетах] → обе стороны ссылаются на номенклатуру ядра
  (`CORE-9`); расхождение сопоставления видно парой строк без пары.

## Раунд П6

28.11.2026 подготовлены три интерактивных варианта на компонентах текущего `shared/ui`.
Постоянные чаты Дизайнера и Архитектора не найдены в доступном списке. Разбор ниже выполнен
исполнителем по порядку `docs/UI.md` и передан владельцу вместе со ссылками.

- [А · Общая таблица](http://127.0.0.1:5277/?section=mockups&project=plan-27-estimate-vs-costs&page=a).
  Все четыре денежные колонки рядом, итог факта под таблицей. Удобно сравнивать материалы между собой.
  Рекомендация исполнителя для рабочего отчёта.
- [Б · Список и подробности](http://127.0.0.1:5277/?section=mockups&project=plan-27-estimate-vs-costs&page=b).
  В списке видны материал и разнесённое. Выбор строки открывает денежные показатели рядом,
  на узком экране под списком. Для сравнения нескольких строк требуется переключаться.
- [В · Группы отклонений](http://127.0.0.1:5277/?section=mockups&project=plan-27-estimate-vs-costs&page=c).
  Материалы разделены по результату сравнения. Неопределённое сравнение показано отдельной группой.
  Больше повторяющихся шапок, зато видна очередь материалов для проверки.

Общие действия — выбор раздела, поиск, отбор превышений, переключение светлой/тёмной темы
и сценариев прав, выключенного Plan, неизвестного НДС факта и неизвестной основы сметы.
Кнопка выгрузки в макете показывает состав будущего XLSX на демонстрационных данных.
Проверены открытие трёх вариантов, смена выбранной строки Б, неопределённая основа в В и
отсутствие горизонтального переполнения страницы при ширине 390 px.
Новые компоненты `shared/ui` для этих вариантов не требуются.

28.11.2026 владелец выбрал [В · Группы отклонений](http://127.0.0.1:5277/?section=mockups&project=plan-27-estimate-vs-costs&page=c).
Производственный экран строится по этому варианту.
