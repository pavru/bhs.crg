# Design: «прочитано, в счёт не положено» — с причиной, всегда

Общая архитектура — `../invrec-00-epic/design.md`. Здесь только решения этого change.

## Context

Сверено по коду ветки от master `c9586405`.

**Где сегодня говорится о не легшем** (все — строками в `InvoiceRecognition.Notes`, `string[]`):

| Что | Где в коде | Сейчас |
|---|---|---|
| шапка: у счёта нет поля с ключом | `InvoiceScanHeader.Of`, `:110` | замечание «Прочитано, в счёт не положено: «ключ» «значение»; … — у счёта нет поля с таким ключом» |
| шапка: поле не заполняется распознаванием | `InvoiceScanHeader.Of`, `case { Unavailable: … }` | замечание «Прочитано, но распознаванием не заполняется: …» |
| шапка: два ключа профиля в одно поле | `InvoiceScanHeader.Of`, группировка | замечание «в поле ведут два поля профиля — взято …» |
| шапка: значение не разобрано | `InvoiceScanReading.ApplyAsync`, `:338` | замечание «… не прочитано как значение поля — впишите вручную» + предложение |
| шапка: поле занято | `ApplyAsync`, ветка `!IsBlank(was)` | только предложение под полем, замечания нет |
| шапка: охрана отказала | `GuardedAsync`, `:531` | замечание «… не записано — охрана записи: …» + предложение |
| строки: нет поля / повтор ключа | `InvoiceScanLines.StrayNote`, `:358` | одно замечание по колонкам: число строк и пример значения, без номеров строк |
| строки: значение не разобрано | `InvoiceScanLines.Line`, `:290` | примечание строки «В файле не прочитано: …» |
| строки: НДС снят «все или ни одной» | `InvoiceScanLines.Strip` | примечание строки и `VatNote` |

**Что выяснилось сверкой:**
- Часть issue сделана ревью PR #1485: «Прочитано, в счёт не положено» уже **не** пишется в примечание
  строки — оно переехало в замечание распознавания (`StrayNote`, доккомментарий `InvoiceScanLines.cs:343-347`: примечание
  строки — поле человека, едет в версии и книгу). «Строки счёта без лишних примечаний» выполнено;
  задача — не вернуть их.
- `StrayNote` добавляется только в ветке «строки легли» (`InvoiceScanReading.cs:466`). Когда строки ушли в
  предложение (у счёта свои строки, `:417-421`; режим НДС человека, `:422-429`) или таблица не прочитана
  (`RowsProblem`), сведение о колонках **теряется**. Это и есть «хранится не всегда»: сырые строки
  (`InvoiceRecognition.Lines`) сохраняются тоже лишь в ветках предложения. Строки исправляет хранение
  списка, а не сырых строк: номер строки файла в записи списка делает сырые строки ненужными для показа.
- Причина «ключ повторяет другой» в issue не названа, а в коде есть — у шапки и у строк. Включена шестой.
- Цели `Origin: Input` (прочитанное для сопоставления сторон — название, ИНН) пропускаются молча и
  законно: они использованы. В список не входят.
- `InvoiceScanReading.cs` — 601 строка с комментариями; сбор кладём в новый файл, чтобы не упереться в
  храповик размера.

## Goals / Non-Goals

**Goals:** каждое расхождение профиля и счёта видно в счёте с причиной — при любом исходе строк;
таблица — одна свёрнутая строка, не шум.

**Non-Goals:** подсказки в редакторе профиля; перераспознавание прежних счетов ради списка; изменение
правил раскладки (что ложится — не меняется, меняется только то, что сказано о не легшем).

## Decisions

### Запись списка
`UnplacedRead(Place, Row, Key, Value, Reason, Detail)`:
- `Place` — `header` | `line`; `Row` — номер строки в прочитанной таблице файла (с 1), только у строк;
- `Key` — ключ профиля как прочитан (без обрезки — опечатка с пробелом видна);
- `Value` — прочитанное, сокращённое тем же `Short` (40 знаков), что у замечаний;
- `Reason` — код: `no-field`, `not-recognizable`, `unparsed`, `guard`, `occupied`, `duplicate-key`;
- `Detail` — причина поля для `not-recognizable` (от ядра, `ModuleFieldTarget.Unavailable`), текст отказа
  для `guard`, ключ-владелец для `duplicate-key`.
Слова причин — на клиенте по коду, рядом с показом (тексты — по Дизайнеру); сервер слов не собирает.

### Сбор и хранение
- `InvoiceScanHeader.Plan` отдаёт записи вместо строк `unplaced`/`off`/«два поля профиля»;
  `InvoiceScanLines.Reading` — записи вместо `StrayNote`, с номером строки (`Cells` знает индекс строки).
- `InvoiceScanReading.ApplyAsync` дописывает `unparsed`, `occupied` (только если значение отличается — как
  сейчас решается, класть ли предложение) и `guard`; добавляет записи строк **до** ветвления по строкам —
  так они не зависят от исхода.
- Новый файл `Endpoints/InvoiceScanUnplaced.cs` — тип записи, коды и сборщик.
- `InvoiceRecognition.Unplaced` — `jsonb` (`null` — распознавание до этого change: «не знаем», а не
  «пусто»; `[]` — знаем, что пусто). `Finish` принимает список. Миграция `CostsDbContext`.
- Вид распознавания (`InvoiceScanRecognition.cs:156`) отдаёт `unplaced` как есть.

### Замечания
Переезжают в таблицу и из `Notes` уходят: «Прочитано, в счёт не положено» (шапка, строки), «Прочитано,
но распознаванием не заполняется», «в поле ведут два поля профиля». Остаются (зовут к действию над
счётом, и их запись есть в таблице): «не прочитано как значение поля — впишите вручную», «не записано —
охрана записи». Не трогаются: «В файле не прочитано» в примечании строки, НДС «все или ни одной» —
`VatNote` и примечание строки (это решение модуля о счёте, а не расхождение профиля).

### Показ
- `InvoiceRecognitionNote.tsx`: строка «Ещё прочитано, в счёт не положено: N — Показать» последней в
  блоке «Замечания распознавания», `text-xs text-fg3`, без `warning`. «Показать» — текстовая кнопка,
  раскрывает таблицу общим компонентом таблиц (`<table>` в `features/` запрещён храповиком, `docs/UI.md`,
  «Таблицы»): «Где» («шапка» / «строка 3»), «Ключ», «Значение», «Причина». `unplaced === null` — строки
  нет; `[]` — строки нет.
- Блок «Замечания распознавания» сейчас показывается, только когда есть замечания или строки
  (`InvoiceRecognitionNote.tsx:126`) — условие дополняется непустым списком: распознавание без замечаний,
  но с колонкой «для наборов данных», иначе молчало бы.
- **Макеты.** Свёрнутая строка с раскрывающейся таблицей — новое взаимодействие; тексты дал Дизайнер
  (разбор 18.10.2026). По правилу владельца (#1545, после issue) — три варианта в Claude Design и выбор
  владельца до кода PR 2. PR 1 (сервер) от этого не ждёт.
  [Макет](https://claude.ai/design/p/0a5fe51c-fa42-4249-9c99-df4ac9c83fa5?file=%D0%9D%D0%B5+%D0%BF%D0%BE%D0%BB%D0%BE%D0%B6%D0%B5%D0%BD%D0%BE+%D0%B2+%D1%81%D1%87%D1%91%D1%82.html):
  1a — плоская таблица по записи на строку, 1b — сводка по ключам, 1c — окно с отбором по причине.
  **Выбран 1b** (владелец, 22.10.2026): свёрнутая строка называет ключи строк с числом строк и число
  записей шапки — опечатку видно без раскрытия; таблица — по строке на ключ и причину («Ключ», «Где»,
  «Прочитано», «Причина»), ключ из нескольких строк раскрывается шевроном до значений по номерам строк.
  Поэтому в таблице колонки «Ключ» и «Где» стоят в другом порядке, чем в пункте выше. Причина называет
  поле счёта подписью (`field`), когда оно есть.

### Сторож и «чем ломается»
- Сервер: `InvoiceScanUnplacedTests` — каждая из шести причин собирается (шапка: нет поля, не заполняется,
  не разобрано, занято, охрана, повтор; строки: нет поля, повтор, номер строки); список хранится при
  легших строках, при строках в предложении и при `RowsProblem`; `Notes` больше не содержит переехавших
  фраз; неразобранное число строки — в её примечании, не в списке. Существующие `InvoiceScanHeaderTests`,
  `InvoiceScanLineKeysTests`, `InvoiceFromScanTests.*`, проверяющие тексты замечаний, переводятся на
  записи.
- Клиент: компонентный тест `InvoiceRecognitionNote` — свёрнутая строка с числом, «Показать» раскрывает
  таблицу, `null` и `[]` — строки нет, окраски предупреждения нет.
- Ломается так: колонка «Артикл» не легла, и об этом молчат (строки ушли в предложение); список
  показывает «0» у старого распознавания; переезд в таблицу вернул фразу в примечание строки.

## Risks / Trade-offs

- [Колонки «для наборов данных» мелькают в каждом счёте — шум] → одна свёрнутая строка, без окраски, а
  не по записи на поле.
- [Старые распознавания без списка] → `null` — ничего не показываем, их текстовые замечания остаются как
  были; перераспознавать не требуется.
- [Охрана отказала по полю — важное прячется в свёрнутой таблице] → замечание об отказе охраны остаётся
  в списке замечаний, а значение — предложением под полем.
