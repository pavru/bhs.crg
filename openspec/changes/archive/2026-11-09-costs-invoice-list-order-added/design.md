# Design: лента счетов — по дате добавления

## Context

- `InvoiceListEndpoint.ListAsync` сортирует `OrderByDescending(IssuedOn).ThenByDescending(CreatedAt)`. В
  PostgreSQL `DESC` ставит `NULL` первыми, поэтому счёт без даты сейчас наверху, а после распознавания
  опускается к своей дате. Этот «подъём» никто не задумывал — он побочный.
- Постраничности у списка нет (named-решение в doc-комментарии: страницы придут с сеткой реестра, G4), то
  есть сортируется весь отобранный набор.
- Клиент порядок не переделывает: сосед для «‹ N из M ›» и прокрутка к открытому берутся из массива
  ответа (`InvoicesPage`, `InvoiceSummary`). Единственная правка кэша — удаление строки из отбора
  «Разобрать» (`InvoicesPage.tsx`, `setQueryData(… filter …)`), порядок она не трогает.
- `Id` счёта — UUID v7 (`01a1…`): он растёт со временем заведения.

## Goals / Non-Goals

**Goals:** порядок ленты определяется только моментом заведения; порядок стабилен между чтениями.

**Non-Goals:**
- переключатель сортировки в ленте (решение владельца: по умолчанию и без выбора);
- реестр счетов и его представления;
- накладные — у них своя лента, о ней замечания не было.

## Decisions

- **D1. Ключ — `CreatedAt DESC, Id DESC`.** `CreatedAt` — момент заведения (бросок файла, «Новый
  счёт»); `Id` — разрыв ничьих: пакет файлов заводит счета в одну миллисекунду, и без второго ключа их
  порядок между чтениями «плавал» бы. Альтернатива «только `Id`» (v7 упорядочен по времени) отвергнута:
  порядок держался бы на свойстве генератора ключей, а не на смысловом поле.
- **D2. Индекс не заводим.** Список сортирует весь отбор без `LIMIT`, и индекс по `created_at` план не
  меняет. Когда придут страницы (G4), индекс заводится вместе с ними под их сортировку.
- **D3. Клиент не трогаем.** Порядок приходит с сервера, «‹ ›» берёт соседа из того же массива. Правка
  клиента нужна, только если проверка 2.2 найдёт место, которое сортирует само.

## Risks / Trade-offs

- [Живые прогоны счёта берут «первую строку» в расчёте на прежний порядок] → задача 2.2: найти такие места
  (`invoice-row` + `first()` / `nth(`) и сверить; новый порядок обычно им помогает — только что заведённый
  прогоном счёт теперь первый.
- [Привыкшие к порядку по дате счёта] → дата счёта остаётся в строке; искать по дате помогает реестр со
  своей сортировкой. Порядок описан в `USER_GUIDE.md`.
