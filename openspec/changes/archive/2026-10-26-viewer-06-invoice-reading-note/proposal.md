# Proposal: строка-оговорка над видом для чтения счёта — в одну строку

Дочерний change зонтика `viewer-00-epic`, общая архитектура — `../viewer-00-epic/design.md` (D6, D10).

## Why

Issue #1495 (эпик #1489). Решение владельца от 18.10.2026 (D6 зонтика): свести строку в одну.

Строка-оговорка над видом для чтения файла счёта (`features/costs/InvoiceFileImage.tsx`) стала
трёхэтажной:
1. фраза «Вид для чтения · N стр. — вёрстка может отличаться…» с подсказкой о раскладке;
2. чип «Раскладка: {профиль} ▾» (#1456);
3. пометка сервера «Лист вписан в ширину страницы по профилю печати…» (`ExcelPageLayout.cs`).

Раскладка названа три раза, а в узкой правой колонке это съедает высоту листа.

## What Changes

- **Одна строка:** фраза + чип раскладки + «Перестроить». В колонке уже 420 px строка переносится
  аккуратно и на лист не наезжает.
- **Пометка сервера о раскладке.** Когда показан чип, отдельной строкой она не выводится: её смысл («в
  Excel печатается иначе») уходит в подсказку чипа. Пометки другого рода остаются строками.
- **Тексты состояний чипа из #1456** («изменён», «удалён», «до профилей», «профиль не применён») не
  теряются: при показанном чипе они переезжают в его подсказку.
- **Сервер.** Ответ `GET /api/costs/invoices/{id}/scan/image` отдаёт пометку о раскладке отдельным
  полем `layoutNote`, а не в общем списке `notes`. Клиент не узнаёт пометку по тексту: имя профиля
  вставлено в неё.

## Capabilities

### New Capabilities
- Нет.

### Modified Capabilities
- `costs`: строка-оговорка вида для чтения — одна строка; пометка о раскладке — отдельным полем ответа
  (`[COST-6.2]`).

  - `BHS.CRG.Infrastructure/Renditions/ExcelPageLayout.cs` узнаёт свои пометки;

  Адрес только читает: If-Match и новые ворота не нужны, прежние ворота модуля и права остаются.
- **Клиент:**

  - `shared/api/invoiceImage.ts` (`layoutNote`).

  состояние профиля и чип стоят «под строкой». Оглавление не меняется.

  `viewer-01` — тогда видно, сколько высоты остаётся листу.
