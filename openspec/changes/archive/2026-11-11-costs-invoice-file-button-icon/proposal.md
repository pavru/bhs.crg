# Proposal: значок «Файл» показывает, что сделает нажатие

## Why

Issue #1874. Кнопка «Файл» в сводке счёта ([COST-6.3]) открывает и закрывает панель файла справа, а на
узком экране открывает файл поверх формы ([COST-6.2]). Значок у неё один при любом состоянии —
`RightPanelOpen`, «открыть панель справа». Когда файл уже открыт рядом, значок по-прежнему зовёт открыть,
хотя нажатие панель закроет. Когда файл открывается поверх формы, значок рисует панель, которой не будет.

Файл рядом всегда занимает место списка («список ИЛИ файл», макет Г, `placeOf`), так что кнопка на деле
переключает «список ↔ файл». Видно это только по подсказке при наведении: открытое и закрытое состояние
выглядят одинаково, а `aria-pressed` слышит только диктор.

В других местах приложения значок меняется с состоянием: предпросмотр в редакторе документов —
`RightPanelOpen` ↔ `RightPanelClose`, панель раздела в рейле — `LeftPanelOpen` ↔ `LeftPanelClose`.
Экран счёта из этого правила выбивается.

## What Changes

- Файл закрыт — значок `RightPanelOpen`; файл открыт рядом — `RightPanelClose` (D1).
- Файл открывается поверх формы — значок открытия поверх, `OpenInFull` (D2).
- Подпись «Файл», подсказки («Показать файл рядом с формой», «Скрыть файл», причина «поверх») и
  `aria-pressed` не меняются (D3). Живые прогоны ищут кнопку по имени «Файл» — оно прежнее.

## Capabilities

### New Capabilities
- Нет.

### Modified Capabilities
- `costs`: новое требование [COST-6.3] — значок «Файл» называет, что сделает нажатие.

## Impact

- **Клиент:** `features/costs/InvoiceFileButton.tsx` (выбор значка по `file`) и
  `InvoiceFileButton.test.tsx`. Значки `RightPanelClose` и `OpenInFull` уже есть в `shared/ui/icons`.
- **Сервер, данные, API:** не меняются.
- **Документы:** `docs/USER_GUIDE.md` — если в описании сводки назван вид значка «Файл».
- **Макеты:** не нужны: нового экрана и взаимодействия нет, значок выбирается из пары, принятой в
  приложении (`docs/UI.md`, «Новый экран: порядок»).
