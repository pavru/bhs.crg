# Ошибки обязательных полей в веб-форме отчёта

## MODIFIED Requirements

### Requirement: [WORK-6] Пометка «нужно для ИД» до подачи

Строка, вид работы которой по признакам из ответа требует место или материалы, SHALL до подачи помечаться «нужно для ИД», пока поле пусто. Веб-форма SHALL обновлять признаки вида при открытии возвращённого отчёта. Отказ подачи MUST называть строки и поля из ответа сервера. Красные ошибки полей и переходы к ним SHALL появляться только по отказу `422` при ручной подаче, включая повторную.

#### Scenario: Место не указано

- **WHEN** у вида работы признак «требует место», а поле места строки пусто
- **THEN** строка помечена «нужно для ИД: место»

#### Scenario: Подача отвергнута

- **WHEN** сервер отказывает в подаче и называет строку 2 и поле «материалы»
- **THEN** экран ведёт к строке 2 и показывает у поля «материалы» причину отказа

#### Scenario: Обязательность сняли после автоподачи

- **GIVEN** отчёт автоподан с пустым обязательным местом или материалами и возвращён в открытом периоде
- **WHEN** обязательность этого поля снимают в справочнике и веб-форму отчёта открывают снова
- **THEN** у этого поля отсутствуют красная ошибка и автоматический фокус с момента открытия
- **AND** после чтения справочника пометка «Нужно для ИД» исключает это поле, даже если при открытии в кэше были прежние признаки
- **AND** повторная подача проходит при соблюдении остальных условий, поле может остаться пустым
- **AND** исходный пропуск по-прежнему доступен в записи автоподачи в журнале согласно [WORK-10]

#### Scenario: Обязательность сохранилась после возврата

- **WHEN** возвращённый отчёт открыт с пустым местом или материалами, которые вид по-прежнему требует
- **THEN** до попытки повторной подачи форма показывает для поля пометку «Нужно для ИД»
- **WHEN** пользователь подаёт отчёт, а сервер отвечает `422` со строкой и полем
- **THEN** отчёт остаётся возвращённым, форма раскрывает строку по её идентификатору, показывает причину у поля и переводит фокус к полю или действию добавления материала

#### Scenario: Сервер уже видит новое требование

- **WHEN** на ручную подачу сервер отвечает `422` с пропуском, а признаки вида ещё загружаются или получены до правки справочника
- **THEN** форма показывает ошибку, раскрывает строку и переводит фокус по ответу подачи
