# Ошибки обязательных полей в веб-форме отчёта

## Context

Автоподача вычисляет пропуски при обработке черновика после конца окна и сохраняет `RequiredMissing`. Возврат меняет статус отчёта и оставляет снимок в DTO. Успешная ручная подача записывает `requiredMissing: null`, а исходные пропуски остаются в событии `auto-submitted`. Перед переходом в «Подан» по запросу ручной подачи сервер читает признаки вида через `RequiredFields` и возвращает `422` со списком `{ line, lineId, field }`, если обнаруживает пропуски. [Автоподача](../../../../src/server/BHS.CRG.Modules.Work/Submission/AutoSubmitJob.cs) · [Отчёт](../../../../src/server/BHS.CRG.Modules.Work/Data/Report.cs) · [Подача](../../../../src/server/BHS.CRG.Modules.Work/Endpoints/ReportDesk.cs) · [Журнал](../../../../src/server/BHS.CRG.Modules.Work/Data/ReportJournal.cs)

Оба режима веб-ввода используют `ReportForm`. Она передаёт в `ReportLines` ошибки текущего отказа или, при его отсутствии, `saved.requiredMissing`. `ReportLineDetails` сверяет каждый такой пропуск только с пустотой поля. Подсказку «Нужно для ИД» вычисляет `missingForId` по справочнику. Признаки могут уже измениться, а под полем всё ещё видна ошибка из снимка. Ветка материалов воспроизведена с синтетическим ответом при закрытии этапа Work. Для места работ тот же путь подтверждён чтением кода. ## Goals / Non-Goals

Исправить источник красных ошибок, сохранить адресный фокус при отказе и обновлять требования вида при повторном открытии. Работа ограничена общей веб-формой и политикой чтения её справочника. История автоподачи доступна в существующих ответах чтения и журнале по действующим правам. Мобильный ввод, управление справочником, правила приёмки и синхронизация открытых вкладок выходят за рамки этого change.

## Decisions

### Источник ошибок поля и фокуса [WORK-6]

Передавать в редактор только перечень `requiredMissing` из разобранного `422` операции подачи. Использовать существующие `reportFailure`, переходы к полям и поиск строки по `lineId`. Первая запись ответа раскрывает строку и фокусирует поле «Место работ» или кнопку «Добавить материал». Переходы из списка отказа используют тот же механизм. Сохранить очистку ошибок и запроса фокуса при принятии свежих данных через `accept`. Сверка с пустотой поля позволяет убрать подпись у уже заполненного поля при правке.

Фильтр снимка по текущему виду всё равно давал бы красную ошибку без попытки подачи, когда поле остаётся обязательным. Для такого случая в форме уже есть «Нужно для ИД». Свежий `422` имеет приоритет и тогда, когда справочник загружается или его данные отстают от серверной проверки.

### Актуальность пометки [WORK-6]

Оставить расчёт `missingForId` по содержимому строки и `requiresLocation` / `requiresMaterials`. Запрос `catalog/work-types` возвращает признаки в `items` и в `selected` для уже сохранённых строк, в том числе у вида вне первой страницы. `reportQuery` перечитывает отчёт на входе, но запрос справочника живёт в отдельном кэше с общим `staleTime` 30 секунд. Изменение справочника само по себе не меняет `reportVersion`. При открытии возвращённого отчёта запросить виды заново даже при свежей записи в кэше. Применить политику к использованию запроса видов в строках возвращённого отчёта, без общего сокращения времени жизни кэша или дополнительных запросов на каждую строку. [Запрос справочника](../../../../src/client/src/shared/api/workEntryCatalog.ts) · [Настройки кэша](../../../../src/client/src/App.tsx) · [Ответ сервера](../../../../src/server/BHS.CRG.Modules.Work/Endpoints/ReportEntryCatalog.cs)

### История и интерфейс [WORK-10] [WORK-59]

Исторический перечень доступен в DTO возвращённого отчёта до успешной ручной подачи. Запись `auto-submitted` хранит его и после неё. Для просмотра истории используется существующий журнал. Очередь и карточка читают собственный расчёт текущих пропусков по Work-31. Правка ограничивается условиями показа существующей пометки и ошибок и подпадает под исключение из правила о трёх макетах для нового экрана, компонента или изменения взаимодействия. ## Risks / Trade-offs

- Кэш отчёта и кэш справочника обновляются независимо. Проверить повторное открытие того же `reportId` с той же версией и заполненным кэшем прежних признаков. После ответа справочника пометка должна отразить новые признаки.
- Снимок может ссылаться на изменённый вид или удалённую строку. Убрать его из ошибок целиком и проверить строки с обоими полями, чтобы ошибка одного поля не переносилась на другое.
- Синтетический ответ формы подтверждает клиентский дефект, а интеграционные тесты уже покрывают части серверного цикла. Сценарий целиком на реальном API входит в верификацию реализации. Основной локальный стенд во время исследования не отвечал.

## Migration Plan

Поставка и откат выполняются обычной заменой версии веб-клиента. Контракт сервера и формат сохранённых отчётов подходят существующим данным без преобразования.
