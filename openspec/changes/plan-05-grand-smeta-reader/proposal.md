# Proposal: разбор файлов ГРАНД-Сметы (OpenXML) по схемам

Дочерний change зонтика `plan-00-epic`, общая архитектура — `../plan-00-epic/design.md` (D6).

## Why

Сметы ведёт сметчик заказчика в ГРАНД-Смете, в системе достаточно импорта (`PLAN-6`, `PLAN-Q1`).
Обязательно — **чтение** файлов формата OpenXML: локальный сметный расчёт, ведомость объёмов работ,
конъюнктурный анализ (`PLAN-7`). Нормативные базы и индексы в системе не ведутся: хранятся результат
расчёта и шифры расценок (`PLAN-8`). Формат внешний и меняется с версиями программы — разбор ведётся по
схемам, версия схемы хранится с файлом (`STG-12`).

Сметчик сохраняет и файлы **без итогов**: программа убирает из них все итоги, оставляя всё, из чего итог
считается, — базисные и текущие цены, индексы, коэффициенты, нормативы НР и СП. Такой файл тоже должен
приниматься (решение владельца 24.10.2026, ревизия `PLAN-8`).

В коде разбора ГРАНД-Сметы нет вовсе; ближайшее — XML-набор данных по выражениям колонок
(`Infrastructure/DataSets/XmlDataSetParser.cs:14`), и он для этого не годится: модуль не ссылается на
`Infrastructure` (`CORE-2`), а разбор «по выражениям» молча теряет колонку новой версии формата.

Разбор вынесен в свой change без экрана и без записи в базу, чтобы его сторож — файлы заказчика и
эталон — стоял до того, как на разборе построят импорт (`plan-07`) и конъюнктурный анализ (`plan-11`).

## What Changes

- Разбор в модуле `plan` (чистый C#, `System.Xml`, без новых пакетов): файл `.gsfx` (ZIP с `data.xml`)
  или голый XML → вид документа (ЛСР, ВОР, КА), версия программы и редакция схемы → проверка по XSD →
  модель разбора.
- **Своя редакция XSD**: официальные схемы 2026.2.3 разработчика программы и перечень правок — каждая
  подтверждена образцом заказчика, который официальная схема отвергает, а программа так пишет.
- **ЛСР:** реквизиты расчёта (номер, наименование, стройка, дата, уровень цен) и **метод расчёта** (БИМ, РИМ,
  РМ); разделы; позиции — порядковый номер в разделе, шифр расценки, наименование, единица расценки, объём,
  итог «Всего по позиции» в текущих ценах (с НР и СП), расчётная цена единицы (итог ÷ объём), ресурсы
  позиции (материалы — наименование, код, единица, количество «всего» на позицию; трудозатраты рабочих
  «всего», чел.-ч), коэффициенты — как есть, без пересчёта. Строка материала по КА — позиция с пометкой и
  ссылкой на КА (поставщик, цена, дата); её цена — сметная цена без НДС.
- **ВОР:** разделы и работы с объёмами, единицами, формулой и строками расчёта объёма, переменными и
  обоснованием (шифр, комментарии сметчика, ссылки на листы чертежей — без содержимого вложений).
- **КА:** поставщики, позиции, коммерческие предложения и минимальная отпускная цена без НДС.
- Результат — модель разбора и перечень **не разобранных** строк с причиной («280 из 300, 20 не разобраны
  ▸»). Частичный разбор — не отказ: решение принимает человек в импорте (`PLAN-7`).
- Неизвестная версия программы или вид документа — отказ с названием версии, а не попытка разобрать.
- **Досчёт итога** (второй PR): файл ЛСР без итогов по БИМ или РИМ разбирается с итогами, посчитанными по
  данным самого файла, с пометкой «посчитано системой»; РМ и незнакомая настройка расчёта — предупреждение
  «обратитесь к разработчику» с названием метода или опции.
- Схемы XSD поддерживаемых редакций лежат ресурсом модуля; список «вид × версии программы → редакция» — в
  одном месте.
- Ни адреса, ни таблицы, ни экрана: потребители — `plan-07`, `plan-11`.

## Capabilities

### New Capabilities
- Нет.

### Modified Capabilities
- `plan`: чтение файлов ГРАНД-Сметы по схемам с отчётом о не разобранном и отказом на неизвестной версии;
  досчёт итога ЛСР без итогов по данным файла.

## Impact

- **Сервер:** `src/server/BHS.CRG.Modules.Plan/GrandSmeta/*` — определение вида и версии, проверка по
  схеме, разбор ЛСР, ВОР, КА; ресурсы `GrandSmeta/Schemas/*.xsd`; досчёт итога — `GrandSmeta/Totals/*`.
- **Тесты:** `src/server/BHS.CRG.Tests/Plan/GrandSmetaReaderTests.cs`, `GrandSmetaTotalsTests.cs`; образцы,
  эталоны и пары смет «с итогом / без итогов» — `src/server/BHS.CRG.Tests/TestData/GrandSmeta/` (условие —
  файлы заказчика, вопрос В-11).
- **Документы:** `docs/DEV_NOTES.md` — поддерживаемые версии и редакции, перечень правок схемы, как добавить
  версию; `docs/tz/50-планирование.md` — ревизия `PLAN-8` (досчёт итога по данным файла).
