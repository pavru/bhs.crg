# Proposal: разбор файлов ГРАНД-Сметы (OpenXML) по схемам

Дочерний change зонтика `plan-00-epic`, общая архитектура — `../plan-00-epic/design.md` (D6).

## Why

Сметы ведёт сметчик заказчика в ГРАНД-Смете, в системе достаточно импорта (`PLAN-6`, `PLAN-Q1`).
Обязательно — **чтение** файлов формата OpenXML: локальный сметный расчёт, ведомость объёмов работ,
конъюнктурный анализ (`PLAN-7`). Нормативные базы и индексы в системе не ведутся: хранятся результат
расчёта и шифры расценок (`PLAN-8`). Формат внешний и меняется с версиями программы — разбор ведётся по
схемам, версия схемы хранится с файлом (`STG-12`).

В коде разбора ГРАНД-Сметы нет вовсе; ближайшее — XML-набор данных по выражениям колонок
(`Infrastructure/DataSets/XmlDataSetParser.cs:14`), и он для этого не годится: модуль не ссылается на
`Infrastructure` (`CORE-2`), а разбор «по выражениям» молча теряет колонку новой версии формата.

Разбор вынесен в свой change без экрана и без записи в базу, чтобы его сторож — файлы заказчика и
эталон — стоял до того, как на разборе построят импорт (`plan-07`) и конъюнктурный анализ (`plan-11`).

## What Changes

- Разбор в модуле `plan` (чистый C#, `System.Xml`, без новых пакетов): файл `.gsfx` (ZIP с `data.xml`)
  или голый XML → вид документа (ЛСР, ВОР, КА) и версия схемы → проверка по XSD → модель разбора.
- **ЛСР:** реквизиты расчёта (номер, наименование, стройка, дата, уровень цен), разделы, позиции —
  порядковый номер в разделе, шифр расценки, наименование, единица расценки, объём, стоимость единицы и
  итог в текущих ценах, ресурсы позиции (материалы — наименование, код, единица, количество;
  трудозатраты рабочих — чел.-ч), коэффициенты — как есть, без пересчёта.
- **ВОР:** разделы и работы с объёмами, единицами и обоснованием.
- **КА:** поставщики, позиции, коммерческие предложения, выбранная (минимальная) цена.
- Результат — модель разбора и перечень **не разобранных** строк с причиной («280 из 300, 20 не разобраны
  ▸»). Частичный разбор — не отказ: решение принимает человек в импорте (`PLAN-7`).
- Неизвестная версия схемы или вид документа — отказ с названием версии, а не попытка разобрать.
- Схемы XSD поддерживаемых версий лежат ресурсом модуля; список версий — в одном месте.
- Ни адреса, ни таблицы, ни экрана: потребители — `plan-07`, `plan-11`.

## Capabilities

### New Capabilities
- Нет.

### Modified Capabilities
- `plan`: чтение файлов ГРАНД-Сметы по схемам с отчётом о не разобранном и отказом на неизвестной версии.

## Impact

- **Сервер:** `src/server/BHS.CRG.Modules.Plan/GrandSmeta/*` — определение вида и версии, проверка по
  схеме, разбор ЛСР, ВОР, КА; ресурсы `GrandSmeta/Schemas/*.xsd`.
- **Тесты:** `src/server/BHS.CRG.Tests/Plan/GrandSmetaReaderTests.cs`, образцы и эталоны —
  `src/server/BHS.CRG.Tests/TestData/GrandSmeta/` (условие — файлы заказчика, вопрос В-11).
- **Документы:** `docs/DEV_NOTES.md` — поддерживаемые версии схем и как добавить новую.
