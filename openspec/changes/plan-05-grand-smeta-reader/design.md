# Design: разбор файлов ГРАНД-Сметы

Дочерний change зонтика `plan-00-epic`, общая архитектура — `../plan-00-epic/design.md` (D6 — разбор по схемам,
решение человека, идемпотентная запись). Здесь только решения этого change.

## Context

Сверено по коду master `6b81e51e`.

- Разбора ГРАНД-Сметы, XSD и OpenXML-смет в коде нет. Ближайшее — `Infrastructure/DataSets/XmlDataSetParser.cs:14`
  (XML-набор данных по выражениям колонок) и `ZipDataSetParser.cs`; оба — в `Infrastructure`, модулю
  недоступны (`ModuleBoundaryTests`).
- Формат: OpenXML ГРАНД-Сметы — файл `.gsfx` (ZIP с `data.xml` в windows-1251) или голый XML; виды
  документов — локальная смета (`OpenXML_LS`), ведомость объёмов работ (`OpenXML VOW`), конъюнктурный
  анализ (`OpenXML_KA`); схемы публикует разработчик программы, известная редакция — 2026.1.1.
- Образцов файлов заказчика в репозитории и в `BHS.CRG-research` нет — запрошены у владельца (В-11).

## Goals / Non-Goals

**Goals:** вид и версия документа определяются до разбора; разбор по схеме; модель ЛСР, ВОР, КА без
потерь значимых полей; не разобранное названо поимённо с причиной.

**Non-Goals:**
- запись в базу, редакции, позиции перечня — `plan-07`;
- сопоставление с видами работ и номенклатурой — `plan-08`;
- хранение и показ КА — `plan-11`; что делать с ВОР в смете — `plan-07` (решение В-7);
- нормативные базы, индексы и пересчёт стоимости (`PLAN-8`); запись файлов обратно (`PLAN-7`, `STG-14`).

## Decisions

- **Состав PR — один.** Каталог `BHS.CRG.Modules.Plan/GrandSmeta`:
  - `GrandSmetaFile.Open(stream)` — ZIP или XML, кодировка из пролога (windows-1251 по умолчанию для
    `data.xml`); вид документа и версия схемы — по корневому элементу и атрибуту версии.
  - `GrandSmetaSchemas` — перечень поддерживаемых пар «вид × версия» и XSD ресурсом сборки модуля. Один
    список: добавить версию — положить схему и строку; ничего больше.
  - Проверка по XSD (`System.Xml.Schema`). Ошибки схемы на уровне позиции не роняют разбор: позиция идёт
    в перечень не разобранных с текстом ошибки и номером строки XML; ошибка на уровне документа (нет
    реквизитов, нет разделов) — отказ.
  - Читатели `LocalEstimateReader`, `VolumeStatementReader`, `ConjunctureReader` → неизменяемые модели
    `ParsedLocalEstimate`, `ParsedVolumeStatement`, `ParsedConjuncture` + `Unparsed[] (path, line, reason)`.
- **Что хранит модель ЛСР.** Позиция — номер в разделе, шифр расценки, наименование, единица расценки как
  текст («100 м»), объём, стоимость единицы и итог в текущих ценах (тот итог, что в ЛСР «всего» по позиции
  с накладными и сметной прибылью — база наценки КП, решение В-8), ресурсы (материалы и
  трудозатраты), коэффициенты — списком «название · значение» без пересчёта (`PLAN-8`). Числа — `decimal`
  в инвариантной культуре.
- **Версия схемы — данные, а не догадка.** Разбор возвращает `SchemaVersion`; импорт кладёт её рядом с
  файлом (`PLAN-7`). Неизвестная версия — `UnsupportedVersion(kind, version)`, текст «формат ГРАНД-Сметы
  версии … не поддерживается; поддерживаются: …».
- **Модуль не зависит от образцов в коде.** Эталоны разбора — JSON рядом с образцом в `TestData`; тест
  сравнивает модель с эталоном. Эталон пишется руками по файлу, открытому в ГРАНД-Смете, а не снимается с
  разбора (иначе сторож проверял бы сам себя).
- **Сторож.**
  - `GrandSmetaReaderTests`: образец ЛСР заказчика — модель совпадает с эталоном (число разделов, позиций,
    итоги, ресурсы первой позиции); образец с испорченной позицией — «N−1 из N» и причина с номером
    строки; файл неизвестной версии — отказ с версией; голый XML и `.gsfx` дают одну модель.
  - Образцы ВОР и КА — то же по своим эталонам.
- **Чем ломается.** Разбор по именам элементов без схемы: новая версия программы переименовала
  элемент — колонка молча пустая, а «разобрано 300 из 300».
- **Условие старта.** Образцы файлов заказчика лежат в `TestData/GrandSmeta` (В-11). Без них change не
  начинается: синтетический файл, написанный по схеме, не проверяет того, что пишет программа заказчика.
- **Зависимости.** `plan-01` (проект модуля). Потребители — `plan-07`, `plan-11`.

## Risks / Trade-offs

- [Сметчик заказчика сохраняет файлы версией, которой нет в списке] → отказ с названием версии; новая
  версия — схема и строка списка, отдельным маленьким PR.
- [XSD большие, разбор медленный на смете в тысячи строк] → разбор идёт фоновой операцией импорта
  (`plan-07`), а не в запросе.
- [Эталон снят с разбора и подтверждает ошибку] → эталон пишется руками по программе; ревью PR сверяет
  его с файлом.
