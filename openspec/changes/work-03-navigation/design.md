# Design: навигация этапа 4

Общая архитектура — `../work-00-epic/design.md` (D3 — право контракта, D15 — носители, D17 — макеты Р0,
D18 — что строит этап 3). Здесь только решения этого change.

## Context

Сверено по коду master `f8a8b222`; механизмы — по `openspec/changes/plan-02-navigation/design.md`.

- **Что приносит `plan-02`:** `NavItem.permission: string | string[]` («любое из») и составная политика
  на сервере; `RailId` с разделом `plan`; `NavItem.entry?: number` и `shared/ui/entryPage.ts`
  (наименьший ранг среди видимых в текущем пространстве, иначе первый видимый, иначе `AUTH-15`); реестр
  панелей карточки стройки `shared/ui/constructionPanels.ts`.
- **Разделы рейла.** Список — `railSections` (`navConfig.ts:68-79`), раздел без пунктов не строится
  (`railSections.ts:buildRail`). Основной список пунктов называется `workNav` (`navConfig.ts:82`): это
  «рабочие пункты» против `settingsNav`, а не модуль `work`. Имя совпадает с кодом модуля, и путать их
  легко.
- **Право контракта** (`plan-21`): модуль, открытый одним правом контракта, приходит с `available: false`
  и раздела не даёт.

## Goals / Non-Goals

**Goals:** раздел рейла `work`; монтажник после входа попадает на свои отчёты.

**Non-Goals:**
- механизмы «любое из прав», страницы входа и панелей карточки стройки — `plan-02`;
- сами страницы и пункты модуля — `work-21`, `work-22`, `work-23`; панель «Назначения» — `work-12`;
- закрепление разделов — `work-04`;
- пространство как граница безопасности — его нет и не будет (`AUTH-16.2`).

Пишущих адресов change не заводит, правило `If-Match` его не касается.

## Decisions

### Состав PR — один
- `RailId` += `'work'`, строка в `railSections` с подписью по Р0 (до выбора — рабочая «Работы»), за
  разделом «Планы». Раздел `costs` уже подписан «Затраты» (П0 этапа 3, `plan-02`).
- Таблица рангов входа пунктов `work` — константы в `navConfig.ts`: `myReports` меньше ранга Главной (`HOME_ENTRY_RANK`) и рангов пунктов
  ядра; остальные и их порядок относительно `myReports` — по Р0. Change экранов вписывают пункт с рангом из таблицы.
- Ранг ниже Главной действует только при одном доступном аккаунту модуле — правило `plan-02` («Вход»,
  П0). Монтажнику доступен один `work` (`plan.estimate.hint` — право контракта), и он попадает на «Мои
  отчёты»; «Администратор», у которого `AllPermissions` даёт и `work.report.own`, — на Главную.

### Вход: ранг у пункта, а не карта «роль → страница»
Карта по ролям противоречит `AUTH-14`: навигация не читает названий ролей. Ранг у пункта вычисляется из
того же ответа доступа механизмом `plan-02`. Что открывается пользователю с `work.report.own` и
`work.report.review` сразу, решает порядок рангов по Р0.

### Сторож и «чем ломается»
- Vitest `railSections.test.ts`: пустой раздел `work` не попадает в рейл; раздел не строится при одном
  праве контракта.
- Vitest `entryPage.test.ts` (`plan-02`) дополняется пунктами `work` с рангами из таблицы: монтажник —
  «Мои отчёты»; «Инженер ИД» с одним `work.facts.read` — вход
  как без модуля; «Администратор» с `work.report.own` — Главная; «Менеджер проекта» (`plan`, `work`,
  `costs`) — Главная.
- Живой прогон `e2e/rail-checks.mjs` — раздела `work` нет без прав модуля. Вход монтажника на «Мои
  отчёты» живьём проверяет `work-22`, когда появляется пункт.
- Ломается так: ранг «Моих отчётов» не задан — монтажник попадает на первый видимый пункт по порядку
  рейла.
- Правка оболочки, поэтому весь список живых прогонов идёт в PR.

### Зависимости
- `plan-02-navigation` и `plan-21-contract-permissions` слиты; `work-10` — модуль.
- `shell-08-home` (Главная) сливается раньше — решение владельца 11.11.2026, см. «Макеты».
- `work-04` правит те же файлы навигации (`navConfig.ts`, `SectionRail.tsx`). Кто сливается вторым, тот
  перебазируется.

### Макеты
Раунд Р0 (общие панели, блок «Работы» карточки стройки, страница входа и «Затраты» — решены раундом П0
этапа 3, `plan-02` «Макеты»):
- раздел рейла `work` и его подпись;
- страницы входа ролей модуля (ранги пунктов);
- закрепление (`work-04`);
- нижняя строка телефона: у «Менеджера проекта» и «Администратора» с разделом `work` шесть пунктов
  (Главная, Стройки, Данные, Затраты, Планы, Работы) при пределе MD3 в пять — что уходит из строки
  («Данные» в меню аватара или закреплением `work-04`); вопрос оставлен открытым в П0.

**Выбор владельца 11.11.2026** — холст «Р0–Р1 · Учёт работ: навигация и сотрудники»,
https://claude.ai/artifact/HGgpB7JPaK5Z8VB3x91nbB (приватный; доступ даёт владелец). Рабочий стол —
вариант **А** (закрепления первой группой в подпанели раздела), телефон — вариант **Б** (нижняя строка у
всех «Главная · Закреплённые · Меню»). Ответы на вопросы листа сравнения:
- Подпись раздела рейла — **«Работы»**. Совпадение с блоком «Работы» карточки стройки владелец принял.
- Вход с одним модулем «Учёт работ»: без своих отчётов, с одной приёмкой — **«Приёмка»** (ранг меньше
  Главной); со своими отчётами и приёмкой — **«Мои отчёты»**.
- Нижняя строка телефона — **три постоянных места «Главная · Закреплённые · Меню»**, от числа модулей не
  зависит; седьмой раздел (ОЖР) её не ломает. «Меню» открывает лист со всеми разделами и их страницами.
  Вопрос, оставленный открытым в П0, этим закрыт.
- Слово «раздел» в подписях навигации **не используется**: им названы разделы стройки (замечание
  владельца на холсте). Кнопка телефона — «Меню», закрепляется «страница».
- **«Назначения» — отдельная страница** в подпанели «Работ», рядом с «Приёмкой» (а не только панель в
  карточке стройки).
- **«Варианты работ» отдельным пунктом не стоят**: правятся в «Общих данных» (довод Дизайнера: пункт в
  рейле «Работ» открыл бы раздел ролям без модуля).
- **Монтажнику — роль без строек**: в рейле у него остаются «Работы», «Стройки» и «Данные» уходят (сейчас
  у «Монтажника» `ReferenceReads` — чтение строек, справочников и наборов данных). Как монтажник
  выбирает стройку в отчёте без чтения строек — через назначения (`work-07`); сверить до кода.
- **Порядок: `shell-08-home` сливается раньше этого change** (пробел C1 разбора Дизайнера): правило
  «один модуль — его страница входа» действует только при объявленной Главной, без неё «Администратор»
  после входа попал бы на «Мои отчёты». Зависимость — в «Зависимостях» выше.

Что ещё нашла сверка с кодом и до кода решается здесь: Главная без пространства (`unscoped`) спорит с
`phoneChrome`, который такие разделы с телефона убирает (C2); на телефоне шесть разделов и у
«Руководителя», не только у «Менеджера проекта» и «Администратора» (C3) — строке «Б» это не мешает.

⚠️ Дельта спек и `tasks.md` этого change написаны до выбора: в них нет ранга «Приёмки» для аккаунта без
своих отчётов, отдельной страницы «Назначения», строки телефона из трёх мест и роли монтажника без строек.
Перед кодом их дописывает сессия `/opsx:apply` этого change (или `/opsx:update`).

## Risks / Trade-offs

- [Ранг входа `work` совпал с рангом другого модуля] → порядок — порядок рейла, `entryPage.test.ts`
  закрепляет его.
- [Механизм страницы входа `plan-02` устроен иначе, чем описано] → перед стартом сверяется master,
  расхождение правится здесь до кода (D18 зонтика).
