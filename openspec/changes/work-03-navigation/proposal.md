# Proposal: навигация этапа 4 — «любое из прав», раздел рейла, страница входа, панели карточки стройки

Дочерний change зонтика `work-00-epic`, общая архитектура — `../work-00-epic/design.md` (D3, D15, D17).

## Why

Экраны модуля `work` открываются разным ролям по разным правам. Сводку видит и менеджер
(`work.report.review`), и руководитель (`work.report.read.all` из `*.read.all`). Сегодня пункт
навигации называет одно право (`shared/ui/navConfig.ts:19`), а ворота адреса — одну политику
(`BHS.CRG.Modules/AppPolicies.cs`). Сводка, закрытая одним `work.report.review`, пропала бы у
руководителя: это и есть «чем ломается» change.

Ещё три места не готовы к модулю:
- после входа каждый попадает на `/document-sets` (`App.tsx:122`), а у монтажника стартовая страница
  своя (`WORK-2`);
- у модуля нет раздела рейла (`RailId` — четыре значения, `navConfig.ts:42`);
- карточка стройки перечисляет свои панели вручную (`features/document-sets/ConstructionDetail.tsx:111-118`),
  и модуль добавить туда свою не может.

## What Changes

- **PR 1 — механизм «любое из прав» и раздел рейла.**
  - `NavItem.permission: string | string[]` («любое из»). `missingFor` называет весь список, страница
    `AUTH-15` пишет «нужно одно из прав: …».
  - Составная политика на сервере: адрес под «любым из» открыт носителю любого из названных прав. Каждый
    код проверяется по справочнику (`AUTH-8.2`). Перепись ворот и `ReadAllWritesNothingTests` её понимают.
  - Раздел рейла `work`. Подпись — по макету Р0: решается и переименование «Учёт» → «Затраты» у раздела `costs`.
    Раздел без видимых пунктов не показывается.
- **PR 2 — страница входа и панели карточки стройки** (после выбора макета Р0).
  - Страница входа по доступу. Пункт навигации может объявить себя страницей входа с рангом. Открывается
    видимый в текущем пространстве пункт с наименьшим рангом, иначе — первый видимый. Нет ни одного —
    честная страница `AUTH-15`.
  - Механизм `shared`: модуль добавляет панель в карточку стройки. Панель отбирается по доступу и по
    пространству. «Каталог», «Наборы данных» и «Подписчики» переезжают на тот же механизм.
- Правка оболочки, поэтому в каждом PR идёт весь список живых прогонов.
