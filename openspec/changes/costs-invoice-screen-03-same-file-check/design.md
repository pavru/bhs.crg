# Design: проверка повтора файла по отпечатку до выгрузки

## Context

Общая архитектура — `../costs-invoice-screen-00-epic/design.md` (D7). Мотивация — `proposal.md`.
Устройство сегодня подробно описано в разборе Архитектора по листу «Ф», §1. Здесь — то, что определяет
решения.

- **Отпечаток считает сервер при приёме** (`InvoiceSameFiles.FingerprintAsync`, своим проходом по файлу)
  в `from-scan` и в `POST …/{id}/scan`. Он хранится в `scan_fingerprint` вместе с печатью пути
  (`scan_fingerprint_seal`). Верят ему только при совпавшей печати (`Invoice.TrustedFingerprint`).
- **Индекс по отпечатку частичный и не уникальный** (`CostsDbContext`): это оговорка, а не запрет.
- **`FindAsync` ищет по счёту**: проекция, предел `Limit = 10`, запас ×2 на недоверенные строки.
- **Чтение счетов открыто всем держателям `costs.invoice.read`** без построчной изоляции (COST-30).
  Ответ «какие счета несут файл X» не раскрывает ничего сверх того, что видно в реестре. Это верно до
  внешних учётных записей (CLAUDE.md, «Условие пересмотра»).
- **Имя пользователя модулю известно только текущее** (`IModuleUser.Name`). Прецедент снимка — книга
  (`author_name`) и версии накладной.

## Goals / Non-Goals

**Goals:**
- Один вопрос на бросок, чистое чтение, по существующему индексу.
- Одна запись двойника для окна, формы и пакета.
- «Не знаем» нигде не выдаётся за «нет»: ни у отпечатка, ни у поставщика, ни у автора.

**Non-Goals:**
- Запрет повтора. Отказ 409 при выгрузке отвергнут зонтиком (D7): в модуле 409 значит «изменили», а в
  пакете любой 409 останавливает загрузку.
- Дозаполнение отпечатков у счетов до #1295 и имён у прежних счетов.
- Закрыть гонку двух пользователей между вопросом и выгрузкой. После заведения остаётся оговорка
  `sameFile`.
- Приложить найденный файл к другому счёту из окна (разбор §4). Это была бы замена скана чужого счёта
  с его `If-Match`.

## Decisions

### D1. Поиск — один путь «по отпечаткам», «по счёту» его зовёт

`InvoiceSameFiles.ByFingerprintsAsync(db, prints, except, ct)`: один запрос `WHERE scan_fingerprint IN
(…)` по индексу. Правило доверия печати — прежнее, в памяти. Предел — `Limit` на каждый отпечаток, запас
×2. `FindAsync(db, invoice)` зовёт его с одним отпечатком и `except: invoice.Id`. Правило доверия и
предел живут в одном месте.

*Отвергнуто:* второй, отдельный поиск для адреса. Два правила доверия разошлись бы при первой правке
печати.

### D2. Адрес — `GET` с повторяющимся параметром

`GET /api/costs/invoices/same-file?fingerprint=a…&fingerprint=b…`, в группе счетов, под
`costs.invoice.read`.
- **Перечень:** от 1 до 50 (`MAX_FILES` клиента), каждый отпечаток — 64 hex. Регистр приводится к
  нижнему, повторы схлопываются. Иначе — 400.
- **Длина адреса:** 50 × ~76 знаков ≈ 3,8 КБ. Это укладывается в предел строки запроса nginx стенда и
  поставки (8 КБ по умолчанию). Проверяется живьём задачей 1.4.
- **Ответ:** `IReadOnlyList<SameFileAnswer(string Fingerprint, IReadOnlyList<InvoiceSameFile> Twins)>` —
  по записи на каждый спрошенный отпечаток, в порядке вопроса.
- **Маршрут** не спорит с `/{id:guid}`: ограничение `guid`.

*Отвергнуто:*
- `POST` с телом. Это чтение, а `POST` в модуле — запись, и перепись If-Match (`InvoiceStaleFormTests`)
  спрашивала бы о нём.
- Адрес на один отпечаток. Пакет делал бы до 50 запросов.

### D3. Поля двойника

`InvoiceSameFile` расширяется, а не дублируется (разбор §3):

| Поле | Источник |
|---|---|
| `SupplierId`, `SupplierName`, `SupplierArchived` | колонка `supplier_id`; название и архив — `IModuleCatalog.RefsAsync(CostsDirectories.Organization, ids)`, **один вызов на ответ и только если двойники есть**. Отказ справочника — `SupplierName = null` при `SupplierId` (правило `InvoiceContracts`) |
| `State`, `Payment` | колонки, словами сервера, как в `InvoiceListItem` |
| `CreatedByName` | колонка `created_by_name` (D4) |
| `Mine` | `created_by == user.Id` |

Состояние и оплата нужны ещё и форме. Громкость оговорки сейчас считается клиентом по своему счёту
(`InvoiceTwinNotes`), а не по двойнику.

### D4. «Кто завёл» — снимок имени при заведении

`Invoice.Create(typeId, user.Id, user.Name)` и колонка `created_by_name` (`NULL`, предел длины как у
`SupplierMatch.ByNameLength`). Ставится в `FromScanAsync` и `CreateAsync`. У прежних счетов —
`NULL`: строки «кто завёл» нет. `Mine` у них всё равно верный, по `created_by`.

*Отвергнуто:* новый порт ядра «имена учётных записей». Он работал бы и для старых счетов, но расширял бы
контракт `BHS.CRG.Modules` ради одной строки окна и показывал бы нынешнее имя, а не имя на момент
заведения.

### D5. Сознательный повтор — отпечаток, повтор которого принят

- `from-scan` принимает поле формы `acceptRepeat` (`true`/`false`, по умолчанию `false`).
- Сервер ставит его, только если при заведении у отпечатка есть доверенные двойники:
  `ScanRepeatAccepted = print`, колонка `scan_repeat_accepted` (text, `NULL`).
- В ответе счёта признак `scanRepeatAccepted` = `ScanRepeatAccepted == TrustedFingerprint`.

**Почему отпечаток, а не флажок.** Признак обязан относиться к файлу:
- замена файла (`AttachScan` с новым отпечатком) гасит его сама, без отдельной ветки;
- **копия.** Восстановление из копии старше колонки её не трогает (`ModuleBackupShapeTests`). Флажок
  остался бы от нынешнего файла и приписался бы файлу из копии. Отпечаток с тем же правилом печати —
  нет, тот же приём, что `scan_fingerprint_seal`.

**Двойников нет к моменту заведения** — гонка, двойник удалён. Поле игнорируется без отказа: черновик
заводится всегда, когда файл годен (`FromScanAsync`). Отказ здесь превратил бы оговорку в запрет.

### D6. Пишущее у этого change — только `from-scan`, и `If-Match` к нему не применим

Новых пишущих адресов нет. `acceptRepeat` — поле существующего адреса заведения.
- **Ворота:** `from-scan` уже стоит под `costs.invoice.edit` в группе модуля (AUTH-8, AUTH-9). Сценарии
  отказов записаны в спецификации и проверяются тестами.
- **`If-Match` не применим — названное исключение.** Версии у счёта до заведения нет. Правило
  спецификации касается адресов `/api/costs/invoices/{id}/…` (`InvoiceStaleFormTests`), и `from-scan` в
  их число не входит, как и `POST /api/costs/invoices`. Повтор заведения после обрыва закрывает не
  версия, а вопрос по отпечатку до отправки: «это вы завели» (`Mine`).

## Risks / Trade-offs

- [Лишний вызов справочника на каждое чтение счёта с двойниками] → только при непустом перечне, одним
  вызовом на ответ.
- [Клиентский и серверный SHA-256 разойдутся] → общий набор примеров C#/TS (ребёнок 14). Серверный тест
  этого change сверяет `FingerprintAsync` с тем же набором.
- [Гонка двух вкладок между вопросом и выгрузкой] → закрывается не здесь: остаётся оговорка `sameFile`
  после заведения, как сегодня.
- [Длинная строка запроса режется прокси заказчика] → предел 50 отпечатков. Проверка через nginx стенда
  (задача 1.4). Если прокси заказчика строже, клиент делит вопрос на части — это забота 14.

## Migration Plan

- **PR 1** — `dotnet ef migrations add InvoiceCreatedByName --project src/server/BHS.CRG.Modules.Costs
  --context CostsDbContext`.
- **PR 2** — `dotnet ef migrations add InvoiceScanRepeatAccepted --project
  src/server/BHS.CRG.Modules.Costs --context CostsDbContext`.
- Колонки допускают `NULL`, умолчаний и переноса данных нет.
- **Откат** — поля ответа необязательны, адрес новый. Миграции обратимы.
