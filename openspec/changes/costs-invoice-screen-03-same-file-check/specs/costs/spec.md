# Spec Delta: costs

## ADDED Requirements

### Requirement: [COST-6.7] Тот же файл — оговорка по отпечатку содержимого
Счёт SHALL называть другие счета, к которым приложен файл с тем же содержимым (SHA-256, посчитанный
сервером при приёме), полем `sameFile` ответа чтения — оговоркой, а не запретом. Счёт без доверенного
отпечатка MUST NOT сравниваться: это «неизвестно», а не «повторов нет».

#### Scenario: Тот же файл у двух счетов
- **WHEN** один и тот же файл заведён двумя черновиками
- **THEN** каждый из них называет другого в `sameFile`, и оба сохраняются без отказа

#### Scenario: Счёт до появления отпечатка
- **WHEN** файл, приложенный к счёту без отпечатка, заводят ещё раз
- **THEN** новый черновик того счёта в `sameFile` не называет, и ответ нигде не утверждает, что файл новый

#### Scenario: Отпечаток от другого файла
- **WHEN** путь файла счёта сменился в обход приёма (восстановление из копии старше отпечатка)
- **THEN** отпечатку этого счёта не верят, и с ним ничего не сравнивается

### Requirement: [COST-6.7] Вопрос «тот же файл» по отпечаткам до выгрузки
`GET /api/costs/invoices/same-file?fingerprint=…` SHALL принимать от 1 до 50 отпечатков (64 шестнадцатеричных
знака, регистр не важен) и отвечать по записи на каждый: отпечаток и его двойники — то же правило доверия
и тот же предел числа, что у `sameFile`. Адрес MUST только читать.

#### Scenario: Пакет из трёх файлов
- **WHEN** спрашивают три отпечатка, один из которых приложен к двум счетам
- **THEN** ответ 200 несёт три записи: у одной два двойника, у двух других пустые перечни

#### Scenario: Пустой перечень двойников
- **WHEN** у отпечатка нет двойников среди счетов с доверенным отпечатком
- **THEN** его запись несёт пустой перечень, и ничего сверх этого — без признака «файл новый»

#### Scenario: Неверный запрос
- **WHEN** отпечатка нет, их больше 50 или один из них не 64 шестнадцатеричных знака
- **THEN** ответ 400 со словами, что не так

#### Scenario: Без права чтения счетов
- **WHEN** адрес вызывает пользователь с `costs.waybill.read`, но без `costs.invoice.read`
- **THEN** ответ — отказ 403

#### Scenario: Ворота модуля
- **WHEN** адрес вызывает пользователь без единого права модуля `costs`
- **THEN** ответ — отказ, а перепись ворот находит адрес в группе модуля

### Requirement: [COST-6.7] Двойник называет, что это за счёт
Каждый двойник в `sameFile` и в ответе вопроса по отпечаткам SHALL нести номер, дату, сумму к оплате, имя
файла, время заведения, поставщика (идентификатор, название, признак архива), состояние документа и
оплаты, имя заведшего и признак «завёл вошедший». Справочник не ответил — названия нет при идентификаторе:
«не знаем», а не «без поставщика».

#### Scenario: Двойник разобран другим
- **WHEN** файл приложен к разобранному оплаченному счёту, который завёл Петров
- **THEN** двойник несёт поставщика, `state` «разобран», `payment` «оплачен», имя «Петров» и `mine: false`

#### Scenario: Свой черновик минуту назад
- **WHEN** ответ на заведение черновика потерялся, и тот же пользователь спрашивает по отпечатку этого файла
- **THEN** двойник — его черновик минутной давности с `mine: true`

#### Scenario: Справочник организаций не ответил
- **WHEN** у двойника есть поставщик, а справочник ядра не прочитан
- **THEN** у двойника есть идентификатор поставщика без названия

### Requirement: [COST-6.7] Кто завёл счёт — имя на момент заведения
Заведение счёта (вручную и из файла) SHALL запоминать имя заведшего, каким оно было в момент заведения.
Счёт, заведённый до этого изменения, MUST NOT выдавать заведшего за неизвестного человека: имени у него
нет, и строки «кто завёл» нет.

#### Scenario: Автор переименован
- **WHEN** пользователь, заведший счёт, сменил имя
- **THEN** двойник называет прежнее имя

#### Scenario: Прежний счёт
- **WHEN** двойник заведён до этого изменения
- **THEN** имя заведшего пусто, а признак «завёл вошедший» считается по сохранённой учётной записи

### Requirement: [COST-6.7] Сознательный повтор файла
`POST /api/costs/invoices/from-scan` SHALL принимать поле формы `acceptRepeat`: при нём и при доверенных
двойниках счёт запоминает, что повтор этого файла принят, и ответ чтения несёт `scanRepeatAccepted: true`.
Признак MUST относиться к файлу: замена файла или чужой отпечаток его гасят.

#### Scenario: Завести ещё один черновик
- **WHEN** пользователь заводит черновик из файла, уже приложенного к счёту, с `acceptRepeat`
- **THEN** черновик заведён, `sameFile` называет двойника, `scanRepeatAccepted: true`

#### Scenario: Двойник исчез до заведения
- **WHEN** `acceptRepeat` пришёл, а двойников у файла к моменту заведения нет
- **THEN** черновик заведён без отказа, `scanRepeatAccepted: false`

#### Scenario: Файл заменили
- **WHEN** у счёта с принятым повтором заменяют файл через `POST …/{id}/scan`
- **THEN** `scanRepeatAccepted: false`, пока новый файл не заведён повтором явно

#### Scenario: Без права правки
- **WHEN** `from-scan` с `acceptRepeat` вызывает пользователь с `costs.invoice.read` без `costs.invoice.edit`
- **THEN** ответ — отказ 403, черновик не заведён

#### Scenario: Ворота модуля
- **WHEN** `from-scan` вызывает пользователь без единого права модуля `costs`
- **THEN** ответ — отказ, а перепись ворот находит адрес в группе модуля

#### Scenario: Заведение не спрашивает версию
- **WHEN** `from-scan` вызван без `If-Match`
- **THEN** черновик заводится: версии у счёта ещё нет, а заголовок `If-Match` требуют только адреса `/api/costs/invoices/{id}/…`
