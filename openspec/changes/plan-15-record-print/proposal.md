# Proposal: печать записи модуля шаблоном Typst и печатная форма КП

Дочерний change зонтика `plan-00-epic`, общая архитектура — `../plan-00-epic/design.md` (D4, D13).

## Why

Печатная форма КП — шаблон Typst ядра, настраиваемый заказчиком (`PLAN-14`). Механизм печати ядра —
шаблоны, библиотека, блоки составных типов, генерация PDF — общий для всех модулей (`CORE-14`, `CORE-21`),
но сегодня печатает он только **экземпляр документа** модуля `id`: генерация берёт `DocumentInstance`
(`Application/Generation/GenerateDocumentCommand.cs:7`), а у `IAppModule` членов печати нет. Запись
модуля (КП — запись схемы `plan`, `PLAN-Q8`) напечатать нечем. Счёт `costs` не печатается по решению
владельца M4 (`Modules.Costs/CostsRecordTypes.cs:132-141`), поэтому механизм до сих пор был не нужен; КП —
первый потребитель, второй — список работ графика (`plan-20`, рекомендация В-10).

Вторая преграда: шаблоны и библиотека Typst закрыты правом модуля `id` (`/api/templates` —
`id.document.read` и `id.config.edit`, `Api/Endpoints/Templates/TemplateEndpoints.cs:22-23`). На
установке без `id` шаблон КП не открыть и не настроить.

## What Changes

- **PR 1 — ядро: печать записи модуля.**
  - `IAppModule` получает объявление печатных форм: тип записи модуля (уже проецируемый в схему типа,
    `ModuleRecordType`) и поставщик контекста — служба модуля, которая отдаёт JSON записи **в правах
    печатающего** (D4: закрытые поля в контекст не попадают вовсе).
  - Адрес ядра `POST /api/print/{typeCode}/{recordId}` (и предпросмотр) — генерация общим путём:
    шаблон — обычный `Template` ядра, привязанный к типу записи; блоки типов, библиотека, ассеты — как у
    документов. Ворота — право чтения записи, которое объявляет печатная форма, и ворота модуля-владельца.
  - Шаблоны и библиотека для типов модулей правятся правом ядра `core.print.edit` (предложено; ждёт
    решения В-13): установка без `id` настраивает печать КП. Шаблоны типов `id` остаются под `id.config.edit`.
  - Объявленная форма без поставщика контекста — отказ при старте.
- **PR 2 — печатная форма КП** (`PLAN-14`). Поставщик контекста КП: шапка, стройка, заказчик, строки,
  наценки скрыты (печатается цена продажи), итог, НДС по режиму КП (ждёт решения В-9), версия и дата
  отправки. Шаблон по умолчанию, который заказчик правит в редакторе шаблонов. Себестоимость в контекст
  печати КП не входит никогда — даже у держателя `plan.estimate.cost` (`PLAN-11`).

## Capabilities

### New Capabilities
- Нет.

### Modified Capabilities
- `core`: печать записи модуля шаблоном Typst — объявление печатной формы, контекст в правах печатающего,
  право на шаблоны типов модулей.
- `plan`: печатная форма коммерческого предложения.

## Impact

- **Контракты:** `BHS.CRG.Modules/IAppModule.cs` (член печатных форм), новый
  `BHS.CRG.Modules/Printing/ModulePrintForm.cs`, `IModulePrintContext.cs`.
- **Ядро:** новый `Api/Endpoints/Generation/RecordPrintEndpoints.cs`, `Application/Generation/` — команда
  печати записи над `IDocumentGenerator`; `Api/Endpoints/Templates/*` — ворота шаблонов по владельцу
  типа; `Api/Auth/CorePermissions.cs` — `core.print.edit` (ждёт решения В-13); проверка при старте.
- **Модуль `plan`:** `Printing/OfferPrintContext.cs`, шаблон КП по умолчанию, регистрация.
- **Клиент:** кнопка «Печать» карточки КП — в `plan-17`; редактор шаблонов показывает типы модулей
  (`features/templates/*`) — правка доступа без нового экрана.
- **Тесты:** `RecordPrintTests`, `ModulePrintFormCatalogTests`, `OfferPrintTests`, `EndpointGateInventoryTests`,
  `PlanOnlyHostTests` (печать КП без `id`).
- **Документы:** `docs/ADMIN_GUIDE.md` (печать КП и право на шаблоны), `docs/DEV_NOTES.md` (как модулю
  объявить печатную форму).
