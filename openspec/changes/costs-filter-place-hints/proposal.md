# Proposal

## Why

Отбор реестра счетов по «Объекту» и «Разделу» сервер сверяет по названию целиком, а поле значения в
условии — голый `<input>`. Опечатка («Комарова, 36» вместо «Комарова 36», «Комарова 36/4 эт.» вместо
«Комарова 36 / 4 эт.», «е» вместо «ё») даёт пустой реестр без единого сигнала, а «Сумма» под таким отбором
становится долей ни на что. Сервер замечает это только задним числом — подписью «доля: названных объектов
нет» в заголовке «Суммы», и то, если колонка на экране. Отборы, пришедшие ссылкой или из сохранённого
представления со старым названием стройки, промахиваются так же молча.

Подсказка по ранее введённому (эпик #1527) сюда не подходит: она адресует поле схемы записи каталога
(`type` + `field`), а колонки таблицы модуля — не поля типа. И стройка — запись справочника, а не
свободный текст. Зато справочник целиком уже есть на клиенте: стройки с разделами — `/costs/constructions`
(тот же порт `IModuleConstructions`, из которого сервер собирает названия для сверки), статьи —
`/costs/articles`. Нового адреса не нужно.

## What Changes

- **Поле значения условия с подсказкой из перечня колонки.** У колонки, для которой экран знает
  перечень значений, поле значения в условии отбора (окошко чипа и расширенный диалог, общий
  `ConditionEditor`) подсказывает из этого перечня. Значение остаётся свободным текстом: «содержит
  Комарова» задаётся, как раньше. [UI-55]
- **Пометка «нет в справочнике».** Значение «равно» / «из списка», которого нет в перечне, и условие
  «содержит»-семьи, под которое не подходит ни одно известное название, помечаются — под полем, на
  значении списка и на чипе условия над таблицей. Тон — предупреждение, сохранение не запирается; пока
  перечень не известен целиком, пометка молчит. Сверка — правилом сервера (целиком, без регистра, ё ≠ е,
  пробелы значимы). [UI-56]
- **«Заменить на похожее».** Если значение не совпало, но ровно одно известное название совпадает мягко
  (ё = е, пробелы по краям и двойные, пробелы вокруг «/»), пометка предлагает заменить одним действием.
  [UI-56]
- **Перечни реестра счетов.** «Объект»: стройки (избранные вперёд), группа «Вне строек» — действующие
  статьи, затем архивные со словом «в архиве», последним — «объект удалён». «Раздел»: «стройка / раздел»
  и «стройка / без раздела» по стройкам (избранные вперёд), последним — «раздел удалён». У «Раздела»
  голое название стройки получает пояснение и два действия на выбор — «Все разделы стройки» и «Без
  раздела». [COST-20.1]
- **Значение вне закрытого перечня колонки-выбора** показывается тем же тоном предупреждения, что
  пометка, а не красным. [UI-56]
- **Флажок `Sections` в объявлении колонки таблицы модуля**, рядом с `Sites`: в клетках — разделы
  справочника ядра в подписи «стройка / раздел». Подсказка экрану, а не правило выдачи. [CORE-33]
- **`SuggestField` принимает готовый перечень** вместо адреса: тот же слой, клавиатура, доступность и
  поведение на телефоне (UI-1, UI-2, UI-4, UI-6–UI-8), без запросов и задержки, с подписями групп. [UI-55]

Не входит: «Поставщик», «Плательщик», «Назначение» и прочие текстовые колонки (им нужен адрес значений
колонки — отдельное решение), отбор в обработке наборов данных, чип «избранные стройки» (`SitesChip`) —
без изменений, таблицы других модулей со стройками — когда появятся.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `sharedui`: поле с подсказкой из готового перечня; поле значения условия отбора подсказывает из
  перечня колонки, помечает значение вне перечня и предлагает замену на похожее.
- `costs`: реестр счетов знает перечни колонок «Объект» и «Раздел» — состав, порядок, слова
  потерянных ссылок.
- `core`: объявление колонки таблицы модуля помечает разделы справочника (`Sections`), как уже помечает
  стройки (`Sites`).

## Impact

- **Сервер:** `ModuleTableColumn` (`BHS.CRG.Modules/Tables`), `TableColumnDto`
  (`BHS.CRG.Application/Tables`), `ModuleTableService.Declared`, объявление `InvoiceTable` (`Sections` у
  «Раздела»). Новых адресов и пишущих API нет; контракт ответа `/api/tables/{адрес}/columns` получает
  необязательное поле `sections`.
- **Клиент:** `shared/ui/SuggestField.tsx` (разделение на список и источник), `shared/filter`
  (`RowFilterValue`, `ConditionEditor`, `FilterChips`, правило сверки и пометки), `shared/api/tables.ts`
  (`TableColumn.sections`, `FilterColumn.known`), `features/tables` (сборка перечней из
  `useCostsConstructions`, `useCostsArticles`, избранного), сторож-реестр строек.
- **Общий набор случаев C#/TS** для подписей разделов и слов потерянных ссылок — формат живёт на сервере
  (`InvoiceShares`) и в копии на клиенте.
- **Порядок работ интерфейса (#1545):** разбор с «Дизайнером» и «Архитектором» (затронут `shared/ui`),
  три макета в Claude Design на новое (пометка, замена, пометка на чипе), выбор владельца — до кода.
