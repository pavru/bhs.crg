# Design: таблицы и опубликованные наборы модуля `plan`

Дочерний change зонтика `plan-00-epic`, общая архитектура — `../plan-00-epic/design.md` (D3 — действующая
редакция, D4 — деньги правом, D12 — права). Здесь только решения этого change.

## Context

Сверено по коду master `6b81e51e`.

- `ModuleTable` (`BHS.CRG.Modules/Tables/ModuleTable.cs:146-160`): код, название, зерно, `Requires`,
  `Isolation`, граница, колонки, служба строк, тип записи, представления. У колонки есть свой
  `Requires` (`:101`) — колонка под правом. `Isolation` — `None` или `PerUser` (`:49-58`).
- Образец — `Modules.Costs/Tables/InvoiceTable.cs` (`Requires: "costs"`, `ModuleTableIsolation.None`,
  `:224-225`). Набор из таблицы строит ядро (`Api/Modules/Tables/ModuleTableDataProvider.cs:23`).
- Сторожа денег по месту хранения — `Tests/Configuration/ModuleMoneyStorageTests.cs`.
- Таблицы схемы `plan`: `estimate_rows` и метод «по действующим» — `plan-06`; распределение — `plan-10`;
  КП — `plan-13`; работы графика — `plan-19`.

## Goals / Non-Goals

**Goals:** три таблицы с колонками под правами; наборы из них; переписи денег знают `plan`.

**Non-Goals:**
- изоляция строк — в `plan` её нет (`CatalogScope` — не граница безопасности, инвариант #675);
- таблица редакций прошлых лет и строк недействующих редакций — набор отдаёт план, а не историю;
- «Ход работ» — свёрстанный экран, не таблица (`plan-25`).

## Decisions

- **`plan.estimate-rows`.** Зерно — «строка действующей редакции сметы»; служба строк читает методом
  «по действующим» `plan-06` и ничем другим. `Requires: "plan.estimate.read"`. Колонки «Стоимость единицы»,
  «Итого» и поля схемы `ПозицияСметы` (`RecordType`) — `Requires: "plan.estimate.cost"`. «Распределено» —
  сумма частей `plan-10`; «сопоставлено» — да/нет с причиной.
- **`plan.offers`.** Зерно — «КП» (действующая версия, `CORE-36`: история в таблицу не идёт). `Requires:
  "plan.offer.read"`: цены продажи и итоги видит только оно. Себестоимости в таблице нет вовсе — она не
  копируется в КП (`PLAN-11`).
- **`plan.schedule-works`.** Зерно — «работа графика». `Requires: "plan.schedule.read"`. Денег нет.
  Предупреждения — кодами сервера (D17 зонтика).
- **Граница выдачи.** «Строки действующих редакций смет всех строек; стоимость — по праву на
  себестоимость», «Коммерческие предложения всех строек, действующие версии», «Работы графиков всех
  строек».
- **Наборы.** `system:table:plan.estimate-rows`, `system:table:plan.offers`,
  `system:table:plan.schedule-works` — без своего кода: их строит ядро из таблиц. Колонка под правом в
  наборе отсутствует у читающего без права и названа в границе.
- **If-Match и ворота.** Таблицы только читают: `If-Match` не нужен. Ворота — `Requires` таблицы и колонок,
  перепись `ReadAllWritesNothingTests`.
- **Сторож.** `PlanTablesTests`:
  - читающий с `plan.estimate.read` без `plan.estimate.cost`: в строках таблицы, выгрузке XLSX и наборе
    нет ни одного денежного значения — проверка по ответу целиком;
  - повторный импорт: в `plan.estimate-rows` только строки действующей редакции;
  - без `plan.offer.read` — таблица КП 403, набор не виден.
  `ModuleMoneyStorageTests`: модуль `plan` в переписи, его денежные поля — только в таблицах модуля.
- **Чем ломается.** Деньги в колонке без `Requires` — сметчик без права себестоимости видит её в
  выгрузке. Служба строк читает `estimate_rows` напрямую — набор удваивает план после повторного импорта.

## Risks / Trade-offs

- [Заказчик добавит денежное поле в схему `ПозицияСметы`] → все поля схемы таблицы — под
  `plan.estimate.cost` целиком (как в ответе строк `plan-06`), а не по тэгу.
- [Набор КП станет обходом прав для печати `id`] → набор под `plan.offer.read`; источник на нём читает в
  правах читающего (`CORE-24`).
