# Design: экран счёта — отмена вместо подтверждения

Общая архитектура — `../costs-invoice-screen-00-epic/design.md`: D6 (отмена вместо подтверждения), D8
(`Snackbar` из `sharedui-md3-12`). Требования — `specs/costs/spec.md`.

## Context

- **Отклонение** — `InvoiceMoreMenu.tsx`: `ConfirmDialog` с тремя пунктами, затем
  `rejectInvoice(...)` (`invoiceReject.ts`) → `POST …/rejected` с `If-Match`. Обратный переход —
  `POST …/draft`. Под отбором «Разобрать» `leadOn` (`InvoicesPage.tsx:217`) ведёт к следующему счёту и
  показывает тост «Вернуться» на 8 с.
- **Удаление строки** — `InvoiceLinesTable.tsx:271-274, 373`: строка уходит из черновика строк без вопроса.
  Сервер при записи уносит её разноску каскадом. Ветку «строка с разноской» берёт #1655.
- **Удаление счёта** — `InvoiceDeleteDialog` и `invoiceDelete.ts`: `canDelete`, `goingAway` (что уйдёт),
  `deleteRecord`. Вызывается из «⋮», из плашки сбоя распознавания («Не тот файл — удалить черновик…») и из
  двойников («Загружен дважды — удалить этот черновик…»). После 11 эти действия живут в banner и в пунктах
  перечня.
- **Сервер** (`InvoiceDeletion.cs`, разбор Архитектора «Ф», В1):
  - `DELETE` с `If-Match` удаляет запись, строки, доли и запись распознавания каскадом, а файл в Garage —
    последним;
  - журнал пишет «удалён насовсем»;
  - идущее распознавание по удалённому счёту завершается без ошибки.

  Восстанавливать не из чего, поэтому «Вернуть» возможен только до отправки.
- **Снэкбар** (`sharedui-md3-12`): по одному, следующий — после закрытия текущего, ошибка не вытесняется,
  действие — text.

## Goals / Non-Goals

**Goals:** три действия без окна, и у каждого настоящая отмена. Отказ отменённого или отложенного действия
выглядит отказом.

**Non-Goals:**
- удаление строки с разноской — #1655;
- окно повтора файла и замена файла с вопросом — 14;
- серверные правки и мягкое удаление (D6 зонтика);
- отмена «Разобран»: у него и сейчас нет окна, а обратный ход — «Вернуть в черновик».

## Decisions

### D-13.1. Отклонение — запрос сразу, «Вернуть» — обратный переход

- Пункт «Отклонить» в «⋮» без многоточия: окна больше нет. Пояснение из окна («по нему не платим; вернуть
  — «Вернуть в черновик»») — подсказкой пункта.
- Успех → снэкбар «Счёт № … отклонён · Вернуть». Под очередью «Разобрать» этот снэкбар заменяет «Вернуться»
  `leadOn`: два снэкбара подряд — это два действия, которых человек не просил.
- «Вернуть» → `POST …/draft` с версией из ответа отклонения, затем `switchTo(id)` к этому счёту. Отказ (409
  или иное) — снэкбар-ошибка со словами сервера, счёт остаётся отклонённым.
- **Альтернатива** — откладывать сам запрос отклонения, как у удаления. Отвергнута: отклонение обратимо на
  сервере, а задержка заставила бы соседа видеть «черновик» дольше, чем надо.

### D-13.2. Удаление строки без разноски

- «Без разноски» — у строки нет сохранённых долей (`line.allocation.parts.length === 0`) или строка новая.
  Иначе — ветка #1655.
- Удаление убирает строку из черновика строк и запоминает `{ line, index }` в снэкбаре «Строка N удалена ·
  Вернуть». «Вернуть» вставляет строку на прежний индекс с прежними полями.
- **До автосохранения (12)** всё живёт в черновике: возврат — правка черновика, запись — кнопкой.
- **После 12** удаление — цельное действие, повод записи строк (D-12.2 ребёнка 12). Чтобы «Вернуть» не
  превращался в повторное заведение, пометка `lines` после удаления ждёт закрытия снэкбара. Ушла раньше
  (другая правка строк, смена счёта) — значит, удаление записано. Тогда «Вернуть» добавляет строку заново
  с теми же полями, с новым `id`. Разноски у неё не было, так что теряется только `id`, на который ничто не
  ссылается.

### D-13.3. «Свежий» черновик

`isFresh(id)`:
- черновик заведён **из файла в этой вкладке** — «Счёт из файла» или бросок. Его `id` записывается в
  множество `createdHere` при ответе заведения;
- **с тех пор из этой вкладки в него ничего не записано**: ни реквизитов, ни строк, ни «Всё верно», ни
  разноски. Сдвиг версии распознаванием записью человека не считается.

Остальные черновики удаляются окном (`InvoiceDeleteDialog`): чужой черновик, черновик прошлого сеанса,
черновик с правками. Признак живёт в памяти вкладки и с перезагрузкой пропадает. Это безопасное
направление: окно спросит лишний раз.

**Альтернатива** — признак на сервере («ни одной записи, кроме заведения и распознавания»). Отвергнута:
сервер не меняется (D6 зонтика), а журнал для такого решения читать дорого и не нужно.

### D-13.4. Отложенный `DELETE` — очередь вне страницы

`features/costs/pendingDelete.ts` — модуль, не компонент: переход внутри приложения его не размонтирует.

```
schedule(id, version) → снэкбар «Черновик удалён · Вернуть»; список прячет id
undo(id)              → убрать из очереди, вернуть в список, switchTo(id)
send(id)              → DELETE …/invoices/{id} с If-Match: последняя известная версия
```

- **Когда уходит запрос** — по закрытию снэкбара: таймаут или крестик. Снэкбар, стоящий в очереди за
  другим, держит удаление до своего показа и закрытия.
- **Версия.** Берётся последняя, которую клиент видел: опрос распознавания перечитывает счёт и обновляет
  её. 409 значит, что после последнего чтения счёт сдвинулся. Тогда снэкбар-ошибка «Черновик не удалён:
  распознавание дописало счёт — удалите ещё раз», черновик снова в списке. Автоповтора нет: удалять то,
  чего человек не видел, нельзя.
- **`pagehide`** — для всех ждущих: `fetch(url, { method: 'DELETE', keepalive: true, headers: {
  Authorization, 'If-Match' } })`. Тела нет, лимит `keepalive` не мешает. `apiClient` (axios) `keepalive`
  не умеет, поэтому здесь прямой `fetch` с тем же токеном. Отказ или неотправка — черновик остаётся.
- **Список.** Пока удаление ждёт, страница отфильтровывает `id` из перечня, а открытый счёт закрывает. Под
  отбором «Разобрать» — ведёт к следующему, как после отклонения.
- **Сосед** в эти секунды черновик видит. Это приемлемо (Архитектор, В1).

### D-13.5. Где кнопка удаления какая

| Место | Свежий черновик | Иначе |
|---|---|---|
| banner сбоя распознавания: «Не тот файл — удалить» | отложенно, без многоточия | окно, «Не тот файл — удалить…» |
| пункт «тот же файл»: «Загружен дважды — удалить» | отложенно | окно |
| «⋮ → Удалить» | отложенно | окно |
| пункт дубликата «Это дубль — удалить…» | окно: дубликат определяется по сохранённым реквизитам, значит, черновик уже правили | окно |

Многоточие в подписи — по правилу «действие с окном»: где окна нет, его нет.

## Risks / Trade-offs

- [Отложенный `DELETE` не уйдёт при закрытии вкладки] → черновик остаётся черновиком (D6 зонтика), это не
  потеря.
- [Токен истёк к моменту `pagehide`] → запрос получит 401, черновик останется. То же безопасное
  направление.
- [Снэкбар ждёт в очереди, и удаление затягивается] → черновик скрыт из списка всё это время. Сосед видит
  его дольше. Приемлемо.
- [«Вернуть» строки после записи меняет `id`] → у строки без разноски на `id` ничто не ссылается (D-13.2).
- [Пересечение с #1655 в одной кнопке удаления строки] → ветки разведены условием «есть сохранённая
  разноска». Если #1655 слит раньше, 13 встраивается в его обработчик, не дублируя вопроса.

## Migration Plan

Один PR, `version:minor`. Откат — revert: окна возвращаются. Сервер не меняется.
