# Proposal: серии записей журнала действий

## Why

Владелец выбрал новый экран счёта (макет «Экран счёта · критический пересмотр», вариант Г, 27.10.2026):
шапка и строки черновика будут писаться сами, по уходу с поля и из строки. У такой записи есть цена.
Журнал действий ([CORE-28]) получает по записи «Счёт изменён» и «Строки счёта изменены» на каждый шаг:
около 30 записей на счёт вместо двух. Экран журнала тонет в однообразных строках одного человека над
одним счётом. Владелец попросил сворачивать такие подряд идущие правки одного объекта и показывать итог
(27.10.2026). Разбор Архитектора выбрал вариант «в», владелец его принял.

Делать это нужно **до** автосохранения экрана счёта. Иначе первым поток записей увидит пользователь, а
не тест.

Проблему нельзя решить, обновляя последнюю запись серии. Журнал по требованию только дописывается
([CORE-28], `IAppendOnlyRecord`, отказ в `AppDbContext.RefuseAppendOnlyEdits`). На неизменности записей
стоит и восстановление копии: известные `Id` пропускаются. Свидетельство, в котором строку можно
поправить, перестаёт быть свидетельством.

## What Changes

- **Ключ сессии при вставке.** `ActivityLog.RecordAsync` смотрит на предыдущую запись той же цели и
  ставит новой строке два значения:
  - `SessionId` — `Id` первой записи сессии;
  - `SeriesHead` — признак «первая запись этого вида в сессии».

  Прежние строки не меняются. Журнал остаётся дописываемым, сигнатура порта модуля прежняя.
- **Сессия правки** — подряд идущие записи одной цели, одного автора, все из одной объявленной группы
  свёртки. Пауза между записями не больше 10 минут, весь интервал не больше 60 минут, полночь по поясу
  компании сессию рвёт. Серия — записи одного вида внутри сессии. Если шапка и строки чередуются, сессия
  не рвётся: на экране получаются два ряда.
- **Свёртку объявляет вид события.** У `ActivityAction` и `ModuleActivityAction` появляется
  необязательное поле `Fold`: группа плюс правило слияния `Before` и `After` (`Span` — первое и последнее
  значение, `Union` — объединение перечней). По умолчанию вид не сворачивается. Проверки при старте:
  - группа принадлежит модулю вида;
  - у всех видов группы одно право чтения;
  - виды из запретного перечня свёртку не объявляют: переходы, оплата, исправление, удаление, закрытие
    периода, права и роли, состав модулей.
- **Чтение по головам серий.** `GET /api/activity` отдаёт ряд серии: число записей, интервал, метку цели
  последней записи (и прежнюю, если она менялась) и слитые «было» и «стало». Видимость и отбор — в
  запросе, как сейчас. Общее число считает ряды. Новый адрес
  `GET /api/activity/series/{sessionId}?action=` отдаёт сырые записи ряда тому, кто вправе их видеть.
- **Экран «Журнал действий»** показывает ряд «Счёт изменён ×9 · 14:02–14:19» и раскрывает его в записи.
- **`costs` объявляет свёртку** четырёх видов:
  - `costs.invoice.changed` и `costs.invoice.lines` — группа `costs.invoice.edit`;
  - `costs.waybill.changed` и `costs.waybill.lines` — группа `costs.waybill.edit`.

  Остальные виды модуля не сворачиваются.
- **Копия переносит ключ.** Запись копии старого формата, без ключа, читается одиночной.

Чего change **не** делает:
- не уменьшает объём журнала и не вводит ретенцию — это отдельное решение о [CORE-28];
- не добавляет значений полей шапки счёта в журнал. Их нет нарочно (#1190): журнал читают без права на
  счета. Свёрнутый ряд «Счёт изменён» называет, какие поля менялись, кто, когда и сколько раз;
- не меняет издателей событий.

## Capabilities

### New Capabilities
- нет

### Modified Capabilities
- `core`: новые требования [CORE-28.2] «Серии записей журнала» и [CORE-28.3] «Объявление свёртки».
  [CORE-28.1] не правится: дописываемость сохраняется. Его же меняет незавершённый change
  `core-activity-channel` — так два change не спорят за одно требование.
- `costs`: новое требование [COST-6] [CORE-28.3] — какие виды журнала модуля сворачиваются.

## Impact

- **Сервер.**
  - Домен: `ActivityRecord` — поля `SessionId` и `SeriesHead`. Миграция ядра (`AppDbContext`): две
    колонки и индексы `(target_id, occurred_at)` и `(session_id)`.
  - Приложение: `ActivityAction`, `ActivityFold`, `IActivityLog` (чтение рядов и записей серии),
    `BackupActivityRecord`.
  - Инфраструктура: `ActivityLog` — сессия при вставке под транзакционным замком по цели, чтение по
    головам с добором хвостов.
  - Api: `ActivityActionCatalog` (проверки свёртки), `ActivityEndpoints` (DTO ряда, адрес записей
    серии).
  - Контракты модулей: `BHS.CRG.Modules/Ports/IModuleActivityLog.cs` (`ModuleActivityAction.Fold`).
  - Модуль `costs`: `InvoiceActions.cs`, `WaybillActions.cs`.
- **Клиент.** `src/client/src/features/settings/ActivityPage.tsx` (ряд серии и раскрытие),
  `shared/api` (типы и хук записей серии).
- **Копия.** Формат записи журнала получает два поля. Старый формат читается без отказа.
- **Порядок работ.** Change предшествует change по экрану счёта и его автосохранению. С
  `core-activity-channel` пересекается по `ActivityRecord` и копии: какой из двух придёт вторым, тот
  добавит своё поле к уже изменённому. Как только у записи появится канал, его смена рвёт сессию.
