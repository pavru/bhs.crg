# Design: прайс-лист и КП без сметы

Дочерний change зонтика `plan-00-epic`, общая архитектура — `../plan-00-epic/design.md` (D4, D5, D12).
Здесь только решения этого change.

## Context

Модель КП, наценки, статусы и версии строит `plan-13`. Порт видов работ с единицей классификатора —
`plan-03` (`IModuleWorkTypes`): у `ВидРаботы` единица обязательна
(`Application/Documents/CoreRecordTypes.cs:117-150`), поэтому цена за единицу однозначна. Прайс-листа
в коде нет нигде.

## Goals / Non-Goals

**Goals:** один прайс-лист с датами действия цен; КП «по прайс-листу» на стройку; честная пометка
«нет цены».

**Non-Goals:** несколько прайс-листов (по заказчику, по региону) — в ТЗ нет; перенос прежних цен —
нечего переносить (`PLAN-Q6`); экраны — `plan-17`.

## Decisions

- **Хранение.** Таблица `plan.price_list_entries`: вид работы (ссылка `CORE-34.1` на запись
  `ВидРаботы`), цена за единицу (`numeric`), действует с (`date`), автор и время. Уникальность — «вид
  работы + действует с». Цена вне единицы классификатора не хранится: единица — у вида работы.
- **Действующая цена** на дату — последняя строка вида работы с «действует с» не позже даты. Считает
  сервер; ответ строки КП несёт `priceSource: { kind: 'pricelist', validFrom }` или
  `{ kind: 'none' }` с кодом пометки `no-price` (D17).
- **Адреса.**
  - `GET /api/plan/pricelist?date=` — под `plan.offer.read`; строки с действующей ценой на дату и историей.
  - `PUT /api/plan/pricelist/{workTypeId}` — завести или изменить цену с датой; `DELETE
    /api/plan/pricelist/entries/{id}` — снять строку. Оба под `plan.pricelist.edit`, с `If-Match` (версия
    строки — `xmin`). Новая строка (`PUT` по паре без существующей записи) версии не требует — названное
    исключение по образцу заведения.
  - `POST /api/plan/offers/from-pricelist` — в группе КП `plan-13`, под `plan.offer.edit`: стройка, дата,
    виды работ с объёмами.
- **КП без сметы** в модели `plan-13` — `source: 'pricelist'`, ссылки на редакцию нет. Носители:
  `drift: null` (не `false`: проверять не с чем, `PLAN-13`), `canBuildSchedule: false` с причиной.
  Построение графика из такого КП не адресуется вовсе: график строится из редакции (`PLAN-15`).
- **Цена в КП замерзает** при заведении строки: смена прайс-листа уже заведённое КП не трогает; обновить
  цены — действие «пересчитать по прайс-листу на дату» в черновике, с показом изменений.
- **Права.** `plan.pricelist.edit` — `ReadAllMark.Out("правит цены продажи")`; «Менеджер проекта»
  получает его (`PLAN-23`). Тест состава доступа по ролям — в этом PR.
- **Сторож.** Правка без `If-Match` — 400, устаревшая — 409; «Сметчик» без `plan.offer.read` прайс-листа
  не читает (403). КП по прайс-листу: вид работы без цены — строка с пометкой, итог без неё помечен
  «неполный».
- **Чем ломается.** Прайс-лист в общей таблице объектов — цены продажи видны «Инженеру ИД» через «Общие
  данные» (`plan-29` ловит). Отсутствующая цена как 0 — КП уходит заказчику с бесплатной работой.

## Risks / Trade-offs

- [Заказчику понадобятся разные прайс-листы для разных клиентов] → таблица заведена с одной осью
  (дата); вторая ось (прайс-лист как запись) — миграцией, когда появится спрос.
- [Цена на дату КП, а работы через полгода] → цена замерзает в КП, обновление — явным действием.
