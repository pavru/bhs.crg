# Фоновый обмен и причины недоставки

## Context

WorkManager, Room, экран связи, профиль с локальным напоминанием, полевые операции отчётов и справочников. Опоры и границы описаны в [эпике](../mob-00-epic/design.md). Условие старта — [mob-03-report-exchange](../archive/2026-11-28-mob-03-report-exchange/tasks.md), [mob-04-reference-sync](../mob-04-reference-sync/tasks.md), [mob-05-unlisted-site](../mob-05-unlisted-site/tasks.md), [mob-07-android-join](../mob-07-android-join/tasks.md).

## Goals / Non-Goals

На стройке связь может прерваться после серверной записи. Монтажнику важно видеть, что осталось на устройстве и требуется ли его действие. Объём и наблюдаемый результат закреплены в [дельте mob](specs/mob/spec.md).

## Decisions

Уникальная фоновая работа для экземпляра и сотрудника, последовательность действий отдельного отчёта. Подтверждение ответа и продвижение курсора записываются с данными атомарно. Успешная отправка текста открывает очередь фото. Повторы с теми же id, ограниченная пауза для сетевых ошибок; конфликт требует явного решения. Число и самый старый ожидающий отчёт сообщать с отметкой времени наблюдения.

Сведения об очереди отправляются по версионному договору состояния устройства из MOB-04, включая пустой обмен с нулём отчётов. Здесь принимается первый реальный путь выдача поясов/вариантов → Room → офлайн-ввод и серверное сохранение веб-полей. Также здесь проверяется перевод очереди со старого id непривязанной записи на итоговый id по договору MOB-05.

## Risks / Trade-offs

Старый клиент может не понимать новой причины. Сохранить очередь и диагностический код, семь согласованных исходов должны вести к семи конкретным сообщениям.
