# Design: комплекты и шаблоны в «Недавних» Главной

Общая архитектура — `../shell-00-epic/design.md`. Механизм «Недавних» построен `shell-08-home`
(`../archive/2026-11-12-shell-08-home/design.md`, «„Недавние“ — по решению В-3»), контракт «Поиск записей» —
`shell-05-palette-data-search` (`../archive/2026-11-12-shell-05-palette-data-search/`). Мотивация —
`proposal.md`, Why.

## Context

Сверено по master `cea145e3` (архив `shell-08-home` слит, [CORE-25.3] и [UI-35] — в `openspec/specs`).

- **Контракт** `IRecordSearch` (`src/server/BHS.CRG.Modules/Search/IRecordSearch.cs`, «со многими
  поставщиками»): у поставщика `Groups`, `SearchAsync` и `CardsAsync`. Группа —
  `RecordSearchGroup(Code, Title, RecordType, Requires, Archive)`; признака «ищется ли группа» нет — всякая
  объявленная группа ищется. Карточка — `RecordSearchHit(Id, Title, Detail, Place, Amount, Level)`;
  `Level` — уровень `CatalogScope`, по нему клиент строит адрес набора данных. Права — два пояса: ключ
  группы (`Requires`, «право списка записей группы») ядро проверяет до вызова, а право, которое знает
  только поставщик, — его ответ «скрыто» (`ContractAnswer.Hidden`), и группа пропадает целиком.
- **Поставщики:** ядро — `CoreRecordSearch` (стройки, наборы данных; не через порт, «ядро — не модуль»),
  `costs` — `CostsRecordSearch` (`services.AddModuleContract<IRecordSearch, CostsRecordSearch>`).
  Каталог групп (`RecordSearchCatalog`) при старте отказывает группе без ключа прав или с чужим ключом.
- **«Недавние»** — `RecentRecordEndpoints`: `POST` принимает только тип, у которого есть группа
  (`catalog.ForRecordType`), иначе 400; `GET` спрашивает `RecordSearchService.CardsAsync` и сопоставляет
  ответ отметкам по `(RecordType, hit.Id)` — **карточка обязана нести тот идентификатор, о котором её
  спросили**, иначе строка пропадёт.
- **Модуль `id`** — обёртка `IdModule` в `BHS.CRG.Api` (#942): комплекты и шаблоны лежат в общих слоях,
  `RegisterServices` пуст. Права: `id.document.read` — чтение комплектов и `GET /api/templates`;
  `id.config.edit` (влечёт только `core.types.edit`, но не `id.document.read`) — правка шаблонов и **пункт
  рейла «Шаблоны»** (`navConfig.ts`, `/templates`). Выключить `id` сейчас нельзя (комментарий в
  `TemplateEndpoints.cs`), но [ID-10] требует, чтобы выключение работало.
- **Экран комплекта** — `/document-sets/:constructionId/sets/:setId` (`SetDetail`, под `IdModuleOnly`):
  маршрут закрыт правом «Строек» (`core.constructions.read`), данные комплекта — `id.document.read`; адрес
  требует стройку. Комплект лежит в разделе (`DocumentSet.SectionId`), раздел — в стройке.
- **Экран шаблонов** — `/templates?type=<documentTypeId>&template=<templateId>` (`TemplatesPage`). Тип,
  который не `Kind = Document` или `IsAbstract`, страница не выбирает и молча показывает «Выберите тип
  документа». Без `?template=` или с мёртвой версией страница **выбирает версию сама** (default+active →
  active → первая), и такой выбор, по её же комментарию, не осознанный: в память не пишется.
- **Версии шаблона** — отдельные строки таблицы со своими `Id`. Страница считает одним шаблоном все строки
  с одним `(DocumentTypeId, Name)` (`groupTemplates`, группировка по имени в списке типа). Уникального
  индекса на эту пару нет (`TemplateConfiguration` — только `(DocumentTypeId, IsActive)` и
  `(DocumentTypeId, IsDefault)`). `UpdateTemplateCommand` зовёт `CreateNewVersion` у **любой** версии: новая
  версия от v2 при действующей v4 даёт вторую действующую с номером 3. Версии удаляются по одной
  (`DELETE /api/templates/{id}`; «очистка версий» на странице — тот же адрес), удалить можно и действующую.
- **Клиент:** `RECORD_GROUPS` (`shared/ui/paletteRecords.ts`) — одна таблица палитры и «Недавних»;
  `openGroups` превращает каждую её строку в чип палитры. `RECORD_ROUTES` (`shared/ui/recordRoutes.ts`) —
  экран по коду типа; `at(level)` — экран, зависящий от места записи; `recordHref(route, id)` строит адрес
  из `path ?? screen` и одного параметра `param`. Потребители маршрута — не только Главная: `recordLink`
  (строка таблицы по `TableDeclaration.recordType`) и `hitRoute` (палитра); оба отказывают маршруту с `at`.
  `recentTarget` (`features/home/recentLink.ts`) берёт знак из группы, экран — из маршрута. Перепись
  `recordRoutesRecent.test.ts` требует, чтобы каждый тип из `RECORD_ROUTES` отмечался `useRecentTouch` и
  каждый отмечаемый тип имел группу.

## Goals / Non-Goals

**Goals:**
- Комплект и шаблон отмечаются, показываются и открываются из «Недавних» по тем же правилам, что три
  прежних типа: в правах спрашивающего, без ссылок в отказ, с отказом группы, сказанным словами.
- Новый тип записи в «Недавних» по-прежнему означает одно: группа у владельца типа + маршрут + отметка на
  экране. Особых путей для `id` нет.

**Non-Goals:**
- Поиск комплектов и шаблонов палитрой — при варианте Б задачи 0.1 (рекомендация) это отдельный change с
  макетом ряда чипов.
- Документ комплекта (`…/sets/:setId/docs/:instanceId`), тип документа, документ качества — не в этом
  change: у каждого свой экран и свой вопрос прав; путь для них тот же.
- Перенос кода комплектов и шаблонов в отдельный проект модуля — остаётся обёрткой (#942).
- Вторая действующая версия от «новой версии» старой (Context) — ошибка вне этого change; здесь только
  правило, по которому карточка выбирает версию детерминированно (Р-5). Её исправление — отдельной задачей.

## Decisions

### Р-1. Владелец — модуль `id`, а не ядро
Поставщик `IdRecordSearch` лежит в `BHS.CRG.Api` рядом с `IdModule` и регистрируется в
`IdModule.RegisterServices` через `AddModuleContract<IRecordSearch, IdRecordSearch>("id")` — как у `costs`.
Тогда выключение `id` ([ID-10]) само убирает его группы: поставщик не зарегистрирован — группы нет,
`POST` такого типа — 400, отметки остаются в таблице и вернутся с модулем.
- *Альтернатива — группы в `CoreRecordSearch`.* Отвергнута: комплект и шаблон принадлежат `id` ([ID-1]),
  и выключенный модуль продолжал бы отдавать карточки своих записей.

### Р-2. Признак группы «только карточки» — рекомендация по задаче 0.1
В `RecordSearchGroup` — необязательный параметр `Searchable = true`. `RecordSearchService.SearchAsync`
не спрашивает группы с `false`; сужение `group=` до такой группы — 400 «неизвестная группа поиска».
`CardsAsync` признака не смотрит. На клиенте у `RecordGroupDef` — `inPalette?: false`, и `openGroups`
такие группы пропускает: чипов и групп палитры не прибавляется.
- *Вариант А — группы ищутся, палитра их находит.* Честнее по смыслу контракта («одно объявление „найти“ и
  „показать по id“»), но меняет палитру: чипов становится восемь («Везде», «Счета», «Стройки», «Наборы
  данных», «Комплекты», «Шаблоны», «Действия», «Разделы»), а это заметная переделка взаимодействия — по
  `docs/UI.md` нужны три макета и выбор владельца. Плюс поиск по шаблонам должен решить, что делать с
  погашенными версиями (`RecordSearchArchive`). При А дельта `core` этого change отпадает, а дельта
  `sharedui` правит [UI-30] и [UI-31].
- *Почему Б:* «Недавние» получают своё сейчас, палитра не меняется без макета, и Б не мешает А потом —
  признак снимается у группы одной строкой.

### Р-3. Права — ключ группы — право данных, право экрана — второй пояс поставщика (задача 0.2)
Одно правило для обеих групп, без правки правила контракта («ключ — право списка записей группы»):
- **Ключ группы** — право, которым читаются её записи: `id.document.read` и у комплектов, и у шаблонов
  (`GET /api/templates` читается им же).
- **Право экрана, если оно другое, поставщик проверяет сам** и без него отвечает «скрыто» — вся группа
  пропадает, как пропадает группа без ключа: комплекты — без `core.constructions.read` (маршрут «Строек»),
  шаблоны — без `id.config.edit` (пункт «Шаблоны»). Так сервер не отдаёт карточек, которые клиент
  открыть не может, и строки «не показано» у бывшего администратора или у роли без «Строек» не копится.
- Клиент по-прежнему проверяет экран сам (`openTo`) — это пояс на случай, если право экрана разойдётся с
  поставщиком; тогда сработает прежнее правило [UI-35] «записи без экрана — сказаны словами».
- Где знание «право экрана» живёт на сервере: константой рядом с группой в `IdRecordSearch`, с
  комментарием о пункте `navConfig.ts`, которому она отвечает. Расхождение ловит vitest-перепись
  (задача 3.5): право экрана группы в `RECORD_ROUTES` совпадает с объявленным на сервере списком.
- *Альтернатива — ключ равен праву экрана* (`id.config.edit` у шаблонов). Отвергнута: у комплекта экран
  требует два права (`core.constructions.read` и `id.document.read`), одним ключом его не выразить, и
  правило контракта пришлось бы менять дельтой `core` ради одной группы. *Альтернатива — права экрана не
  проверять на сервере* — вечная строка «не показано» у тех, кто экран потерял.

### Р-4. Как открыть запись, если её адрес требует другую запись — поле `Opens` и `href`
Комплекту для адреса нужна стройка, шаблону — тип документа. В `RecordSearchHit` — необязательное
`Opens: RecordSearchOpens?`, где `RecordSearchOpens(Guid Under, Guid? Id = null)`: `Under` — запись, под
которой открывается экран (стройка комплекта, тип документа шаблона), `Id` — что открыть, если не сама
запись (выбранная версия шаблона, Р-5). Прежние поставщики поле не заполняют.
- **Клиент.** `recordHref` с одним параметром такой адрес не строит (`/templates?type=…&template=…` — два
  параметра, и открыть надо `Opens.Id`, а не `item.id`). Поэтому у маршрута — `href?: (id, opens) =>
  string`, который строит адрес целиком; `screen` остаётся — им `openTo` проверяет право раздела.
  `recentTarget`: у маршрута с `href` — `href(item.id, item.opens)`, а без `opens` в ответе строки нет
  (адрес без стройки вёл бы на чужую страницу). Комплект: `/document-sets/<Under>/sets/<id>`; шаблон:
  `/templates?type=<Under>&template=<Opens.Id ?? id>`.
- **Другие потребители `RECORD_ROUTES`** маршрут с `href` открыть не могут — у строки таблицы и у палитры
  `opens` нет. `recordLink` и `hitRoute` отказывают ему так же, как маршруту с `at`: иначе строка таблицы с
  `recordType = КомплектДокументов` дала бы `/document-sets/<setId>` — страницу стройки, которой нет.
- *Альтернатива — `Level` для комплекта* (`Section`, раздел, стройка). Подходит комплекту, но не шаблону:
  тип документа — не уровень `CatalogScope`, и смысл поля размылся бы. Одно новое поле на оба случая.
- *Альтернатива — сервер отдаёт адрес.* Отвергнута: модуль адресов клиента не знает (`recordRoutes.ts`).

### Р-5. Шаблон в «Недавних» — строка шаблона, ведёт на его текущую версию (задача 0.3)
Рекомендация — **Б**.
- **Что такое «шаблон».** То же, что у страницы шаблонов: все версии с одним `(DocumentTypeId, Name)`
  (`groupTemplates`). Две записи одного имени в одном типе страница и так показывает одним шаблоном, и
  «Недавние» с ней не расходятся.
- **Текущая версия** — по правилу авто-выбора страницы, но детерминированно: действующая по умолчанию →
  действующая → любая; среди равных — больший `Version`, затем поздний `UpdatedAt`, затем `Id`. Две
  действующие (ошибка из Context) дают ту же версию при каждом чтении. Её `Id` — в `Opens.Id`.
- **Карточка** по любой отмеченной версии — карточка шаблона: название, тип документа, «v<N>» текущей
  версии; `Id` карточки — тот, о котором спросили (сопоставление в `ReadAsync`).
- **Тип документа, который страница не выбирает** (`Kind ≠ Document` или `IsAbstract`), — карточки нет:
  ссылка открыла бы пустую страницу ([UI-35.1] «ссылку в отказ блок не даёт»).
- **Свёртка.** Отметки v3 и v4 одного шаблона после разрешения дают одну строку: `ReadAsync` сворачивает
  строки с одинаковым ключом **`(RecordType, Opens?.Id ?? hit.Id)`**, оставляя позднее открытие. Ключ по
  `hit.Id` по умолчанию — обязателен: у комплекта `Opens.Id` пуст, у счёта, стройки и набора нет `Opens`
  вовсе, и ключ `(RecordType, Opens.Id)` свернул бы все комплекты (и все счета) в одну строку.
- **Удалили отмеченную версию.** По отметке тогда не найти ни имени, ни типа, и живой шаблон пропал бы из
  «Недавних». Поэтому удаление версии, после которого шаблон жив, **переносит отметки на текущую версию**:
  обработчик `DeleteTemplateCommand` (`BHS.CRG.Application/Templates/Handlers.cs`) зовёт службу ядра
  «Недавних» — интерфейс `IRecentRecords.ReassignAsync(recordType, from, to)` в `BHS.CRG.Application`,
  реализация рядом с `RecentRecordEndpoints` (туда же переезжает SQL отметки). Одна команда «перенести или
  слить»: позднее открытие побеждает, ключ таблицы не нарушается. Удалили последнюю
  версию — отметки остаются и не показываются (запись удалена), как у всех.
- *Вариант А — ведёт на ту версию, что открывали.* Без свёртки, текущей версии и переноса, но «Недавние»
  уводили бы на погашенную версию, которую нельзя править на месте (`UpdateContent` — 409), версии одного
  шаблона шли бы разными строками, а удалённая очисткой версия пропадала бы, хотя шаблон жив.
- *Вариант В — погашенная версия не показывается.* Свёртки и переноса не нужно, но шаблон пропадает из
  «Недавних» у всех, кроме того, кто сохранил новую версию, — ровно у тех, кому он нужен.

### Р-6. Когда шаблон отмечается
Отметка — только **осознанное открытие**: человек выбрал шаблон в списке (`selectTemplate`) или пришёл по
адресу с `?template=` (в том числе из «Недавних»), и страница в режиме «Шаблоны». Авто-выбор страницы
(вход без адреса, смена типа, подмена мёртвой версии), восстановление из памяти браузера и режимы
библиотек (`systemlib`, `typeblocks`, `userlib`) не отмечают: иначе заход за библиотекой Typst или смена
типа в селекторе заполняли бы «Недавние» шаблонами, которых никто не открывал, и вытесняли бы
настоящие записи (их двадцать). Хук получает `null`, пока выбор не осознанный.
- *Альтернатива — отмечать всё, что показано* (как у прочих экранов). Отвергнута: у прочих экранов
  показанное и есть открытое, а здесь страница сама выбирает версию по умолчанию.

### Макеты
Под правило трёх макетов (`docs/UI.md`, «Новый экран: порядок») этот change, по нашему прочтению, не
попадает — нового экрана, компонента и переделки взаимодействия нет; подтверждает владелец (задача 0.4).
Строки блока «Недавние» те же (`ListItem`, знак группы — `Description` у шаблона, у комплекта — знак из
`shared/ui/icons`, выбранный в задаче 3.1), меняется только их набор. Если владелец выберет вариант А
задачи 0.1, макеты нужны — для палитры.

## Risks / Trade-offs

- [Свёртка версий шаблона прячет вторую отметку] → место в двадцати не освобождается, пока старую
  отметку не вытеснят. Приемлемо: строк не больше двадцати, вытеснение — то же, что у всех.
- [Карточка шаблона читает текущую версию — лишний запрос] → один запрос на группу: версии ищутся по
  `(DocumentTypeId, Name)` всех спрошенных сразу, не по одной.
- [Перенос отметок пишет из `id` в таблицу ядра] → не напрямую, а службой ядра «Недавних»; модуль `id` —
  обёртка в `BHS.CRG.Api`, и граница `ModuleBoundaryTests` не задета. Перенос — в той же единице работы,
  что удаление: удаление без переноса не сохраняется.
- [Право экрана записано и на клиенте, и на сервере] → перепись (задача 3.5) сверяет их; расхождение —
  красный тест, а не молчаливая строка «не показано».
- [Новое поле контракта] → необязательное, с умолчанием; переписи контрактов (`ModuleContractProbes`)
  дописываются, прежние поставщики не меняются. `ModuleBoundaryTests` не задет: контракт — в
  `BHS.CRG.Modules`, где он и был.
- [Признак «только карточки» забудут снять, когда палитра будет готова] → признак виден в объявлении
  группы, и change палитры начнётся с него (Non-Goals).

## Migration Plan

Миграций базы нет: `user_recent_records.RecordType` — строка, новые типы ложатся в ту же таблицу.
Откат — удаление поставщика: `POST` новых типов снова 400, а их отметки в таблице не показываются
(тип без владельца карточек не получает) и вытесняются обычным порядком.
