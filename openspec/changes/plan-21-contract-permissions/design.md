# Design: «право контракта»

Дочерний change зонтика `plan-00-epic`, общая архитектура — `../plan-00-epic/design.md` (D11 — вид права,
D12 — права объявляются с первым адресом, D17 — носители). Здесь только решения этого change; разбор
совпадает с `work-02-contract-permissions` этапа 4, откуда change забран (D2).

## Context

Сверено по коду master `6b81e51e`.

- Правило «модуль открыт» — одно место, `BHS.CRG.Modules/ModuleAccess.cs:13-17`, проверка по префиксу
  кода. Статический метод без справочника прав: признак права он узнать не может.
- Спрашивают его пять мест: ворота `module:` (`ModuleAccessHandler`, `PermissionPolicies.cs`), ответ
  доступа (`Api/Endpoints/Account/AccountEndpoints.cs`), аудитория уведомлений
  (`Api/Notifications/PermissionAudience.cs`), каталог журнала по модулям
  (`Api/Activity/ActivityActionCatalog.cs`), наборы модулей в параметре доступа
  (`Api/Auth/DataAccessResolver.cs`). Тесты — `McpGateInventoryTests`, `ReadAllWritesNothingTests`,
  `PermissionCatalogTests`.
- `AppPermission` (`BHS.CRG.Modules/AppPermission.cs:28`) несёт код, объяснения, `UsuallyWith` и
  `ReadAllMark`; проверка — `Validate()`. Справочник `PermissionCatalog` собирает права ядра и
  включённых модулей.
- В составах ролей уже стоят `plan.estimate.materials` («Снабженец», `Api/Auth/SystemRoles.cs:100`),
  `work.facts.read` и `costs.materials.read`. Права не объявлены, поэтому синхронизатор их не выдаёт.

## Goals / Non-Goals

**Goals:** признак на праве; одно правило «модуль открыт», которое признак знает; носитель признака
для администратора.

**Non-Goals:**
- объявление самих прав контракта — `plan-23`, `plan-24`, этап 4 (D12);
- механизм межмодульного контракта — `plan-22` (D10);
- новые адреса. Пишущих адресов change не заводит, правило `If-Match` его не касается.

## Decisions

### Состав PR (один)

- `AppPermission` получает `bool Contract = false`.
- `PermissionCatalog`: множество кодов прав контракта; отказ сборки, если признак стоит у права ядра.
- `ModuleAccess.IsOpen(code, granted, catalog)`. Статический метод без справочника удаляется, а не
  остаётся рядом: старая сигнатура молча считала бы право контракта открывающим. Компилятор находит все
  пять мест и тесты.
- `ModuleAccessHandler` получает `PermissionCatalog` из DI.
- `PermissionView` в `Api/Auth/RoleEditor.cs` — поле `Contract`. Его отдают `/api/roles/permissions` и
  `/api/account/permissions`.
- Подпись в `features/settings/RolesPage.tsx` и `features/account/MyPermissionsSection.tsx` — по
  готовому месту объяснения права, без нового экрана: макеты не нужны (`docs/UI.md`, «Макеты не нужны»).

### Почему признак, а не проверка внутри адресов модуля

Право внутри адресов не отменяет префиксного правила: дверь `plan` открылась бы у «Монтажника», и пустое
«Планирование» появилось бы в навигации.

### Композиция с «читать всё»

Пометка `ReadAllMark` у права контракта обязательна, как у любого права модуля. Права контракта этапа
помечаются `Out` (D12): «читать всё» сводит чтение модуля, а право контракта — выдача другому модулю.

### Сторож и «чем ломается»

- `ContractPermissionTests` — живой хост с тестовым модулем, объявившим одно обычное право и одно право
  контракта (образец тестового модуля — `Tests/Configuration/DisabledModuleTests.cs`):
  - роль только с правом контракта: `available: false`, адреса группы — 403, уведомление модуля не видно;
  - роль с правом контракта и обычным: модуль доступен.
- Ломается так: вернуть проверку по префиксу без справочника — первый сценарий краснеет. Объявить
  `plan.estimate.hint` обычным правом — у «Монтажника» появляется пустое «Планирование»; это ловит тест
  состава доступа по ролям в `plan-23`.

### Зависимости

После `plan-01` (модуль, у прав которого появится признак). Потребители — `plan-02` (навигация не
открывает модуль правом контракта), `plan-22`, `plan-23`, `plan-24`; этап 4 — `work-09`, `work-27`.

## Risks / Trade-offs

- [Признак пропустят при объявлении нового права для чужой роли] → тест состава `/api/account/access`
  по ролям в каждом PR, объявляющем право (D12).
- [Модуль, у которого все права — контракта, не открыт никому] → это верный ответ: своих экранов у
  такого модуля нет.
