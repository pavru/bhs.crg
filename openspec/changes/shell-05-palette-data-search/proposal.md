# Proposal: палитра находит записи — поиск по данным в правах спрашивающего

Дочерний change зонтика `shell-00-epic`, общая архитектура — `../shell-00-epic/design.md` (D1, D3, D6).

## Why

Issue #1433 (часть 2; эпик #1428): палитра (Ctrl K) задумана одним входом в «найти» и «сделать». Первая
часть (PR #1478) сделала «сделать» — действия и разделы. «Найти» нет: палитра не находит ни счёта, ни
стройки, ни набора данных, и человек идёт в раздел и ищет там списком. ТЗ требует того же: «поиск ищет
везде и помечает найденное „вне пространства“» (`AUTH-16.1`), а поиск по всем модулям отвечает в правах
того, кто спрашивает (`CORE-34`).

Серверного адреса поиска записей нет: список счетов ищет по уже загруженному (`InvoicesPage.tsx:521`),
`GET /api/document-sets/search` ищет документы комплектов, а не записи групп палитры. Форму адреса — один
на все сущности или по адресу на модуль через контракт модуля — issue велит согласовать с Архитектором
до начала: она в Open Questions `design.md` с вариантами и рекомендацией.

## What Changes

- **Сервер.** Поиск записей по строке запроса: счета (`costs`), стройки и наборы данных (ядро). Отвечает в
  правах спрашивающего: группа, на чтение которой у человека нет права, не возвращается вовсе. Архивные
  записи не предлагаются — тем же правилом, что `purpose=choice` (#1185). Группа выключенного модуля
  отсутствует, остальные отвечают. На группу — не больше 5 записей и признак «есть ещё».
- **Палитра.** Группы «Счета», «Стройки», «Наборы данных» между «Действиями» и «Разделами», с
  подсвеченным совпадением и пометкой «вне пространства». Отказ группы — сказан словами, а не «Ничего не
  найдено».
- **Чипы и Tab.** Чипы области «Везде», «Счета», «Стройки», «Наборы данных», «Действия», «Разделы» — по
  правам. Tab сужает поиск до группы раздела, в котором находится человек; подвал называет «Tab искать
  только в …».
- **Действие с найденным.** Найденная запись предлагает действие её экрана с ней (по решению владельца,
  В-2: «Новая накладная на стройку „…“»).
- **Переход к записи** — адресом её экрана: стройке и набору данных нужен параметр открытия записи
  (`RECORD_ROUTES`), у набора данных его сейчас нет.
- Не меняется: действия и разделы палитры, их отбор по правам (`availableActions`, `visibleNav`).

## Capabilities

### New Capabilities
- `sharedui`: общие компоненты интерфейса — оболочка, командная палитра, храповик интерфейса; здесь —
  группы данных палитры, чипы области, Tab и действие с найденным.

### Modified Capabilities
- `core`: поиск записей по всем модулям в правах спрашивающего — без архивных, без выключенных модулей.

## Impact

- **Сервер:** адрес поиска (форма — В-1) и поставщики групп: `BHS.CRG.Modules.Costs` (счета),

  Если выбран вариант контракта — зависимость от `plan-22-module-exchange` (`CORE-34`).

  `shared/api/recordSearch.ts`, `shared/ui/recordRoutes.ts`; экран наборов данных — параметр записи в
  адресе.
- **Документы:** `docs/UI.md` (абзац «Палитра»), `docs/USER_GUIDE.md`.
- **PR:** два — сервер, затем клиент; оба с меткой `version:minor`.
