# Подписанный APK, обновление и приёмка поставки

## Context

Будущая сборка Android, существующий release.yml, поставка web по /m/, инструкции администратора и монтажника. Опоры и границы описаны в [эпике](../mob-00-epic/design.md). Условие старта — [mob-09-photo-outbox](../mob-09-photo-outbox/tasks.md), [mob-10-device-desk](../mob-10-device-desk/tasks.md).

## Goals / Non-Goals

Заказчик должен получить тот же подписанный APK с экземпляра и с выпуска и обновить его на телефоне с неотправленной сменой. Объём и наблюдаемый результат закреплены в [дельте mob](specs/mob/spec.md).

## Decisions

Один идентификатор приложения и подпись для всех заказчиков. Ключ подписи хранить в защищённом контуре выпуска, определить владельца и процедуру восстановления доступа. Версию привязать к версии выпуска, Android versionCode должен возрастать. Для обновления использовать прежнюю подпись. Перед публикацией сравнить контрольные суммы двух файлов.

## Risks / Trade-offs

Потеря ключа делает штатное обновление установленного APK невозможным. До первого выпуска закрепить ответственного за хранение и восстановление подписи.
