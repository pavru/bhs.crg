# Design: оболочка, вариант B — общая архитектура

Документ общий для дочерних change `shell-05`, `shell-07`, `shell-08`: каждый ссылается сюда и не повторяет
сказанного. Мотивация — `proposal.md`. Правила интерфейса — `docs/UI.md`, раздел «Оболочка: рейл
разделов и подпанель».

## Context

Сверено по коду ветки от master `c9586405` (22.10.2026).

**Что было до эпика** (из #1428): рейл 224 px — 10 рабочих пунктов и 11 пунктов «Настройки системы»; низ
рейла ~280 px (тема, пользователь, пароль, «Сообщить об ошибке», «Выйти», версия), на экране 900 px
навигация прокручивалась; тема — из трёх мест, смена пароля — из трёх, выход — из двух; пилюля
пользователя с `ChevronsUpDown` вела ссылкой на `/profile`; палитра (Ctrl K) и «?» без видимого входа;
в шапке два текстовых переключателя (пространства и «Избранные стройки»); задачи и уведомления — две
кнопки.

**Что есть сейчас:**
- рейл разделов 88 px и подпанель 240 px из одного источника — `shared/ui/navConfig.ts`
  (`railSections`, `workNav`, `settingsNav`), раскладку сверяет `railSections.test.ts`;
- шапка: пространство, поиск (дверь к палитре), `ActivityCenter`, «?», `AccountMenu`;
- палитра `shared/ui/CommandPalette.tsx`: действия `PALETTE_ACTIONS` (`paletteActions.ts`), тема, выход,
  разделы; чипы «Везде / Действия / Разделы»; подвал с клавишами и примером запроса;
- телефон: `BottomNav`, меню раздела в `PageHeader`, «Администрирование» в меню профиля, `PrimaryFab`;
- системная «Назад» закрывает верхний слой (`historyLayers.ts`, `NavigationGuard`);
- `/` по-прежнему ведёт на `/document-sets` (`App.tsx:122`), пункта «Главная» в рейле нет.

## Goals / Non-Goals

**Goals:**
- закончить вариант B: поиск по данным в палитре, подсказка умения «перетащить сканы», Главная;
- каждое правило оболочки записано в `docs/UI.md` и сторожится там, где это возможно.

**Non-Goals:**
- пересмотр экранов модулей под телефон (каркасы умеют, экраны — по мере надобности, `docs/UI.md`);
- переименование токенов Fluent → MD3 (отложено);
- навигация модулей этапов 3–4 (`plan-02-navigation`, `work-03-navigation`) — но с ними есть пересечение,
  см. D5.

## Decisions

### D1. Решение — вариант B «Разделы и подпанель»
Макет: канвас «Оболочка BHS.CRG · два варианта», нижний ряд — вариант B:
https://claude.ai/artifact/UEWyhUxdz6ScU954sETuP4 (канвас личный: другим нужен доступ). Сверен с
разбором дизайна от 01.10.2026: аккаунт перенесён в шапку, одна основная кнопка на экран, «Настройка
системы» свёрнута в один раздел.
- Узкий рейл из разделов «Стройки», «Данные», «Учёт», через черту — «Система»; у раздела своя подпанель.
- Шапка слева направо: пространство, поиск-и-действия (Ctrl K), активность, «?», аватар с меню профиля.
- На телефоне — нижняя навигация, «Администрирование» — в меню профиля.

Макеты оставшихся детей уже выбраны этим решением: палитра — артборд «A · Открыт поиск (Ctrl K)»
(палитра одна для обоих вариантов), подсказка о сканах — пунктирная строка на артборде «B · Счета»,
Главная — артборд «B · Главная „Продолжить работу“». Выбор сделан до правила трёх макетов (#1545,
19.10.2026); `docs/UI.md` («Новый экран: порядок») называет эпик прецедентом двух вариантов. Что макет
не покрывает (телефон, пустые состояния), решается в design дочернего change.

### D2. Решения владельца (17.10.2026)
- Пространства **остаются**. Переключатель — в шапке перед поиском, короткое имя без строки состава.
- «Счета» и «Реестр счетов» **не объединяются**: «Реестр» стоит в группе подпанели «Отчёты и закрытие
  месяца», и разница видна.
- «Настройка системы» — раздел рейла с подписью «Система», заголовок подпанели — «Администрирование»
  (полное слово в 80 px рейла не помещается).
- На рабочем столе «Система» живёт в рейле; меню аватара — только про самого пользователя. На телефоне
  раздел открывается пунктом «Администрирование» в меню профиля.
- Главная нужна, в варианте «Продолжить работу»: `/` — Главная, первый пункт рейла — «Главная» (#1436).

### D4. Правила оболочки и где они записаны
Правила из #1428 записываются в `docs/UI.md` по мере реализации. Сверка на 22.10.2026:

| Правило | В `docs/UI.md` |
|---|---|
| На экране одна основная (залитая) кнопка | да — «Язык формы» (`Button`), «Заголовки», `PALETTE_ACTIONS.primary`; сторож `paletteActions.test.ts` |
| Меню аватара — только то, что касается самого пользователя | да — «Оболочка», абзац о шапке (`AccountMenu`), исключение телефона |
| Подпанель — только у разделов со списками; в карточке стройки её место у навигации стройки | да — «Оболочка» (`panelOnlyAt`) |
| Пункт навигации не прижимается к низу рейла | да — «Оболочка» |
| Наведение мыши может скрывать только ускоритель для действия, у которого есть и видимый вход | **нет.** Рядом только «Подсказка — пояснение, а не единственный путь» (о `Tooltip`) и «Действия строки по наведению — `group-hover/row:`» без оговорки о видимом входе |

Пятое правило записывается задачей 1.4 зонтика. Сторожа у него нет и не планируется: «есть ли видимый
вход» — суждение, а не узор кода; правило держит ревью по `docs/UI.md`.

### D5. Пересечение с навигацией этапов 3–4
`plan-02-navigation` (и повторяющий его `work-03-navigation`) планирует «страницу входа по доступу»: `/`
открывает видимый пункт с наименьшим рангом. Главная #1436 (решение владельца 17.10.2026) делает `/`
Главной для всех. Это одна и та же точка — индекс-маршрут `App.tsx:122`. **Решено владельцем
22.10.2026 (вариант Б, `shell-08-home` В-1):** Главная — пункт ядра с рангом по умолчанию
`HOME_ENTRY_RANK` в расчёте страницы входа `plan-02`; пункт модуля с меньшим рангом её перебивает
(монтажник — «Мои отчёты», `work-03`). Вписано в `plan-02-navigation` и `work-03-navigation`.

### D6. Проверка — весь список живых прогонов
Правка оболочки затрагивает каждый экран. Поэтому в каждом PR эпика прогоняется весь список живых
прогонов CI (работа «живые прогоны» в `.github/workflows/ci.yml`: `npm run test:e2e:ci` и проверки
`e2e/*-checks.mjs`), а не выборка. Подписи меню и палитры ищут как минимум `e2e/keyboard-smoke.mjs` и
`e2e/limited-smoke.mjs`; раскладку рейла на 375 и 390 px — `e2e/rail-checks.mjs`.

## Risks / Trade-offs

- [Главная и «страница входа» `plan-02` разойдутся в одном маршруте] → D5, вопрос до кода `shell-08`.
- [Поиск по данным появится раньше механизма контрактов `plan-22`] → форма адреса — вопрос Архитектору
  в `shell-05` с вариантами, один из которых не ждёт `plan-22`.
- [Правило о наведении без сторожа] → записано словами и сверяется ревью; не делать вид, что его сторожит
  храповик.
