## Goals / Non-Goals

**Goals:** закрытие не проходит, пока у стройки открыто окно подачи; отчёт закрытого периода меняется
только исправлением с причиной; досылка к принятому видна менеджеру пометкой.

**Non-Goals:**
- переключатель версий и подпись в карточке отчёта (`CorrectionBar`) — экран `work-21`;
- поля заказчика после закрытия — `work-24` (тот же путь исправления);
- перенос `costs` на базовый тип версии (D11).

## Decisions

- **PR 1 — ядро.**
  - `ModuleClosingSection` получает `Blocking: IReadOnlyList<ModuleClosingLine>` (третий список, а не
    флаг у строки: незавершённое и запрещающее читаются по-разному, и смешать их в одном списке —
    значит однажды запретить закрытие «3 счёта не разобраны»).
  - `ClosingSection` (домен) и отпечаток включают `Blocking`; в запись о закрытии он ложится пустым —
    иначе закрытия не было бы.
  - `PeriodClosureService`: перед записью, под замком, ненулевая запрещающая строка — `ConflictException`
    с текстами строк. Предпросмотр — `blocking` в `ClosingSectionDto` и `canClose` в `ClosingPreviewDto`.
  - Диалог: запрещающие строки — отдельным блоком раздела над незавершённым, кнопка «Закрыть» заперта
    с причиной (видна, а не спрятана); под заголовком диалога — «граница и „сегодня“ — по поясу
    компании». **Макеты: раунд Р4** (диалог закрытия с запрещающими строками) — выбор владельца
    вписать сюда ссылкой; до выбора клиентская часть PR 1 не начинается, серверная — может.
  - `BHS.CRG.Modules/Data/ModuleRecordVersion.cs` — абстрактный базовый тип `IAppendOnly`: `Id`,
    `RecordId`, `Number` (уникален в записи), `Content` (JSON), `Reason`, `AuthorId`, `At`.
    `Tests/Configuration/RecordVersionInventoryTests.cs` по образцу `InvoiceBookInventoryTests`: наследники
    базового типа во всех модулях (`SolutionModules.WithCore`); набор — только в файлах записи и чтения
    истории; `ExecuteUpdate`/`ExecuteDelete`/сырой SQL — красный; файлы итогов (вердикт «суммы») к
    набору не обращаются. `InvoiceVersion` — исключение с причиной (D11). Самопроверка на образцах.
- **PR 2 — модуль `work`.** Пути — по раскладке `work-13`.
  - `Closing/WorkClosingReport.cs` — `IModuleClosingReport`: `DateRule` «Отчёт относится к периоду по
    дате смены; сутки — по поясу стройки». Запрещающее «в окне подачи: N» — черновики с датой смены в
    отрезке `ClosesAnew` (окно открыто или автоподача ещё не прошла): после закрытия они остались бы
    черновиками навсегда. Незавершённое — поданные. Замороженное — принятые. Дата — колонка даты
    смены, а не время доставки и не конец окна. Ссылки строк — на очередь с отбором, только если числа
    сходятся (правило `Link`).
  - Отказ правки закрытого — общий шаг пишущих адресов отчёта: дата смены ≤ действующей границы
    стройки (`IModulePeriods`) → 409 с адресом исправления; запись — внутри `OpenPeriodWrite`, как у
    `costs`. Порядок отказов: ворота → право → изоляция (404) → период (409) → `If-Match`; адреса с этим
    порядком вписаны исключением в перепись версий-после-нужды, по образцу `VersionAfterNeed`.
  - **Приёмка поданного отчёта закрытого периода разрешена, возврат — нет.** Приёмка меняет статус, не
    строки и объёмы; без неё «ждут приёмки» закрытого периода висели бы вечно. Возврат ведёт к правке
    монтажником, а она запрещена. Решение предлагается владельцу в раунде Р4; до ответа — так.
  - `Data/ReportVersion.cs : ModuleRecordVersion`, таблица `work.report_versions`; миграция схемы `work`
    (`--context WorkDbContext`). Действующая версия — в основной таблице (D11).
  - `POST /api/work/reports/{id}/correction` под `AppPolicies.Permission("work.report.review")` в группе за
    воротами модуля; стройка — из назначений «менеджер» или `work.sites.all` (`work-11`); причина
    обязательна; одним `SaveChanges` — версия, новое содержимое, журнал отчёта (`work-14`); ключевое
    действие — и в журнал ядра. If-Match — `SeenVersion`, как `InvoiceDesk.cs:242`.
  - Ответ отчёта: `versions` и `view` (`corrected` | `at-closing`); «на момент закрытия» — версия,
    действовавшая в момент записи закрытия (`PeriodClosure.At`), а не последняя до исправления.
  - Досылка: правка монтажником принятого отчёта открытого периода — статус «подан», код
    `accepted-changed` в каталоге пометок `work-16`; сторож «каталог сервера = каталог клиента» расширяется.
- **Сторож.** PR 1 — `PeriodClosureTests`: пробный модуль с запрещающей строкой — предпросмотр
  `canClose: false`, закрытие 409 без записи и без журнала; `costs` без изменений;
  `PeriodClosureInventoryTests` зелёный; `RecordVersionInventoryTests`. PR 2 — `WorkClosingReportTests`
  (стройка западнее компании, ночная смена 31.10, доставка 01.11), `ReportCorrectionTests` (400/409
  `If-Match`, 403, 404 чужой, 501, «не нужно»), `ReportClosedPeriodTests` (правка, возврат — 409,
  приёмка — да), досылка с пометкой.
- **Чем ломается.** Ночную смену 31.10 отнести к 01.11 по времени доставки — октябрь закрыт без неё, а
  ноябрь получает чужой объём. Запрещающее как незавершённое — стройка западнее закрывается с открытым
  окном, автоподача упирается в закрытый период.
- **Зависимости.** Этап 2 — служба закрытия. `work-13` (отчёт, строки, адреса), `work-14` (журнал),
  `work-15` (окно мгновением, автоподача), `work-16` (каталог пометок, приёмка, возврат), `work-11`
  (стройки менеджера), `work-07` (изоляция). Экран переключателя — `work-21`.

## Risks / Trade-offs

- [Закрытие компании упирается в одну стройку на дальнем востоке] → строка называет число, ссылка ведёт
  в очередь; это и есть решение Р-6 — ждать окна, а не терять черновик.
- [Разрешённая приёмка после закрытия расходится с «отчёты не меняются»] → названо решением с причиной,
  уходит владельцу вопросом Р4.
- [Базовый тип без второго наследника] → перепись видит наследников во всех модулях, `costs` назван
  исключением; следующий модуль с версиями (`ozhr`) строится на нём.
