# Spec Delta: core

## ADDED Requirements

### Requirement: [CORE-35] [WORK-52] Строки, запрещающие закрытие периода
Раздел модуля в диалоге закрытия SHALL уметь называть строки, которые закрытие запрещают, отдельно от
незавершённого. Предпросмотр `POST /api/periods/close/preview` MUST отдавать их полем `blocking` раздела и
`canClose: false`; закрытие `POST /api/periods/close` при ненулевой такой строке MUST отвечать 409 с её
текстом и числом и ничего не записывать.

#### Scenario: Предпросмотр с запрещающей строкой
- **WHEN** модуль называет в разделе строку «в окне подачи: 3», и менеджер открывает диалог закрытия
- **THEN** ответ предпросмотра несёт эту строку в `blocking` раздела модуля и `canClose: false`
- **AND** диалог показывает строку как мешающую закрытию, а кнопка «Закрыть» заперта с этой причиной

#### Scenario: Закрытие в обход диалога
- **WHEN** закрытие отправлено, пока у модуля есть ненулевая запрещающая строка
- **THEN** ответ 409 с текстом строки и числом, записи о закрытии и записи журнала нет

#### Scenario: Запрет снят
- **WHEN** запрещающая строка обнулилась, и диалог показан заново
- **THEN** `canClose: true`, закрытие проходит обычным порядком с отпечатком нового перечня

#### Scenario: Модуль без запрещающих строк
- **WHEN** закрывают период при включённом одном `costs`
- **THEN** поле `blocking` у его раздела пусто, и закрытие идёт как прежде

### Requirement: [CORE-35] Правило даты называется вслух
Диалог закрытия SHALL показывать у раздела каждого модуля его правило даты (`dateRule`) и рядом —
правило ядра: граница закрытия и «сегодня» считаются по поясу компании. Модуль, относящий документ к
периоду по поясу стройки, MUST говорить это в своём правиле.

#### Scenario: Модули с разными поясами в одном диалоге
- **WHEN** диалог закрытия открыт при включённых `costs` и `work`
- **THEN** у раздела учёта работ стоит «по дате смены, сутки — по поясу стройки», а у диалога — «граница — по поясу компании»

### Requirement: [CORE-36] Базовый тип записи версии
Прежние версии записи модуля SHALL храниться таблицей схемы модуля только на дописывание по общему
базовому типу контрактов: номер, содержимое документом, причина, автор, время. Перепись MUST падать на
правку, удаление и сырой SQL по такой таблице вне её файлов записи и чтения истории, а также на чтение
истории запросом сумм.

#### Scenario: Правка прежней версии
- **WHEN** код меняет или удаляет запись версии через отслеживание изменений
- **THEN** сохранение отвергается

#### Scenario: Обход отслеживания
- **WHEN** в коде модуля появляется `ExecuteUpdate`, `ExecuteDelete` или сырой SQL по таблице версий вне её файлов
- **THEN** перепись падает с названием файла и строки

#### Scenario: Запрос сумм читает историю
- **WHEN** запрос итогов модуля обращается к таблице версий
- **THEN** перепись падает: суммы считаются только по действующим версиям

#### Scenario: Версии счетов
- **WHEN** экземпляр работает с модулем `costs`
- **THEN** версии счёта хранятся как прежде; исключение названо в переписи с причиной «живые данные не переносятся ради имени»
