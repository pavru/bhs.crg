# Design: заявки на закупку из материалов сметы

Дочерний change зонтика `plan-00-epic`, общая архитектура — `../plan-00-epic/design.md` (D10 — контракты,
D12 — права с первым адресом, D17 — носители, D18 — макеты). Здесь только решения этого change.

## Context

Сверено по коду master `6b81e51e`.

- Заявок в коде нет; `costs.request.*` выписаны «до этапа 3» (`Modules.Costs/CostsModule.cs:78`), в ролях
  стоят (`Api/Auth/SystemRoles.cs:72,100`).
- Отпущенное на стройку — внутренняя модель `Modules.Costs/Data/IssuedMaterials.cs:34` (по проведённым
  накладным, строки без номенклатуры — числом).
- Проверка версии записи — связка `InvoiceDesk` (`Endpoints/InvoiceDesk.cs:251`, `SeenVersion`); образец
  удаления черновика — `InvoiceDeletion.cs`.
- Материалы позиций сметы — контракт «Плановые работы», часть `materials` (`plan-23`), в правах
  спрашивающего.

## Goals / Non-Goals

**Goals:** заявка из материалов сметы с честными предложенными количествами; связь «заявка — счета»;
«заказано / выставлено / отпущено».

**Non-Goals:**
- согласование заявки и маршрут (`COST-9`, `STG-14`);
- цены в заявке — их нет: заявка про количества, деньги — у счёта;
- разноска счёта по заявке автоматически — разноска остаётся своей (`COST-10`);
- сравнение со сметой по деньгам — `plan-27`.

## Decisions

- **Модель.** `PurchaseRequest` (стройка, номер по порядку в модуле, статус, автор, `xmin`) и
  `PurchaseRequestLine` (номенклатура — обязательна, `CORE-9`; количество; единица; позиция перечня —
  необязательна; примечание). Запись модуля, не документ с суммами: в `AccountingDocuments` не входит,
  закрытие периода её не касается.
- **Создание из сметы.** `POST /api/costs/requests/draft-from-estimate` — предложение без записи:
  стройка, позиции перечня или раздел сметы → строки «по смете − отпущено» по номенклатуре; пометки
  `issuedExceeds` (отпущено больше сметы — 0 и пометка, а не отрицательное), `unmatchedIssued` (строки
  накладных без номенклатуры — числом). Затем человек правит и сохраняет `POST /api/costs/requests`.
  Двухшаговое: предложение не пишет ничего и `If-Match` не требует (названное исключение, как
  `WritesNothing` у счёта).
- **Без права на материалы сметы.** Часть `materials` пришла `Hidden` — предложение отвечает «скрыто
  правами: нужно право plan.estimate.materials», а не пустым списком. `plan` выключен — 409 «нужен модуль
  „Планирование“».
- **Статусы.** `draft → submitted → closed`; `submitted → draft` — возврат автором с причиной в журнал;
  правка строк — только в черновике. Каждый переход и правка — `If-Match` (400 без заголовка, 409
  устаревший), под `costs.request.edit`. Удаление — только черновик, без связанных счетов.
- **Связь со счётом.** `Invoice.PurchaseRequestId` (необязательный). Ставит и снимает её правка шапки
  счёта под `costs.invoice.edit` и `If-Match` счёта; заявка другой стройки или в черновике — 422 с
  причиной. Закрытая заявка новых счетов не принимает.
- **«Заказано / выставлено / отпущено».** По номенклатуре: количество строк заявки; сумма количеств
  строк связанных счетов с этой номенклатурой; отпущено на стройку по `IssuedMaterials` (не по заявке —
  накладная о заявке не знает, и это сказано подписью колонки).
- **Права.** `costs.request.read` (`ReadAllMark.In`), `costs.request.edit` (`Out` с причиной).
  Объявляются здесь — вместе с первым адресом (D12).
- **Ссылки `CORE-34.1`.** Номенклатура и позиция перечня строки, стройка заявки — объявления в
  `CostsReferences.cs`; удаление занятой записи справочника — отказ с числом.
- **Экраны (PR 3).** Макеты П6: три варианта, выбор владельца, ссылка — здесь. Список — `DataGrid`;
  карточка — list-detail; мастер «из сметы» — `Modal wide`.
- **Сторож.** `PurchaseRequestTests`: смета 100 м кабеля, отпущено 30 — предложено 70; отпущено 120 —
  0 и `issuedExceeds`; без права на материалы — «скрыто правами»; `plan` выключен — 409; правка без
  `If-Match` — 400, устаревшая — 409; правка подданной — 409; без `costs.request.edit` — 403; без модуля
  `costs` — 501. `InvoiceRequestLinkTests`: счёт к заявке чужой стройки — 422; «выставлено» считает
  только связанные счета. Переписи записи и ссылок.
- **Чем ломается.** Количество «по смете» без вычета отпущенного — снабженец закупает второй раз.
  Пустой список материалов при отсутствии права — читается как «в смете материалов нет».

## Risks / Trade-offs

- [Единицы сметы и накладной разные] → сравнение по номенклатуре и её единице; строки с иной единицей
  помечены `unitMismatch`, а не складываются.
- [Заявка без модуля `plan` нужна всё равно] → `COST-5.1` прямо говорит «без `plan` заявки нет»; ручное
  создание без сметы — не в этом change.
