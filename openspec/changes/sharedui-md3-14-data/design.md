# Design: таблица данных, сетка правки и списки по MD3

Общая архитектура — `../sharedui-md3-00-epic/design.md`: D6 (слой состояния), D7 (таблица плотности),
D8 (data table — расширение), D10 (три макета), D11 (правка ожиданий тестов), D12 (документы и
дизайн-система). Требования — `specs/sharedui/spec.md`.

## Context

Сверено по коду ветки от master `1e81da2e`.

- Классы таблиц — в одном месте, `shared/ui/dataTable.ts`:
  - `dtCard` — `rounded-xl border bg-surface`;
  - `dtTable` / `dtTh` / `dtTd` — шапка `--dt-head: 42px`, клетка `px-3 py-2`, текст `text-sm`;
  - `dtTableCompact` — шапка 32, клетка `py-1`, `text-xs`;

  - `dtRow` — наведение `black/[.03]`, в тёмной теме `white/[.05]`.
- `DataGrid.tsx`: открытая строка — `bg-brand-subtle`, `marked` — `bg-warning-subtle`, закреплённые клетки
  повторяют фон строки сами; итог — `bg-muted`.
- `EditGrid.tsx`: клетку-поле рисует экран. `sheet` берёт `dtTdSheet`, шапку `dtThCompact` с

## Goals / Non-Goals

**Goals:** одна шкала плотности для всех таблиц и списков, сказанная словами MD3; шапка без заливки;
выбор и наведение ролями.

**Non-Goals:**
- Логика таблиц: колонки, сортировка, закрепление, виртуализация, сохранённые представления — без
  изменений.
- Ячейки-поля экранов (`Select`, `DateInput compact`, `SuggestField compact`) — вид поля даёт
  `sharedui-md3-11-inputs`; здесь только рамка клетки.
- Кнопки-иконки в строках — `sharedui-md3-10-actions`.

## Decisions

- **Плотность — переменными, а не классами по месту.** `dataTable.ts` получает `--dt-head` и `--dt-row`
  на таблице: 56/48 для −1, 48/40 для −2. Клетка берёт `h-(--dt-row)` и вертикальный отступ 0. Так одно
  число правится в одном месте, а e2e меряют то же.
- **Поле в клетке без рамки** — общий класс клетки правки `dtCellField`: прозрачный фон, нижняя черта
  прозрачна, у `:focus-within` — `primary`, у `aria-invalid` — `error`. Экраны, рисующие поле в клетке,
  берут этот класс, а не свои рамки.
- **`sheet`** — по рекомендации В5 строка 40, а не 28. Если владелец оставит 28 — это отступление D8,
  и `/opsx:update` перепишет сценарий «Строки массива документа».
- **Выбор** — `secondary-container` и на закреплённых клетках. Фон им задаёт переменная строки
  `--dt-row-bg`, а не повтор условия в каждой клетке: сегодня это повтор в `DataGrid.tsx:350`.
- **Итог** — `surface-container`: заливка, отличимая от строк, без рамки сверху.
- **Отвергнуто — оставить шапку на заливке.** Так было бы ближе к Fluent и к привычке пользователей, но
  data table MD2 и вариант Г держат шапку без заливки. Различие шапки дают роль `title-small` и черта.
- **Отвергнуто — плотность −3 (36) для реестров.** Её нет в D7. Только решением В5 и отступлением.

## Risks / Trade-offs

- [Строка 36 → 48: на 1366×768 реестр теряет 4–5 строк] → три макета на реальных таблицах — реестр
  счетов, строки счёта, матрица разноски — на 1366×768 (зонтик, D10); решение — по макету.
- [Колонки действий и `fixed-width` уже не вмещают кнопки 40] → перепроверка уровня `fixed-width` после
  `sharedui-md3-10-actions`; ширины колонок — по месту в PR.
- [Матрица разноски `fullScreen` с десятками колонок] → она на −2 (40), как сетка правки; проверка —
  `allocation-matrix-smoke`.
