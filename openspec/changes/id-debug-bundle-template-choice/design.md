# Design: шаблон документа выбирается одним правилом

## Context

Выбор шаблона экземпляра сейчас написан трижды, и копии разошлись:

| Где | Набор `TemplateIds` | Явный `TemplateId` | Запасной |
|---|---|---|---|
| `GenerateDocumentHandler.cs:50–70` | все активные выбранные, в порядке строк базы; ни одного — отказ | только среди шаблонов типа, неактивный допустим (закреплённая версия) | по умолчанию → «первый активный» без порядка |
| `PreviewDocument.cs:58–73` | первый активный в порядке набора; ни одного — дальше по цепочке | среди шаблонов типа | то же, без порядка |
| `GetGenerationDebugBundle.cs:58–65` | **не читает** | `GetByIdAsync` — шаблон любого типа | то же, без порядка |

Комментарий в коде пакета («тот же выбор шаблона, что и в `GenerateDocumentHandler`») неверен с тех
пор, как генерация научилась наборам. Предпросмотр помечен «зеркалит генерацию» и тоже расходится.

Клиент (`GenerationTab.tsx:100–103`) показывает «эффективный» шаблон своим правилом: первый выбранный
→ `templateId` → по умолчанию → `activeTemplates[0]`. Список шаблонов (`ListTemplatesQuery`) приходит
без порядка.

### Что выяснилось сверкой

- В issue два места, в коде их три: предпросмотр тоже выбирает сам.
- Порядок набора `TemplateIds` у генерации тоже не детерминирован: файлы выпускаются в порядке строк
  кандидатов, а не в порядке выбора.

## Goals / Non-Goals

**Goals:** одна функция выбора; детерминированный порядок; пакет, предпросмотр и генерация согласны
всегда.

**Non-Goals:**
- выбор шаблона пакета параметром запроса (`?templateId=`) — пакет отлаживает то, что выпустит
  генерация; понадобится другой шаблон — отдельной задачей;
- уникальность «по умолчанию» на уровне базы: правка шаблона уже снимает признак с остальных
  (`Templates/Handlers.cs:160`), а функция всё равно упорядочивает и этот случай;
- переписывание правила на клиенте: ему хватает порядка списка.

## Decisions

- **D1. `TemplateChoice` в `Application/Generation`** — чистая функция над экземпляром и кандидатами
  типа. Возвращает упорядоченный набор (генерация) или отказ; `First` — для предпросмотра и пакета.
  Правило взято у генерации: она — источник истины, выпущенный PDF и есть то, что отлаживают.
- **D2. Порядок кандидатов — `CreatedAt`, затем `Id`.** «Первый активный» на живой системе до
  восстановления фактически означал самый ранний вставленный — порядок строк кучи. `CreatedAt`
  сохраняет этот смысл, а копия переносит `CreatedAt` шаблона, поэтому после восстановления выбор тот
  же. Отклонено:
  - по `Name` — меняет выбор на действующих системах;
  - по наибольшей `Version` — версии одного имени и так не бывают активны одновременно, а между
    разными именами номер ничего не значит.
- **D3. Набор `TemplateIds` — в порядке набора.** Это порядок, в котором человек отметил шаблоны;
  выпуск файлов в этом же порядке.
- **D4. Явный `TemplateId` — только шаблон этого типа**, неактивный допустим: так генерация уже
  обслуживает закрепление на версии (`DomainObject.PinsTemplate`). Пакет перестаёт принимать шаблон
  чужого типа.
- **D5. Отказ «ни один из выбранных не активен» — общий.** Предпросмотр сейчас молча падает на шаблон
  по умолчанию и показывает документ, которого генерация не выпустит. Это отказ, переодетый в результат.
  Отказ один, его текст — из генерации.
- **D6. Список шаблонов типа упорядочен так же** (`ListTemplatesQuery`). Запасной выбор клиента
  `activeTemplates[0]` после «по умолчанию» тогда совпадает с серверным без правки клиента.
- **Сторож.** Интеграционный тест: два активных шаблона, экземпляр с `TemplateIds` → генерация,
  предпросмотр и пакет берут один и тот же; два активных без «по умолчанию», вставленные в обратном
  порядке `CreatedAt`, → все трое берут ранний; все выбранные неактивны → один отказ у всех.

## Risks / Trade-offs

- [На действующей системе с несколькими активными шаблонами без «по умолчанию» физический порядок
  расходился с `CreatedAt`] → тогда выбор сменится один раз, на детерминированный. До слияния — запрос
  на копии базы заказчика: типы, где активных больше одного и ни один не по умолчанию; число — в
  описании PR (агрегатом).
- [Порядок выпуска файлов набора меняется на порядок выбора] → проверить при реализации, что от
  порядка не зависит ничего, кроме последовательности файлов в ответе (имена, сборка комплекта);
  нашлось — записать в D3 до кода.
