# Proposal: шаблон документа выбирается одним правилом

## Why

Issue #1401 (bug, репетиция выпуска 17.10.2026; решение владельца — задача, не до выпуска).
Отладочный пакет (`GetGenerationDebugBundle`) выбирает шаблон не так, как генерация: не читает
`TemplateIds` экземпляра и берёт «первый активный» шаблон типа без порядка. После восстановления копии
пакет одного экземпляра стал отдавать другой шаблон, хотя генерация того же экземпляра не изменилась.
Тот же запасной выбор без порядка есть и в `GenerateDocumentHandler`: при нескольких активных шаблонах
и пустом `TemplateIds` выбор зависит от физического порядка строк — после восстановления копии он
меняется.

Слитый `id-template-version-integrity` (#1958, архив #1961) и #1963 причину не убрали. Действующая
версия теперь одна на **шаблон** — группу версий одного названия в типе. Но шаблонов в типе может быть
несколько, а действующая версия есть у каждого. Поэтому «первый активный» по-прежнему выбирает между
разными шаблонами без порядка.

## What Changes

- **Одна функция выбора шаблона** для генерации, предпросмотра и отладочного пакета. Сверка нашла
  третье место с собственной копией правила — предпросмотр (`PreviewDocument.cs:55–69`); оно тоже
  переходит на общую функцию.
- Правило — нынешнее правило генерации: выбранный набор `TemplateIds` (активные, в порядке набора) →
  явный `TemplateId` шаблона этого типа → шаблон по умолчанию (активный) → самый ранний шаблон.
- **Запасной выбор детерминирован и не прыгает от версий.** «Самый ранний» — шаблон, созданный раньше
  других (наименьший `CreatedAt` среди версий одного названия), при равенстве — по названию, затем по
  `Id`; берётся его действующая версия. Новая версия раннего шаблона выбор не меняет. Порядок набора
  `TemplateIds` — порядок, в котором его выбрал человек, а не порядок строк в базе.
- Отладочный пакет берёт **первый** шаблон того набора, который выпустила бы генерация; явный
  `TemplateId` чужого типа он больше не принимает.
- Все выбранные шаблоны неактивны — генерация, предпросмотр и пакет отвечают одним отказом. Сейчас
  генерация отказывает, а предпросмотр молча берёт шаблон по умолчанию.
- Список шаблонов типа (`ListTemplatesQuery`) отдаётся в том же порядке, внутри шаблона — от новой
  версии. Форма генерации на клиенте (`templateRefs.ts`, `effectiveTemplateOf`) выбирает тем же
  правилом: пин на историческую версию видит, а при выборе, где ни один не действует, запасной шаблон
  не показывает.
- Документы без выбора сбрасываются в черновик, когда сменился шаблон, который они берут. Это бывает
  при правке на месте, новой версии и удалении версии, а не только при смене «по умолчанию».
- Что считается выбором `TemplateIds`, решает одно правило у домена, выбора шаблона и сборки
  комплекта.
- «Действующий шаблон типа» (`GET /api/templates/active`, `GetActiveTemplateQuery`) отвечает по тому же
  запасному правилу. Сейчас он отдаёт первую попавшуюся действующую строку.

## Capabilities

### New Capabilities
- Нет.

### Modified Capabilities
- `id`: выбор шаблона документа одним правилом для генерации, предпросмотра и отладочного пакета.

## Impact

- **Сервер:**
  - новая `Application/Generation/TemplateChoice.cs`;
  - `GenerateDocumentHandler.cs:46–65`, `PreviewDocument.cs:55–69`,
    `GetGenerationDebugBundle.cs:33–40`;
  - порядок в `Templates/Handlers.cs` (`ListTemplatesQuery`, `GetActiveTemplateQuery`);
  - сброс документов без выбора: `DocumentTemplateInvalidator`, новая версия и удаление версии в
    `Templates/Handlers.cs`, возраст шаблона без текстов — `ITemplateNames.FirstCreatedAsync`;
  - разбор выбора: `TemplateRefJson.SelectionIds`, `DomainObject`, `DocumentSetAssemblyService`.
- **Клиент:** `templateRefs.ts` (`effectiveTemplateOf`) и `GenerationTab.tsx`.
- **API:** формы ответов не меняются. Меняются порядок списка шаблонов и выбор при нескольких
  активных шаблонах без шаблона по умолчанию: он детерминирован.
- **Тесты:** юнит-тесты функции и новый интеграционный класс выбора шаблона.
