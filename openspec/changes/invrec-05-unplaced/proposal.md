# Proposal: «прочитано, в счёт не положено» — с причиной, всегда

Дочерний change зонтика `invrec-00-epic`, общая архитектура — `../invrec-00-epic/design.md` (D1 — решения
владельца, D2 — сделанное).

## Why

Issue #1484 (эпик #1479, `блокирует-прод`). Решение владельца: при сохранении профиля соответствие
полям счёта не проверяется — профиль кормит и наборы данных. Значит, единственное место, где видна ошибка
(опечатка в ключе, колонка без поля, поле, которое распознавание не заполняет, отказ охраны), — итог
распознавания в счёте. Без этого отказ переодет в результат: колонка добавлена, ничего не легло, никто не
сказал.

Сейчас о не легшем сказано текстом в «Замечаниях распознавания», и не всегда: сведение по колонкам строк
(`StrayNote`) пишется только когда строки легли в счёт (`InvoiceScanReading.cs:466`), а при строках,
ушедших в предложение (у счёта свои строки, режим НДС человека), — теряется. Номера строк файла в нём
нет, занятое поле шапки (значение ушло в предложение) не названо вовсе.

## What Changes

- **Сервер** собирает «прочитано, в счёт не положено» по шапке и по строкам: где (шапка / строка файла N),
  ключ профиля, прочитанное значение, **причина**:
  - «у счёта нет поля с таким ключом»;
  - «поле не заполняется распознаванием» (с причиной поля: файл, ссылка…);
  - «значение не разобрано»;
  - «охрана отказала: …»;
  - «поле занято — в предложениях»;
  - «ключ повторяет другой — поле уже заполнено им» (найдено сверкой: два ключа одного поля).
- Список **хранится всегда** — при легших строках, при строках в предложении, при непрочитанной таблице.
- **Клиент:** в «Замечаниях распознавания» одна тихая строка «Ещё прочитано, в счёт не положено: N —
  Показать»; «Показать» раскрывает компактную таблицу «где — ключ — значение — причина». Без жёлтого:
  колонка «только для наборов данных» законна.
- Текстовые замечания, переехавшие в таблицу, из списка замечаний уходят: «Прочитано, в счёт не
  положено: …» (шапка и строки), «Прочитано, но распознаванием не заполняется: …», «в поле ведут два поля
  профиля». Замечания, зовущие к действию над счётом («не прочитано как значение поля — впишите
  вручную», «не записано — охрана записи»), остаются, и их поле есть в таблице.
- «В файле не прочитано: …» (цель есть, значение не разобрано) остаётся в примечании строки.
- **Не входит:** подсказки в редакторе профиля (позже, по запросу).

## Capabilities

### New Capabilities
- Нет.

### Modified Capabilities
- `costs`: итог распознавания счёта называет прочитанное, что не легло в счёт, с причиной.

## Impact

- **Сервер (`BHS.CRG.Modules.Costs`):** новый `Endpoints/InvoiceScanUnplaced.cs` (сбор и причины);
  `InvoiceScanHeader.cs`, `InvoiceScanLines.cs` (отдают записи вместо текста), `InvoiceScanReading.cs`
  (сбор всегда, охрана), `Data/InvoiceRecognition.cs` (колонка `unplaced`), `InvoiceScanRecognition.cs`
  (поле вида); миграция `CostsDbContext`.
- **Клиент:** `features/costs/InvoiceRecognitionNote.tsx`, `features/costs/recognition.ts`, тип вида
  распознавания.
- **Документы:** `docs/ADMIN_GUIDE.md` (профиль «Счёт на оплату»: где видно, что колонка не легла).
- **PR:** два — сервер (разблокирует: список копится с первого распознавания), затем клиент после выбора
  макета; оба — `version:minor`.
