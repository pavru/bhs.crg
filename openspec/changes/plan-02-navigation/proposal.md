# Proposal: навигация модуля — «любое из прав», раздел рейла, страница входа, панели карточки стройки

Дочерний change зонтика `plan-00-epic`, общая архитектура — `../plan-00-epic/design.md` (D2, D16, D17, D18).

## Why

На странице стройки модуль `plan` занимает два пункта — «Сметы» и «График» (`PLAN-20`), а ядро добавляет
«Ход работ» (`PLAN-21`), видный по праву любой из своих колонок. Сегодня ни одно из этих мест к модулю не
готово:
- пункт навигации называет одно право (`shared/ui/navConfig.ts:19`), политика адреса — одно право
  (`BHS.CRG.Modules/AppPolicies.cs:20`): пункт «Ход работ» под одним правом пропал бы у «Снабженца» или
  «Руководителя»;
- у модуля нет раздела рейла: `RailId` знает четыре раздела (`navConfig.ts:42`);
- после входа каждый попадает на `/document-sets` (`App.tsx:122`): «Сметчик» без
  `core.constructions.read` видит отказ сразу после входа;
- карточка стройки перечисляет свои панели вручную (`features/document-sets/ConstructionDetail.tsx:31,112-118`),
  модуль добавить туда свою не может.

Механизмы спроектированы в `work-03` этапа 4; их первый потребитель — здесь, поэтому строит этап 3
(D2 зонтика). `work-03` оставляет себе раздел `work`, его пункты и ранг входа монтажника.

## What Changes

- **PR 1 — «любое из прав» и раздел рейла.**
  - `NavItem.permission: string | string[]` («любое из»); `missingFor` называет весь список, страница
    `AUTH-15` пишет «нужно одно из прав: …».
  - Составная политика на сервере: адрес под «любым из» открыт носителю любого из прав, каждый код
    проверяется по справочнику (`AUTH-8.2`); атрибут MCP принимает тот же список. Переписи ворот понимают
    составное имя.
  - Раздел рейла `plan` («Планирование» — подпись по макету П0). Раздел без видимых пунктов не
    показывается; модуль, открытый одним правом контракта, раздела не даёт.
- **PR 2 — страница входа и панели карточки стройки** (после выбора макета П0).
  - Страница входа по доступу: пункт объявляет себя страницей входа с рангом; открывается видимый в
    текущем пространстве пункт с наименьшим рангом, иначе первый видимый, иначе страница `AUTH-15`.
  - Механизм `shared`: модуль добавляет панель в карточку стройки, называя право (или «любое из») и
    раздел ядра. «Каталог», «Наборы данных», «Подписчики» переезжают на тот же механизм с прежними
    адресами. Реестр проверяет `PLAN-20`: у модуля не больше двух панелей.
- Пунктов модуля этот change не заводит: «Сметы», «График», «Ход работ» вписывают `plan-09`, `plan-20`,
  `plan-25`.
- Правка оболочки, поэтому в каждом PR идёт весь список живых прогонов.
