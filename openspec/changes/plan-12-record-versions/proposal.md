# Proposal: базовый тип записи версии в контрактах модулей

Дочерний change зонтика `plan-00-epic`, общая архитектура — `../plan-00-epic/design.md` (D2, D5).
Задача ядра, забранная у этапа 4 (`work-19`, D11 `work-00-epic`).

## Why

Версии есть у отчёта монтажника, счёта, накладной, КП и записи ОЖР, и хранятся они одинаково: в основной
таблице — действующая версия, прежние — в таблице истории; запросы сумм историю не читают (`CORE-36`).
Иначе каждый запрос сумм помнил бы отбор «действующая версия», и одна забытая проверка молча удвоила бы
цифры. Форма есть только у счёта (`Modules.Costs/Data/InvoiceVersion.cs`), и только в его модуле.

Этап 4 собирался вынести её в контракты первым на `work` (D11 этапа 4). Теперь первым идёт этап 3, и
первый потребитель — версии КП (`PLAN-12`, `plan-13`): отправленное предложение не правится, правка
создаёт новую версию. По правилу «поддержка едет с первым потребителем» базовый тип строит этап 3, а
`work-19` берёт готовый.

## What Changes

- `BHS.CRG.Modules/Data/ModuleRecordVersion.cs` — абстрактный базовый тип `IAppendOnly`: идентификатор,
  запись, номер (уникален в записи), содержимое документом JSON, причина, автор, время.
- Перепись `RecordVersionInventoryTests` по образцу `InvoiceBookInventoryTests`: наследники базового типа во
  всех модулях; обращения к их наборам — только в названных файлах записи и чтения истории;
  `ExecuteUpdate`, `ExecuteDelete` и сырой SQL по таблицам версий — красный; файлы итогов к таблицам версий
  не обращаются. Самопроверка на образцах.
- `InvoiceVersion` на базовый тип **не переносится** — исключение названо в переписи с причиной: перенос —
  миграция живых данных ради имени.
- Ни одной таблицы версий этот change не заводит: первая — версии КП (`plan-13`), вторая — версии отчёта
  (`work-19`).

## Capabilities

### New Capabilities
- Нет.

### Modified Capabilities
- `core`: базовый тип записи версии в контрактах модулей и перепись обращений к истории версий.

## Impact

- **Контракты:** новый `src/server/BHS.CRG.Modules/Data/ModuleRecordVersion.cs`.
- **Тесты:** новый `src/server/BHS.CRG.Tests/Configuration/RecordVersionInventoryTests.cs` (модули — через
  `Tests/Common/SolutionModules.cs`); `ModuleBoundaryTests` зелёный.
- **Этап 4:** `work-19` строит `ReportVersion` на готовом типе; core-дельта `work-19` о базовом типе
  снимается (пометка в зонтике `work-00-epic`).
- **Документы:** `docs/DEV_NOTES.md` — как завести версии записи модуля и почему суммы не читают историю.
