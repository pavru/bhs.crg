# Design: базовый тип записи версии

Дочерний change зонтика `plan-00-epic`, общая архитектура — `../plan-00-epic/design.md` (D2, D5).
Здесь только решения этого change.

## Context

Сверено по коду master `6b81e51e`.

- Образец формы — `Modules.Costs/Data/InvoiceVersion.cs`: `IAppendOnly`, `InvoiceId`, `Number` (уникален в
  счёте), `Content` (JSON), `Reason`, `AuthorId`, `At`; снимок содержимого — `Snapshot`.
- Правку и удаление строк `IAppendOnly` отвергает `ModuleDbContext` (`BHS.CRG.Modules/Data/IAppendOnly.cs`,
  комментарий); мимо отслеживания (`ExecuteUpdate`, `ExecuteDelete`, сырой SQL) ловит только перепись по
  исходникам.
- Образец переписи — `Tests/Configuration/InvoiceBookInventoryTests.cs` (словарь «кому позволено и
  почему»); модули — `Tests/Common/SolutionModules.cs` (`Projects`, `WithCore`).
- Проект этого типа в этапе 4 — `openspec/changes/work-19-period-closure/design.md:46-51`; здесь он
  строится без изменений, кроме того, что исключение `InvoiceVersion` и первый наследник — другие.

## Goals / Non-Goals

**Goals:** один тип версии для всех модулей; перепись, которая ломается на обходе и на чтении истории
итогами.

**Non-Goals:**
- общая служба версий ядра — версии в схеме ядра писались бы второй транзакцией (`CORE-4`, D11 этапа 4);
- перенос `InvoiceVersion` — миграция живых данных ради имени;
- взгляд «на момент закрытия» (`work-19`), сравнение версий КП (`plan-13`).

## Decisions

- **Тип.** `public abstract class ModuleRecordVersion : IAppendOnly` с `Id` (`Guid.CreateVersion7`),
  `RecordId`, `Number`, `Content` (jsonb), `Reason` (может быть пустой: у КП новую версию рождает
  «отправлено», а не исправление), `AuthorId`, `At`. Наследник называет таблицу и единственный индекс
  `(RecordId, Number)` в своём контексте — конфигурацию даёт общий помощник в контрактах, чтобы индекс не
  забывали.
- **Действующая версия — в основной таблице** записи; номер действующей хранит запись (`CurrentVersion`),
  прежние — наследником. Запросы сумм читают только основную таблицу.
- **Перепись `RecordVersionInventoryTests`.**
  - Находит наследников `ModuleRecordVersion` во всех проектах модулей по исходникам.
  - Для каждого — словарь «файлы, которым позволено обращаться к набору, и почему» (запись версии и чтение
    истории); иное обращение — красный с файлом и строкой.
  - `ExecuteUpdate`, `ExecuteDelete`, `FromSql*`/`ExecuteSql*` с именем таблицы версий — красный в любом
    файле.
  - Файлы, помеченные как итоги (`*Views.cs`, `*Totals.cs`, `*ClosingReport.cs`, а также файлы, названные в
    словаре вердиктом «суммы»), к наборам версий не обращаются.
  - `InvoiceVersion` — исключение с причиной; новый тип с той же формой мимо базового типа ловится
    сравнением полей (`IAppendOnly` + `Number` + `Content`) и требует записи в исключения.
  - Самопроверка на образцах в тестовом каталоге: каждый запрет красный на своём образце.
- **Порядок слияния.** PR этого change сливается до PR 2 `plan-13` (версии КП) — его первого потребителя.

## Risks / Trade-offs

- [Перепись по исходникам ложно краснеет на имени] → словарь разрешений с причинами; исключение
  добавляется с причиной, а не отключением проверки.
- [`work-19` строит по прежнему проекту] → зонтик `work-00-epic` и `work-19` получают пометку; core-дельта
  `work-19` о базовом типе снимается.
