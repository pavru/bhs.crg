## Тест четырёх макетов work-12

22.11.2026 для сравнения нового процесса подготовлен отдельный
[интерактивный стенд назначений](http://127.0.0.1:5200/work12.html), также доступный в
[каталоге](http://127.0.0.1:5200/?section=work12). Это эксперимент по закрытому change, без изменения
реализованного экрана и прежнего выбора владельца А+.

**Статус: восстановленный макет, не первичный.** По запросу владельца стенд сохранён 22.11.2026
для дальнейшей работы. Происхождение и статус записаны в `src/client/design-system/work12/metadata.json`
и показаны в каталоге и на самом стенде. Вариант 4 восстановлен из текущего кода; А–В — новые концепции
по требованиям закрытого change. Исходный Р2 в доступном экспорте отсутствует.

- [А · Состав бригады](http://127.0.0.1:5200/work12.html?variant=a) — карточки по группам, назначение в общем окне.
- [Б · Рабочее место](http://127.0.0.1:5200/work12.html?variant=b) — список и подробности, назначение на странице.
- [В · Периоды в центре](http://127.0.0.1:5200/work12.html?variant=c) — лента и два шага «период → сотрудники».
- [4 · Из текущего кода](http://127.0.0.1:5200/work12.html?variant=code) — прямой импорт `AssignmentsPanel`
  и её рабочих окон из приложения; оболочка стройки сокращена для сравнения.

Все четыре используют текущие `shared/ui`, тему, вымышленных сотрудников и одну фиксированную дату
стройки (22.11.2026). Переключатель сценария показывает обычную бригаду, просмотр без права назначения,
пустой список, отсутствие справочника, 409 при правке и 422 при назначении пачки. Действия меняют только
данные в памяти страницы, до перезагрузки; запросы приложения перехватываются локально.
Фикстуры демонстрируют ответы и не заменяют проверку серверных правил назначений.

Исходники: `src/client/design-system/work12/`; отдельная точка входа `work12.html` включена в сборку
каталога. Новые варианты — новые проекты, а не восстановление утраченного исторического Р2.

## Что восстановлено

22.11.2026 из экспорта `E:\Claude` от 16.11.2026 восстановлены 51 проект с макетами и 50 проектов
с историческими разборами и снимками, всего 203 страницы. Сохранены исходные тексты, данные,
варианты компоновки, вложенные компоненты Claude Design, циклы, условия и доступные изображения.
Решения владельца о выбранных вариантах остаются в документах change.

В разделе «Восстановленные макеты» доступны поиск, выбор проекта и страницы, ширина просмотра,
масштаб, отдельное окно и сравнение с оригиналом. Разборы и снимки доступны через фильтр состава
архива. Оригинальные варианты светлой и тёмной тем на сравнительных листах сохраняются.

Типовые кнопки, кнопки со значком, поля текста и даты, списки выбора, флажки, переключатели, чипы и
пометки в макетах отображаются компонентами текущего `shared/ui`. Стили этих компонентов изолированы
от старых стилей макета; действия передаются исходным сценариям страницы. Тема и значки берутся из
текущего кода. Изменение компонента обновляет его отображение в запущенном каталоге.

Специальные таблицы, навигационные компоновки, иллюстрации и пояснения сохранены из исходников
макета. Это восстановление проектных решений; структура старого экрана сама не меняется вслед за
структурой приложения. Исторические снимки остаются изображениями. Примеры новых компонентов и
состояний живой библиотеки добавляются явно.

## Ссылки и происхождение

Ссылка на проект: `http://127.0.0.1:5200/?section=mockups&project=<UUID>`.
Для конкретной страницы добавляется `page=<имя файла в URL-кодировке>`. Старые публичные ID Claude
сохранены как псевдонимы; `project` также принимает известный ID прежнего артефакта.

- `src/client/design-system/mockups/manifest.json` — перечень проектов, страниц, старых ID, ссылок
  из документов и происхождения. Там же SHA-256 исходного архива.
- `src/client/design-system/mockups/sources.zip` — локальная копия исходных страниц и ресурсов.
  Каталог читает её напрямую; доступ к `E:\Claude` при обычном запуске не нужен.
- `src/client/design-system/restore-mockups.py` — повторяемый импорт из экспорта владельца.
- `src/client/design-system/update-mockup-links.py` — перевод только распознанных ссылок на макеты
  и снимки в локальный каталог. Ссылки на другие рабочие документы Claude он сохраняет.

Импорт читает экспорт без изменения файлов. Для повторного импорта из другого каталога:

```powershell
python -X utf8 src/client/design-system/restore-mockups.py --export E:\Claude
```

**Не найден в экспорте:** «Р2 · Учёт работ: назначения»,
[исходная ссылка](https://claude.ai/artifact/SQn3oWKHrGEeuEQ4o2ySn1), решение владельца от 20.11.2026.
В ZIP от 16.11.2026 этого проекта нет; внешняя ссылка сохранена в архивном change `work-12`.
Макет по описанию заново не придумывался. Рабочее обсуждение ТЗ модульной архитектуры — отдельный
документ, его ссылка в `docs/tz/README.md` остаётся прежней.

## Проверка

```powershell
npm --prefix src/client run ui:catalog:check
npm --prefix src/client run ui:mockups:browser
npm --prefix src/client run ui:catalog:build
```

Браузерная проверка требует запущенного каталога. Она открывает каждую страницу, проверяет
завершение восстановления, содержимое, JavaScript, ресурсы и неразрешённые шаблоны значков.
Изолированные демонстрации не обращаются к API приложения; введённые в них данные не сохраняются
в производственную базу.
