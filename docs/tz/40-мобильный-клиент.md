# 40. Полевой API и приложение Android

Метки пунктов: `MOB-*`. Предметная часть — в `30-учёт-работ.md`.

## 1. Общие условия

**[MOB-1]** Приложение **нативное, Kotlin** (Compose, локальная база Room, фоновая отправка
WorkManager). Причина отказа от веб-приложения в телефоне: очистка данных браузера незаметно уносит
неотправленные отчёты, фоновую синхронизацию убивает энергосбережение, а сервисный работник требует
доверенного сертификата — то есть отсекает заказчиков с внутренним удостоверяющим центром.

**[MOB-2]** Приложение ставится на **личные телефоны**. Значит: минимум данных компании на
устройстве, явный отзыв устройства, никакого доступа к личным данным телефона кроме камеры и
хранилища снимков приложения.

**[MOB-3]** **Офлайн — обычный режим работы, а не сбой.** Ввод отчёта не зависит от сети никогда:
ни при запуске, ни при сохранении, ни при подаче. Сеть нужна только для отправки.

**[MOB-4]** Приложение **одно на всех заказчиков**. Экземпляр выбирается на этапе подключения.

## 2. Подключение

**[MOB-5]** Подключение делается **по приглашению**, которое создаёт менеджер или администратор в
вебе. Приглашение содержит: адрес сервера, одноразовый код, срок годности и — для внутреннего
сертификата — отпечаток ключа сервера.

**[MOB-6]** Первый запуск — честные **два шага**: получить приложение, затем подключиться к серверу.
При публичном сертификате оба шага закрываются одной ссылкой `/m/join` (установка и подключение).
При внутреннем сертификате приложение передаётся мессенджером, а приглашение сканируется уже внутри
приложения.

**[MOB-7]** Экран подключения показывает **название организации, полученное с сервера**, и просит
подтверждения. Причина: пересланная ссылка с подменённым адресом иначе увела бы отчёты на чужой
сервер молча.

**[MOB-8]** Разрешение на камеру для подключения **не требуется**: код можно ввести руками.

## 3. Транспорт: https, http и перенаправление

**[MOB-9]** Поддерживаются три режима связи, режим задаётся приглашением:

| Режим | Когда | Проверка сервера |
|---|---|---|
| `https-pinned` | внутренний или самоподписанный сертификат | отпечаток ключа из приглашения |
| `https-system` | публичный сертификат (Let's Encrypt и подобные) | обычная проверка доверия Android |
| `http` | сервер без TLS | проверки нет ⚠️ |

**[MOB-10]** ⚠️ В режиме `http` токен устройства и содержимое отчётов идут **открытым текстом**.
Режим включается только явным выбором при создании приглашения, приложение показывает это состояние
постоянной пометкой на экране состояния, а веб предупреждает администратора при создании такого
приглашения. Незашифрованный трафик разрешается в настройках Android **только для адреса из
приглашения**, а не для всех адресов.

**[MOB-11]** **Перенаправление http → https.** Итоговый адрес определяется один раз при
подключении: приложение делает запрос сведений о сервере и запоминает адрес, на который пришёл
ответ. Дальше оно обращается прямо по нему.
Причина: при кодах 301 и 302 отправка отчёта теряет тело запроса, и отчёт молча превращается в
пустой запрос.

**[MOB-12]** Переход с `http` на `https` принимается автоматически и фиксируется в состоянии
подключения. Обратный переход, с `https` на `http`, — **отказ** с объяснением, а не тихое понижение
защиты.

## 4. Протокол

**[MOB-13]** Полевой API живёт под отдельным началом адреса `/api/field/`, чтобы на публикующем
прокси можно было написать одно правило: наружу только `/api/field/` и `/m/`.
⚠️ Это прокси, **публикующий нас наружу**, — не тот, через который система сама ходит в интернет
(`CORE-25.2`). Настройки у них разные и не связаны: первый живёт у администратора сети, второй в
настройках экземпляра.

**[MOB-14]** Адреса делятся на две части:
- **без версии** (замороженные навсегда): сведения о сервере, подключение, обновление токена,
  проверка связи;
- **`/api/field/v1/`**: обмен отчётами. Здесь допустимы только добавления, закреплённые тестом на
  неизменность контракта.

**[MOB-15]** **Идентификаторы создаёт клиент.** Повторная отправка того же отчёта не создаёт
дубликата и возвращает тот же результат. Сеть на стройке рвётся посередине запроса регулярно.

**[MOB-16]** Порядок получения изменений с сервера — по **серверной последовательности**, не по
времени. Часы телефона для этого непригодны.

**[MOB-17]** **Часы телефона — заявление, а не факт.** Сервер сохраняет и время устройства, и своё;
расхождения, перевод времени назад и задержка доставки показываются менеджеру нейтральными
пометками, но отчёт не отвергается.

**[MOB-18]** Момент подачи вычисляют **и сервер, и приложение, одинаково** (см. `WORK-10`).
Совпадение расчётов закрепляется общим файлом примеров, который используют тесты обеих сторон.
В файле примеров обязательно есть ночная смена: окно подачи до конца следующих суток (`WORK-10`) — именно ночью телефон и сервер разошлись бы первыми.

**[MOB-19]** Сессия устройства — около 90 дней, с обновлением токена и окном повтора: потерянный на
плохой сети ответ не должен выкидывать монтажника из приложения посреди смены.

**[MOB-20]** Отправка фото — **отдельная очередь** после текста отчёта (см. `WORK-34`).

## 5. Отказы

**[MOB-21]** Приложение различает **семь причин**, почему отчёт не ушёл или не принят, и для каждой
показывает свою фразу. Во всех случаях отчёт на телефоне **не стирается**.

| Причина | Что видит монтажник |
|---|---|
| Нет сети на телефоне | «Нет связи. Отчёт сохранён и уйдёт сам» |
| Сервер недоступен | «Сервер компании недоступен» — с уточнением про офисную сеть, если так настроено |
| Сертификат не совпал | «Сервер не подтвердил себя. Обратитесь к администратору» — отправка запрещена |
| Устройство отозвано | «Доступ отозван» — очередь **не стирается** |
| Приложение устарело | «Обновите приложение, чтобы отправить N отчётов» — ввод при этом работает |
| Период закрыт (`WORK-15`) | «Период по 30.09 закрыт. Отчёт сохранён у вас — сообщите менеджеру» |
| Отчёт за эту дату и смену уже ввёл менеджер (`WORK-31`) | «За 17.09 (день) уже есть отчёт, введённый менеджером. [Открыть его] [Отправить как правку]» — молча не сливается и не отвергается |

Мягкий случай: **стройку сняли с назначения**, пока телефона не было на связи. Отчёт принимается
(работа была), менеджер видит пометку «стройка не назначена на дату» (Ревизия 18.09.2026).

**[MOB-22]** Причину отказа сервер отдаёт **отдельным полем**, а не текстом ошибки: текст пишет
приложение, чтобы формулировка не зависела от версии сервера.

**[MOB-23]** Общей фразы «ошибка отправки» не существует. Причина: «нет сети у телефона» и «сервер
компании недоступен» требуют от человека разных действий.

## 6. Обновление и раздача

**[MOB-24]** Приложение собирается **в каждом выпуске системы** и раздаётся двумя путями: с сервера
заказчика по адресу `/m/` и ассетом выпуска на GitHub. Магазины приложений не используются.

**[MOB-25]** ⚠️ **Риск раздачи вне магазинов.** Google вводит обязательную проверку разработчиков
для приложений, устанавливаемых вне Google Play на сертифицированных устройствах. До начала работ
над приложением (этап 5) это проверяется, и при подтверждении компания проходит регистрацию
разработчика заранее — приложение одно, регистрация нужна одна. Запасной путь — RuStore.

**[MOB-26]** **Обновление не мешает вводу и не стирает очередь.** Ввод отчётов никогда не
блокируется версией; устаревшая версия может лишь потерять право отправки. Обновления локальной
базы приложения, стирающие данные, запрещены.

**[MOB-27]** Уведомлений с сервера (push) в первой версии нет. Синхронизация — при запуске, при
появлении сети и периодически. Напоминание подать отчёт — локальное уведомление телефона.

## 7. Устройства и отзыв

**[MOB-28]** Устройство отзывается из веба, **причина обязательна**: замена телефона, увольнение,
телефон утерян.

**[MOB-29]** Досылка после отзыва:

| Причина отзыва | Что принимается |
|---|---|
| Замена телефона, увольнение | Отчёты за даты не позже отзыва, в течение 14 дней |
| Телефон утерян | Ничего |

Срок 14 дней — настройка экземпляра.

**[MOB-30]** Перед отзывом веб показывает, **сколько отчётов не отправлено** с этого устройства и
какой самый старый. Отзыв вслепую уносит несданную работу.

## 8. Экраны приложения

**[MOB-31]** Пять-семь экранов: список своих отчётов, ввод отчёта, выбор работы, состояние
подключения, профиль. Конкретный состав — за Дизайнером.
**Рабочих пространств в приложении нет** (`AUTH-16.1`): оно обслуживает один модуль, сужать нечего, и
переключателю в этих экранах места нет.

**[MOB-32]** Два **независимых** индикатора у каждого отчёта: доставка (на телефоне / отправляется /
на сервере) и жизненный цикл (черновик / подан / принят / возвращён). Смешивать их нельзя: «на
сервере» не значит «принят».
Поэтому у двух индикаторов **разные средства**: доставка — значками, жизненный цикл — только словом («Подан», «Принят», «Возвращён»). Знак ✓ для обоих не годится (Ревизия 18.09.2026).

**[MOB-33]** Ввод конкретной работы обязан стоить меньше нажатий, чем ввод произвольной: поиск,
недавние, работы этой стройки. Иначе монтажник выберет «прочее» и напишет текстом — так и умер
справочник в старой системе.

**[MOB-33.1]** Приложение работает на **телефонах и планшетах, в обеих ориентациях**. На планшете и в
горизонтальной ориентации список отчётов и открытый отчёт стоят рядом в две панели; на телефоне в
вертикальной — друг за другом.

## 8.1 Примерные экраны

**[MOB-35]** **Смена** (дневная или ночная, `WORK-4`) — часть ключа отчёта, поэтому выбирается **в
шапке рядом с датой** («Отчёт 17.09 · ночь»), а не среди полей; по умолчанию дневная, и тому, кто
работает днём, трогать её не нужно. После подачи смена не меняется — только через возврат. Ночные
отчёты помечены в списке «☾ ночь»; кнопка создания отчёта в ночной смене после полуночи подписана
«Ночная смена 16.09» — смена относится к дате начала (`WORK-8`). Решение 18.09.2026 по `WORK-Q3`,
уточнено Ревизия 18.09.2026.
Кнопка продолжает ночную смену («Ночная смена 16.09»), пока открыто окно подачи вчерашней ночи (`WORK-10`) и у сотрудника есть ночной отчёт за вчера; правило — в общем файле примеров `MOB-18`.

**[MOB-36]** **Исправления к эскизам `MOB-34`** (Ревизия 18.09.2026), обязательны при отрисовке:
- в заголовке отчёта — только стройка; разделы, если их несколько, — строкой ниже («К1, К2»): раздел у
  строки работы, а не у отчёта, и монтажник не должен решить, что на второй корпус нужен второй отчёт;
- смена — по `MOB-35`;
- комментарий при возврате — одна строка с многоточием и «ещё ▾» (`MOB-Q2`); после повторной подачи
  предупреждение гаснет до нейтральной строки истории («Был возврат 16.09 · комментарий ▸») — в эскизе
  сейчас над поданным отчётом висит ⚠;
- доставка и цикл — разными средствами (`MOB-32`).

**[MOB-37]** **Что телефон получает с сервера**, кроме своих отчётов (Ревизия 18.09.2026): классификатор видов
работ с признаками `work.requires*`, разделы назначенных строек, подсказки материалов из `costs` и
`plan` (`WORK-5.1`), позиции перечня этих строек и **участников бригады** — сотрудников, назначенных на
ту же стройку на ту же дату, только ФИО (`WORK-24`). Для каждого справочника — свой курсор по серверной
последовательности (`MOB-16`) и предел объёма (`MOB-2`). При выключенном `costs` или `plan` подсказок
нет, и это видно, а не выглядит пустым результатом.
Строка работы отправляет **вид работы, раздел стройки и единицу**; id позиции перечня — только подсказка. Позицию находит или создаёт сервер (`CORE-12`).

**[MOB-34]** ⚠️ **Эскизы ниже частично устарели** — при отрисовке сначала `MOB-35` и `MOB-36`. Эскизы ниже показывают **состав и порядок** элементов, а не оформление: оформление — за
Дизайнером, в Material 3. Числа и названия — примеры. Условные знаки: `[ … ]` — кнопка,
`( )` — выбор, `▸` — переход, `●` — индикатор.

**Список моих отчётов.** Главный экран. У каждого отчёта два независимых индикатора (`MOB-32`):
доставка слева, жизненный цикл справа. Возвращённые — сверху.

```
┌──────────────────────────────────┐
│ Мои отчёты            ⚙  ● в сети│
├──────────────────────────────────┤
│ ⚠ Возвращён: 1                   │
│ ↑ 16.09 ЖК «Северный», К1        │
│   Возвращён · «уточните метры»  ▸│
├──────────────────────────────────┤
│ ✓ 17.09 ЖК «Северный», К2        │
│   Подан · 3 работы · 8 ч        ▸│
│ ◷ 15.09 Склад «Восток»           │
│   Черновик · не отправлен       ▸│
│ ✓ 14.09 ЖК «Северный», К2        │
│   Принят · 2 работы · 9 ч       ▸│
├──────────────────────────────────┤
│ Не отправлено: 1 (с 15.09)       │
│        [ + Отчёт за сегодня ]    │
└──────────────────────────────────┘
 доставка: ◷ на телефоне  ↑ отправляется  ✓ на сервере
```

**Отчёт за день.** Стройка — только из назначенных (`WORK-21`) или «объекта нет в списке»
(`WORK-22`). Время — на отчёт целиком (`WORK-7`). Комментарий менеджера при возврате — строкой вверху
отчёта (`MOB-Q2`).

```
┌──────────────────────────────────┐
│ ← Отчёт 17.09.2026   Подан ✓     │
├──────────────────────────────────┤
│ ⚠ Менеджер вернул 16.09 14:20:   │
│ «Кабель по К1 — 120 м, не 210.   │
│  Проверьте и подайте заново»     │
├──────────────────────────────────┤
│ Стройка  ЖК «Северный»         ▾ │
│ Время    8 ч 00 мин            ▾ │
├──────────────────────────────────┤
│ Работы                           │
│ Прокладка кабеля   120 м   К1   ▸│
│ Монтаж щита          1 шт  К1   ▸│
│   ◉ 2 · фото отправляются        │
│ [ + Работа ]                     │
├──────────────────────────────────┤
│ [ Сохранить ]    [ Подать ]      │
└──────────────────────────────────┘
```

**Выбор работы.** Поиск, недавние и работы этой стройки — выше полного классификатора (`MOB-33`).

```
┌──────────────────────────────────┐
│ ← Работа   ⌕ кабел_              │
├──────────────────────────────────┤
│ На этой стройке                  │
│  Прокладка кабеля в лотке, м     │
│  Прокладка кабеля в трубе, м     │
│ Недавние                         │
│  Монтаж щита, шт                 │
│ Весь классификатор            ▸  │
└──────────────────────────────────┘
```

**Строка работы.** Место и материалы обязательны, только если того требует вид работы (`WORK-6`).
Материалы подсказываются: отпущено на стройку → по смете → весь справочник (`WORK-5.1`).

```
┌──────────────────────────────────┐
│ ← Прокладка кабеля в лотке       │
├──────────────────────────────────┤
│ Объём      [ 120 ] м             │
│ Раздел     Корпус 1            ▾ │
│ Место *    эт. 3, оси А–В        │
│ Материалы *                      │
│   ВВГнг-LS 3×2,5   120 м       ✕ │
│   [ + Материал ]  отпущено: 4    │
│ Бригадная  ( ) нет  (•) да       │
│   Участники: Иванов, Петров   ▸  │
│ Комментарий                      │
│ Фото  [◉] [▣]  2 из 10           │
├──────────────────────────────────┤
│ [ Готово ]                       │
└──────────────────────────────────┘
```

**Подключение.** Первый запуск: сканировать приглашение или ввести код вручную — без разрешения на
камеру (`MOB-8`). Перед сохранением — название организации с сервера (`MOB-7`).

```
┌──────────────────────────────────┐
│ Подключение к компании           │
├──────────────────────────────────┤
│ [ Сканировать приглашение ]      │
│ или введите вручную              │
│ Сервер  crg.example.ru           │
│ Код     4F7K-92QD                │
├──────────────────────────────────┤
│ Сервер представился как:         │
│  [лого] ООО «Пример Монтаж»      │
│ Это ваша компания?               │
│ [ Нет ]            [ Да, войти ] │
└──────────────────────────────────┘
```

**Состояние подключения.** Одна из пяти причин отказа своей фразой (`MOB-21`), режим связи
постоянно на виду (`MOB-10`).

```
┌──────────────────────────────────┐
│ ← Связь с сервером               │
├──────────────────────────────────┤
```
